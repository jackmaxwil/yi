# D374: the plan tool reads the call it can and says what it changed, instead of...

Status: accepted

## Decision

The plan tool reads the call it can and says what it changed, instead of refusing
(amends the whole-plan apply): a label past the 80-char cap is cut to it everywhere
it is named; `init` while a plan is open adds its new todos to that plan, and its
goal stays; `retry` on a running todo, like `done` on a done one, changes nothing
and says so; `set`, `supersede`, `decompose` or `append` with no rows reads the
plan; a `todos` string whose braces do not balance is mended where each row opens
and closes; `decompose` naming no todo splits the one running; an op on a label the
open plan lacks runs on the one sub-plan that holds it; `block` on a failed todo
retries it first; a whole-plan `set` whose every row is left out is refused, since
nothing landed; a stated accept on a worktree child is a verdict, not a misread

## Why

The owner's target is zero misreads and zero stale-state refusals, and the second
and third stage 5 runs counted misread 9, stale 3 and misread 5, stale 7, each one a
call whose intent was clear

## Reversible via

Restore the refusals in `natural`, `PlanTool::apply` and `apply::apply`, and the
`Declared` string in `declare::normalize`
