# D591: A hard link to a file inside a credential store is refused by identity. The...

Status: accepted

## Decision

A hard link to a file inside a credential store is refused by identity. The read
gate checks the descriptor it opened. In auto mode, while a complete scan of the
stores finds a store file with a name outside them, every bash command asks, since
the sandbox matches the name opened; a rule, a grant or yolo that allows a call
allows it here as it allows a direct store read; the ask is its own kind, so an
approved or rule-allowed call stays contained. While the scan is cut (past
`STORE_SCAN_CAP` entries, or a store that cannot be read), only a named path with
more than one name asks, a redirect source or target included, judged from the cwd
and each distinct `cd` target, up to `CD_DIRS_MAX` (64) dirs, past which the command
asks and names the cap, and the ask and the read gate's open name the cap or the
path, while no protected-path verdict is made of a file the scan could not judge;
the stores are walked once per auto-mode bash decision and never cached, so a link
made mid-session is seen by the next one (3 ms warm at 616 entries, up to
`STORE_SCAN_CAP` entries when cut). The searched tree is never walked (amends D323
and D339, which left the hard link open). Left open: a single-file bind mount of a
store file, which keeps one link; a store file created after a gate's scan, for the
rest of that one call; an APFS clone, which is a new file; and the target of a
symlink inside a store, readable by its own name (#2156)

## Why

A hard link outside a store read a key past the gate's spellings and past Seatbelt;
review of #2136 found a belt that walked the searched tree refusing `rg foo` after
12-14 s, and review of #2153 found that an alias hit took the call out of the
sandbox and that a lexical belt missed `cd`, `xargs` and `git grep`

## Reversible via

Drop `Aliases` from `ReadGate` and the `command_reads_alias` ask from `decide`
