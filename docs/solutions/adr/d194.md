# D194: a cancelled command's whole process tree dies, not only its group

Status: accepted

## Decision

A cancelled command's whole process tree dies, not only its group: `kill_tree` reads
the process table once before any signal (`/proc/<pid>/stat` on Linux, where comm
may hold spaces and parens so the fields split right of the closing paren; `/bin/ps
-eo pid=,ppid=` on macOS, which has no `/proc`), floods from the shell's pid, and
after the group kill sends each walked pid its own KILL through the shell builtin,
best effort

## Why

In the v4 sweep a trial ran `timeout 900 python …`: GNU timeout re-groups its child,
so the group kill (#383) left python running and holding the capture pipes, and the
model's `pgrep -f` then matched its own wrapper's command line and read the dead as
alive; the walk must precede the group kill because a re-grouped descendant
reparents to init once its parent dies and the table no longer ties it to the shell

## Reversible via

Drop `descendants`, `process_table` and `pid_kill` from `process.rs`; the group kill
alone returns
