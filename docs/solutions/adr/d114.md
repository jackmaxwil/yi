# D114: D54 matches results, paths, and skill pointers

Status: accepted

## Decision

The D54 matcher stays one engine. It gains `scope: result` and `scope: error`
(post-tool, remind-only), `paths:` as a glob AND against the call's `path`
argument (`yi-permission::PathGlob`, compiled once per rule) — it reads that
argument and nothing else, so a rule with `paths:` never fires on a tool that
has no path, `bash` among them. `after: N` counts, and the latch is keyed on,
(rule, needle, path), so the same needle on a new path can still speak while a
result whose surrounding lines changed is still the same evidence. Optional
SKILL.md `trigger:` compiles to `Relevant: skill://name`; the two-pointer cap
per scan applies to those pointers alone — a user's own rule is their words and
is never dropped — and a pointer dropped by the cap is not latched, so it
speaks on the next matching scan. A pointer is suppressed after a `read` of
that skill. Gate remains pre-spawn. Regex and stream abort stay out.

## Why

The 0.139.0 cassette scored current recall at 0 on rustc codes that exist only
in a tool result. Skill `trigger:` is optional frontmatter the author already
wrote; a pointer the model fetches is cheaper than injecting the file.
`yi-permission::PathGlob` is the path compiler already paid for.

## Reversible via

Drop `check_result`, `discover_armed`, and the new frontmatter keys.
`rules_e2e::the_lane_fixture_runs_through_the_engine` runs the fire-lane
fixture through the real engine, so the reversal is measured, not asserted.
