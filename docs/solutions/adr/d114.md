# D114: compaction's recall half is an extractive view plus store-native grep

Status: accepted

## Decision

Compaction keeps the P7 LLM summarizer exactly as it was, and gains a
deterministic half beside it. `compile_view` (P19) renders
`<yi_compact_view>` — the cumulative file lists, this round's outstanding
errors, and a rolling 120-line brief that cites every summarized turn as
`(#entryId)` — and `compose_summary` prefixes that view ahead of the LLM
prose, so the post-compact window opens with addressable citations instead of
prose alone. Each compact recompiles the view from the current summarize slice
plus the previous view's `[Brief]` lines, so the brief rolls rather than grows.

The recall half is `SessionStore::grep`: case-insensitive substring over
message text, tool I/O and compaction/branch summaries, thinking excluded,
answering one-line snippets centered on the needle. The host exposes it as
`history.grep`, the kernel skill calls it `await compact.recall("needle")`,
and the hit's `entryId` pulls the full entry through the existing
`history://<agent>/<id>` seam. The post-compaction affordance names both
verbs. No new primary `Tool`, no new crate, no query syntax on `history://`
(D98: schemes are nouns).

## Why

The window after compact held LLM prose plus the P17 user floor, and a turn
the keep-recent window dropped was discoverable only by dumping `history://`
wholesale or grepping opaque JSONL. The log already keeps everything
(`Entry::Compaction` is append-only), so the gap was discovery, not retention.

A compiled transcript as the *summarizer* — the 2026 view-oriented-compiler
move — was weighed and rejected: D21 ports compaction from one reference only,
and the LLM summary is what carries forward intent. The view is host-authored
inside its own wrapper so the UPDATE summarizer treats it as not-its-job, and
it is rebuilt from the slice on every compaction, so it cannot drift from the
log it cites.

Substring rather than a regex crate or embeddings: zero new dependencies, and
the same measurement bar as §14.6 applies — a regex mode lands when grep
measurably fails, which is also the bar embeddings have never cleared. Recall
rides the `compact.run` precedent (host verb plus kernel skill) because the
tool registry stays closed.

## Reversible via

Delete `crates/context/src/view.rs`, the `Preparation.view` field and the
`history.grep` registration. Summaries keep working, because the view is a
prefix on the summary body and old compaction entries never carried one.
