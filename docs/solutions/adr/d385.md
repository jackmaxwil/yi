# D385: cut tool output is kept in the family board's `spills/`...

Status: accepted

## Decision

Cut tool output is kept in the family board's `spills/` (`<sessions>/family/<root
id>/spills/`), which every member of the family writes and reads, walled children
included, and which `yi sessions rm` removes with the session; the hourly sweep that
deleted a spill after 7 days is gone, so a spill lives as long as its session; a
reader session gets its host's board the same way (overrides D340's per-session
spill dirs, amends D316's sweep)

## Why

The owner: "Override D340. I accept the security hole. It has more value than this
esoteric risk", and originals kept "As long as the session" and readable by the
"Whole family"; a child could not open a pointer its parent pasted into its brief,
and a pointer older than a week found nothing; the board was already shared, spared
for walled kernels and removed with the session, so no new root or wall was needed;
the old `~/.yi/spills` and `~/.yi/tool-output` stay walled for walled sessions and
are no longer swept; a contained kernel may write the board but not its `spills/`,
so no cell swaps the dir for a link between the host's check and its open; weighed:
a root with no session id (`yi rpc`) spills under `rlm-<pid>/family/`, which nothing
removes, as nothing removes the rest of that dir, and `/new` in one process keeps
the first session's board for spills as D242 keeps it for the board, so removing
that first session removes them

## Reversible via

Set the session's spill dir back to `~/.yi/spills/<session id>` in `attach_runtime`
and restore `sweep_hourly`
