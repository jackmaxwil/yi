# D455: a login for a provider whose model list is the account's own (cursor, kimi)...

Status: accepted

## Decision

A login for a provider whose model list is the account's own (cursor, kimi)
refreshes that list on success and prints the ids, so a new account model resolves
on the first run after login

## Why

The owner: "use the new kimi k3.1 model", whose id is known only from /models; a
first `--model kimi/<id>` was refused as unknown until a separate `yi catalog
refresh`

## Reversible via

Drop the post-login refresh in yi-cli's `login::refreshed`
