# D63: syntax highlighting is a hand-rolled scanner, not syntect

Status: accepted

## Decision

Syntax highlighting is a hand-rolled five-language scanner in
`yi-tui::highlight` — Rust, Python, shell, JSON and TypeScript/JS — not
`syntect`, and not behind a cargo feature. §8.14's earlier line, "`syntect` with
a trimmed syntax set is a later `highlight` feature", is revised by this row.

## Rationale

The dependency was measured before it was rejected, and the first measurement was
wrong in the dependency's favour. That probe loaded syntect's syntax set and
printed a count without ever parsing a line, so link-time optimisation stripped
the parser it never called and reported 681,984 bytes — +0.38 MiB. The figure
was cited in this row and in the ledger before a rendered frame prompted a second
look. A probe that loads a set *and* runs one `parse_line`, which is what a
highlighter does, reports 1,758,384 bytes against a 286,048-byte baseline built
beside it: +1.40 MiB, over 32 transitive crates, against 0.25 MiB of headroom
under the 6 MiB dist budget. The lesson generalises past this decision: a size
probe that does not exercise the code path being bought measures the linker, not
the dependency.

The second measurement is the one that settles it. syntect carrying **no**
grammars at all — its code alone, which is the shape a trimmed dump would
ship — is 1,395,168 bytes, +1.06 MiB. The 75 bundled syntaxes are therefore only
about 355 KB of the total, so trimming the syntax set down to the five languages
Yi actually shows cannot bring it inside the budget; it would save a third of an
overrun that is four times the headroom. The vendored `.sublime-syntax` blobs and
the `yaml-load` build step a trimmed dump would also cost stop being the argument
against it, because the bytes never worked.

synoptic, the one comparable pure-Rust alternative, was measured on the same
bench at 1,295,632 bytes, +0.96 MiB, and it depends on `regex`, which deny.toml
bans outright rather than by budget. The floor under both is the same thing: a
sublime-syntax grammar and a synoptic rule are both regexes, so a highlighter of
that shape carries a regex engine, and a regex engine is most of a megabyte.
There is no configuration of either crate that avoids it. Every figure and the
correction are recorded in docs/size-ledger.md.

The scanner covers exactly the languages Yi's own surfaces show, and cost 16,544
bytes — a sixty-fourth of the cheapest crate that would have done it. The scope that keeps it small is the scope
that keeps it honest: scanning is per line, so a string or block comment crossing
a line boundary is not tracked, because that state costs a parser and buys one
mis-coloured row. A line over 4 KiB renders plain. There is no token cache,
because the cost a reference LRU-256 exists to amortise is an FFI hop and a regex
engine, and this is a char walk. An unknown language name renders plain rather
than guessing.

The cargo feature goes with the dependency. A feature exists to make a dependency
optional, and there is no dependency — a feature gating nothing gates nothing,
and would only add a build configuration nobody exercises. The policy borrowed
from the reference is kept exactly: foreground and bold, never a background, never italic
or underline. A background would fight the U37 tint the row renders inside, and
the other two attributes are what terminals render least consistently.

## Reversal path

Delete the module and the four call sites; every surface renders the plain text
it rendered before.
