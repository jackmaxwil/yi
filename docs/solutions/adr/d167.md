# D167: the forge CLI is `fgj`

Status: accepted

## Decision

The forge CLI is `fgj`: the origin URL picks `fgj` (any host) or `gh` (github.com)
behind the same `match` D122 set, `open_pr_in` reads `fgj pr list --json` rows by
`head.ref`, `host_of` reads the origin's host for `fgj api --hostname`,
`scripts/forge_pr.py` sends bodies through `fgj api --input -` and reads a 404 from
`HTTP 404` on stderr, and the tracking script, the metadata gate, `docs/FORGE.md`
and the yi-track and yi-forge skills spell every fix line in fgj's `gh`-shaped verbs
(a milestone through `fgj api -X PATCH … -F milestone=<id>`, this build's `issue
edit` having no milestone flag)

## Why

Tea 0.15.1 ships go-sdk v1.2.0, written against a Gitea whose routes this Forgejo
(15.0.7+gitea-1.22.0) does not serve: `tea actions runs view|logs` are 404s, `pr ls`
needed `--fields --output tsv` to parse, `issues` and `--add-labels` match no other
forge CLI; fgj (codeberg.org/romaintb/fgj) is Forgejo-native, detects repo and host
from `origin`, carries `--json` on every list and view and `fgj api` with methods,
fields and stdin bodies, verified against the forge 2026-09-08 (issue #312); job
logs stay unserved by this Forgejo either way

## Reversible via

Restore the `tea` spellings in the six files; nothing else changed
