# D304: the fixer is a fresh `yi ask --auto` on the PR branch, never the authoring...

Status: accepted

## Decision

The fixer is a fresh `yi ask --auto` on the PR branch, never the authoring session:
`just pr fix N` hands it the last round's high and medium findings (template and
duplicate findings are the author's), it may decline a medium one with a reason that
lands in the commit body, and the host discards the whole change if it touched
`.forgejo/`, `.github/` or `scripts/guardrails/`, commits through the hooks (its
accept) with its subject when that passes the subject rule and a fixed one
otherwise, and pushes to the branch without force; it runs only on a head a round
has read, only for a branch in this repository, and a PR still blocked after three
rounds goes to the owner; nothing in the lifecycle merges

## Why

The owner chose "Auto-push to PR branch" and "Fresh fixer always"; the gates' own
files are walled by the host because a fixer that can edit its judge has no judge,
and #334-#364 were merges nobody asked for

## Reversible via

Delete `cmd_fix`; the rounds keep listing findings for a person to fix
