# D131: a harness run is isolated and the invariants check themselves

Status: accepted

## Decision

A harness run is isolated and the invariants check themselves: every driver of the
real binary — `scripts/tui_pty.py`, `evals/run.py`, the drives — runs under an
ephemeral absolute HOME, `yi tui --headless` implies `--here` unless `--lanes`, a
relative HOME is refused at boot naming itself, and `yi doctor` reads one table of
invariants (HOME absolute, config parses, catalog cache age, daemon socket alive or
absent, every ledger row's root exists, lanes consistent with the pool and no
orphan) printing one line per row, exit 1 on any failure, `--fix` for the safe
repairs (a dead socket file, an orphan the pool can reap) and `--json` for CI

## Why

Four of the eleven escapes of 2026-09-05 were harness runs under the developer's
HOME: killed drives left three orphaned lanes, a relative HOME planted a worktree
beside the repository with an error naming the wrong step, and a stale ledger row
from a deleted worktree was resumed at boot. None was a fixture's business; each was
an environment nobody checked. The table is data the binary reads, so a new
invariant is one row and one check, and the repairs are the ones a human would type
anyway — a relative HOME and a gone ledger root are reported, not guessed at. Plan:
docs/plans/2026-09-05-the-ci-is-the-first-user.md §3.A–B, step 1 of §7

## Reversible via

Drop `doctor.rs` and the `--lanes` flag; the harnesses keep their `--home` defaults,
which cost nothing
