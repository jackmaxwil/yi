# D195: the tool surface a session registers is locked and priced from the session's...

Status: accepted

## Decision

The tool surface a session registers is locked and priced from the session's own
table: `yi_runtime::session_tools` holds the construction `main.rs` had inline,
`AgentSession::tools()` exposes the registered set, and the request-budget test
builds a real session over `attach_runtime` and prints a `TOOL_SURFACE` line per
tool, per kernel extra and for the identity fragment; `check_request_budget.py`
locks each line's sha256 in `tool_surface.json`, and a PR whose diff moves a key
owes a `## Claims ledger` table, an added key also `## Neighbour matrix` and `##
Dogfood` (`surface_problems` in check_pr_metadata.py judges the section's shape;
`just pr-body` prints the skeletons and now prefills the template's `## Seen red`;
`just pr open` drops a counted section the author's prose already heads); the
dogfood method is the `yi-dogfood` skill, with its four testing rules in 080 (Refs
#376)

## Why

D171's worst defects were claims that unit tests and fixtures passed, found only by
real files and a played session; the budget test priced a hand-built table (builtin
tools plus plan and todo) that understated the surface a model reads by 2,635 bytes
— the measured tools block is 19,383, not 16,748 — so a description could change
under a green budget with nothing owed; and `just pr open` appended the prefilled
sections even where the author had written them

## Reversible via

Delete the lock, `surface_problems` and the skeletons; `session_tools`, the skill
and the 080 rules stand alone
