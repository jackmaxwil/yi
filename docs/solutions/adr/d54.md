# D54: triggered rules are a deterministic layer that speaks

Status: accepted

## Decision

Yi discovers user-authored rules in `~/.yi/rules/*.md` and `<cwd>/.yi/rules/*.md`
(project shadows global by name) and fires them at the moment they apply. The
runtime is a *matcher delivering the user's own verbatim words*, never a reviewer
generating judgment: zero rules ship built in, the trigger is a literal the
author wrote, every rule carries a repeat gap, and the delivered text is the rule
body unedited. `mode: gate` denies at the tool seam before the permission check
and before any spawn, carrying the body and source path as evidence; `mode:
remind` speaks at the boundary. The V7 emission guard is deliberately excluded
from this path.

## Rationale

This threads D50, which deleted the deterministic advisor. D50's failure was
runtime-shipped, always-on heuristics speaking in the runtime's own voice; every
axis is inverted here — user-authored, precisely triggered, gapped, verbatim.
A surveyed TTSR lifecycle supplies the pattern. §16's TRACE evidence puts compiled
checks at 2–37% violation against 57.5% for recalled prose, so this is the
ladder's middle rung between doctrine text in the system prompt and a permission
hold.

The guard exclusion was found by test: its session-scoped dedupe silently
swallowed a re-arm the user had asked for by writing `gap: 2`. The per-rule gap
latch is the noise budget instead.

## Reversal path

Delete `yi-runtime::rules` and the two seam hooks (the adapter pre-check and the
boundary observer). Rule files are inert markdown without them.
