# D343: a prompt or skill that lists a tool's fields lists them in a `<!-- yi

Status: accepted

## Decision

A prompt or skill that lists a tool's fields lists them in a `<!-- yi:schema <tool>
<json-pointer> -->` block rendered from the live schema: one line per property in
schema order, with its type, `required`, its enum values and its description;
`prompt_drift::every_schema_block_is_the_schemas_own_rendering` re-renders every
block in `crates/runtime/src/prompts/*.md` and `skills/*/*/SKILL.md` and fails on
any difference, names the blocks the plan's todo and contract-item shapes must have
(orchestrate, the plan skill, the review skill), and `just schema-blocks`
(`YI_BLESS=1`) rewrites them; the plan tool's contract fields gain the descriptions
the rendering reads; prose outside a block is not derived

## Why

The owner: "skills and prompts like orchestrate cannot be allowed to drift. skills
should be derived from actual schema", and chose generated blocks over expansion at
load and a name check; after #957 fixed orchestrate.md by hand, the plan skill still
taught title, acceptance, check and deps, and the review skill a todo-level `check`
the tool never had. Blocks keep the committed file identical to what the model reads

## Reversible via

Delete the blocks' markers and the test, restore hand-written field lists
