# D302: a reader's answer shape and shared context go to the provider

Status: accepted

## Decision

A reader's `schema` reaches the provider through `yi_ai::schema`. Anthropic gets
`output_config.format` only when the schema closes every object (properties, all of them
required, `additionalProperties: false`) and carries no keyword strict mode refuses; chat
`response_format` and Responses `text.format` get it always, with `strict` set by that test. The
reader's question names the schema. Its partition is its own first message, kept in the
transcript, and `LlmContext.shared_through` is `Some(0)` when a sibling sent the same partition
within 300 s, for the breakpoints to mark

## Why

The owner chose to send the answer schema to the provider and to mark context several children
share. Plan readers were refused as prose ten times in row 0058, and the judge replay needed
`response_format` to get JSON at all (row 0060). A schema strict mode refuses would 400 on
Anthropic, so an open one stays guidance there (#824)

## Reversible via

Drop the schema kwarg and `yi_ai::schema`, send the partition inside the question message again,
and remove `shared_through`
