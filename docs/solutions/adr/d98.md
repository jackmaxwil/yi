# D98: every reference is a URL, and one resolver is the only read path

Status: accepted

## Decision

`yi_types::url::Url` is the one reference type. It parses at construction —
scheme, path, optional fragment — and serializes as the flat string, so a plan
file, a delegation context, a `Done` output and a commit trailer all carry the
same bytes. Eight schemes resolve internally, and the set is open: an
unrecognized scheme parses into `Scheme::External(String)` rather than failing,
because `https`, `github`, `s3` and `mount` are legal *references* even where
they are not free reads.

`crates/runtime/src/fetch/` is the only thing that turns one into content.
`Resolver::resolve` is a single match with one arm per scheme and no write arm:
a URL names a noun, and every effect stays a tool call under permission.

| scheme | serves | needs attached |
|---|---|---|
| `local://<path>` | a workspace file; an absolute path only inside the spill dir | nothing |
| `plan://<plan>[/<todo slug>]` | the plan file, or one todo's record plus its `## <label>` prose section | nothing (it reads `plans.dir` directly) |
| `history://<agent>[/<entry>]` | the transcript, or one entry | a session store |
| `user://<n>` | the n-th user message, verbatim | a session store |
| `kernel://[<agent>/]<var>` | `repr()` of a live kernel variable, truncated at 8,192 chars | a `KernelVariables` backend |
| `checkpoint://<tree>/<path>` | a file as of a shadow-gitdir capture | an opened shadow gitdir |
| `mcp://<server>/<resource>` | an MCP resource, exactly as the server returned it | an `McpResourceRead` |
| `agent://<plan>/<todo>` | whatever the child's reap pin points at | a pin in the fetch log |
| anything else | nothing — refused | — |

A missing backend is `FetchError::Unsupported` naming what is missing, not a
silent empty read: *"kernel://main/x: unsupported here; missing an
agent-to-kernel reader on this resolver: nothing attached one at composition."*
`wiring.rs` attaches all of them for a live session; `yi fetch <url>` at the CLI
attaches the plans dir and the MCP one-shot only, so the same URL that resolves
in-session reports which backend the CLI lacks.

**The seam enforces three terms, before any scheme arm runs.**

*Permission.* `Wall::check_url` is the first statement in `resolve`. `deny_url`
is a literal prefix match over the rendered URL — one vocabulary for files,
kernels, agents and remotes — and `deny_read` maps into `local://` alone,
because a fetch is read-only and a write wall has nothing to say about it. The
refusal text is the wall's own, so a denied fetch and a denied tool call read
identically to the model. An `External` scheme is refused with the reason
rather than resolved: *"external scheme https is a tool call under permission,
not a free read."*

*Provenance.* `fence_untrusted` wraps content in E4's yard fence — the same
`<<<yi-external … trust="untrusted">>>` sentinel `ext/assemble.rs` already used
for instruction sources — with a nonce taken from the first 12 hex of the
content's own sha256. The order inside it is load-bearing and was learned the
hard way: control bytes are stripped *first*, then `<<<` is escaped to `<\<<`.
Escaping first let `<<\0<` slip past the escape and re-form an unescaped
sentinel once the control byte was dropped, forging `trust="trusted"` inside a
body; the test that reproduces it is `fenced_content_cannot_close_its_own_fence`.

*Cost.* Internal schemes are free. External ones are refused here so they go
back out through the broker that already prices tool calls.

**References carry expectations.** `local://` and `checkpoint://` take a
`#L<start>-<end>@<TAG>` fragment; every other scheme refuses one at parse. The
tag is four UPPERCASE hex digits (lowercase does not parse), line zero and an
inverted range are refused at construction, and a range past EOF refuses rather
than truncating — and does not land in the log, so a clamped read can never
back a citation. A tag mismatch is `FetchError::Stale` naming both tags.

**The log is the pin ledger and the instrument.** Every *successful* fetch
appends a `custom{fetch}` entry — url, sha256 of the served text, and which
backing store served it — and pushes a record into `FetchLog`. `backs()` keys on
scheme plus path: a fragment is an expectation about content, not an identity,
so a fetch of the file backs a citation of a span inside it. `unbacked()` is the
whole fabrication check.

**Ephemeral and durable are typed, and terminal records are durable-only.**
`Scheme::durability` calls `agent://` and `kernel://` ephemeral. `TodoState`'s
`Done{output}` and `Failed{last}` are gated by `table::check_terminal`, which
uses the owner-relative `terminal_durability(url, owner)`: `kernel://main/x` is
durable, `kernel://<child>/x` is not. That asymmetry is the whole point — the
owner's namespace outlives every child, which is what makes it the target a
child's variable is promoted *into* at reap. `PlanOpError::EphemeralTerminal`
is the refusal.

**Pins are minted by the host.** `SessionDelegate::reap` registers
`agent://<plan>/<todo>` → `history://<plan>/<todo>` in the same log, and
`register_pin` refuses both wrong directions: a durable source (nothing to
downgrade) and an ephemeral target (a pin that dies with its referent).
`rewrite_terminal` maps a citation list through the pins and fails the record on
an unpinned ephemeral. No model ever types a hash.

**`user://<n>` is 1-based over `Attribution::User` alone.** A host-minted
user-role message — compaction filler, a synthesized preamble — is invisible to
the index, so interleaving one cannot shift what an existing citation names, and
`user://1` over a transcript holding only host-minted messages fails with
*"the transcript holds 0"*.

The resolver is 1,421 lines over three files, the URL type 338, and 25 tests
carry them.

## Rationale

Before this row, a delegation context, a `Done` output, a plan body reference, a
compaction citation and a permission wall were five mechanisms with five
security models. Collapsing them buys one enforcement point that cannot drift
per scheme — but the sharper win is an instrument that did not exist at all.

**What a child was handed against what it actually read is now a grep.**
*Supplied* is the URL list in the delegation; *referenced* is the fetch log's
records for that agent. Over-supply and under-supply were the fan-out work's
most valuable metric and its most expensive to instrument; here they cost
nothing, because the log has to exist anyway to hold the pins. Fabrication
detection lands on the same data: a citation absent from the log is a lookup
failure, not a judgment call, at zero model cost. And a URL in a prompt is a
short stable string, so heavy context stops moving transcript bytes and composes
with the cache breakpoints instead of fighting them.

**Pins are host-minted because the alternative is a model typing cryptography.**
An agent cites what it fetched, in the live form it fetched it; the log already
holds the tree, tag and hash of everything it served, so the host rewrites at
the terminal seam. This is the same lesson as opaque ids, applied to hashes: any
identifier a model has to reproduce exactly is one it will eventually reproduce
approximately.

**Two bounds are recorded rather than hidden.**

The first is the hashline tag. It is a whole-file xxh32 masked to 16 bits —
65,536 buckets — over `SnapshotStore`, which keeps four versions per path for at
most 256 paths and 64 MiB and evicts by LRU. Two consequences follow, and the
implementation states both rather than implying more. A file that changed but
landed in the same bucket passes: the tag detects drift, it does not
authenticate content. And an expired pin — a tag that was real but whose
snapshot has been evicted — is not distinguishable at this seam from one a model
invented, because both are simply *not the live tag*. So the error says exactly
that and nothing more: *"the referent moved, or the tag was never minted."*
The sha256 in the fetch log is the evidence-grade half; the tag is a cheap
staleness anchor that fails loud, and it is not a signature.

The second is reach. `local://` and `plan://` resolve anywhere, against the
filesystem. `history://` and `user://` need a store, and `history://` serves
only the agent the resolver is attached to, naming it in the refusal — the
cross-session corpus the design sketches waits on a store that can open a
session file it is not attached to. `kernel://` needs a `KernelVariables`
backend and a kernel already running (a fetch must never boot one), and it
parks the calling thread, so it is reachable only through the `spawn_blocking`
contract `wiring.rs` honors. `checkpoint://` needs the shadow gitdir to open,
and `mcp://` needs the one-shot CLI reader — every MCP socket and token stays in
`yi mcp`, never in the resolver. `agent://` needs a pin, and then resolves only
as far as that pin's target does. External schemes never resolve.

Three smaller honesties in the same spirit. `backs()` ignoring the fragment
means the unbacked check catches *never read this file*, not *never read those
lines*. Cost is enforced today only in the negative — the resolver holds no
cache and prices nothing, because nothing it serves costs money yet; the log
holds hashes, not bodies. And `Wall::from_kwargs` does not yet parse a
`deny_url` key, so the only denies a live wall carries into URL space are its
`deny_read` paths mapped onto `local://`; the URL vocabulary is enforced,
tested, and so far spoken by no producer.

The parts that deliberately did not fold are what keep this from rotting into a
capability system: no verbs, no writes, no scheme that could name a secret,
resolvers built in rather than pluggable. `kernel://` is the one arm where a
path segment reaches a runtime, and it is narrowed twice — validated as an ASCII
identifier of at most 128 bytes, then passed as a JSON string literal into a
namespace *lookup*, never an eval.

## Reversal path

Delete `crates/runtime/src/fetch/` and, with it, `Wall::check_url` and
`Wall::deny_url`, which have no other consumer. The walls fall back to their
path-prefix form over tool arguments, which is the only enforcement any caller
relies on today. `yi_types::url` stays: D97 addresses todos with it and D99's
commit trailer is one of its strings, so the reference type outlives the read
path.
