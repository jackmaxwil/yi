# D328: ACP v2 conformance is measured against a vendored upstream schema tag...

Status: accepted

## Decision

ACP v2 conformance is measured against a vendored upstream schema tag (amends D1):
the hand-rolled subset stays in `yi-types::acp`, `schema/v2/schema.json` at
`schema-v2.0.0-alpha.5` is vendored byte for byte under
`crates/cli/tests/fixtures/acp-v2/` with its sha256 pinned in the test, and every
frame a faux session emits must pass it strictly (no custom field at the root of a
spec type, no `other` value that does not begin with `_`); Yi's own fields on
standard shapes ride `_meta.yi`; a `session/prompt` is answered with `messageId`
only once its `user_message` is emitted; a newer alpha is followed by adding its
file beside the old one when it changes a shape Yi emits or decodes, never by
tracking upstream per commit; the official `agent-client-protocol` crates are not
adopted

## Why

A strict alpha.5 client could not use Yi and no test could see it: `initialize`
advertised no `session`, so such a client never called `session/new`; the prompt
response lacked the required `messageId`; an edit's diff rode a root `content` field
no spec client reads, so it approved blind; config options nested under `kind` and
list rows without `cwd` were dropped as invalid items; the types-only crate still
requires `anyhow` (banned), adds a second `strum` (multiple-versions deny) and would
breach the yi-types dependency wall, and its v2 module sits behind
`unstable_protocol_v2` outside semver

## Reversible via

Adopt `agent-client-protocol-schema` in `yi-types` once it drops `anyhow` and
stabilizes v2, deleting the standard types and keeping `AcpExtensionUpdate` as its
`OtherSessionUpdate`
