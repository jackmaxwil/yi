# D402: yi-context depends on yi-tools, so compaction reads an `edit` call's files...

Status: accepted

## Decision

Yi-context depends on yi-tools, so compaction reads an `edit` call's files from the
`[path#TAG]` section headers of its `patch` with the hashline patch parser rather
than a second header parser

## Why

The `edit` tool takes only `patch`, so compaction's file tracking, which read a
`path` argument, recorded no edited file in production: `modifiedFiles` held only
`write` paths, the brief named an edit with no file and no read was ever marked
stale; yi-tools does not depend on yi-context, and yi-runtime, the only consumer of
yi-context, already builds yi-tools

## Reversible via

Drop yi-tools from yi-context's manifest and boundaries row and move the header
parser into yi-context
