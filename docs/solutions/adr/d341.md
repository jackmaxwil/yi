# D341: a walled session reads no transcript but its own (amends D340, D335)

Status: accepted

## Decision

A walled session reads no transcript but its own (amends D340, D335): a session
whose wall is not empty has every session store, `~/.yi/sessions` and the
`--session-dir` in use (`tools::session_stores`, the stores the broker holds host-
owned, now carried to a child broker by `for_child`), added to its calls'
`deny_read` beside the spill roots, and its own transcript file spared:
`ToolContext::transcript` joins `recovery_dir` in `ReadGate::except`, so `read` and
a grep naming the file open it while every other transcript and every walk under a
store is refused, and a contained command's profile denies each store and re-allows
reads of the own transcript in a later rule (`Sandbox::spared`, now a list); a
walled reader's `tree://` read takes the stores as walls too
(`Resolver::file_walls`); the own transcript is the file alone, not its dir or its
children's, which reach a parent through `history://` and the mailbox on the host

## Why

#971, review of #968: a juror could `read` and grep its author's transcript, which
holds every tool output, file and turn its wall hides, bypassing the `history://`
deny through the file; weighed: sparing the own transcript dir (a child's `sub-*`,
holding its children), rejected, since a root session's dir is every session of its
cwd and nothing a walled session does reads a child's file; walling the stores in
the wall itself, rejected, since the kernel profile takes the wall and its private
dir and the family board sit under the store; a walled session's kernel cells and
its uncontained bash still read transcripts, the open item #885 named for spills

## Reversible via

`own_walls` without `session_stores`, `ToolContext::transcript` unset and
`Resolver::file_walls` back to `deny_read`
