# D75: plan tasks carry an executable acceptance check

Status: accepted

## Decision

`Task.check` is additive on yi-types; the done transition runs it through
`goal::run_check` (exit-0-only, 2,000-char evidence tail) and a red check refuses the
transition with that tail. The advisor digest header counts check-less done-claims in one
sentence; no Reviewer enum.

## Rationale

D52 host-verifies every plan transition except the one that matters — done was still taken
on the model's word. TDFlow measures 94.3 % with human-written tests against 68.0 %
self-written, so the check is the bottleneck, and LLM self-critique is net-negative
(2402.08115, 2310.01798): the gate has to be executable, not prose. `run_check` has enforced
goal completion since 0.33.0, so this is a field read on an existing seam.

## Reversal path

Drop the field read and the digest count. The field survives as unknown data on older
readers under the §19 additive law, and the fixture keeps deserializing.
