# D160: the kernel boots with what the machine has and says what it lacks

Status: accepted

## Decision

The kernel boots with what the machine has and says what it lacks: `find_toolchain`
takes `uv` on PATH or under `~/.local/bin`, else a `python3` (or `python3.13/12/11`)
that is 3.11+ and imports `venv` and `ensurepip`, else the uv installer when
`YI_INSTALL_UV=1`, else one error naming all three; the venv is built with
`--system-site-packages` on either toolchain from the interpreter that exists (a
managed CPython only when none is 3.11+, no `--seed` on the uv path), the required
set (`ipykernel`, `dill`, the runtime) in one call with `--compile-bytecode`, the
bundled skills in one degradable call, and only the default extras the venv cannot
already import in a third; readiness is one probe subprocess; a
`ModuleNotFoundError` in a cell appends "`x` is not installed in the kernel. Run
`%pip install x` in a cell; `pip` in bash installs into a different Python"; the
environment block carries `kernel: ready|booting|idle|unavailable: <reason>`; `yi
doctor` gains `kernel-toolchain` and `kernel-boot` (build ms or `cached`, kernel
start ms, bootstrap-cell ms), `--fix` builds the venv, and the harbor adapter runs
`yi doctor --fix --json` at install and refuses an image whose kernel rows are red;
`extract.py` counts `kernel_dead` and `module_missing`

## Why

Across the 158 sessions of rows 0018-0023, 8 of 9 `ipython` calls returned "uv is
required to set up the Python kernel" (the v4 images ship python3 and no uv), the
one kernel that booted died on `import xlrd` because the venv was sealed from the
image's packages, no session ever reached `rlm`, and the model used bash for the
rest of every hour (issue #289); a cold build also downloaded a CPython beside an
existing python3, seeded pip the uv path never used, installed 262 MB of extras
before the kernel was usable, and probed readiness twice
(docs/archive/plans/2026-09-08-pass-levers.md S2)

## Reversible via

Delete `Toolchain`, `find_system_python`, `create_venv`, `pip_install` and the two
doctor rows; `ensure_uv` and the single install call return
