# D367: while a cell a client sent through `_yi/kernel_execute` runs, a child's...

Status: accepted

## Decision

While a cell a client sent through `_yi/kernel_execute` runs, a child's lifecycle
notice queues without waking the idle parent, amending §7.5's wake (a model-run cell
already holds the parent running, so its notices only queue); unseen notices wait
for the next turn

## Why

The Python client's journey caught the idle root taking a paid model turn for every
finished child its own cell was about to read with `rlm.result`, which at 128 wide
would be up to 128 turns of the root's whole frame

## Reversible via

Drop the `user_cell_running` check in `wake_idle_hook`
