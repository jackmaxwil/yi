# D58: agent messages carry a provenance envelope, not the assistant role

Status: accepted

## Decision

An agent's words reach another agent as a provenanced `custom{agent_message}` —
`<agent_message from="…">…</agent_message>` inside a user-role message — not as
an injected assistant-role message the way B6 specifies. Host status
notifications stay user-role, unchanged.

## Rationale

B6 took its role split from codex and prime, whose providers accept consecutive
same-role messages. Anthropic's Messages API requires roles to alternate, and a
child's report lands exactly where a turn just ended, so the assistant-role form
would put two assistant messages back to back on Yi's own default provider. That
hazard cannot be exercised offline — the faux provider does not model it — so
shipping it would have meant shipping an unverifiable wire risk.

The hardening B6 actually wants is provenance the model can see, and the envelope
carries it: the text is visibly another agent's, not the user's. The
`yi_internal_context` wrapper was the other candidate and is wrong here for a
different reason — it is dropped at compaction by design, and a child's report is
content the parent needs to keep.

## Reversal path

Swap `agent_message()` in `crates/runtime/src/mailbox.rs` to build an
`AgentMessage::Assistant`. Nothing else reads the envelope.
