# D418: a kernel cell calls the session's own tools through one host verb,...

Status: accepted

## Decision

A kernel cell calls the session's own tools through one host verb, `tool.call`,
which runs the same adapter a model call runs, so rules, wall and broker judge each
nested call on its own arguments; `ipython` and a root's `ask_user` are excluded,
write and exec calls are serialized by one lock, and every call that ran is a
`NestedCall` row on its cell's `ipython` result

## Why

Kernel Python could not call `grep`, `edit`, `write`, `get_context`, `todo` or
`annotate`, and `rlm.fetch` returns text with no hashline tags, so a program could
find lines but never edit them; host verbs bypassed the adapter's gates

## Reversible via

Drop the `tool.call` and `tool.list` registrations and `yi.tools`; the rows are
optional and readers that find none behave as before
