# D235: every open request is answered or chased, and every run ends with an answer

Status: accepted

## Decision

Every open request is answered or chased, and every run ends with an answer: when a
member's run concludes `Completed` with a request to it still open,
`SubagentHost::chase_open_requests` steers it once through its queue (a waking host
notice naming the id and the `reply_to` call, `Desk::nudged`), and a second such
ending routes that run's last assistant text as the reply with `Envelope.answered_by
= "final_text"`; a plain `inform` from X to a child with exactly one request open to
X is rewritten into the reply to it (`as_answer`); `rlm.wait` returns at once with
`state` `asks` and cause `asks` while a child asks its caller and with `state`
`settled` and `finished` when every child has an exit, else `moved` or `timeout`,
and `_calm` pauses the helpers that wait on one child (`RLMSpawnHandle.result`,
`result`, `Todo.result`, `Run.settle`) on such a reply; every public `rlm` call is
an `RLMCall`, a task subclass scheduled on the running loop at the call, marked
taken when awaited, called back, or read, and the post-run-cell hook starts nothing,
waits for and names only the calls nobody took (revises D232);
`LoopConfig::last_word`, asked once when `should_stop_after_turn` stops a turn that
ended on tool calls, runs one more turn with tool choice `none` carrying `[deadline]
Time is up ...` when the wind-down, not a parent's cancel, stopped it; `yi ask`
gives a turn in flight 90 s past `--deadline`, then aborts the session and shuts its
runtime down within 10 s, exits 1 when the run ended without a final answer, and
names services and open requests in its leftovers; a child's `Receipt` carries
`presented` (stage M4 of `docs/plans/2026-09-23-the-mailbox-delivers.md`; amends
D230, D232, D233 and D234)

## Why

The paid confirmation of M1-M3 at 9f29fa88 found a service that answered a request
in prose while the parent's `rlm.request` waited out 300 s (2 of 3 rounds), a parent
that answered a blocked child with four plain sends and waited on it each time, un-
awaited sends that ran only after the result they were meant to shape, a wait loop
on a family with nothing live that ran until the 540 s kill against a 420 s deadline
(the deadline's watcher never ran again once `yi ask`'s follow returned on its
single-threaded runtime), three runs the wind-down ended on a tool call with no
answer and exit 0, and receipts that read `queued` whichever way a message went

## Reversible via

Drop `chase_open_requests`, `Desk::nudged`, `as_answer`, the `asks` and `settled`
returns and `_calm`; return coroutines from `_handed_out` and run the unstarted ones
in `_settle` again; drop `LoopConfig::last_word`, the follow grace, the abort and
runtime shutdown and the no-answer exit in `yi ask`; and drop `Receipt.presented`
(an older reader ignores it)

## Amends D232

D232 kept every call a coroutine and ran the ones a cell never started after the cell,
so a send the cell never awaited went out after the result it was meant to shape. Every
call is now a task from the moment it is made. Gathering a collected list, a stored call
awaited later, a conditional await and a semaphore helper keep working, since a task is
awaitable, and the after-cell hook reports what nobody took and runs nothing.
