# D390: a reduced output keeps every line naming an error, failure, panic,...

Status: accepted

## Decision

A reduced output keeps every line naming an error, failure, panic, traceback,
exception or assertion from the middle its head and tail cut, with 3 lines either
side and at most 60 such lines (`SIGNAL_ROWS`, named in a row when it cuts); runs of
passing-test lines (cargo, pytest, jest; never a line naming a failure) become one
`[N passing tests omitted: a-b]` row; grep, rg and ag output of `path:line:` matches
over two or more files shows at most 3 matches a file, the rest as `[+N more in
<path> (GREP_PER_FILE 3): output lines a-b]`, and takes no middle pass, so a search
for `error` stays inside its line budget; a counted row carries the first line it
stands for, so a gap beside it claims no line twice; a failure or passing-test line
is never read as progress

## Why

Recorded from the real tools: a `python -m compileall` printed its one `SyntaxError`
at line 814 of 1,506 and the reduced output dropped it; `pytest -v` lines end `[
54%]`, which the progress rule read as a bar, so each overwrote the one before and
the FAILED line at 223 of 419 was lost; one busy file filled an `rg -n` head over
283 files

## Reversible via

Drop `is_signal`'s middle pass from `cap_lines`, `collapse_passes` and `per_file`,
and the progress exemption in `compress`
