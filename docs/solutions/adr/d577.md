# D577: a message's content block or stop reason of a type this build lacks decodes...

Status: accepted

## Decision

A message's content block or stop reason of a type this build lacks decodes to
`Other`, keeps its raw value and re-emits it as serde_json writes it, as an unknown
entry does; provider history, the TUI, console and ACP transcripts and compaction
input show one `[… 1 content block left out: …]` row where it sat, never its type,
while an explicit whole-entry read (`history://<agent>/<entry-id>`, `user://<n>`)
returns the entry as written; an unknown stop reason reads as a turn that ended

## Why

A session a newer build wrote (an older daemon reading it after a new variant lands,
or Pi) was refused whole as an invalid file over one inner tag, and a block sent raw
to a provider that cannot read it fails the request, while one dropped with nothing
in its place tells neither the model nor the user a block was there

## Reversible via

The `Other` arms of `Content` and `StopReason`, `UNREAD_CONTENT` and `shown_text` in
`crates/types/src/message.rs`, and their arms in the consumers; a session holding
such a line is then refused again
