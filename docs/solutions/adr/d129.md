# D129: the model picker shows each row's mark

Status: accepted

## Decision

The model picker shows each row's mark: `yi-tui::logos` ships the provider and lab
logos as 32×32 coverage masks (`crates/tui/data/logos/*.a8`, rasterized once by
`scripts/logos.py` from models.dev's SVGs, deflated into one blob by
`crates/tui/build.rs`), tinted with the orb's ink at transmit; on kitty each visible
model row gets one placement at the two-cell slot after ` › ` (`place_nth`, one
placement id per row so a repeated image still shows on every row), all placements
are deleted and re-placed whenever the visible rows change, and none outlives the
popup; elsewhere the slot is a two-letter glyph in the key's accent. An OpenRouter
row is keyed by its lab, a native row by its provider; a lab whose SVG models.dev
serves as a shared placeholder ships no mask and keeps the glyph

## Why

Every mark models.dev serves is `currentColor` or a stroke, so the alpha channel is
the whole asset — 1 KB per logo, 8 KB for the set, and a colour the theme owns
instead of a black mark that vanishes on a dark ground. Pre-rasterized masks were
chosen over an SVG rasterizer (resvg/usvg is a new dependency against a full
transitive budget) and over fetching beside the catalog (the fetch would still need
a rasterizer). One placement per row rather than one per image because kitty's `p`
is the placement's identity: two rows showing OpenAI must be two placements or the
second `place` moves the first. Delete-then-replace on any change keeps the lifetime
rule one sentence — a placement belongs to the open picker — at the cost of a few
hundred bytes on a scroll, which is rare. The user chose the lab-logo-on-OpenRouter-
rows and 3 + labs set (2026-09-05); five labs turned out to share a placeholder SVG,
so eight masks ship

## Reversible via

Delete `crates/tui/src/logos.rs`, `build.rs` and `data/logos/`; the slot falls back
to the glyph everywhere, or `slot` and `visible_keys` go and the row is ` ›
provider/id` again
