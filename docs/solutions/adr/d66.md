# D66: every animated glyph derives from one clock

Status: accepted

## Decision

Every animated glyph derives from the App's single 80 ms tick, converted once
through `motion::elapsed_of`. No surface keeps a counter of its own, and only the
live region animates.

## Rationale

Two counters drift. A screen whose spinner, task cells and HUD pulse out of phase
reads as several unrelated animations running beside each other rather than one
program working, and the drift grows with session length, so the failure appears
only in the sessions long enough for it to matter. Deriving every frame from one
tick makes phase a property of the clock instead of a coincidence the surfaces
have to maintain.

The 80 ms tick is also the frame scheduler's wake boundary, which makes it the
real resolution of anything Yi can show. A dwell shorter than a tick renders as a
tick — the scheduler cannot wake to draw it — so specifying an animation in
sub-tick units is describing motion the terminal will never display. That is why
the eased breath is specified in milliseconds and quantised at the call site
rather than pretending to a precision the frame loop does not have. Two cadences
ride the one clock: braille at 80 ms for a call in flight, the diamond `◇◈◆◈` at
250 ms for agent-level work, so a family pulses together.

The live-region restriction is the scrollback rule again, in the form animation
takes. A committed row is in the terminal's own scrollback and cannot be
repainted, so an animated glyph written there is frozen at whatever frame it
happened to be at the moment it committed — a spinner stuck mid-rotation, which
reads as a hang rather than as history. A committed cell therefore keeps its
static glyph, which is the one frame it could ever show in that position.

Everything here is a pure per-frame function and is tested as one. The faux
provider answers instantly, so no run ever observes a turn in flight and no
end-to-end drive can watch these animate; the per-frame math and the state
transitions are asserted directly instead.

## Reversal path

Drop the `motion` call sites; `spinner_frame` still renders every surface as it
did.
