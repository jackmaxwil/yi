# D108: a fixture is the production shape

Status: accepted

## Decision

A test's fixture is the smallest input that fails in the field, not the
smallest one that is convenient to type.

- The TUI's life-sized corpus is scrubbed session files under
  `crates/tui/tests/fixtures/sessions/`, replayed through
  `yi_runtime::faux::stream_with_deltas` into the same `App::reduce_agent`
  the screen runs. A session is ground truth for input *shape*; the expected
  output still comes from the invariant, never from what Yi rendered.
- The `rlm` package has a lane of its own: `python/yi_runtime/tests` runs in
  `check_guardrails.sh` under stdlib `unittest`, against a faked host.
- A schema is a well-formed object or it is refused at construction, so a
  malformed one can never validate anything.
- A PR that adds or changes a test writes its seen-red line: the failure the
  test produced against the unfixed code, and where its fixture came from.
- A T3 paid run is recorded into the corpus, so the shape it bought is paid
  for once and replays free thereafter.

## Why

Fourteen defects sat beside green tests whose fixtures were the shape that
works: a three-paragraph newline-terminated thought where the field sends one
unterminated paragraph, a two-row traceback where the kernel sent forty-nine,
data that misses a valid schema where the caller passed a schema that was the
integer `30`. Each fixture was typed by the person whose code it exercised, so
it chose the case that agreed with the code. Beside that, 1,789 lines of the
`rlm` shim had no test at all, because every Rust test called `SubagentHost`
directly and routed around the shim the kernel actually imports.

The session that surfaced all of it is 169 KB and replays in milliseconds. A
recorded artifact costs a scrub and a file; imagination costs a defect per
shape the author did not think of.

## Reversible via

Delete the fixtures directory, the helper and the `run` line; the doctrine
line in `.ruler/080-testing.md` stands alone.
