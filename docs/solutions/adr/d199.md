# D199: todo state is chrome, not transcript

Status: accepted

## Decision

Todo state is chrome, not transcript: `App::sync_port` reads `plan_progress` and
`todo_list` from the port for the HUD, and the console's `paint_chat_pane` calls it
before `paint_pane`, so the block above the composer shows in a console pane as it
did in the standalone TUI; a `todo` call that succeeds commits no card, since the
HUD carries the list, and one whose header counts every item done commits a
`Cell::Footer` `Todos N/N`; a refused call keeps its card; `hud::todo_rows` renders
the checklist markers as glyphs (`✓` done, `▶` running in the accent, `○` pending,
`!` blocked, `−` dropped) and windows `TODO_ROWS` so the running item and the row
after it stay in view, with `+N above` and `+N more`; `todo::text::header` marks a
cut running label with `…`

## Why

On the 2026-09-14 console session `analyze yi agent` seven open todos drew no block
above the composer: `RemotePort` held the `_yi/todo` list but `paint_pane` never
copied it into `app.todos`, which only the standalone `render` did; meanwhile six
`todo` cards stacked in one turn and the header ended mid-phrase on a cut label

## Reversible via

Drop `sync_port` for the two assignments in `render`, commit every todo card again,
render the checklist text verbatim
