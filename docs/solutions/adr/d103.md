# D103: an applied plan op is a durable record on the owning session

Status: accepted

## Decision

Every applied op lands as one `custom{plan_op}` entry on the owning session.
`PlanOpRecord` (`crates/types/src/plan/ledger.rs`) carries the plan, the op, the
actor, the timestamp `at`, and — when the op moved a todo — the todo label and
the `from`/`to` state names, plus `todos`, the count the plan carried once the
op had applied. It flattens an `extra` map like every other durable shape, and
the optional fields skip serializing when absent.

`OpSink` is the write seam on the engine and `SessionOpSink`
(`crates/runtime/src/plan/ledger.rs`) is the one implementation: resolve the
store handle, serialize, `append_custom`. Its append result is deliberately
discarded — a ledger write never fails an op, because the plan file is the
state and the record is the observation of it. `wire_plan_engine` installs it
with `with_op_sink`.

`records()` is the reader: `find_entries` oldest-first, keep the entries whose
`custom_type` is `plan_op`, decode. Everything §12 promised is a query over
that plus the plan's own edges, and nothing else:

`report(plan, records)` walks the stream once and produces a `TodoOutcome` per
todo — `running_ms`, `waiting_ms`, `blocked_ms`, `retries`, `ended` — bucketed
by the `from` state each transition left. Blocked time counts on the critical
path, because a successor gated behind a blocked todo cannot start through it
however little of the wait was work. `critical_path` is the longest chain over
`after` edges, memoized with an explicit stack rather than recursion.
`serial_fraction` is the critical path over the wall clock, returned raw: above
one means the path overlapped itself, which a re-cut plan can do, and the
caller sees the ratio rather than a clamp. `discovery_ratio` is todos added
mid-flight over todos at init — the widest the plan ever got, against
`at_init`. A todo still in flight accrues to the last recorded op and never to
now, so the same stream read twice reports the same numbers. A plan with no op
stream reports empty rather than guessing
(`a_plan_with_no_op_stream_reports_nothing_rather_than_guessing`).

`lint(plan, width)` is the mechanical half of the doctrine and reads the plan
file alone. Five rules, each a mechanical fact: `ephemeral-terminal` (a
terminal record naming a URL that will not outlive the run), `unrunnable-acceptance`
(acceptance is prose, so nothing adjudicates done but the model), `no-probe` (an
external block only a person can clear), `unknown-blocker` (a blocker tag that
landed in the untagged tail, which the probe ladder cannot read), and `width`
(more ready delegated todos than the measured dispatch width, so some will be
held). It returns findings and never a verdict.

`why::answer` walks one line to its goal: `git blame --porcelain -L` for the
commit, `git show -s --format=%B` for the body, the `Plan: plan://` trailer out
of it, then the plan file for the todo label and the goal. Absent halves are
absent rather than guessed — a commit with no trailer answers with a commit and
a subject and three `None`s, and a trailer whose plan file is gone still names
the todo slug. The label is recovered by re-slugging each todo and comparing,
never by inverting a slug. `commits_for` is the reverse over the same data:
every commit that carried this todo's trailer.

The CLI is two thin verbs. `crates/cli/src/plan.rs` is `yi plan lint` and `yi
plan report`, both resolving an unnamed plan the same way the tool's own
unnamed ops do — the named one, or the single `Active` root — so the operator
and the model see the same plan. `crates/cli/src/why.rs` picks direction by
shape: `<file>:<line>` runs forward, anything else runs the reverse index. The
op stream lives on the session that wrote it, so `report` with no session named
reads the newest session for this workspace.

`TodoStateName` is promoted out of the plan file's own serialized
representation (`crates/types/src/plan/doc.rs`) so the event log and the
document share one state vocabulary, `Other(String)` tail included.

`crates/runtime/tests/plan_ledger.rs` covers the three halves —
`every_applied_op_reaches_the_sink_with_the_state_it_moved_between`,
`the_outcome_ledger_is_a_difference_of_recorded_timestamps`,
`a_plan_with_no_op_stream_reports_nothing_rather_than_guessing`, and
`the_lint_reads_the_file_and_never_refuses_anything`. The T2 journey
`a_hand_written_plan_lints_resolves_and_answers_why` in
`crates/cli/tests/journeys.rs` drives the built binary over a hand-written plan
file: lint names its three findings by rule, `yi fetch plan://` serves the
todo's prose section, `yi plan report` names the plan with no op stream at all,
and a real git commit carrying a real trailer is walked back by `yi why`.

## Rationale

The plan file is the state, and it carried no record of *when* it moved. Every
duration §12 named — the outcome ledger, the Amdahl fraction, duration priors,
an OpenTelemetry span — was a query over a store that did not exist, so the
whole §12 yield was a promise rather than a feature.

**Timestamps do not belong in the plan file.** A Done plan gains history and
never mutations; a frontmatter that grew a transition list per todo would
mutate on every op, would make the human diff unreadable, and on a long run
would hit the 32 KiB frontmatter cap that `precheck` enforces. The session's
own entry tree already has both properties the ledger needs — append-only, and
durable past the process — and the fetch log had already proved the shape on
`custom{fetch}`. So the op stream is a second reader of a store that had to
exist anyway, and this row adds no store.

That the yield is *queries* rather than tables is what keeps it cheap. The
report holds no state, the lint holds no state, `yi why` holds no index — the
reverse direction is a `git log` over the same trailer the forward direction
read. Nothing to migrate, nothing to keep in sync with the plan file, and a
number that looks wrong is traceable to two entries in a session file.

The lint is bounded by what a lint may be: advisory, mechanical, run at a cut
boundary rather than per op. Every rule it carries is a fact about the document
— a state the step table cannot move, an acceptance no machine can adjudicate,
a block nothing can clear, a ready set wider than the measured cores. A rule
that needed a fitted threshold would be a judgment, and there is none here.

## Reversal path

Delete `crates/runtime/src/plan/{ledger,why}.rs`, the `OpSink` seam and its
`with_op_sink` installation, and the two CLI verbs. `yi_types::plan::ledger`
stays as an unread durable shape, which is additive and loads either way; the
`custom{plan_op}` entries already written keep round-tripping through the
session file's unknown-data path, and `TodoStateName` stays because the plan
document's own representation is what it was promoted out of.
