# D314: a session's children cache as one family

Status: accepted

## Decision

A session's children cache as one family: the root session's id is the family key,
carried by the root's `ProviderStream` (`build_session` passes it, cut to 64
characters) and by every child's, which `ProviderStream::for_child` makes with the
family's credentials, faux script and key but a five-minute stable prefix; the key
goes out as OpenRouter `session_id` and as `prompt_cache_key` on api.openai.com and
the Responses API; `Breakpoints::build` honours `LlmContext.shared_through` (D309)
as a `SharedEnd` breakpoint on the last message of the run a sibling sent, on every
reuse, one-shot readers included, and keeps, when slots run short, the system end,
the tail, the shared end, the previous tail and the universal end, in that order,
one breakpoint per message; `LlmContext::prefix_key` hashes the route, schema,
tools, system, effort, `tool_choice` and `messages[..=through]` less the fields no
wire carries, so siblings over one run share a key and a schema-only request never
shares a tool loop's

## Why

Children shared nothing warm: `session_id` was `None` on every stream, so no
affinity key was ever sent, and OpenRouter forwards one to Z.AI, whose replicas
otherwise split a family (a Parasail pin read 0 of 6,773 tokens on the second
sibling, Z.AI read 6,720); `shared_through` was set by D309 and read by no encoder,
so on a breakpoint engine the second sibling wrote the partition again instead of
reading it; children shared the root's `ProviderStream` and so its one-hour stable
TTL, paying 2x instead of 1.25x on a prompt that is not the root's (design
2026-09-28 §7, §8 C3)

## Reversible via

`ProviderStream::new(None)` in `build_session`, `Arc::clone` in `child_factory`,
drop `SharedEnd` from `Breakpoints::build`; `prefix_key` has no caller yet and goes
with it
