# D372: `set` with `todos` rows is the plan tool's whole-plan write (amends D194 and...

Status: accepted

## Decision

`set` with `todos` rows is the plan tool's whole-plan write (amends D194 and the op
table's `set`): a row is a todo's spec plus a `state` (`pending`, `running`, `done`,
`blocked`), and the call reconciles the plan to it and lands with each row it could
not reach carrying a condition in the reply, instead of refusing the call; each row
is parsed alone first, and one that cannot parse (a label past the cap, a malformed
contract) is left out and named; a row whose move needs the engine is set where it
stands and moved by the op that verifies it after the set lands: `done` on a row
with a contract or a delegation runs `done` and its check, `running` on a delegated
row runs `start`, and `blocked` runs `block` with the row's `on` (the user when
absent), `note` (its label when absent) and `options`; the set itself is retried
against the engine's plan issues with the smallest repair named as a condition: an
`after` closing a cycle or naming no todo is left out, a second row with a label
already used is left out, a contract the engine refuses is left out; an issue with
no repair and any other engine error still refuse the call; the reply is the plan's
view followed by one `note:` line per condition; a checklist `list`, and `todos`
rows that carry only a label, are read as before

## Why

The owner chose "Whole-plan apply" and "JSON rows, text shorthand" as the plan
tool's write and set the target ("figure out how to get failure rate and refusals to
0%"); the dogfood session that wrote its plan with one whole-list `set` had zero
plan errors in seven rounds, Codex's `update_plan` refuses nothing but unparseable
JSON, and baseline row 0073 put 26 of 29 counted failures on the plan tool's sixteen
ops; the stage 1 live run showed a refused cycle edge retried four times, which a
left-out edge with its reason answers

## Reversible via

Delete `plan/apply.rs`, its two hooks in `plan/tool.rs`, `todos` from `set`'s keys
and `state` from the todo schema; `set` with structured rows is refused again
