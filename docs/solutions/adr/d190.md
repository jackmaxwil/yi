# D190: tool-call arguments that leak GLM's native markup parse back into real arguments

Status: accepted

## Decision

Tool-call arguments that leak GLM's native markup parse back into real arguments: a
parsed key holding `<arg_key>path</arg_key>` is renamed to `path` (a canonical key
already present wins), and an arguments string that is bare
`<arg_key>k</arg_key><arg_value>v</arg_value>` pairs — both tags or neither — reads
as an object, each value parsed as JSON where it parses

## Why

17 v4 calls arrived with the markup where the argument names belonged and errored on
the missing fields (the 2026-09-11 v4 sweep); the salvage layer already repaired
escapes and closed partials, and the markup was the one corruption it could not see

## Reversible via

Drop `clean_arg_keys` and `salvage_arg_markup`; the strict parse stands alone
