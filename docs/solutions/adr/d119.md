# D119: a root session is worktree-first, on a pooled lane

Status: accepted

## Decision

Unless `--here`, `lanes.enabled: false`, or a cwd outside a repository, a root
session claims a *lane*: one of N fixed slots (`lanes.slots`, default 3) under
`~/.yi/lanes/<repo-hash>/<n>`, outside the checkout. The claim resets the slot to
`origin/main` (then `main`, then `HEAD`), branches `yi/<session>`, and every tool,
extension, plan and checkpoint runs there. The session file stays keyed by the
trunk cwd, so `--continue` from the trunk finds it. A child spawned with
`isolation='worktree'` claims from the same pool off the parent's HEAD and merges
back into the parent's checkout. A claim that fails fails the start; there is no
fallback to the trunk.

## Why

The trunk checkout was every session's working directory. A `git reset` in one
session ate a sibling session's uncommitted edits, and the person's editor saw
agent churn. A fresh `git worktree add` per session was a cold build cache every
time, because cargo, tsc and uv key their caches by absolute path; a fixed slot
path is warm by construction, and a claim on a tree that already holds last
time's files rewrites only what moved.

## Reversible via

`--here` everywhere, or `lanes.enabled: false`. Deleting `crates/runtime/src/lane/`
returns children to the pre-0.148.0 `git worktree add` under the session
artifacts.
