# D180: a read is refused only where a read does harm

Status: accepted

## Decision

A read is refused only where a read does harm: a call that only reads and reports
itself reversible is judged by `read_is_catastrophic`, which holds the workspace
`.git`, a path at or under a credential store in home or a directory above one, `/`,
`/home`, `/Users` and `/root`, a `/proc` path through a link (`root`, `cwd`, `fd`,
`map_files`), and `/dev`, while every other call keeps M10's whole list; a tool's
default `irreversible` follows the call's own kind (`kind_for`), so grep's
replace+apply is judged as the write it is; `command_reads_credentials` shares the
credential-store list; the yolo fragment names what a read may not touch (amends
D15)

## Why

D15 listed system paths because destroying one is catastrophic, and the check ran on
every target before the mode was read, so under `--yolo` a `read` of
`/etc/nginx/nginx.conf` was denied while `bash cat` printed the same bytes (the
2026-09-10 harness audit, S3): the denial bought no safety and cost turns; what a
read can do is put a key in the transcript, where it has left the machine, or never
finish on a device (`/dev/zero`, `/dev/tty`); a directory above a key store stays
refused because grep's walk skips only `.git` and would carry into `~/.ssh`; other
users' key stores sit under `/home` or `/Users` whatever HOME is; `/proc/self/root`
names `/` and `/proc/self/cwd` the working tree by a link a lexical check never
follows; `/proc/self/environ` becomes readable, which `bash env` already printed;
grep's apply had passed the gate as a read, and the lighter list would have let it
rewrite `/etc`

## Reversible via

Send every target through `is_catastrophic` again and restore `self.kind()` in the
default `irreversible`
