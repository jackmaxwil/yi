# D228: a contract's checker runs after every covered write

Status: accepted

## Decision

A contract's checker runs after every covered write: `Contract.covers` names globs
relative to the checkout, absent when empty so no frozen digest moves, and a write-
kind tool call that did not error runs the `cmd` items of each todo running by the
writer (an owner's inline todos, a child's own) whose contract covers a written
path, with the frozen manifest, on the live tree in the writer's own checkout, and
appends `contract "<label>" check: pass` or `fail: <detail>` to the result; a
verdict is kept per todo and item against the digest of the covered paths and bytes;
the preview journals nothing, mints no token, digests no protected path and charges
no refusal, so `done` stays the one acceptance (extends D194; stage G4 of
`docs/plans/2026-09-22-the-engine-runs-the-plan.md`)

## Why

F0e sessions ran `check.py` by hand after saves, or not at all until `done` refused;
the contract already names the checker, so running it where the write lands removes
a step the model had to remember, and a preview that could mint a token or charge a
refusal would let a save stand in for verification

## Reversible via

Delete `plan/covers.rs`, `ToolAdapter`'s check slot and `Contract.covers`; a
contract written with `covers` then parses with the field ignored
