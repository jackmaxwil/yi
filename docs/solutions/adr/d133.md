# D133: the CI is the first user

Status: accepted

## Decision

The CI is the first user: a `live` job on every pull request builds the binary and
runs `evals/run.py --live` — `evals/fixtures/live/*` scenarios through the real
binary against `openrouter/deepseek/deepseek-v4-flash-0731`, each judged by its
`reward.sh`, by `yi doctor --json` afterwards (a red row is `Invariant::<row>`), and
by a refusal's own stderr; every scenario ends `pass`, `fail` or `inconclusive`
(timeout, no key, provider trouble, budget), only `fail` is red; spend is capped in
code from measured usage ($1 a run) and the day's cap is the ledger's; the report is
one upserted PR comment (`scripts/live_report.py`) with statuses, classes and the
telemetry rollup; without the `OPENROUTER_API_KEY` secret the job reports
inconclusive. Plan law 3 keeps its sentence for T0–T3 and gains the tier T3-live
beside T3

## Why

Plan 2026-09-05 §3.C–D and §4: every gate proved fixtures and every escape of
2026-09-05 lived in the environment, at the seams, or in a number nobody measured.
Law 3's "never in any gate" guarded against unbudgeted spend; a cap enforced in code
from measured usage guards the same thing with the run inside the gate, and the
flash model prices at $0.05 per million input tokens, so the cap is a guard against
bugs, not bills. Law 2 is untouched: no model judges a model, a scenario without a
shell verifier is refused by the schema. Advisory first: a required status that is
red for the weather gets ignored, as the `title` job's history shows

## Reversible via

Delete the `live` job and the `--live` door; the scenarios stay user-run under law 3
as written
