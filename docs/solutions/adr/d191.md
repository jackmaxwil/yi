# D191: `yi login` is native and ships no provider identity

Status: accepted

## Decision

`yi login <provider>` / `yi logout` are native. `yi-oauth` carries PKCE, the loopback
listener, the 0600 token store under `~/.yi/providers/tokens` (atomic tmp+rename, the
mode set at creation, a stale tmp retried once), and the verbs.

No provider identity is compiled in. An OAuth provider is described entirely by a file
the user writes at `~/.yi/oauth/<provider>.json`: `client_id`, `authorize`, `token`,
`scopes`, the redirect, plus `stream_headers` sent on every request for that provider
and `refresh_headers` sent only on the token-refresh call. Yi ships no such file and no
client id; `yi login <provider>` without one names the path and the example instead of
failing obscurely.

`openai`, `openrouter` and `google` remain pasted keys (`--key` or stdin), which need no
profile. An env key outranks a stored credential. A stored OAuth token is refreshed
before it is handed out, and a refresh that fails falls back to what is on disk so the
provider names the 401 rather than the store.

Profile headers reach the wire through D170's `merge_headers`, so a profile name replaces
the adapter's header case-insensitively and an empty value removes it.

`scripts/oauth-profile-gen.py` is the scaffold that writes a profile. The plumbing —
paths, JSON shape, 0600, atomic replace, validation — is complete; the `discover_*`
functions return `REPLACE_ME`, and the script exits 1 naming every unfilled field.

## Why

OAuth lived in the design as Bun while the binary had only env keys, and MCP already had
PKCE and a loopback to reuse.

The identity is data rather than code because a client id and a wire identity that are
not yours are the provider's business, not the binary's. Compiling them in distributes
them to every clone of the repository, and a provider's terms may forbid presenting
them; leaving them to a file the user writes puts the choice, and the responsibility,
with the person who accepted those terms. The same reasoning excludes shipping or
hooking up a discovery script: the scaffold's `discover_*` functions are stubs.

Profiles live beside the token store rather than under `~/.yi/catalog/` because the
background catalog refresh (D128) rewrites the files in that directory from the bundled
entry, which would silently wipe a hand-written header on the daily refresh.

The file store is not the keychain so HOME-isolated tests cannot clobber a human's
tokens.

## Reversible via

Delete `crates/oauth`, drop `yi-oauth` from `yi-ai`, drop the `login`/`logout` verbs and
the `oauth` / `extra_headers` options on the adapters; env keys still stream.
