# D191: a `timeout_secs` past the ceiling says so

Status: accepted

## Decision

A `timeout_secs` past the ceiling says so: a bash result opens with `[timeout_secs
900 capped at 600]` whenever the clamp lowered the ask, success or timeout, where
the cap was silent and the model kept re-asking; and the bash default rises 120 s ->
300 s, the wait clamp's top, so a build or a short suite finishes inside the default

## Why

The cap was invisible: a model that asked 900 and was killed at 600 read `timed out
after 600s; pass timeout_secs up to 600` and could ask 900 again; at least six v4
trials lost a turn and up to two minutes of wall re-learning the 120 s default the
description already named (the 2026-09-11 v4 sweep); a hung command now holds the
turn five minutes instead of two, bounded, and the description and schema name the
new pair

## Reversible via

Restore 120 and drop the cap note; the timeout message already names the ceiling
