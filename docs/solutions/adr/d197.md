# D197: a tool call the model wrote as text is the call it spells

Status: accepted

## Decision

A tool call the model wrote as text is the call it spells: `yi_ai::leak::recover_in`
runs in both mappers' `finish` and turns every well-formed
`<tool_call>NAME<arg_key>K</arg_key><arg_value>V</arg_value>…</tool_call>` block in
the message's text into a `Content::ToolCall` (id `leak-N`; a value that parses as
JSON structure or a number is one, anything else is the string), cuts the block from
the text, and turns a `Stop` into `ToolUse`; a message whose text opens with
`<tool_call>` and carries no call ends the turn as `StopReason::Error` with
`UNPARSED_MARKUP` (`flag_unparsed_markup` in `run_loop`) instead of prose

## Why

On the 2026-09-14 console session `analyze yi agent` glm-5.3-flash streamed
`<tool_call>read<arg_key>path</arg_key><arg_value>…/plan/SKILL.md</arg_value></tool_call>`
as content with `finish_reason: stop`; the turn rendered the markup as an answer,
ran nothing (0 tools, 14 s, $0.006) and the session sat idle; `todo::tool::unleak`
already repaired the same markup inside a real call's arguments, so the whole-call
leak was the one shape nothing read

## Reversible via

Delete `leak.rs`, the two `recover_in` calls and `flag_unparsed_markup`
