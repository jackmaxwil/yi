# D339: a tool judges the file it opened, not the name a check saw (amends D323)

Status: accepted

## Decision

A tool judges the file it opened, not the name a check saw (amends D323): every file
a tool call names opens through `ReadGate::open`, `open_write` to write or `remove`
to delete. That covers read (a file, a directory's skeleton heads, a glob), write
and its preview diff, edit (its reads, writes, `MV` destination and deletes), grep
and grep `apply`, `get_context` (skeletons, symbol ranking, the issues file), the
bash tag snapshot, `fetch::read_text` for every scheme that serves a host file, and
plan `import` and `submit`'s `local://` outputs. The gate resolves the path, judges
the resolved path with D323's gate, D15's destroy gate for a write and the wall
lists the caller passes (`deny_read`, and `deny_write` too for a write), then opens
that path with no link left to follow. On macOS that is `O_NOFOLLOW_ANY`; a kernel
that ignores the flag (before macOS 11, found by one probe of `/etc`) gets every
gated open refused with a message naming the limit. On Linux the file is opened
through its parent directory held open and checked, and the kernel's name for each
descriptor (`/proc/self/fd/N`) must equal the path judged. A write opens an existing
file untruncated or creates a missing one with `O_EXCL`, and truncates through the
handle. A delete checks that the name still has the identity of the file it opened;
Linux then unlinks inside the held directory, macOS by name. The document converter
reads the judged bytes on stdin. The broker still judges the name first; a refusal
at the open is a `PermissionDenied` error naming the resolved path. Commands
contained by Seatbelt were never exposed, since the kernel resolves links when it
applies the profile. Windows left: on macOS a parent swapped between a delete's
check and its unlink (1 key deleted in 100,000 tries in the #963 review; #964); a
hard link to a key (as D323); the syntax check after a write and the write tool's
`create_dir_all`, which use the name; the document type sniff before a write
(`write_refusal`), which returns a kind only; and `local://`'s workspace-containment
check, which still checks then opens a path outside the tree that is no key and no
wall. `ReadGate` now writes and deletes too; its name is kept for this change

## Why

The reviews of #885, #903 and #911 read a key 40 times in 20,000 tries by swapping a
link between the check and the open, and a write, an edit and a grep `apply`
reopened the name after its check the same way. `O_NOFOLLOW` guards only the last
component and std has no `openat`, so opening the resolved path with no link
anywhere on it (macOS) or through its checked parent and its descriptor's name
(Linux) is the std-only way to make the path judged the path opened; reading the
descriptor's path on macOS (`F_GETPATH`), `openat2` or `unlinkat` needs `unsafe` or
a new direct dependency

## Reversible via

Open the name in `ReadGate::opened` without `no_link`, `beside` and `opened_at`
