# D96: pane content is an enum, and kernel media rides the existing details record

Status: accepted

## Decision

`PaneContent` (`crates/console/src/model.rs`) is a plain enum —
`Session { session, transcript }`, `Markdown { path, source }`,
`Diff { path, source }`, `Notebook { session, cells }` — with one render arm
per variant in `crates/console/src/render.rs` and one reduce arm per variant
in `app.rs`. The navigator doubles as the command line that swaps a pane's
kind: `md <path>` and `diff <path>` resolve a path into the matching variant,
`nb` opens a notebook pane (`crates/console/src/app.rs`, the `("md", path)` /
`("diff", path)` / `"nb"` arms).

Kernel cell media does not get a new wire shape. `ExecuteResult::attachments`
(`crates/types/src/kernel.rs`, `KernelAttachment { mime_type, data, path }`)
was already produced by the kernel; `crates/tools/src/ipython.rs` now puts
that array itself into the `ipython` tool call's details record under
`attachmentMedia`, alongside the existing `attachments` count. The console's
notebook pane reads `attachmentMedia` off the details record
(`crates/console/src/app.rs`) to populate `NbCell::images`, and
`crates/console/src/kitty.rs` transmits each base64 PNG straight through as a
kitty `f=100` graphics placement — no decode, no re-encode, because the
payload the kernel emitted is already base64.

## Rationale

The alternative on the table was a `dyn PaneView` trait, one implementation
per pane kind. Each kind needs different state mutation from the same update
stream, so a trait would have grown one downcast per reducer arm to get that
state back out — worse than the enum, which keeps every match exhaustive and
lets the compiler enforce that a new variant touches every arm that needs it.
Four variants is not enough kinds for the indirection to pay for itself.

Before this landing, the details record carried only `attachments.len()` — a
count with no reader — and threw the image bytes away before they reached any
consumer. Carrying the array costs no new schema: `KernelAttachment` already
existed as the kernel's own wire shape, so the notebook pane needed no image
dependency and no new type, only a reader for a field that was already
produced and previously discarded.

## Reversal path

Collapse the non-`Session` variants back out of `PaneContent`, revert the
`ipython` details record to a bare `attachments` count, delete
`crates/console/src/kitty.rs`, and remove the `md`/`diff`/`nb` navigator
command arms.

boundary the pane shell lives inside is D95.
