# D557: a catalog entry's `readTimeoutSecs` (default 60 s) is the model's own read...

Status: accepted

## Decision

A catalog entry's `readTimeoutSecs` (default 60 s) is the model's own read deadline,
applied per read so it bounds the idle gap between chunks and never the whole body,
and a timeout is neither retried nor resent

## Why

Four commands ended mid-task on a gateway that answers only when its first token is
ready, the fixed 60 s was the HTTP client's and named nothing, and the retry layers
spent it three times over

## Reversible via

Delete the field from the catalog entry, which restores the client's constant
