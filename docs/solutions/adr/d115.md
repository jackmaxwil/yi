# D115: compaction is a deterministic fold; the LLM summary is a mode

Status: unshipped (0.140.0). The skip-LLM fold and Goal/Next-only P7 duplicated P8/P17 and did not implement the observation-mask or `C(H)` methods those papers describe. P19 keeps the pointer index; P7 is the full checkpoint again.

## Decision

Compaction is a per-kind fold over the entry log. `compile_view` renders
pointer-only successful tool results, `stale` on a read whose path a later
edit in the span touched, decision lines kept whole, a `[Kernel]` persist
note, and an `[Earlier]` index of brief lines that rolled past the cap
(`first user line … (#first..#last)`, cap 24). The LLM summary is a config
mode (`compaction.mode = summary | fold`, default `summary` in this landing).
Fold skips `complete_text`. Summary mode restricts P7 to `## Goal` / `## Next
Steps` because the fold already SELECTED the rest. This supersedes D21's
port scope for compaction: the method is the fold, not the donor summarizer.

The default stays `summary` until `docs/eval-ledger.md` carries an
`ident-survival` row for each mode.

## Why

CompInt retained 17 % of constraints, ConstraintRot climbed 0 → 30 % after
compaction, JetBrains' masking matched or beat an LLM summary, and ARC's
id-addressable recall is 99.4 %. The extractive view already named files,
errors, and turns; paraphrasing them in P7 was a second lossy copy.

## Reversible via

Set `compaction.mode = summary`. Delete `[Earlier]`, `stale`, `[Kernel]`,
and the per-kind `brief_line` arms; the brief degrades to the 0.137.0
one-liners and P7 can grow its sections back.
