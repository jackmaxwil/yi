# D53: the plan is a session-store fact

Status: accepted

## Decision

The plan is `Fact::Plan`, stored beside the goal like every other fact — never a
transcript entry and never an event-only tool. It is an expand-only task DAG:
transitions run through one legality table, a done claim is host-verified (D52),
`plan.edit` adds or reopens and refuses to remove, reword, or replace, and the
frontier is derived from dependencies rather than stored. The goal's
continuation prompt carries the frontier, and a plan untouched for N completed
turns steers one latched reminder. Plans may be model-inferred; goals stay
explicit-only (G2) — a plan is structure, a goal is autonomy.

One-in-one-out: the M4 embedding API row is demoted to not-in-scope in §1.1.

## Rationale

codex's `update_plan` at 2026-08 HEAD is still `send_event`-only, and codex's own
Plan Mode bans it — D26's "a print statement with a schema" is a current failure,
not a historical one. The 0.11.0 ledger note had already pre-committed the
fact-backed shape. The test D26 sets is whether the state changes what the
runtime does next: here it does, because the frontier drives unattended
continuation and the staleness latch reads the same fact.

## Reversal path

Delete `yi-runtime::plan` and the `Fact::Plan` arm. Stored plan facts keep
parsing through the wire enum, so nothing on disk is orphaned.
