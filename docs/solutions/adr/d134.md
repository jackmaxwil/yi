# D134: every error carries a class from one closed vocabulary

Status: accepted

## Decision

Every error carries a class from one closed vocabulary:
`yi_types::telemetry::ErrorClass` renders `kind:detail` — `tool:<errorKind>` from
the loop's own taxonomy, `provider:error`, `transport:http_<status>` / `timeout` /
`proxy` / `body` read from the provider's error text, `refusal:<which>` for the five
refusals, `invariant:<doctor row>`, `harness:<what>` — a tool span carries its
result's `errorKind`, a request span the provider's class, a refusal prints its
class after the reason on stderr and over ACP, `yi stats telemetry` counts by class
and the live judge treats a class absent from the last ten runs as a finding

## Why

Plan 2026-09-05 §3.D: "identify critical runtime bugs" is only mechanical when an
error is countable, and until now a tool error was a wire string, a provider error
prose, a refusal an exit code — nothing a run could compare with the last run. The
vocabulary is closed and printable so a new class is a diff, not a grep; the tool
half reuses `ToolErrorKind` (the loop already stamps `details.errorKind`), so no
producer changed shape and the session file is byte-identical

## Reversible via

Delete the enum; spans keep a free-form `class` string and the judge keeps counting
strings
