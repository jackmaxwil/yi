# D345: a walled session reads no session's transcript file but its own (amends...

Status: accepted

## Decision

A walled session reads no session's transcript file but its own (amends D340, D335):
a session whose wall is not empty has every session store, `~/.yi/sessions` and the
`--session-dir` in use (`tools::session_stores`, the stores the broker holds host-
owned, now carried to a child broker by `for_child`), added to its calls'
`deny_read` beside the spill roots, and its own transcript file spared:
`ToolContext::transcript` joins `recovery_dir` in `ReadGate::except`, so `read` and
a grep naming the file open it while every other transcript and every walk under a
store is refused, and a contained command's profile denies each store and re-allows
reads of the own transcript in a later rule (`Sandbox::spared`, now a list);
`Resolver::wall` carries the stores for a walled reader, so `local://`,
`checkpoint://`, `tree://` and `plan://` refuse a transcript, a store inside the
workspace included; a walled holder's broker (marked by `for_child`) refuses
outright, before any ask, a retry whose remembered refusal lies in a protected dir,
so neither an asker nor the auto reviewer runs it outside the sandbox; a contained
refusal at, or from a command naming, a path under the own walls is never
remembered, so a later call neither asks nor claims the own transcript; the own
transcript is the file alone, not its dir or its children's, which reach a parent
through `rlm.wait` and the mailbox on the host; `history://` stays governed by
`deny_url` alone

## Why

#971, review of #968: a juror could `read` and grep its author's transcript, which
holds every tool output, file and turn its wall hides, bypassing the `history://`
deny through the file; review of #979: `local://` and `checkpoint://` served a store
inside the workspace, and an approved retry after a contained refusal ran the read
outside the sandbox (as it did for spills since D340); weighed: sparing the own
transcript dir (a child's `sub-*`, holding its kernel state and children), rejected,
since no tool path needs it and a root session's dir is every session of its cwd;
walling the stores in the wall itself, rejected, since the kernel profile takes the
wall and its private dir and the family board sit under the store; still open:
`history://<id>` serves any transcript to a walled session whose `deny_url` lacks it
(readers and typical plan workers are walled `deny_write` only), and a walled
session's kernel cells and uncontained bash (Linux, yolo, an approved credential or
network call, a retry after a pathless refusal) read transcript files, the open item
#885 named for spills

## Reversible via

`walled_roots` without `session_stores`, `ToolContext::transcript` unset,
`Resolver::wall` without the stores, `walled_retry` and the own-wall filter on kept
refusals removed
