# D613: the autofixer calls a base red only when the forge's own test lane on it ran...

Status: accepted

## Decision

The autofixer calls a base red only when the forge's own test lane on it ran to its
end and failed, and closes its red-base issue when that lane is green again (revises
D519's red base, which the fixer's clone alone decided)

## Why

The clone measures its runner as well as the code: #2237 failed on its CI runner's
load, two other tests failed only in the fixer's clone, at main too, and the fixer
reran the gate, opened #2330 against a main the forge had green all night, and
parked #2237 on an issue only that clone could close

## Reversible via

Remove `base_lane` and its three uses in `attempt` and `settle_base_red` of
scripts/pr_autofix.py, so a `BaseRed` from the clone is a red base again
