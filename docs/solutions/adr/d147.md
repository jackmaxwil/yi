# D147: a turn that thinks past the output limit is sent back to act

Status: accepted

## Decision

A turn that thinks past the output limit is sent back to act: the OpenAI-completions
and responses paths send `min(catalog maxTokens, 32768)` as the per-turn output
ceiling (`yi_runtime::provider::output_cap`; Anthropic already sent the catalog
value), and the loop, when a turn ends on `length` with no tool call, sends one
hidden `custom{length_redrive}` message once per prompt: "The reply hit the output
limit before any tool call. Act on the next item now: make the tool call, then
explain; the thinking is not the work." A second length stop ends the loop; a length
stop with tool calls keeps failing them as before; the todo interception still
refuses `Length`. `extract.py` counts the message as `length_redrive`

## Why

Every photonic-waveguide-routing attempt on rows 0017 and 0018 ended after one
131,072-token reasoning turn with `stopReason: length` and no tool call, four
identical zeros at $0.035 each (issue #264): the request never carried an output
ceiling, so OpenRouter's default for the model applied, and the loop read a length
stop with no calls as a finished answer. The ceiling is a constant, not a config
knob, because no user has asked for a number; the re-drive is in the loop because
the coupling's `is_terminal` refuses `Length` by design and a test pins it

## Reversible via

Delete `output_cap` and the two `max_tokens` lines; delete `length_redrive` and the
`length_redriven` branch in `run_loop`
