# D148: a numbered request is the list, and the list exists before the third change

Status: accepted

## Decision

A numbered request is the list, and the list exists before the third change: when
the list is empty and the prompt carries two or more enumerated lines (`1.`, `1)`,
`- `, `* `, the detector `eager_init` already reads), the coupling seeds one pending
item per line under the default phase before the prelude, cut to the label max,
duplicates once, recorded with actor `prompt`, and the prelude says the list was
seeded and what to add; an open list is never reseeded and nothing is forced. When
the list is empty and `FIRST_LIST_WORK = 3` changes have landed since the prompt
(edits, writes, and bash the gate does not allow), one hidden `todo_nudge` asks for
the list, once per prompt; the `NUDGE_WORK = 12` nudge keeps its job for a list that
exists and went stale

## Why

Ledger row 0014: five of eleven journey sessions made three or more mutating calls
with no todo list at all, and on the v4 subset every near-miss (music-harmony, bun,
foodstuff, cargo) passed 60-85 % of a numbered instruction's checks and stopped one
requirement short (issue #266); the user's own enumeration is the one list the model
cannot summarize into fewer items, and `multi_step_without_todo` still counts todo
calls, so a seeded list the model never steps still reads as no list

## Reversible via

Delete `seed`, `seeded_text`, `first_list` and `FIRST_LIST_WORK`; `enumerated`
returns to a bool
