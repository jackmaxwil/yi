# D117: the model's seat decides the tool surface

Status: accepted

## Decision

Five tools, and every change is judged by the call, the re-read or the prompt
rule it removes from the model's path.

`edit` anchors never go stale. A line cited from an older snapshot moves onto
the current file through the diff between the two texts
(`hashline::rebase`, over `diff::line_map`): a line maps only when its text is
unchanged, a cited line that changed rejects with the current text under the
cited numbers, and a block op rebases only when the whole old block mapped
contiguously. The `#TAG` on a section header is optional — `[path]` names the
version this session last showed — and the prompt's "re-ground after every
edit" rule is gone. Python and YAML get an indentation block resolver, chosen
by extension beside the brace scanner.

Everything that shows code anchors an edit. A bash command that is one plain
view of one existing file (`cat`, `head`, `tail`, `sed`, `rg`, `grep`; no
pipe, no redirect) records a snapshot and prefixes its output with the
`[path#TAG]` header; the lines the output showed verbatim are the seen set, so
the blind-edit guard holds. A read-only command (the existing `read_only_command`
screen, now with grid's query verbs) is a Read-kind call and overlaps with the
other reads in its message; `Tool::kind_for(args)` is the per-call kind the
loop and the wall consult.

`read` answers for what its path names: a file as before, a directory as a
listing with a skeleton row per source file, a glob as every match whole while
the byte budget lasts and skeletons after; `find="text"` returns the enclosing
block around the first match plus every whole-word reference to its identifier
in the tree, tagged; a read cut by a cap ends with the file's numbered
skeleton. The `glob` tool is deleted.

`grep` is a regex by default (`literal: true` is the exception), takes one
pattern or an array of alternatives, and gains `block`, `def`, `count`,
`multiline`, and `replace` with `apply` — the rewrite is previewed as a diff,
written only with `apply`, capped at 50 files / 500 hits, every written file
tagged, and the call is Write-kind only when it applies.

`plan op=set list="…"` takes a markdown checklist (`- [ ]`, `- [>]`, `- [x]`;
two spaces nest) as the whole list: a surviving label keeps its edges,
delegation and sub-plan, a new one starts plain, a missing one leaves, states
are as written. `Todo` gains `children` (grouping only). The plan tree renders
children indented, the HUD shows `Plan done/total · now: label`, and every
plan reply prints the same progress line.

After an edit to a `.rs` or `.py` file the edit result carries a
`[grid check]` layer from `grid check --quick` (two seconds, forty lines):
exit 3 renders the findings, anything else renders a named absence, and the
edit stands either way.

Every cap these tools set is loud (`.ruler/045-loud-caps.md`): a `[…]` row at the
point of the cut names kept over total, the cap, and the next call. That covers
the read skeleton (first 40 of N declarations), directory and glob heads per
file (`… +N more`), the glob walk limit, the byte-budget switch to skeletons,
`find`'s fallback window when no block resolver exists, the near-miss list,
grep's block fallback per hit, its tag cap per page, its context clamp, its
binary skips, `get_context`'s per-file heads, and the grid layer's line cap.

## Why

Every session replayed showed the model reading and searching through bash,
whose output could not anchor an edit, and calling grid by hand; the plan tool
had six uses against thirteen ops. The tax was calls: grep→read→edit→read for
one change, read→read for a big file, edit→read→edit for two edits to one
file. Grid was weighed as the engine under read and edit and cut: Rust and
Python only, a chart that is pre-edit until a 245 ms survey, and a second
grammar for a subset of files; the line mapper solves the stated pain for
every file with nothing outside `tools`. Grid keeps the two seams that answer
"what did I break" and "who calls this". Rejected inside this landing: datum-
addressed sections, per-line hash tags, a delta read, a second todo tool, a
nested batch tool, a status-row plan segment (the HUD carries it; the daemon's
`_yi/status` does not, yet).

## Reversible via

Drop `hashline::rebase` and the optional-tag arm in `Patcher::prepare`; the
bridge in `BashTool::execute`; `kind_for` back to `kind`; the glob/dir/find
arms of `HashlineReadTool::execute` and the `GlobTool` from git; grep's
`Options` back to the `regex` flag; `OpKind::Set`, `SetRow` and
`Todo::children`; `grid_check` in the edit tool. Each phase's tests name the
behaviour they pin.
