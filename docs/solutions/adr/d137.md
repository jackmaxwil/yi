# D137: todos are a session tool and plans are a delegation ledger

Status: accepted

## Decision

Todos are a session tool and plans are a delegation ledger: `todo` is registered at
every depth, persists as `custom{todo}` entries on the session (never a file in the
tree), nests one level, and moves an item with one op each between pending, running,
blocked (on user, external or child), done (with `evidence`) and abandoned (with a
reason); every result ends with `next:` lines naming the legal moves with the label
filled in, and an illegal move is refused with the legal ones listed. The loop
coupling re-homes on it: eager init is a hidden prelude on a multi-step prompt (a
forced `tool_choice` is opt-in), the mid-run nudge fires once per crossing of
changes landed (edits, writes, and bash the permission verdict does not allow) and
twice per cycle, and a turn that stops with an item still pending or running is re-
driven up a three-rung ladder keyed on the open set's fingerprint (progress restarts
it), capped at six re-drives per cycle with the counter persisted in
`custom{todo_intercept}`, never after an aborted, errored, length or deferred stop,
never while a child runs, and suppressed only by an item blocked on the user or an
`ask_user` call, never by a question mark; an empty stop is re-driven at most three
times. The plan tool keeps checks, edges, sub-plans and delegation, and its `set` no
longer allocates a goal-less plan. The list renders live as a HUD block in the TUI
and the console (`_yi/todo` update and request; the replay frame carries it), rides
the environment block as one line, and prints through `yi todo`

## Why

A glm-5.3-flash session asked to rate the repository ran the suite for four minutes,
read no source file, stopped with the work unfinished and no list anywhere the user
could see; the only checklist Yi had was a git-tracked plan document under
`.yi/plans/` that a three-step task should never create, the interception that stops
a turn from ending with open work was bound to that store and escapable with a
trailing `?`, and the user's 2026-08-31 directive for a dedicated todo tool had been
folded into the plan engine instead of built. Seven reference agents were read for
the bounds (jcode's fingerprint and cap, strix's persisted counter, dsh's terminal-
stop rule and bookkeeping exclusion, OMP's empty-stop cap); none reads its list back
at stop time, so every bound here carries a test seen red first

## Reversible via

Delete `crates/runtime/src/todo/`, `yi_types::todo`, the HUD block, the `_yi/todo`
surfaces and `yi todo`; the plan tool's `set` regains its `checklist` allocation and
the coupling returns to `plan/loop_coupling.rs`
