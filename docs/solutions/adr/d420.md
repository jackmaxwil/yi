# D420: an interactive `yi tui` or `yi console` given `--control <socket>` connects...

Status: accepted

## Decision

An interactive `yi tui` or `yi console` given `--control <socket>` connects to that
unix socket before it takes the screen and plays the drive's timing steps (`tick`,
`hold`, `release`, `wait-idle`) sent one per line on the same code the headless
drive runs, answering each `ok` or `error: <why>` on one line once done, a first
`tick` freezing the clock; `tui_see.py`'s Ghostty proxy still types the scene's keys
as terminal bytes and sends those steps there, opening a frozen scene with `tick 0`,
so frozen scenes play in Ghostty (CI no longer routes them headless) and `wait-idle`
is the binary's own turn state; a `tick` waits up to 5 s for an armed hold to be
reached; the orb steps on the app clock

## Why

The owner wants held and ticked scenes in true colour with kitty images, and the
proxy's stand-in for `wait-idle` (a screen still for a second, digits ignored)
called a turn idle while it was still writing its checkpoint

## Reversible via

Drop `--control`, `Control`, `serve`, `serve_solo` and the proxy's control branch,
and route scenes with `tick` or `hold` back to the headless host in `tui_see.py ci`
