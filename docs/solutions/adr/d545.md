# D545: amends D278's lowercase ASCII tokens

Status: accepted

## Decision

Amends D278's lowercase ASCII tokens: notes and past sessions are tokenized in
Unicode: a token is a run of `char::is_alphanumeric`, `_` or a combining mark
(virama, Indic, Thai, accent blocks) lowercased with `str::to_lowercase`, `.` `/`
`-` still join and the 61 function words still drop; `history.search` keeps one BM25
index per process, per file set (at most eight sets), rebuilt when any session
file's stamp (length, mtime, device, inode) moves and never kept for a file that
cannot be stat'd

## Why

The ASCII tokenizer split an accented word into fragments, so `résumé` was indexed
as `r` and `sum` and matched a note about a sum; every query rebuilt the index over
every unit and one cold parse held the file map lock against every other search

## Reversible via

Restore `is_ascii_alphanumeric` and `to_ascii_lowercase` in `memory::rank::tokens`
and the per-query `Bm25::new` in `history::search_reply`
