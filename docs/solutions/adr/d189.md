# D189: the todo tool reads its fields by the name a model gives them

Status: accepted

## Decision

The todo tool reads its fields by the name a model gives them: `action`/`operation`
read as `op`, `checklist` as `list`, `tasks`/`todos` as `items`,
`task`/`item`/`title`/`text`/`name` as `label`, `item_id`/`task_id` as `id`, `proof`
as `evidence`, `why` as `reason`, `message` as `note`, `parent` as `under`,
`blocked_on` as `on`, `section` as `phase`; the canonical key wins, a renamed call's
result opens with `(fields: "task" read as "label")`, and every argument error ends
with a full call for its op (`drop requires "reason"; a full drop call looks like
{"op": "drop", ...}`)

## Why

41 of 352 todo calls errored across 18 v4 trials, each error a turn spent re-
deriving the schema from a message that named the missing field but not the shape of
a working call (the 2026-09-11 v4 sweep)

## Reversible via

Drop the alias table and the examples; the schema in the tool list already names
every field
