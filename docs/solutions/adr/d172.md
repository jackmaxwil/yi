# D172: the public mirror is a derived history, not the forge's

Status: accepted

## Decision

The public mirror is a derived history, not the forge's: `scripts/mirror/sync.sh`
clones `main`, rewrites it with `git filter-repo` (the paths in `exclude.txt`
dropped at every commit, the literals in `replace.txt` substituted in blobs and
messages, identities through `mailmap.txt`, nothing pruned, so every commit and
every pull request's merge subject survives one for one), scans every blob line,
message and identity of the result against `deny.txt`, and force-pushes it to
`github.com/jackmaxwil/yi`; `check_public_surface.py` holds the tree to the same
rules at every commit, so a file that names the estate fails until it is excluded or
its text replaced; LICENSE (MIT, which the workspace already declared) and
CONTRIBUTING.md land with it

## Why

A forge push mirror can only publish the forge's literal history, and that history
names the estate: across 1148 commits no credential and no private address, but the
forge's hostnames in 12 paths, the forge user's own address on every merge it wrote,
and a register and planning docs that describe containers, VMs and a stored
credential's status; rewriting the forge instead would break every pull request's
recorded ids and every worktree, and a squash pays the same tree scrub to lose the
history; filter-repo is deterministic, so the derived history is reproducible from
the forge and a push is a fast-forward until a rule changes, and one list driving
both the rewrite and the gate is what keeps the gate from drifting from the mirror
(issue #370)

## Reversible via

Delete `scripts/mirror/`, `check_public_surface.py` and its two aggregator lines;
the GitHub repository is deleted by hand, and what it published stays published
