# D142: two lane verbs, and the pool asks at claim

Status: accepted

## Decision

Two lane verbs, and the pool asks at claim: `/land "Title"` fetches and merges
`origin/main` first (a conflict aborts, verifies the tree clean, steers with at most
20 fenced file names, pushes nothing), then pushes and opens, and on green merges;
`/land` with no title reports the landing, asking the forge for an open pull request
by head branch when the handle is unlanded, so a resumed session finds its pull
request instead of opening a second; `/discard` throws away; `/pr` and `/base`
answer with a pointer to `/land`; `/lanes` reads the pool from a lane or the trunk;
one poller per handle (`compare_exchange` on an `AtomicBool`, a second `/land` is
refused as in progress); a full pool at an interactive start lists what was left,
asks outside the pool lock, and applies the answer through `reap_left_by`, which
refuses a slot whose session changed; an unread tree is never offered as lossless;
the model's environment block loses the lane line and gains `landing: …` only while
a pull request is open or merged; the TUI stamps when a landing arrived and the
segment says `· 3 h ago` past two poll periods; lane verbs run off the render thread
(`Command::Slash`) and the solo TUI routes them at all

## Why

Nine words stood before a person's first landing and one of them (`land with /land`)
was addressed to the model, which cannot run it; a resumed session started
`Unlanded` and `/land` opened a second pull request the forge refused; the solo
TUI's slash table never routed `/land`, so only the console had the verbs; two
`/land` calls were two pollers

## Reversible via

Restore `/pr` and `/base` in `slash::lane_verb`, drop the prompt arm in
`claim_lane`, and put the lane line back in `environment::hook`
