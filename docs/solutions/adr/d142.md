# D142: bash has a clock and refuses an unbounded root walk

Status: accepted

## Decision

Bash has a clock and refuses an unbounded root walk: every command runs under
`timeout_secs` (default 120 s, ceiling 600 s), named in the schema so the model
raises it for a build or a suite; past it the process group is killed through the
job registry's own `kill` and the result reads `[timed out after Ns; pass
timeout_secs up to 600 for a longer run, or narrow the command]` with `timedOut` in
the details, while a shorter `auto_background` still wins and backgrounds instead;
and a walk of `/`, `~`, `$HOME`, `/home`, `/opt`, `/root`, `/usr` or `/var` by
`find` without `-maxdepth`, `-prune` or `-quit`, recursive `grep`, `rg` without
`--max-depth`, `du` without `-d` or `ls -R` is refused before it spawns with
`[refused: `find /` walks the whole filesystem; search from the cwd, add -maxdepth
N, or name the directory you expect]`; `extract.py` counts both as `bash_timeouts`
and `broad_search_refused`

## Why

Ledger row 0015's seen-red rollouts include one that spent its whole 600 s attempt
inside `find / -name slug.py`: the tool had no wall clock (`run_or_background`
waited on `recv()` unless `bash.auto_background_ms` was set) and the permission gate
calls a root walk safe, so in auto mode the walk ran unasked and held the turn until
the harness killed the trial (issue #263). A refusal is one deterministic string the
model narrows on in one turn; an injected `-maxdepth` would change the answer set
silently

## Reversible via

Delete `clamp_timeout`, the `TimedOut` arm and `broad_search`; `run_or_background`
returns to `recv()`
