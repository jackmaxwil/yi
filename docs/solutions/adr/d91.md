# D91: the dist build belongs to the aggregator, not to `just guardrails`

Status: accepted

## Decision

`just guardrails` no longer depends on `build-dist`. `check_guardrails.sh` runs
`cargo build --profile dist -p yi-cli` itself, inside the same branch that
decides whether `binary_size` and `startup` run at all, and announces
`skip build-dist` under `CI` beside the two skips D70 and D68 already print. A
build that fails fails both gates rather than leaving whatever binary happens to
be on disk to answer for the tree.

## Rationale

`binary_size` and `startup` are the only two readers of `target/dist/yi` — a
grep over the tree finds one further mention, a policy string in
`crates/runtime/tests/gate_battery.rs`, which never opens the file. Both gates
announce-skip when `CI` is set: D70 because the baseline is a macOS arm64 byte
count and any other target measures a different binary against it, D68 because a
shared runner cannot resolve a 5 ms budget.

A `just` dependency cannot see that branch. It fires before the script starts, so
every CI job built the shipping binary — fat LTO, `codegen-units = 1` — and then
skipped both of the gates that would have opened it. Measured on run
33445818093, a green two-OS gate: `Finished dist profile [optimized] target(s)
in 1m 44s` on `macos-latest`, `in 2m 49s` on `ubuntu-latest`. That is 13 % and
17 % of each job's wall clock spent on an artifact with no reader.

Moving the build to the decision preserves the guarantee D31 wrote it for. The
reason `guardrails` depended on `build-dist` was that "a gate measuring whatever
stale binary is lying around measures nothing"; locally the build still runs
immediately before the two gates read it, which is the same ordering with one
fewer place to state it. The failure branch is the half the recipe-level
dependency gave for free and a bare `cargo build` inside `run` would not: under
`set -u` without `-e`, a failed build would otherwise fall through to two gates
that would happily measure a binary from an earlier commit.

This is not a revision of D68 or D70. Those skips existed before this change and
are unchanged by it; what changes is only that the runner stops producing an
input that nothing on it consumes.

## Reversal path

Restore `guardrails: build-dist` in the justfile and collapse the aggregator's
branch back into the two independent `if` blocks it replaced.

Source of truth: the decision log in docs/ARCHITECTURE.md (D91); the gates
themselves are D68 and D70, and the profile is docs/YI_DESIGN.md §13.2.
