# D326: the memory journal reads and appends through the plan journal's line reader,...

Status: accepted

## Decision

The memory journal reads and appends through the plan journal's line reader,
amending D277: `plan::journal::Journal::lines` gives both journals one line split in
which a line over `RECORD_CAP` is damage, `append_line` follows every append with
`sync_data`, and a torn last line is set aside to `ops.torn.<nonce>` with its bytes
kept instead of cut; a line that is not a record still marks the memory journal
broken and its replay reads on past it, while the plan journal stops there as before

## Why

The memory journal cut a torn tail on replay, destroying what a crash left, and
never synced an append, where the plan journal kept both rules over the same digest-
chained format (audit 2026-09-28, #842)

## Reversible via

Give the memory journal its own reader again: cut the torn tail, append without sync
