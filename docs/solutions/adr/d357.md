# D357: the read gate's delete unlinks through the parent it opened as judged on...

Status: accepted

## Decision

The read gate's delete unlinks through the parent it opened as judged on every
system, with `rustix` 0.38 as a direct dependency of `yi-permission` (amends D339,
which left macOS unlinking by name): the parent opens with `O_NOFOLLOW_ANY` on macOS
and under the name judged on Linux, then `unlinkat(dir, name, 0)` removes the entry
inside it, a link itself when the name is one

## Why

Std has no `unlinkat`, and the review of #963 measured one key deleted in 100,000
parent-swap removes on macOS; `forbid(unsafe_code)` stays, rustix 0.38 is the
version crossterm already links, and `/dev/fd/N/name` does not resolve under a
directory descriptor on macOS

## Reversible via

Drop `rustix` and unlink by the resolved name again
