# D100: `Blocked{on: External}` is a scheduled question, not a dead end

Status: accepted

## Decision

A todo blocked on an external condition may carry a probe, and the host runs
it. `ProbeLadder` (`crates/runtime/src/plan/probe.rs`) holds one pending slot
per blocked todo, keyed `<plan>/<label>`, and `tick(now)` walks the canonical
plan for `TodoState::Blocked { on: BlockedOn::External { probe }, .. }`.

The interval is a saturating ladder. `Rung::delay` shifts `FIRST_DELAY` (60 s)
left by the rung count with `checked_shl`, then clamps to `MAX_DELAY` (30
minutes), so the sequence is 60, 120, 240, 480, 960, 1800, 1800 — forever. A
rung past the point where the shift overflows still names the ceiling rather
than wrapping (`a_rung_far_past_the_ceiling_still_names_the_ceiling`). A slot
seen for the first time is entered with its due one full rung ahead, so
blocking a todo never runs its probe inside the same turn.

A pass is a host op, not a suggestion: `unblock` applies `OpRequest { actor:
Actor::Host, op: Op::Unblock { label } }` against the engine and says so on the
session as a `plan_probe` custom message delivered `Steer`. A red probe climbs
one rung and is not re-run before the new due time
(`a_red_probe_is_not_re_run_before_its_rung_comes_due`). A block carrying no
probe cannot be cleared by a machine at all, so it nudges its owner with the
same message channel and sets its next due at `MAX_DELAY` — the ceiling
interval is the nudge interval. A todo that leaves the blocked state leaves the
ladder with it (`forget_all_but`, `a_todo_that_is_no_longer_blocked_leaves_the_ladder`).

The probe itself is `crate::goal::run_check(command, PROBE_TIMEOUT_MS)` with a
30-second budget: `sh -c`, exit zero is a pass. A probe and a goal check are
one mechanism, so nothing new adjudicates a shell command. `ProbeRun` is a
function alias and `with_run` swaps it, which is how the ladder's decisions are
tested without a shell; `Verdict` is kept as data for the same reason — a tick
returns `Unblocked`, `Retry` or `Nudged` and the test reads the verdict rather
than a clock.

`spawn` runs the ladder off the wall clock in its own tokio task: sleep
`next_wake` — the minimum due, floored at one second and capped by `IDLE_POLL`
(60 s) so a block that opens between ticks is still noticed — then tick under
`spawn_blocking`, because `run_check` parks the thread. `wire_plan_engine`
(`crates/runtime/src/wiring.rs`) makes the one `spawn` call, inside the
`wiring.depth == 0` arm, so only the owner runs probes and a child never does.

## Rationale

The loop already had the posture and nothing was on the other end of it.
`stop_posture` in `crates/runtime/src/plan/loop_coupling.rs` returns
`StopPosture::Cadence` for `BlockedOn::External` — "check on a cadence, do not
spin" — which is a promise the runtime could not keep, because no component
checked anything. A todo waiting on a deploy, a review or a vendor sat until a
person noticed, which is the one shape of stuck the topology was supposed to
have no answer for.

Turns are the wrong clock, and that is the whole reason the ladder is a task.
The sessions that need re-checking are exactly the ones that have gone quiet on
`Cadence`: a loop that has stopped generating turns cannot be the thing that
counts them. The ladder therefore reads `Instant`, sleeps, and applies its op
through the engine like any other actor.

The ceiling is what keeps a permanently unsatisfiable condition cheap. A
condition nobody will ever meet costs one `sh -c` every thirty minutes rather
than one per turn, and the exponent never grows without bound.

**The reset on resume is a bound, recorded rather than smoothed.** Due times
live only in `ProbeLadder`'s in-memory map, so a resumed session restarts every
ladder at the first rung and re-runs the probe a minute later, however many
attempts the previous process had already climbed. That is a deliberate trade,
not an oversight: a probe is cheap and re-running one is not the runaway that
the spawn fuse guards against, so it does not earn a durable counter or a
frontmatter field. The cost is that a long-lived block crossing many restarts
is checked more often than the ladder's shape suggests.

## Reversal path

Delete `crates/runtime/src/plan/probe.rs` and its one `crate::plan::probe::spawn`
call in `wire_plan_engine`. `BlockedOn::External`'s `probe` field goes back to
being carried in the plan file and never run, which is what shipped before this
row; `StopPosture::Cadence` stays, because the loop coupling derives it from
the plan alone and has no dependency on the ladder.

`unblock` goes through is the same one every other actor's op does.
