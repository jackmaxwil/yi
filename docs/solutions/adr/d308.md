# D308: a PR is reviewed in rounds, and a round is a comment whose shape, not its...

Status: accepted

## Decision

A PR is reviewed in rounds, and a round is a comment whose shape, not its author's
tool, makes it one: first line `<!-- yi-round <n> -->` (the upsert key), second
`<!-- yi-round-meta pr= sha= base= verdict=clean|blocked|override
mode=shadow|blocking high= medium= low= -->`, the confirmed findings as JSON in a
last comment line; only a comment from an allowed author (`YI_ROUND_AUTHORS`, else
the `fgj` login, `forgejo-actions` and `yi-bot`) counts, and a round posts as the
account `fgj` is signed in as, which in the `review` job
(`.forgejo/workflows/review.yml`, on each new head of a same-repo draft) is `yi-bot`
through the `REVIEW_BOT_TOKEN` secret in `FGJ_TOKEN`, so a marker in a body, a diff
or another account's comment is text; `just pr review N` (`scripts/pr_review.py`)
runs intake (the template check, and a duplicate check: the same `Closes #N`, or 8
or more shared normalized 6-line windows of added text, with changelog,
ARCHITECTURE, ADR and baseline files skipped and a stack's own neighbours exempt),
then read-only readers, one per probe file in `skills/yi/pr-review/probes/`
(frontmatter `id`, `question`, `claim`, `when`, `severity`, `refute`, the brief as
body; correctness, tests and simplify always, necessity on a whole-PR read, perf and
security when the change touches their paths), each one `yi ask --confirm --schema`
in a detached checkout of the head with only its own claim section, fenced as data,
and a model whose family is not the authors' (`anthropic` is avoided); then refuters
that default to refuted, one per low or medium finding and three per high kept on a
majority; a finding survives only when the host finds its quote on the line it names
at that head, and a high one whose line the diff did not add is kept as medium,
since a round judges the change and not the codebase; a high finding blocks, and
`/override <reason>` from an allowed author posted after a blocked round and before
the next reads that round as `override`; round one reads the merge base to the head,
a later one reads from the newest clean head still in the history, and a second read
of an unchanged head reads the first read's range; a reader or refuter that does not
answer leaves no round; a head is read at most twice while clean and once when
blocked, under a per-PR flock in the common git dir, so a repeated or racing trigger
posts nothing; a draft may be readied after two rounds whose last is on its head and
not blocked, which `just pr ready` enforces only when `pr_review.MODE` is `blocking`
(it ships `shadow`); `just pr sweep` reviews and fixes the open drafts in one pass,
and `forgejo://<host>/<repo>/pulls` emits each open head once per sha so a
subscription runs it; `just pr replay N… --label L --out F` reads labelled PRs
without posting and counts lens findings apart from intake, the evidence the flip to
`blocking` waits on

## Why

The owner's lifecycle (plan `docs/plans/2026-09-26-pr-lifecycle.md`, stages 1, 2 and
4): the last 80 merged PRs had one formal review; the plan's review pod and
`verify_quotes` need a kernel host and no verb runs a plan program headlessly, so a
round is a script over `yi ask` and the host checks quotes itself; the first dry run
read clean with every lens exiting 4, which is why a silent lens is no round; the
window threshold is measured (the four compaction PRs #159, #170, #172, #174 share
16 to 35 windows pairwise, unrelated pairs at most 2), and the plan's second cluster
(#405, #406, #409) shares none: it was never a duplicate set

## Reversible via

Delete `scripts/pr_review.py` and the three verbs; rounds already posted are inert
comments
