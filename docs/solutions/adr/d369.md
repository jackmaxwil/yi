# D369: every plan and todo refusal names its class in `details.errorKind`, and the...

Status: accepted

## Decision

Every plan and todo refusal names its class in `details.errorKind`, and the closed
taxonomy gains `stale` (the call named state the world no longer holds: a plan
already closed, a label gone, a list changed since the model saw it) and `verdict`
(the tool understood the call and a rule said no: a cycle, a failing check, a cap);
the class is read from the engine's own error variant by an exhaustive table
(`plan/kinds.rs`, `TodoError::kind`), a misread is `invalid_args` and a safety
refusal `denied`; the session miner carries `errorKind` into its issues and
`evals/surface.py` counts failed calls as misread, stale, verdict, exit, api_misuse
(a kernel call into rlm/yi), safety, tool or untagged, printing the eval ledger's
new `tool-failures` cell; the twelve #982 dogfood prompts join the surface scenarios
as `plan-*`

## Why

The owner set the target ("figure out how to get failure rate and refusals to 0%")
and what counts toward it ("Misreads + stale state"), and a target is only as good
as its count: the dogfood's first classifier matched error text with regular
expressions, which a reworded message escapes, while the engine already names every
refusal by variant (`PlanOpError::code`); the baseline row 0073 counts 26 misreads
and 3 stale of 254 calls, and none untagged

## Reversible via

Drop `plan/kinds.rs`, `TodoError::kind` and the two variants (`yi stats` and the
graph predicates then see `tool_error` again), and the census's `classes`
