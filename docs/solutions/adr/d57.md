# D57: Direct OpenAI is a real openai-responses adapter

Status: accepted

## Decision

Direct OpenAI is a real `openai-responses` A3 adapter, never an alias onto `openai-completions`. Conversation state stays in Yi (`store: false`, no `previous_response_id`). Hosted OpenAI tools stay off; Yi's tool loop and permission broker own side effects. Stream terminals are `response.completed`, `response.incomplete` (length), `response.failed`, and `error`; Done/Error is emitted when that event arrives, not at HTTP EOF. D29 freeform `edit` is still JSON-schema functions on this path.

## Rationale

Chat Completions cannot do tool calling with reasoning on GPT-5.4+; aliasing Luna onto `/chat/completions` would look live and then drop tools. Server-side response ids fight rewind, compaction, and the disk transcript. An in-request hosted-tool loop bypasses M10. OpenAI's contract has four terminals including `incomplete`; treating EOF as success is the langchain/OpenClaw incident.

## Reversal path

Drop the match arm (Luna falls back to faux again); D29 freeform is an additive tool-format row.
