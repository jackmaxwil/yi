# D94: a TUI recording is captured at the draw boundary and rendered outside the binary

Status: accepted

## Decision

`RecordingBackend` (`crates/tui/src/capture.rs`) wraps ratatui's `TestBackend`
— the one the headless drive harness asserts frames against — and mirrors
every non-empty `draw` into a `CrosstermBackend<CastWriter>` at the same time.
`CastWriter` writes an asciicast v2 file: a JSON header line, then one
`[time, "o", payload]` event per flush, with the synchronized-update bracket
(`CSI ?2026h/l`) stripped because it means nothing to a player and would
otherwise appear on every idle tick.

`just tui-proof <script>` drives the real loop with `--record` and `--snap`
to produce a motion cast and a one-frame still cast, then renders both through
`agg` (`brew install agg`, dev-only, never linked into the binary) into
`run.gif` and `still.gif` for the pull request.

## Rationale

A model reads a text grid; a person judging whether a UI looks right cannot.
Closing that gap without taxing the shipped binary means the artifact has to
be produced outside it: fonts, rasterizers, and image encoders are exactly
what the size ledger (D69) exists to keep out of `yi` itself. Teeing
crossterm's own generated bytes, rather than hand-rolling an emitter, means
the escape sequences a recording plays back — scroll regions, clears, SGR —
are the same bytes the terminal path already exercises under test, not a
second implementation of them.

## Reversal path

Drop the `--record`/`--snap` flags and `crates/tui/src/capture.rs`; the frame
dumps and every assertion path that reads `RecordingBackend::screen` are
untouched.
