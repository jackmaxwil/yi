# D97: the plan is a git-tracked document and `Fact::Plan` is a pointer at it

Status: accepted

## Decision

A plan is one Markdown file with YAML frontmatter, `<plan-id>.md` under
`plans.dir` (default `.yi/plans/`, `PlansConfig` in `crates/types/src/config.rs`).
The frontmatter is the ledger: `format`, `plan`, `goal`, `version`, `touched`,
`tier`, `spawns`, `state`, and the `todos` list. The Markdown body under it is
prose in `## <heading>` sections, parsed and re-rendered verbatim.

`Fact::Plan` keeps its exact wire shape and gains one field, `doc:
Option<String>`. Set, it names the file that is truth. It is a bare `String` on
purpose — a validating newtype on a durable JSONL field would make one bad byte
cost the whole session file, so a malformed pointer parses, round-trips, and
stays visible (`crates/types/src/plan.rs`,
`a_malformed_doc_pointer_leaves_the_fact_loadable`).

**One process writes.** Every `PlanEngine::apply` takes `PlanStore::lease()`
first, and every write is tmp-plus-rename into place. The lease is a `.lease`
directory whose arbiter is a uniquely named `hold.<pid>.<n>` file the holder
writes and then reads back — not the directory, so a holder whose file is gone
releases nothing and cannot unlock whoever took the path over. Staleness reuses
K1's rule verbatim, branching: a parseable pid file makes staleness dead-pid
only (`yi_kernel::bootstrap::read_lock_pid` plus `process_is_running`), and the
30 s mtime rule (`lock_missing_pid_is_stale`) covers the arms K1 leaves it.

**The user's editor is the sanctioned second writer.** `PlanStore::user_edits`
diffs the engine's last-known `PlanFile` against what is on disk into typed
`UserEdit` rows — goal reworded, plan state changed, spawns changed, todo
added/dropped/state-changed/edges-changed/edited/reordered, preamble or section
edited. That one differ also renders the human-readable plan diff, through
`Display`. `fold_user_edits` replays each row before the engine's own op: each
bumps `touched`, and a folded edit that moves a delegated todo out of Running
reaps its child through `reap_leaving_running`, the same call an engine op makes.

Todos are addressed by verbatim label. `Plan::validate` refuses duplicate labels
*and* labels that collide after slugging, because a `plan://` URL addresses a
todo by the slug of its label (`SLUG_MAX` 40, `TODO_LABEL_MAX` 80). `after`
edges carry ordering and no data; they are sibling-only and acyclic, checked at
every insert rather than at read.

`version` bumps on `supersede` alone. A separate monotonic `touched` counter
bumps on every framed op and every folded user edit, and the staleness latch in
`plan/mod.rs` reads `touched`. `drop` marks `Abandoned`. `Plan::finished()` is
*every todo terminal* — Done, Failed, or Abandoned, and non-empty — not every
todo Done, so one dropped todo cannot wedge a plan forever. `framed` recomputes
`state` each pass over `Active | Done` in both directions rather than latching.

Every mutating op is gated on the target plan's state and routed through one
step table (`plan/table.rs`: `STEPS`, `from`/`op`/`to`), so legality is data.
`step_todo` is the single site that writes a todo state, which is what gives
reap-on-leaving-Running exactly one implementation. `supersede` reaps every
Running delegation in the plan family — the root plus every `<root>.<child>` —
marks each `failed: superseded: <reason>`, abandons the sub-plans, and returns
before any write if a reap fails.

Four bounds are mechanisms rather than advice:

- The **spawn fuse** is a private `spawns` field on the *root* frontmatter with
  `charge_spawn` as its only writer, so a crash-and-resume cannot refill it;
  `SPAWN_CAP` is 64, and a sub-plan dispatch charges the root's fuse.
- The **dispatch width** is `clamp(cores − 1, 1, 8)` measured from
  `std::thread::available_parallelism`, so a two-core container serialises
  without anything knowing which benchmark it is running.
- **Promotion runs at reap**, whatever the outcome: `step_todo` hands the
  host-minted `last` into the new state, so a child that failed after real work
  leaves its product behind on the `Failed` todo.
- The **32 KiB frontmatter cap** is checked in `precheck`, for every file in
  the write set, before any of them is written — refused, never trimmed.

`proptest` joins dev-only under the D71 pattern to fuzz the step table.

## Rationale

The fact was the store, and that is what it cost. A child could not read a plan,
because a fact lives inside one session's mutation log. A human could not open
one, diff one, or review one in a pull request. It did not survive the session
that wrote it. And a forty-todo ledger sat inside every request prefix on every
turn, because the only way for the model to see the plan was for the plan to be
in the context. A file fixes all four at once: a child reads `plan://`, a person
reads `git diff`, the file outlives the session, and the prefix carries a
summary line and the frontier (`summary_line`, `frontier_text`) instead of the
ledger.

**D53 is reconciled, not repealed.** D53's expand-only rule was defending
against a plan that quietly loses work — a reword that erases what was agreed, a
delete that hides a task that failed. Nothing here deletes: `drop` is a state,
not a removal; a reword is append-new plus abandon-old; a superseded generation
keeps its file forever, which is why `allocate_child` suffixes rather than
overwrites. `supersede` is the one audited exception, and it is exactly the
thing D53 was defending against silent versions of: it bumps `version`, records
the reason on every todo it terminates, and leaves the old generation on disk.

The `version`/`touched` split falls out of that reconciliation rather than being
a separate choice. Once edits stop bumping `version` — because only `supersede`
bumps it — a staleness latch keyed on `version` goes quiet during exactly the
churn it exists to watch: a plan being worked hard for twenty turns would look
untouched. So the signal moves to its own monotonic counter, `touched`, which
every op and every folded hand edit advances.

**YAML because the second writer is a person with an editor.** Frontmatter is
the format a plan file can be opened in, hand-edited, and diffed without a tool.
Hand-rolled because no YAML crate is here, `toml` is banned by name in §13.5 and
enforced by `deny.toml`, and the transitive budget (`deps_budget.json`, 167) had
one unit of headroom. The measured trade: `plan/yaml.rs` is 733 lines of code
for a strict subset that converts between text and a value tree and refuses
everything outside it *by line number* — against a general YAML crate, which is
not 733 lines and not one dependency. The subset earns a second guarantee for
free: `PlanStore::write` emits, re-parses, and compares the value tree before it
writes, so `Drifted` and `Unreadable` are refusals with nothing written rather
than a file on disk that no longer says what the engine thought it said.

**The fuzzer earned its dev-dependency before it was finished.** `plan_fuzz.rs`
drives random op sequences against the real engine, a real temp store and a stub
delegate, and re-asserts every insert-check invariant after every op; it rides
`just check` at 256 cases and soaks on `PROPTEST_CASES` at roughly linear cost.
Its first run found `retry` on a finished sub-plan leaving the plan `Done` with
a `Pending` todo in it. An adversarial review reached the same latch from the
other side.

Between them the fuzzer and that review found **twenty defects**. Every one was
reproduced as a failing test before it was fixed, and every one left that test
behind. Three of the sharpest:

- **`block` leaked a live child.** Blocking a Running delegated todo moved the
  state and never reaped, so a real child kept running against a plan that had
  stopped waiting for it. The fix was not a guard in `block`: it was making
  `step_todo` the only writer of todo state, so *every* exit from Running reaps
  — `drop`, `block`, `fail`, `done`, and a hand edit alike
  (`blocking_a_running_delegated_todo_reaps_the_child`).
- **`supersede` counted phantom flight forever.** The abandoned sub-plans it
  left behind still held their Running todos, and `family_flight` still counted
  them, so the dispatch width stayed permanently spent on children that no
  longer existed. `family_flight` now counts only `Active` plans, and supersede
  terminates the sub-plan todos it reaps
  (`supersede_terminates_sub_plan_todos_and_frees_the_width`).
- **`Done` latched irreversibly.** A plan whose last todo `Failed` is finished
  by the terminal rule but is not over — a Failed todo is still workable. The
  latched version could not be found by an unnamed `View` and could not be
  retried. State is now recomputed each pass, so the plan is reachable, `retry`
  reopens it to `Active`, and only a genuinely finished plan refuses
  (`a_plan_whose_last_todo_failed_stays_reachable_unnamed`).

## Reversal path

Delete `crates/runtime/src/plan/{store,ops,table,tool,dispatch,loop_coupling,yaml}.rs`
and the `doc` pointer field. `Fact::Plan` still carries `tasks`, every existing
session file still loads, and the three durable v4 fixtures still round-trip
byte-identically, because the pointer is additive and the legacy shape never
changed.

Two bounds are honest rather than flattering. `supersede` is **file-atomic, not
side-effect-atomic**: it refuses before any write if a reap fails, and
`write_all` cap-checks every file in the set before writing any of them, so no
file is ever half-written — but the reaps that already succeeded are not undone,
and the write set is a sequence of individually atomic renames rather than one
transaction. A crash between two of those renames leaves the family consistent
per file and inconsistent across them. Fold-time reaps share the same bound: a
hand edit that moves a delegated todo out of Running reaps its child during
`fold_user_edits`, and a refusal later in the same op does not bring the child
back.
