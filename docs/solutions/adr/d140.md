# D140: evals measure five axes from the run's own record and Terminal-Bench v4 is...

Status: accepted

## Decision

Evals measure five axes from the run's own record and Terminal-Bench v4 is the pass
axis's external row: `evals/axes.py` reads any directory of trials (harbor
`result.json`, run.py `row.json`, a journey's session files) and prints pass,
persistence, rigor, experience and economy per trial and the ledger row, every
column a deterministic function of the event stream, the v4 session JSONL and the
telemetry sidecar as docs/plans/2026-09-06-tbv4-evals/axes.md names it; `extract.py`
v5 adds `intercept_count`, `intercept_max_rung` and `regression_seen_red`; the
ledger gains `persistence`, `rigor` and `experience` on the right; the v4 run is a
pinned six-task subset by digest with the timeout multiplier in the fingerprint, on
`openrouter/z-ai/glm-5.3-flash` only, user-run under the existing caps, never a
leaderboard claim

## Why

Issue #100 asked for a real row and the benchmark moved under it (all 89 TB2.1 tasks
archived, every v4 task at 28,800 s, verifier separate, reward hacking judged over
ATIF, submissions closed); the driver named a flag harbor lacks and a directory it
never writes, so its money gate failed open; the prompt-surface instrument already
computes the persistence and rigor facts from the JSONL, and law 2 forbids a judge,
so the axes are the instrument's columns on the ledger and nothing else

## Reversible via

Delete `axes.py`, the three signals and the three columns; the driver and adapter
keep the S1 repairs, which fix defects rather than add design
