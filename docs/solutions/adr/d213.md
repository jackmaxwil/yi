# D213: a read has pages and the unit is the listing's own

Status: accepted

## Decision

A read has pages and the unit is the listing's own: the `fetch` host request takes
`offset` and `limit` (`fetch::Page`, parsed by `Page::from_payload`) and a paged
reply carries `next_offset`, null at the end; the unit is bytes of a `local://`
text, entries of a `history://` listing, and chars of a `kernel://` repr, whose page
is clamped to `VARIABLE_MAX_CHARS` and carries no truncation marker; a request
naming neither key is answered key for key as before (`Fetched::into_reply`), so no
existing caller and no prompt byte moves; a zero, negative, fractional or non-
numeric number is refused at the host boundary, never clamped, a huge limit means
the rest, and an offset past the end is an empty last page; both cuts of a byte page
land on a char boundary and the end always passes the offset, so a page is always
text and a walk always advances, wherever the caller's arithmetic fell; a page is
refused on any other scheme, on one `history://` entry, and on
`history://<agent>/tail/N`, a window anchored at the end of a growing listing, so
any append slides it, while the whole listing and `since/<seq>` are anchored at the
start and page cleanly; a paged read of the reading session's own history appends
no fetch-log row (`FetchLog::remember`), so a walk of it ends at any limit rather
than chasing the rows each page wrote; a page is refused beside D164's `object`
rather than dropped; `rlm.fetch(url, offset=, limit=)` returns `rlm.Page`, a `str`
with `next_offset`
(stage F1c of `docs/archive/plans/2026-09-12-yi-operating-system.md`; extends D164)

## Why

A read was whole or nothing: a spill file, a long transcript or another member's
repr past the 8 KiB cap cost its full size in context or lost its tail behind a
marker nobody could read past, and the scatter lead's quote check reads a whole page
for one line; the cursor is returned rather than computed by the caller because only
the host knows where a char boundary or the end is, and refusing a bad number rather
than clamping it keeps a model from looping on a read it did not ask for

## Reversible via

Delete `Page`, `fetch_page` and the `page` argument of the three resolvers and of
`KernelVariables::read`; `fetch` answers every request whole again and `rlm.fetch`
drops two keywords
