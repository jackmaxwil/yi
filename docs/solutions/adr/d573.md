# D573: two upstream-switch misses inside 30 minutes put the host that last read the...

Status: accepted

## Decision

Two upstream-switch misses inside 30 minutes put the host that last read the route's
cache entry first in OpenRouter's `provider.order` for an hour, on that route only,
and only where the routing config sets no order of its own

## Why

OpenRouter moves a conversation between hosts under a live entry and the new host
cannot read it; the session ledger already names the switch, and a configured order
is the owner's, so the pin only fills an absent one, with fallbacks still allowed

## Reversible via

Remove the pin branch in `cache_miss::MissTracker::escalate` and the `order` field
in `openai::routing_params`
