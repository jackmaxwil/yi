# D392: plugins are pinned external programs installed on request

Status: accepted

## Decision

Plugins are pinned external programs installed on request: a const table in yi-tools
pins each one's version and one sha256 per target; `yi plugin` (add, remove, list,
sync) verifies a download before unpacking and publishes one member into
`~/.yi/plugins/<name>/<version>/`, deleting older versions; Yi uses only the pinned
version, else one on PATH, and the bash tool, the post-edit check and the kernel put
installed plugins first on PATH; the code that reads a plugin stays compiled in, so
excluding dynamically loaded plugins still holds; a row may also publish skill
directories from the same verified archive (ripwire's 16, all but `ripwire-mcp`),
read by `yi://skills/<name>` and never listed, with one Yi skill carrying
`requires:` as the catalog's pointer to them

## Why

The owner: "ripwire should be packaged as an optional yi plugin with easy install"
and "plugins should be a generic system"; ripwire's own installer also activates
seventeen skills and hooks for every agent it finds, and any ripwire on PATH was
used whatever its version, where Yi parses the 0.6.5 format

## Reversible via

Delete the table, `yi plugin`, the doctor row and the PATH lines; a ripwire on PATH
keeps working as before
