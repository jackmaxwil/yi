# D85: tests are tiered, and a ledger row names its journey

Status: accepted

## Decision

Four tiers, each named by where it runs and what it may spend:

- **T0** — unit and contract tests. `just check`. Zero spend.
- **T1** — faux cassettes: the behavior baseline plus the plan, goal and permission e2e suites
  over `faux/faux-1`. `just check`. Zero spend.
- **T2** — real-binary journeys: the built `yi` driven end to end, offline. Zero spend. A cheap
  one rides `just check` too; one that sleeps or boots a process tree per assertion is
  `#[ignore]`d with a `tier-2 journey` reason and runs only in `just journeys`, which
  `just postmerge` and the CI postmerge lane depend on. The attribute is the lane, and
  `check_test_tiers.py` holds the reason string exact: Rust spells "slow", "flaky" and "paid"
  with the same attribute, so an ignored paid test would enrol itself in a push-to-main gate
  silently. A run that costs money cannot be written as `#[ignore]` at all.
- **T3** — paid smoke: one real-provider run per suite, ledgered in docs/eval-ledger.md with
  its config fingerprint. Opt-in and user-run, never inside any gate.

Every feature-ledger row names its journey test in a `journey:` clause — new and edited rows at
land time, existing rows in the `O13` annotation pass. The clause is prose in the note column;
no mechanical gate reads it yet.

## Rationale

The ledger asserted "live" on row after row with no named proof, and the zero-spend line was
folklore: what `just check` may run, what needs a built binary, and what costs money are three
different answers that nothing had written down. A T2 journey was therefore as likely to be
skipped as run, and a paid run was one careless `just` recipe away from sitting in a gate.
Naming the tier is what makes the prompt-flywheel plan's law 3 structural rather than
remembered.

The inventory the taxonomy forced is the other half of its value: laying the nine journeys a
user can actually drive against the tests that exist named three real holes, two of which the
same landing closed.

No gate over the clauses yet, deliberately. A grep over a markdown table is brittle, and the
annotation pass has to finish before the question of whether a gate would pay is even
decidable.

A tier names spend and prerequisites, not one lane. Reading it as a lane is what let five rows
label tests "T2" that `just journeys` filtered out, and the repair is not symmetric: the two
daemon journeys sleep 13 s apiece and leave `just check`, where every PR on both matrix legs
paid for them, while the ACP and TUI journeys measure ~1 s and stay. Marking a one-second
journey `#[ignore]` to satisfy a definition would run it less often, which is the opposite of
what naming the tier was for.

## Reversal path

Drop the taxonomy text and the `journey:` clauses, delete `check_test_tiers.py` and its line in
check_guardrails.sh, and delete the two `#[ignore]` attributes on the daemon journeys to put
them back in `just check`. Every other test stays an ordinary test in the lane it already runs
in.
