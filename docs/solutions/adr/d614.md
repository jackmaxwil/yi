# D614: the model gets one tool, `show`

Status: accepted

## Decision

The model gets one tool, `show`: a file, optionally at a line, and a strength
(`peek`, `tab`, `front`), and nothing else, so it cannot read the layout, close,
move or resize. It is a request the client answers (`_yi/show`), so the model reads
what happened, and one left unanswered for five seconds says so and the turn goes
on. It is offered only in a session whose client said it can show things when it
opened it (`_meta.yi.shows`), and both of Yi's clients answer it, the console and Yi
Desktop

## Why

The owner chose "Says what, not where" on 2026-11-21 and approved this row on
2026-11-23 with one change: "this should be supported in both the desktop app and
TUI. this is a durable principle. we must have parity between desktop app and tui";
asked whether one-in-one-out applies to a tool a terminal session never carries, the
owner chose "No, nothing leaves"; Zed's follow-the-agent guesses from what a tool
touched, where this is said on purpose and answered

## Reversible via

Remove the tool, `_yi/show` and `_meta.yi.shows`; each client keeps opening panes by
its own rules
