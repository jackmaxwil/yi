# D69: the dist profile optimises for size at every level

Status: accepted

## Decision

`[profile.dist]` and `[profile.dist.package."*"]` both carry `opt-level = "z"`,
revising D31's `"s"`. The §13.2 comment that read `"z" measured too; "s" usually
wins on startup-heavy code` is deleted rather than amended, because it was the
prediction this measurement contradicts.

## Rationale

Four binaries were built from one tree and measured, rather than reasoned about.
Against a control that reproduced the baseline byte-exact:

| variant | bytes |
|---|---|
| `s` everywhere (D31) | 6,041,360 |
| `z` on the workspace crates only | -16.4 % |
| `z` everywhere | 4,636,896 (-23.2 %) |
| plus nightly `-Zlocation-detail=none -Zfmt-debug=none` | a further -316,368 |

D31 chose `"s"` to protect startup. That reason does not survive contact with a
timer: `yi --version` is 3.7 ms under `s`, under workspace-only `z`, and under
`z` everywhere, and a full faux turn is 138.4 / 138.0 / 137.7 ms across the same
three. Both numbers must be taken idle — the first attempt read 11.4 ms because a
dist build was running beside it, which is the same trap the startup ratchet
carries a warning about.

The folklore is not baseless, only misapplied. `"s"` beats `"z"` where the code
spends its time in a loop the optimiser wants to unroll and vectorise. Yi's
startup is a process spawn, one JSON parse and a write; there is no loop to
unroll, and the cost that remains is paging in the text segment, which is exactly
what `"z"` reduces.

The nightly probe is rejected in the same breath it is recorded. 316,368 bytes
does not buy the loss of `rust-toolchain.toml`'s exact-stable-as-MSRV pin or of
every derived `Debug`. The rest of min-sized-rust's ladder is rejected on the
measurement rather than on taste: rungs 1-6 (release, strip, `opt-level`, fat
LTO, `codegen-units = 1`, `panic = "abort"`) were all already in place at D31;
build-std and `panic=immediate-abort` are hello-world wins, and `std` is 533 KiB
of a 4.5 MiB `.text` here; UPX would trade the 5 ms startup budget for
decompression on every exec and antivirus heuristics on a personal binary.

The win is headroom, not a number for its own sake. D63 recorded 0.25 MiB left
under the 6 MiB budget, which is what made a syntax highlighter a dependency
question at all. This is 1.58 MiB.

## Reversal path

One word at each of the two sites in `Cargo.toml`; every ratchet re-measures on
the next `build-dist`.
