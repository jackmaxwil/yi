# D348: a walled session's kernel boots only under a sandbox profile, so on Linux,...

Status: accepted

## Decision

A walled session's kernel boots only under a sandbox profile, so on Linux, which has
no Seatbelt, a juror or any role-root walled child has no ipython and its cell is
refused with the reason; readers and workers never had ipython

## Why

#1001: on Linux the kernel and its `bash()` jobs ran with no profile, so a cell met
no wall at all; Landlock is not a small change, and only bash has a container path
(D286)

## Reversible via

Give the kernel a Landlock or container profile, then drop the refusal in
`KernelService::ensure_inner`
