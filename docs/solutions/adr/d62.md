# D62: the kernel cell renders from its own record

Status: accepted

## Decision

The `ipython` cell renders from its own D60 record through `yi-tui::pycell`, not
from U15's generic tool shape, and its collapsed head is byte-identical to its
expanded head. The one-line preview is the scored line of the source rather than
the cell's first line, and it is redacted before it reaches a frame.

## Rationale

The kernel is Yi's largest tool and rendered as its most anonymous one.
`⊙ ipython import pandas as pd` names the bookkeeping and hides the work, and a
cell that wrote three files, printed forty lines and raised an exception looked
on screen exactly like a `glob`. The generic shape has no vocabulary for a
kernel call: it cannot say how much went in and came out, cannot style stderr
apart from stdout, and cannot tell a traceback from output. The record D60 put on
the result already carries all of that, so rendering from it is reading what is
there rather than inferring from prose.

The scored preview follows from the same complaint. A cell's first line is
usually an import, a comment or a decorator — the lines a reader already knows
are there. Scoring skips those and `print`/`len`, and ranks an effect call above
a binding and a binding above a bare call, so the row names the work. A `%%bash`
cell says `bash` on its chip, because its output is a shell's and calling it
Python would mislabel the streams beneath it.

The byte-identical head is the difference between a mode toggle a reader can use
and one that scrolls the transcript out from under them. A head that changes
width when the body opens reflows every row below it, so the eye loses the cell
it was looking at at the moment it asked to see more of it. Fixing the head makes
expansion a purely additive event.

Redaction is not tidiness. The source reaches the screen, the terminal's own
scrollback, and every frame dump taken for a bug report, so a scratch cell
holding a key leaks into artifacts nobody re-reads before sharing. That is a
trust boundary, and it over-redacts by design: a token *containing* an `sk-` run
of key-shaped characters is replaced, not only one starting with it, along with a
quoted literal on a line naming key, secret, token or password, and any long
base64 run. A false positive costs a mangled preview; a false negative costs a
credential.

## Reversal path

Delete the `name == "ipython"` arm in `ToolCell::lines`; the generic head, digest
and typed body still render the same result.
