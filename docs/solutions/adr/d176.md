# D176: a kernel cell has a wall clock, and an abandoned internal cell frees the kernel

Status: accepted

## Decision

A kernel cell has a wall clock, and an abandoned internal cell frees the kernel:
`KernelService` fires a cell's abort at `KernelServiceOptions::cell_ceiling`, bash's
600 s ceiling (`MAX_TIMEOUT_SECS`) unless set, on a clock started after the kernel
boots so a venv build is not the cell's time (`Instant::checked_add`; past its
range, no clock), and `ipython`'s description names it; an internal cell (the
debounced snapshot, a variable read, a namespace listing) forced to `Aborted` after
the one-second grace clears the active slot, where a user cell keeps it for the
busy-reuse recovery, and goes out with `stop_on_error` off, since ipykernel aborts
every request queued behind a failed one; a `%%bash` cell comes back aborted at the
ceiling while its shell runs on, which nothing in Yi reaches yet

## Why

The watcher's only exit was the interrupt, so a `while True:` loop, a blocking read
or a `%%bash` cell held the turn until harbor killed the container, and a `%%bash`
cell stepped around bash's ceiling (the 2026-09-10 harness audit, B6); the
snapshot's 5 s abort left its cell in the slot after the grace, so the user's next
cell spent the five-second busy window interrupting a kernel that had not returned
and ended `BusyAfterInterrupt`, which restarts the kernel with at most its last
finished snapshot (S7); clearing the slot alone lost that cell instead, since
ipykernel aborted it behind the internal cell's `KeyboardInterrupt` and Yi reads an
aborted request as an empty success; a probe's `%%bash` child wrote its file after
the abort, since IPython's magic ends the cell on a `TypeError` (a
`CalledProcessError` whose exit status is still `None`) without stopping its shell,
and 0.214.0's group kill covers the bash tool, not the kernel

## Reversible via

Drop `cell_ceiling` and the `ceiling_at` term from the watcher; pass `false` to the
grace's `resolve_active` and send `stop_on_error` true again
