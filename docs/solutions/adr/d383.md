# D383: `yi

Status: accepted

## Decision

`yi://` is the one address of the documents the prefix names but does not carry:
`yi://tools/<name>` and `yi://skills/<name>`, resolved by `read` and `rlm.fetch`;
skill pointers from rules, `$name` and the classifier read `Relevant:
yi://skills/<name>`, replacing `skill://`, which no scheme ever served

## Why

A pointer the model cannot follow is not a pointer; one namespace instead of an
alias

## Reversible via

Point `SKILL_ADDRESS` back at `skill://`
