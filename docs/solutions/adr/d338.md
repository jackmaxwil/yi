# D338: compaction is due while the whole request leaves the reserve for the summary...

Status: accepted

## Decision

Compaction is due while the whole request leaves the reserve for the summary
request, and a cold summary attempt reads the history as text (amends D337, and
design §4.4's `BodyAfterPrefix` scope): `Compactor::due` charges the last reported
usage, the provider's count of the whole request with its system prompt and tools,
plus what follows it at bytes/3 (the charge `Compactor::elide` uses), against window
− reserve, so a history is due at window − reserve − the observed prefix counted
past that prefix. The newest reply with a usage that the latest compaction kept in
its tail counted the history before that compaction, so `due` does not read it
(`Compactor::stale`, in memory, so a resumed session may compact once more) and
counts every message at bytes/3 until a fresh reply lands; with no usage at all the
count is the messages alone, without the system prompt and tools. The server-
observed prefill, `yi_context::Scope`, `scoped_tokens`, `Prefill` and
`Compactor::on_usage` are deleted. A cold attempt (the trimmed retry, both over-
window attempts, and a first attempt on a `models.summarizer` of another model)
sends no tools, so its converted history goes out as one `serialize_conversation`
text (labeled turns, tool calls as `name(args)`, results cut to 2,000 characters)
with the directive after it, each tool output's lines after the first indented so
none reads as a role line such as `[User]:`; the warm request's bytes are unchanged.
A `models.summarizer` on another model makes every compaction cold, so its summaries
always read this text

## Why

#947: charging only the body past the first request's input made compaction due at
window − reserve + prefix, past the window whenever that input exceeded the reserve,
so the summary request went out over the window and needed the cold retry or the
D337 rescue; the tenth-price of a cached prefix does not shrink the window it fills.
#948: on the native Anthropic wire a cold attempt carried `tool_use` and
`tool_result` blocks with no `tools` field, which the Messages API refuses. The
other fix, the loop's tool table with `tool_choice: none`, would add every schema,
uncached, to the request that exists because the history is too long or the warm
reply called a tool, and hand tools to a summarizer model that may not take them

## Reversible via

Restore `Scope::BodyAfterPrefix` and `Compactor::on_usage` in `Compactor::due`, and
send `convert_to_llm` alone on a cold attempt
