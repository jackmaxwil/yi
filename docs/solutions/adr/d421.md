# D421: a root session is read by `history

Status: accepted

## Decision

A root session is read by `history://<id>` in any repository the user has, by its
name (its name fact, else its first prompt's title) in the reader's repository first
and then any other, and a child as `history://<root>/<child>` through the
`custom{child}` trail its root keeps; a name two sessions carry is refused listing
both; under a history wall, which names sessions by id, neither a name nor
`root/child` resolves

## Why

The owner's round 4 answer "Read first, then full": reading another session's record
answers most questions without waking it, and the model was asked to know session
ids it could not find

## Reversible via

Widen `find_session` back to one repository and drop `find_named`, `child_of` and
the `names` switch
