# D588: a custom provider in `providers` names the wire it speaks with an optional...

Status: accepted

## Decision

A custom provider in `providers` names the wire it speaks with an optional `api`
(`openai-completions` when unset, `openai-responses`, `anthropic-messages`; any
other value refuses at load), and a custom Messages endpoint gets its key as
`authorization: Bearer` through `compat.bearerAuth`, never `x-api-key` (amends D562)

## Why

GitHub #6 asked for OpenRelay, a gateway on the user's own machine serving OpenAI
responses and Anthropic messages with one bearer key, as a built-in provider with an
empty bundled catalog whose models lived in the refresh cache; a field on the
existing custom provider reaches the same gateway, and any other, with no vendor id
reserved in yi-types and no hand-written cache file that doctor reads as stale

## Reversible via

Delete `api` and `CustomApi`, so every custom provider speaks completions again and
a config naming `api` refuses as an unknown field
