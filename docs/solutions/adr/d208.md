# D208: the status row names the tree the session runs in, not the root its client...

Status: accepted

## Decision

The status row names the tree the session runs in, not the root its client opened:
`LaneHandle::row_label` is the one place the row's `<repo> ⎇ lane <slot>` text is
built (the standalone TUI's own copy is deleted), the ACP worker emits `_yi/workdir`
with the lane's path and that label when a session attaches and whenever either
changes (`Parent::watch_workdir`, beside `watch_goal`, diffed so a quiet turn sends
nothing), the console decodes it to `Decoded::Workdir` and calls `App::set_workdir`,
which repoints `options.cwd`, `options.lane` and rereads the branch; the daemon's
`SessionEntry.root` stays the launch root, because it is the worker routing key
(D143)

## Why

On the 2026-09-14 session the console status row read `~/Development/yi@main` for a
session that ran in lane slot `~/.yi/lanes/897d6e9162485667/2` and edited a third
tree: `state.root` is sent once at `session/new`, `make_chat` passes `lane: None`,
and the TUI rereads the branch from that fixed path, so the row named the wrong tree
and the wrong branch for the whole session

## Reversible via

Drop `watch_workdir`, the `_yi/workdir` arm and `set_workdir`, and rebuild the row
label in `shells.rs`
