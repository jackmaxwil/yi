# D335: kept permission rules are ledger entries and flow down only (#600 stage 2c;...

Status: accepted

## Decision

Kept permission rules are ledger entries and flow down only (#600 stage 2c; amends
D207, D312 and D331): each rule an "always" keeps is appended to the holder's own
session JSONL as `Entry::Custom { custom_type: "permission_rule" }` carrying its
`SessionPermissionRule`, and `AgentSession::attach_store` replays them through
`PermissionBroker::replay` on `--continue`, a resume or a rewind; replay re-checks
each rule against the session's wall and today's credential list, so a write grant
whose directory, or what a link there now leads to, is protected (`$HOME`, `~/.yi`,
a credential store, a git host-run path) or walled is dropped rather than widened,
while every other rule needs no re-check because the gate's protected-path denials
(D323) come before any session rule; the exact-command session pass of D331 persists
with the rest, since a resumed session is the same session, and stays its exact
bytes plus the directory it was kept in; each child gets its own broker from
`PermissionBroker::for_child`, sharing the family's mode, holds, asker, reviewers
and ask journal but holding a copy of its parent's rules, from which a walled child
drops every exact-command rule, the one kind that can run a command outside its
wall; a child's rules journal into its own transcript, so nothing it keeps reaches
its parent or the parent's ledger; the broker's separate list of kept write
directories is gone, read from the rules instead (`yi_permission::write_grant_dir`);
a kernel `bash()` job builds its profile at each spawn, so a grant kept after the
kernel was wired reaches it; `/permissions` lists the kept rules under the mode

## Why

The dogfood fix plan's row 27 and the sandbox plan's §3.2: a kept rule lived only in
the broker's memory, so `--continue` asked again for what the user had said "always"
to, and every child shared its parent's broker, so a grant a child kept widened its
parent's next run and a walled juror inherited its parent's session pass and ran
outside its wall

## Reversible via

Share the parent's broker in `wiring::child_broker` and drop the replay from
`AgentSession::attach_store`
