# D386: a spill is redacted before a byte is written

Status: accepted

## Decision

A spill is redacted before a byte is written: key-shaped tokens (AWS, GitHub, `sk-`,
Slack, Google, JWT), `Authorization` and bearer values, a value of 16 or more token
characters assigned to a secret-looking name, and the body lines of a private-key
block (PEM or PGP; the block ends at its END line or at the first line that is
neither base64 nor a header) become `[redacted: <kind>, <n> chars]`, one line per
line, so a line number into the file still lands; an assigned value needs a digit
unless its name is upper case or it is written `name=value` as `.env` writes it, so
source code naming a token passes and a digit-less `.env` passphrase does not; the
shapes are their own list rather than session mining's `redact()`, which masks whole
keyword lines and high-entropy runs for recorded cassettes (a spill must keep every
other byte of a line), or `memory/doc.rs`'s refusal check; stdout and stderr each
have their own redactor, since a line one leaves open is not closed by the other; a
redactor that cannot build keeps nothing

## Why

A key printed by `env` or `cat .env` was written verbatim, and with the family
reading one dir every model the family routes to would receive it; the output the
model saw at the cut is unchanged, since that text already went to the session's own
provider

## Reversible via

Drop `Redactor` from `Spill::write` and `Spill::keep`
