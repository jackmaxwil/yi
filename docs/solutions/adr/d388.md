# D388: an `annotate` tool writes `custom{annotation}` records on the session's own...

Status: accepted

## Decision

An `annotate` tool writes `custom{annotation}` records on the session's own history:
`pin` keeps the newest stored tool result whose call (as a placeholder names it,
e.g. read `src/lib.rs`) contains `call` out of every cut, `discard` waives that
result's age and size floors so the next priced cut takes it, and a `finding`
(`note`, at most 280 chars, refused past it with both numbers) is listed whole under
`[Findings]` in every compaction view, read from the branch's records at each
compaction; targets resolve through the session store, since the session's message
list catches up only when a run ends, matching the placeholder's brief or any
argument in full; a call matching nothing is refused with the newest five calls, a
pin or discard of a result already cut is refused with the request it was cut at,
and a discard no cut could take (a `plan`, `todo` or `ask_user` result, one with an
image, the newest read of a file) is refused with the rule that keeps it; a result
cut on a discard says `you discarded it` in its placeholder; findings render one
line each under `[Findings, as the model recorded them]`

## Why

The owner made annotations "a foundational Yi primitive" and chose to "Start small"
with the three kinds stage 6's cut and compaction already read; a model had no say
over what the price rule cut, and a summary's rewording could lose a fact it had
established; the per-call field, `Intent`, `Constraint`, `Link`, `rlm.annotate` and
inheritance by children wait for readers

## Reversible via

Drop the `annotate` tool and `Cut::note`; the records stay, unread
