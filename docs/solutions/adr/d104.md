# D104: the plan DAG is a panel, not an inline checkbox list

Status: accepted

## Decision

`/plantree` opens a titled, box-drawn panel over the plan the runtime is
already holding. `PlanTreeView` (`crates/tui/src/plantree.rs`) is built from a
`Plan` plus its sub-plans, flattened once at open into `Row`s — depth,
`is_last`, a filter string, and styled cells — because `Plan::ready()` walks
the whole document and a draw runs per frame.

The panel shows the full DAG. A plan's head row is its id, version, goal and
state; each todo is a glyph plus its label plus a detail cell — the agent for a
Running todo, the blocker and note for a Blocked one, the output URL for a Done
one, the cause and last product for a Failed one, and the delegation's role and
acceptance where one exists. A todo with `after` edges gets one dim `after:
<labels>` row beneath it at one more level of depth, and a sub-plan is pushed
recursively under the todo that owns it, matched through `PlanTier::Sub`'s
parent address. A ready todo's label takes the accent; a gated one does not.

Nothing here is new vocabulary. The glyphs are `hud.rs`'s — `☐` for pending,
`☑` for done — extended over the states a card status does not carry (`◆`
Running in the child's own `name_accent` color, `✗` Failed, a struck `☐` for
Abandoned). The gutter runes, the borders, the divider, the row padding and the
scroll window are `tree.rs`'s `gutter_prefix`, `top_border`, `divider`,
`bottom_border`, `row` and `window_lines`, promoted from private to
`pub(crate)` and otherwise untouched.

**The panel does not mutate anything.** `handle_key` moves the selection, edits
a filter query, and closes — `Esc` *and* `Enter` both return
`PlanTreeResult::Close`, because there is nothing to activate. Filtering keeps
the selection valid (`reselect`), which is the one invariant a filter over an
index into all rows has to carry. `open_plan_tree` reads through
`session.plan_service()` and posts a notice when no plan service is attached or
the read fails.

`crates/tui/tests/plantree.rs` holds five tests:
`panel_renders_every_state_glyph_and_the_dag_edges`,
`a_ready_pending_todo_is_accented_and_a_gated_one_is_not`,
`a_long_detail_truncates_inside_the_panel_instead_of_wrapping`,
`keys_move_filter_and_close_the_panel`, and
`a_sub_plan_nests_under_the_todo_that_owns_it`.

## Rationale

**Reference-first found the opposite default, and it was taken anyway.** codex,
oh-my-pi and opencode all render a plan as a flat inline checkbox list in the
transcript; none of them has a popup, and only OMP draws tree runes at all —
and it draws them to nest tasks under phases, never to draw dependency edges.
By the house rule, that flat inline list is the default and a deviation is
something to justify rather than assume.

The justification is a requirement the donors' shape cannot carry. §6 requires
the full DAG — every plan, every todo, every state, every `after` edge, every
sub-plan — to be readable by the user and by an agent at any depth. A flat
inline cell in the transcript can carry a checklist; it cannot carry an edge or
a nested sub-plan, and it cannot carry them at whatever size the plan happens
to have reached, because a transcript cell is committed at a fixed height and
scrolls away. The deviation is recorded rather than smoothed: this is not the
shape the references converged on, and the reason it differs is a requirement
they do not have.

The deviation is confined to the container. Every glyph, rune and border a
reader sees is one already in this tree, so the panel looks like the rest of
the TUI rather than like a second design; the choice was which surface holds
the DAG, not what a DAG looks like. Reusing `tree.rs`'s helpers rather than
copying them is what makes that literal — a change to the border or the scroll
window moves both panels at once.

Read-only is a mechanism, not a stylistic restraint. The plan tool is the only
writer, and every mutating op is gated on the plan's state and routed through
one step table; a panel that could move a todo would be a second writer with
neither the lease nor the table, and would put the engine's own reap-on-leaving-
Running seam behind a keystroke. `Enter` closing rather than activating is that
rule made visible at the one key a user would expect to act.

## Reversal path

Delete `crates/tui/src/plantree.rs`, the `plantree` verb in `commands.rs` and
its `input.rs` arm, and the `plan_tree` field on `App` with the
`pending_open_plan_tree` flag and the `render.rs` branch that reads it.
`tree.rs`'s promoted helpers stay `pub(crate)` and its own panel is unchanged,
because nothing about them changed except their visibility.
