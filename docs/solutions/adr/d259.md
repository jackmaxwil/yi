# D259: judge replay is stage 0's falsification test

Status: accepted

## Decision

Judge replay is stage 0's falsification test: `evals/judge_replay.py` (seven-
primitives plan section 14, #609) replays the owner's recorded Yi v4 sessions and
Claude Code transcripts read-only. A boundary is a human message whose nearest
message ancestor on the session tree is an assistant turn end; the judge's input
ends at the boundary (the owner's earlier messages on that tree path as
`[u1]..[uN]`, the turn's final text and a digest of its tool calls) and never holds
what came after. The label comes from the owner's next message and the agent's reply
to it (`objected`, `check_revealed`, `accepted`), owner marks winning. The held-out
split is 30% of conversations by the hash of a file name, never within one: files
that share or bridge to an entry id are one conversation (Claude Code rewrites a
resumed transcript under the same ids), and a boundary found in several counts once.
The judge cites by quote and the host resolves each quote to a UTF-8 byte range of
the named message. The gate line reads PASS iff held-out citation resolution >=
0.95, the conversation-bootstrap 95% lower bound of held-out balanced accuracy >
0.5, no held-out verdict ran a tool and every held-out call returned a verdict. A
root `yi ask` takes no wall or deny rule from config, so every call runs under
Seatbelt (`/usr/bin/sandbox-exec`), denied reads and writes under the corpora and
the real `~/.yi` and `~/.claude` and reads of `--out` and other calls' scratch; a
real run refuses without it. Nothing is written into any session, plan or corpus,
and paid runs are the owner's, capped and ledgered

## Why

The plan's intent record, previews and judge (stages 1-2) all rest on one bet: that
a judge reading the owner's words by address predicts the owner's objections. The
recorded corpus already holds the answer, what the owner said next, so the bet is
tested there before anything irreversible is spent; a split inside a conversation
would leak correlated boundaries into held-out, and an input that held the next
message, or a judge that could read it off disk, would score recall of the answer,
not prediction

## Reversible via

Delete `evals/judge_replay.py`, `evals/replay/`, `evals/fixtures/replay/`,
`evals/tests/test_judge_replay.py`, its selftest check and its `postmerge-evals`
line; nothing in Yi reads them
