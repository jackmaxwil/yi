# D174: a row names the build, upstream and routing it ran on, and a trial its budget

Status: accepted

## Decision

A row names the build, upstream and routing it ran on, and a trial its budget:
`crates/cli/build.rs` stamps `yi --version` from the `version:` line of
docs/ARCHITECTURE.md, the one version source (a tree without the line does not
build), where every build had reported the workspace's `0.2.0`; the completions
mapper keeps the `provider` each OpenRouter chunk names, or the generation record's
`provider_name` on a settled turn, as one `upstream` diagnostic per message (free-
form `details`, no schema change), which `yi_usage.upstreams` tallies as
`byUpstream` for the trial record and `evals/axes.py` prints as the ledger's
`upstreams` cell; `EVAL_ROUTING`, a JSON object (anything else is refused), goes
verbatim into the trial config's `routing` key through `yi_usage.eval_config`, the
one writer for `evals/run.py` and the harbor adapter, and rides the fingerprint's
mode as `+routing{…}`; the harbor adapter rewrites the task's closing `You have
28800 seconds` to the multiplier's share, the same number `--deadline` carries; and
the event tee appends, so a resumed trial keeps its first segment (amends D159)

## Why

Rows 0023, 0025 and 0026 ran three builds that all hashed `yiVersion` 0.2.0, so only
a hand-typed sha told them apart; every turn of row 0028 paid exactly twice the
bundled catalog and nothing recorded which upstream served it, though the name
arrives on every chunk and in the settle record; a routing A/B needed a rebuild; the
instruction promised eight hours against a one-hour kill and the model read both
numbers; and `tee` truncated a resumed trial's events (the 2026-09-10 harness audit,
S1, S2, S4, E4, X1)

## Reversible via

Read `CARGO_PKG_VERSION` again and drop the build script; `note_upstream`,
`upstreams` and the cell, `eval_config` with `routing_label`, and `with_budget` each
delete cleanly; `tee -a` back to `tee`
