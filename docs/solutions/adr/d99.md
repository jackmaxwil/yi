# D99: a plan-attributed commit carries one `Plan:` trailer, and the gate checks it is a URL

Status: accepted

## Decision

`scripts/guardrails/check_commit_style.py` keeps its rule — a commit carries no
trailers — and admits a third carve-out beside the two it already had.

The three, as the gate encodes them: the optimizer's run record, `Opt-Run`,
`Opt-Delta`, `Opt-Lever` and `Opt-Cases`, plus `Signed-off-by`, which git
appends itself (one case-insensitive `TRAILER_OK` pattern); and now `Plan`,
whose value must match `^plan://[a-z0-9.-]+/[^\s]+$`. Every other key is
reported as `unexpected trailer`. `Co-authored-by` naming an assistant —
claude, anthropic, copilot, cursor, codex, gemini or devin, matched
case-insensitively on a word boundary — is reported by its own name, and a
`Co-authored-by` naming a human still fails as an unexpected trailer. This row
narrows the ban by one key; it does not loosen it.

The value is the URL `TodoAddr::to_url` renders in `crates/types/src/plan/ids.rs`:
`plan://<plan id>/<slug of the verbatim todo label>`. The label is slugged
because a URL cannot carry whitespace — lowercased, non-alphanumeric runs
collapsed to `-`, hard-cut at 40 bytes and then back to the last word boundary.

Trailers are read through git's own parser (`%(trailers:only,unfold)`), not by
matching lines in the body. That was already load-bearing before this row: the
gate's own first commit named a banned trailer in its prose, and any
line-matching pattern would have flagged it.

## Rationale

The trailer is what makes one query answerable: `git blame` → commit → todo →
goal → the `user://<n>` message that asked for it, resolving "why does this
line exist" with no inference and no model in the loop.

That index has one property the rest of the ledger's yield does not: it accrues
or it does not exist. Every other query D97 and D98 make possible — a todo's
duration from its transition timestamps, a fetch's provenance from the log, a
plan's history from the file in git — reads state the runtime writes anyway,
and can be written months from now over data already on disk. The trailer is
the only one whose data has to be present at commit time. A `Plan:` trailer
added in six months indexes the next commit and nothing before it, and history
is the half of this index that matters. So it is paid for on day one, and the
`yi why` command that reads it can land whenever.

The value is checked rather than accepted as free text for the same reason: a
trailer nothing can resolve indexes nothing. `Plan: #42` or `Plan: the auth
work` costs the same to type and buys nothing, and the failure would surface
only when someone finally ran the query over a year of commits.

Two bounds are worth saying plainly. The check is a shape check: it does not
open `plans.dir`, so a trailer naming a plan that never existed passes, and it
is looser than `PlanId::new` — the Rust type allows at most one `.` and 96
bytes, while the regex accepts any run of `[a-z0-9.-]` and any non-whitespace
todo segment. It buys the case that actually happens (a hand-typed or invented
value), not the case where the runtime emits a malformed URL, which `to_url`
already refuses at the source. And the gate scans `HEAD --not origin/main`, so
it judges what a branch is about to add and never the landed history.

## Reversal path

Drop `PLAN_TRAILER` and its branch in `trailer_errors` from the gate and the
carve-out from `.ruler/090-workflow.md`; the ban returns to two carve-outs, and
existing `Plan:` trailers survive in history as ordinary body text.
