# D84: the forge is GitHub, and `.github/` returns as thin callers

Status: accepted

## Decision

`.github/workflows/pr.yml` runs `just prepush` on a Linux + macOS matrix for every pull
request. `.github/workflows/postmerge.yml` runs `just postmerge` and `postmerge-evals` on every
push to `main`. `.github/PULL_REQUEST_TEMPLATE.md` is a cold-reader narrative — summary, user
outcomes, UI changes, files-edited map, schema changes, LOC and justification, architecture
notes, screenshots — with zero checkboxes; gate proof lives in the CI status checks alone.

Branch protection on `main` — PR-only, `pr.yml` required, linear history — is `O6`'s enforcing
half and remains a settings act the user performs, so no commit closes it.

docs/FORGEJO.md becomes docs/FORGE.md: the thin-caller and local-gate doctrine survives, the
forge is named as GitHub, and the Forgejo specifics compress to a move-note. `just publish`
keeps its Forgejo shape until a release actually needs GitHub's API (`O2`).

## Rationale

0.60.0 deleted `.github/` to refuse "a second unrun copy of the rules". That reason is honored
rather than reversed: a workflow that calls the same recipes the git hooks call is not a second
rule set, and it is the only way a Linux-only or macOS-only break is caught before it lands —
this machine has one installed target.

Meanwhile the doc had outrun reality in two directions. It described runners, secrets and a
publish path for a Forgejo server that does not exist, while the remote is GitHub with merged
PRs on `main`; and it cited the `.github/` deletion at 0.59.0 when the changelog puts it in the
0.60.0 row. The campaign brief inherited that wrong citation from the doc.

Checkboxes are refused on the same ground the second rule set was: a box a human ticks is a
claim, not evidence, and the gate already produces the evidence. D68 and D70's CI skips fire on
`CI=true` already, so the matrix needs no new branch in the aggregator.

## Reversal path

Delete `.github/` and revert the doc move. Branch protection is a settings change no code
reads, so it unwinds independently.
