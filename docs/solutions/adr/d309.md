# D309: a reader's `schema` reaches the provider (`yi_ai

Status: accepted

## Decision

A reader's `schema` reaches the provider (`yi_ai::schema`): Anthropic
`output_config.format` only when the schema closes every object (properties, all
required, `additionalProperties: false`) and carries no keyword strict mode refuses,
chat `response_format` and Responses `text.format` always with `strict` set by that
test; its question names the schema; its partition is its own first message (kept in
the transcript), and `LlmContext.shared_through` is `Some(0)` when a sibling sent
the same partition within 300 s, for the breakpoints to mark

## Why

The owner chose to send the answer schema to the provider and to mark context
several children share (2026-09-28); plan readers were refused as prose ten times in
row 0058, and the judge replay needed `response_format` to get JSON at all (row
0060); a schema strict mode refuses would 400 on Anthropic, so an open one stays
guidance there (#824)

## Reversible via

Drop the schema kwarg and `yi_ai::schema`, send the partition inside the question
message again, and remove `shared_through`
