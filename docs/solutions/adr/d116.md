# D116: user session constraints are pinned verbatim

Status: unshipped (0.140.0). A keyword pin is not CompInt's `C(H)` list; P17 already keeps user text. `[Pinned]` and `is_constraint_line` are deleted.

## Decision

User lines that match the survival-eval markers (`must`, `never`, `don't`,
`dont`, `always`, `only`) are copied into a `[Pinned]` section of the compact
view. The section is exempt from `[Brief]` roll and `[Earlier]` collapse.
`compose_summary` integrity-checks that every pin is a substring of the
compaction body and writes the count to `details.pinned`. Assistant decision
markers stay in the brief; this pin is user-only. No SLM extractor.

## Why

CompInt retains 17 % of session constraints under summarizers; the 90 % fix
is a running list appended after compact, not a better prompt. ConstraintRot
goes 0 → 30 % violation when the rule is dropped and 0 % when it survives;
pinning restores 0 % at under 0.5 % tokens. `[Earlier]` kept only the first
user line of a rolled window, which is how a `never` in turn 0 disappeared.

## Reversible via

Delete `[Pinned]` and `is_constraint_line`. The fold still runs. Constraints
roll into `[Earlier]` again.
