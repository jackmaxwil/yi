# D151: a number without a source is sent back once

Status: accepted

## Decision

A number without a source is sent back once: when a turn ends cleanly and its text
carries a digit run of three or more with no word character or dot on either side
(`numbers_of`, the same numerals `extract.py`'s `count_claim` reads) that appears in
no persisted tool result and no user message, the todo coupling sends one hidden
message once per prompt: "Each number in the answer needs its source: quote the tool
result it came from, or remove it. Numbers without a source: <list>." The re-drive
is recorded as `custom{todo_intercept}` with reason `unsourced` and rung 0, so
`intercept_count`, `intercept_max_rung` and `intercept_capped` do not move, and
`extract.py` counts it as `unsourced_redrive`; it runs before the open-todo ladder
and never on an empty or terminal stop

## Why

`count_claim` fired on six sessions across the 2026-09-07 rows, and the assessment-
quality autopsy that started the prompt-surface work was one such claim, a line
count nobody had measured (issue #271); the check reads the store the extractor
reads, so the two cannot disagree, and it is a deterministic data trigger, never a
judge

## Reversible via

Delete `numbers_of`, `seen_text`, `unsourced`, `unsourced_text` and the
`Cycle.unsourced` gate
