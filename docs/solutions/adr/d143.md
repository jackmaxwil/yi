# D143: one lane line says where the work is, from git and the ledger, never from a...

Status: accepted

## Decision

One lane line says where the work is, from git and the ledger, never from a new
file: `SlotView::{Idle, Held, Orphan}` carries the slot path and, for a holder,
`Holder { session, branch: Option<BranchName>, tree: TreeState, age }` where
`TreeState::Known { modified, untracked, ahead, behind }` comes from `git status
--porcelain` and `rev-list --left-right --count` against the `origin/main` last
fetched (a listing never fetches), `age` from the branch reflog's creation entry,
and `TreeState::Unread { step }` names the read that missed the listing's single
3-second deadline and never renders as clean; `format_lanes(views,
Option<&DaemonLedger>)` prints path, holder (the ledger's first-prompt name and root
when the id is there, bounded and printable), tree, age, and for a left slot the
verdict a reap would carry (`the next claim takes it`, `reap keeps the branch; the
uncommitted paths are lost`, `tree unread`); `yi lanes` joins the ledger, `/lanes`
prints without it; the status row reads `repo ⎇ lane N` on a lane and `path@branch`
under `--here`; the quit line is slot, branch, path and pull request; `yi doctor`
opens the pool with `lanes.slots`; `Pool::open` writes nothing; the ACP worker
claims under its store id (`SessionBuilder` takes the id) so a console session's
lane resumes and two sessions on one worker hold two branches; the forge's job list
is cut to 32 at the parser; and one HEAD reader (`lane::head` →
`Head::{Branch(BranchName), Detached(Sha)}`, a bounded file read with no git
process) serves the status row, the environment block and the pool, replacing
`status::git_branch`, `git status --branch` parsing and `symbolic-ref` per slot

## Why

The live pool showed two `pid-` orphans with no path, age, tree state or holder a
person could recognise, one holding the only copy of an untracked path a reap would
lose; the daemon path never bound the store id, so its lanes were named by worker
pid, could not be reclaimed, and a second `session/new` on a worker failed `checkout
-B`; three HEAD parsers spelled a detached head three ways, one of them a 120-second
spawn per slot on the TUI's port call

## Reversible via

Drop `Holder` and `TreeState` back to `session`/`branch` strings, delete
`lane_line`'s verdict, and read HEAD with `symbolic-ref` again
