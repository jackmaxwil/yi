# D193: the plan store is an append-only journal with a typed checkpoint, recovery...

Status: accepted

## Decision

The plan store is an append-only journal with a typed checkpoint, recovery
reconstructs, and user authority is a confirmed channel:
`.yi/plans/<slug>/ops.jsonl` is the journal, one digest-chained record per applied
or refused op, appended and `sync_data`ed under the store lease before anything else
moves, and `plan.json` (format 2, schema-validated on read) is its checkpoint
carrying the `seq` and digest it reflects, regenerated from the journal on a read
and refused as `ExternalEdit` on a mutation when it disagrees; a damaged committed
record stops every read and mutation with `RecoveryRequired` naming the record, a
torn tail is set aside with its bytes kept, and `yi plan repair` reduces the journal
to state with no effects and lists a `Running` todo with no live child as
`NeedsReconciliation`; `requestId` is the caller's idempotency key on every op
including `init` and `import` (the same args replay the recorded result, other args
are refused as `RequestIdReused`, an id the journal cannot hold is refused at the
boundary, and an engine-minted id carries the clock), and a `set` that opens a plan
journals the opening `init` under `<requestId>/init` so the caller's id names the
`set`; a checkpoint with no journal beside it (a clone) is `JournalMissing`, blocks
nothing, and `Op::Import` of that checkpoint or of a format-1 document adopts it as
a new generation with the original bytes kept as an artifact blob, refused when the
journal already holds the plan; hand-edit folding is gone; `Actor::User` is minted
in one place, `authority::confirmed`, by a process holding a tty asker, and since
the daemon fans a worker's ask out to every attached client the serve worker
confirms nothing: `_yi/plan {action: submit}`, `yi rpc` and `yi plan fuse reset`
refuse an administrative op as `NoConfirmer`; the platform this commit protocol
assumes (a local filesystem that honors `fsync`, one host, one writer holding the
store's lease) and the STRIDE walk over the journal are the "Trust boundaries of the
plan journal (D193)" section of this file, which the ADR cites rather than restates
(amends D97 and D105; carries D26 and D53)

## Why

The plan was a Markdown document the engine wrote and re-read, so a crash between
the write and the sink lost the record of what happened, a hand edit was folded into
state as if the engine had made it, `spawns` could be lowered by an edit, and
nothing could say whether a delegated todo's child had ever been spawned; the F0b
review then found the engine's own first write publishing no `.gitignore`, a damaged
first record handing back the unverified checkpoint, a reused `request_id` answered
from a 64-reply cache with the old result, a malformed one silently swapped for a
minted id, a pid-scoped auto id that could collide across processes, `init` and
`import` refusing a retry the journal had already committed, an import overwriting
live state when only the checkpoint file was lost, a clone's checkpoint blocking
`init` while every mutation said `NoPlan`, a missing sub-plan reported as tampering,
and no shipped surface able to complete the confirmed verbs; the second round found
the worker's confirmation answerable by its own submitter, a reused `request_id`
replayed across op kinds, a confirmed op re-resolving its root, an empty journal
wedging the store, and an imported graph skipping the validator; the plan's own
review named the same ground: R2, that `framed` writes the plan and then emits the
record (`ops.rs:535-541`, `ops.rs:255-257`, `ledger.rs:19`), so no second sink makes
the snapshot and the log atomic; R3, that `do_start` spawns inside `mutate` before
the write persists (`ops.rs:535-539`), so a crash between them orphans a child; S1,
taken as the protocol and refused as a relocation, so the journal stays beside the
checkpoint in the directory D97 tracks; S2, that `yi plan fuse reset` was reachable
from the agent's own `bash` tool, so CLI argv stood in for a human; and S3, that the
format-1 bytes are kept rather than truncated on read

## Reversible via

Restore the frontmatter writer and `fold_user_edits` from 0.246.0, read `plan.json`
as authority, and drop `plan/journal.rs`, `state.rs`, `recovery.rs`, `import.rs`,
`artifact.rs`; the format-1 reader stays two releases, so a binary from before this
version still reads the documents it wrote; an executed format-2 root needs an
export path that writes the Markdown view, not a checkout of views
