# D178: reasoning cuts are counted per prompt and a truncated call is a length strike

Status: accepted

## Decision

Reasoning cuts are counted per prompt and a truncated call is a length strike: a
tool call no longer zeroes the cut count, and the prompt's sixth cut ends the run
(`CUT_STOP_AT` 6, where D168 ended it at twelve in a row), so the re-drive that
names the write follows the prompt's second cut, not the second in a row; a length
stop that carries tool calls still fails them and now counts toward D153's three, so
only a turn whose calls run starts that count over; one check after each turn ends
the run on repeats, length stops or cuts, before the steering queue is read, so a
bare length stop counts even when a steer is waiting (amends D153 and D168)

## Why

A tool call between cuts zeroed both counts, so twelve was never approached: the
audit slice's photonic trials were cut 22 times, never more than four in a row, and
the cuts took 64–67% of each trial's request wall (the 2026-09-10 harness audit,
B3); six cuts at the measured 160 s median are about sixteen minutes, a quarter of a
one-hour trial; a call past the 32,768-token output ceiling is failed and asked for
whole, comes back truncated with new partial arguments, and neither the repeat
breaker nor a length count the call itself reset could end it (B4: the path is
confirmed, the trigger unobserved)

## Reversible via

Restore the reset of both counts on any turn with calls, `CUT_STOP_AT` 12, and the
length and cut check inside the re-drive branch
