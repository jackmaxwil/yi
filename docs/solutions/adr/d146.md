# D146: a dead stream is sent once more, and it says so

Status: accepted

## Decision

A dead stream is sent once more, and it says so: a provider request whose body died
before its first SSE event showed the reader nothing and billed nothing, so the
request layer (`pump_sse_with_resend`) sends it once more, a stream that had
delivered anything is never replayed, a second death carries both errors, and a
resend rides the message as a `stream_resent` diagnostic with the first error;
`ErrorClass` names the transport faults it used to call `provider:error` —
`transport:os_<errno>`, `transport:tls`, `transport:closed`

## Why

Ledger row 0017's second photonic attempt died on its third request with `Bad
address (os error 14)` before any byte, the turn read `usage.unknown`, the trial
scored 0 and the cap probe stopped the driver; the same row's bun attempt died on a
TLS handshake and the first on a stream closed mid-body, and every one read
`provider:error` in the span (issue #256). Nothing observed and nothing billed is
the one case a replay cannot duplicate; the diagnostic is what lets the ledger count
resends instead of guessing from two request spans

## Reversible via

Delete `pump_sse_with_resend` and call `pump_sse` on the response again; drop the
three variants and their needles
