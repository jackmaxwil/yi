# D340: a spill is kept per session, and a walled session reads back only its own...

Status: accepted

## Decision

A spill is kept per session, and a walled session reads back only its own (amends
D316): spills live in `~/.yi/spills/<session id>/` (`ToolContext::recovery_dir`,
named by the attached store's id, or by a fresh id while no store is attached, and
nothing is kept for an id that is not a valid session id), no longer in the flat
`~/.yi/tool-output` every session shared; a session whose wall is not empty, a
write-only one included, has the whole spill root and the flat dir added to its
calls' `deny_read`, and its own dir spared: `ReadGate::except` keeps the own dir
outside every wall the gate is handed, so `read` and grep open the session's own
pointer while every other spill and every walk under the root is refused, and a
contained command's Seatbelt profile denies both roots and re-allows reads of the
own dir in a later rule (`Sandbox::spared`), so the profile is the same size at any
number of sessions and a dir made while a command runs is walled from it; the root
and the session dir are created 0700, made 0700 again when open to group or others,
and refused when either is a link, which turns the spill off; a `.part` name is 128
bits from `/dev/urandom`; a taken name is compared by length, then a buffer at a
time, through `ReadGate::open`; the hourly sweep walks each session dir under the
root, deleting `.txt` older than 7 days and `.part` older than a day, removes a
session dir idle for 7 days once that empties it, and never follows a link; the same
sweep makes the flat dir 0700, ages its files out by that rule and removes it once
empty; the `spill` module is crate-private, and its integration test includes the
source by path

## Why

#888: a walled juror could read another session's spill, which can hold what its
wall hides; #881: a repeated output's compare read both files whole (up to 512 MiB),
a linked root was followed and swept, the 0755 flat dir from the old tee stayed
0755, and a planted `.part` name turned spilling off; review of #968: a profile
listing every other session's dir cost 0.86 s per contained command at 200 dirs and
7.2 s at 600, failed to compile near 1000, and missed a dir made mid-command;
weighed: keying per family, rejected, since a walled juror shares a family with the
session whose output its wall hides; walling spills from unwalled sessions too,
rejected, since their uncontained bash reads any file the user can; a write-only
wall walls spills too, since the juror's wall is write-only, so a worker walled that
way cannot read a pointer its parent pasted; a walled session's kernel cells and its
uncontained bash still read spills, the open item #885 named; the transcripts under
`~/.yi/sessions` are open to a walled juror (#971)

## Reversible via

`ReadGate::except` and `Sandbox::spared` unset with `ToolAdapter::spill_walls`
empty, and `default_spill_root` back to `~/.yi/tool-output` with `session_spills`
returning the root
