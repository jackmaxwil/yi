# D340: a spill is kept per session, and a walled session reads back only its own...

Status: accepted

## Decision

A spill is kept per session, and a walled session reads back only its own (amends
D316): spills live in `~/.yi/spills/<session id>/` (`ToolContext::recovery_dir`,
named by the attached store's id, or by a fresh id while no store is attached, and
nothing is kept for an id that is not a valid session id), no longer in the flat
`~/.yi/tool-output` every session shared; each call of a session whose wall is not
empty adds every other entry of `~/.yi/spills`, and the flat `~/.yi/tool-output`, to
that call's `deny_read`, so the wall's target check, `read` and every walk through
`ReadGate`, and a contained bash's profile refuse them as any walled path; the root
and the session dir are created 0700, made 0700 again when open to group or others,
and refused when either is a link, which turns the spill off; a `.part` name is 128
bits from `/dev/urandom`; a taken name is compared by length, then a buffer at a
time, through `ReadGate::open`; the hourly sweep walks each session dir under the
root, deleting `.txt` older than 7 days and `.part` older than a day, removes a
session dir idle for 7 days once that empties it, and never follows a link; the
`spill` module is crate-private, and its integration test includes the source by
path

## Why

#888: a walled juror could read another session's spill, which can hold what its
wall hides; #881: a repeated output's compare read both files whole (up to 512 MiB),
a linked root was followed and swept, a 0755 dir from the old tee stayed 0755, and a
planted `.part` name turned spilling off; weighed: keying per family, rejected,
since a walled juror shares a family with the session whose output its wall hides;
walling spills from unwalled sessions too, rejected, since their uncontained bash
reads any file the user can; the list is read once per call, so a session dir made
while a long contained command runs is not walled from that command; a walled
session's kernel cells and its uncontained bash do not carry the per-call list, the
open item #885 named; `~/.yi/tool-output` is no longer written or swept, and can be
deleted by hand

## Reversible via

`ToolAdapter::call_wall` returning the session's wall unchanged, and
`default_spill_root` back to `~/.yi/tool-output` with `session_spills` returning the
root
