# D451: `kimi` is a catalog provider whose model list is the account's own `GET...

Status: accepted

## Decision

`kimi` is a catalog provider whose model list is the account's own `GET
<api_base>/models` (the kimi profile names `api_base`): a model Moonshot lists, K3.1
included, resolves the day it is listed and no Kimi model id or price is compiled
in; `protocol` picks the wire (absent: chat completions at the base; `anthropic`:
Messages at the base less `/v1`; `response`: Responses), an unknown protocol or a
missing positive `limit.context` is a `rejected` line, cost is zero (a subscription,
spend is read from `/usages`)

## Why

The owner: "use the new kimi k3.1 model", with the id read from /models at runtime;
Kimi Code itself provisions from this endpoint (kimi-code managed-kimi-
code.ts:551-587)

## Reversible via

Drop `kimi` from PROVIDERS, `data/kimi.json` and `kimi.rs`'s catalog half
