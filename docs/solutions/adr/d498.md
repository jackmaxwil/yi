# D498: a bash command still running after 60 s becomes a job by default in every...

Status: accepted

## Decision

A bash command still running after 60 s becomes a job by default in every session
that outlives its idle (the terminal UI, the console, `yi serve`, `yi rpc`, `yi
acp`); `bash.autoBackgroundMs` unset means 60,000 there, `0` turns backgrounding
off, and `yi ask` keeps it off unless set (amends D13's default-off)

## Why

The owner: "this should be default for everyone with yi, not just my personal
config"; on 2026-10-23 `glm-5.3-flash` appended `just check` piped to `tail -5` to a
read and passed no `wait`, so the turn sat on "Running…" for the whole gate and then
ran it again, and D305's `wait` only helps a model that passes it. `yi ask` exits
once its session is idle and nothing in it waits on a job, so a job the default
backgrounded there is never heard and outlives the run (#819)

## Reversible via

Return `configured_auto_background` to `None` when the key is unset and drop its
`exits_idle` argument; a config written meanwhile keeps its value, and `0` reads as
off on both sides
