# D55: comment referents are typed, comment grants are named

Status: accepted

## Decision

A Rust item named in a doc comment is written as an intra-doc link (`` [`AgentSession::attach_store`] ``), never bare backticks; bare backticks then mean not-an-item — a parameter, a serialized wire name, or a symbol in a reference codebase. `rustdoc::broken_intra_doc_links` is denied workspace-wide and `cargo doc --workspace --no-deps --document-private-items` runs in `check_guardrails.sh`. `private_intra_doc_links` stays `allow`: Yi publishes no crate, so `pub` means "visible to the next crate up", never docs.rs. Separately, a comment claiming §18 grant (1) or (2) opens its first line with `Incident:` or `Invariant:`, a closed vocabulary `check_comments.py` enforces by rejecting any other capitalized `Word:` prefix.

## Rationale

D49 fixed *how much* comment the tree carries and left *what a comment points at* unspecified, so one sigil carried three unrelated referents: `` `resize_viewport` `` (a local fn), `` `display_data` `` (a Jupyter wire tag) and `` `history_cell/messages.rs:530` `` (a path in `ref/`) were indistinguishable to a reader and to every tool. Links make the first kind machine-checked at zero comment-volume cost — the gate caught a stale pointer on its first run, `Terminal::set_viewport_height`, a method renamed to `resize_viewport` whose comment never followed. The tag makes the grant §18 already defines auditable, which it was not: 6 of roughly 1,161 comment lines said which licence they were invoking, and three others (`Precedence:`, `Draining:`, `Detached:`) had started a private dialect.

Only Rust items are in scope. Design-doc anchors (§19, D47, U35) and `ref/` line spans are not Rust items and rustdoc can never check them; `ref/` spans are re-verified on re-clone by the Appendix A discipline instead.

## Reversal path

Drop the two `[workspace.lints.rustdoc]` rows and the `cargo doc` line in `check_guardrails.sh` — links degrade to prose that still reads correctly. The tag check is one regex and one set in `check_comments.py`.
