# D502: the first install checks the archive's sha256 against the release's...

Status: accepted

## Decision

The first install checks the archive's sha256 against the release's `SHA256SUMS`,
then, when the release carries a `.sig` and `ssh-keygen` is on PATH, the signature
against the one `allowed_signers` line it embeds, refusing a bad one or a `.sig` it
could not fetch for any reason but absence; with no `.sig` or no `ssh-keygen` it
says the sha256 is its only check

## Why

The install script runs before any `yi` exists, so it cannot use `yi update`'s
verifier, and a key fetched beside the archive would prove nothing the digest does
not; the embedded line is the same trust anchor `yi update` compiles in, held equal
by a test

## Reversible via

Fetch nothing but the digest, the archive and the `.sig`; drop the embedded line and
verify through `yi update` after the first install
