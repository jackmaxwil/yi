# D107: scrollback order is antecedent-before-dependent, not arrival

Status: accepted

## Decision

Scrollback is append-only, so the order rows reach it is the order a reader
keeps forever. That order is antecedent-before-dependent, never plain arrival:

- A message's thought commits whole before any of its prose commits. Every
  prose row — a stable paragraph mid-stream or the remainder at `MessageEnd` —
  passes through one path, `commit_prose`, and that path flushes whatever of
  the thought is still uncommitted before it writes a prose row. `MessageEnd`
  is a `commit_prose` call, not a second writer with its own copy of the
  blank/gutter/retain sequence.
- A task cell commits after the tool cell it was born under, never before. A
  child that finishes while an `ipython` call is still running is held in the
  live region, drawn as a finished `✓` task under the running cell, and
  commits when that cell does.
- Every `Cell` family names its antecedent in an exhaustive `match` in
  `crates/tui/tests/tui_unit.rs`, so a new family fails to compile until it
  says which pair test covers the case where its dependent finishes first —
  or says it has none.

## Why

Two writers fed `pending_commit` — the markdown stable cut and the child
roster — and each kept correct time alone. They were never run against each
other. A thought with no blank line in it never reached a stable cut, so it
waited for `MessageEnd` and landed under the answer it preceded; a child that
finished fast landed above the `ipython` cell that spawned it, because the
roster poll committed the task cell while the tool cell was still live; and a
fifth writer at `MessageEnd` duplicated `commit_prose` line for line, which is
where the thought flush had to be added twice or not at all. Every fixture that
passed had chosen a shape where the two clocks agreed: a three-paragraph,
newline-terminated thought, and a child that finished after its cell.

## Reversible via

Delete the hold in `commit_finished_tasks` and the flush in `commit_prose`;
the pair tests fail and name them.
