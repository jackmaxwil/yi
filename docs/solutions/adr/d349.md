# D349: where Seatbelt exists, a walled session's call never runs outside the...

Status: accepted

## Decision

Where Seatbelt exists, a walled session's call never runs outside the sandbox unless
the user chose yolo: one that needs the host (network, an install, a credential
store), a retry of a pathless refusal, and an `exec://` source are refused before
anyone is asked, whatever a rule, an approval or the classifier would say

## Why

The review of #1002: outside the sandbox the command text is the only wall, and `cd
..`, a variable, `$(…)`, a script or `curl file://` read past it; inside, Seatbelt
walls the roots in every spelling

## Reversible via

`PermissionBroker::confines_walled` returning false
