# D132: a run's numbers are spans Yi writes itself

Status: accepted

## Decision

A run's numbers are spans Yi writes itself: with `telemetry.enabled`, one line per
span goes to `<session file>.telemetry.jsonl` — a `request` span (time to first
token, total, tokens, cache reads and writes, cost, provider, model) stamped by a
forwarding wrapper on `ProviderStream::stream` that adds no event and drops none,
and `tool` and `turn` spans written synchronously at the session's one event-send
site; `yi stats telemetry <dir>` rolls every sidecar under a directory into one
record by the formulas `yi stats` already uses; the span shape is
`yi_types::telemetry::Span` with an `extra` map, additive from here

## Why

Plan 2026-09-05 §3.E: nothing in any gate measured time to first token, cost, cache
rate or tool ability, and every field but the two timings already sat in the session
record under no shared key. A spawned observer task was the first draft and never
ran before `yi ask` exited on a current-thread runtime, which is why emission is
synchronous at the send. No OpenTelemetry crate: it is absent from §13.3, the JSONL
converts outside the binary, and the binary's only new code is a writer; the key is
config, not a `YI_*` variable, because the env surface is capped and every row is a
baseline

## Reversible via

Delete `runtime/telemetry.rs`, the `with_telemetry` builder and `set_telemetry`; the
sidecar is never read by anything the loop needs
