# D442: A root session always has ask_user and a question is drawn as a card

Status: accepted

## Decision

A root session always has ask_user and a question is drawn as a card

## Why

The owner asked Yi to ask many more multiple-choice questions in design talk,
recommended option first, and to show what each option looks like; a root with no
reviewer had no question tool, so a question was prose or a muted todo row, and the
card needs a producer on every root

## Reversible via

Restore the `wire_role` guard on `parent`, the §1.2 cut-list entry, drop
`crates/tui/src/question.rs`, and remove the terminate-persistence hunks in
`crates/runtime/src/session.rs`, `crates/runtime/src/session/run.rs` and
`crates/session/src/store.rs` (`append_message_with_terminate`); the one durable
change, no schema change, is that a turn-ending tool result now persists `terminate:
Some(true)` in the session JSONL, a field v4 `Entry::Message` already carries and
that every reader today destructures away
