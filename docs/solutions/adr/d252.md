# D252: a session's plan and todos are its own

Status: accepted

## Decision

A session's plan and todos are its own: `.yi/plans` is shared by every session in
the workspace, so a session names only the roots its own `plan_op` ledger touched
(`plan::ledger::owned_roots`). `canonical_plan` falls back to the Active root among
them, not any Active root in the directory; `PlanEngine::roots` scopes the engine's
unnamed ops (`resolve`, `latest`, the delegated-owner and child-finish lookups) and
the `init`/`import` conflict checks to `with_owned`, which `wire_plan_request` fills
from the session's ledger and its host's; and `AgentSession::attach_store`
rehydrates the `TodoStore` from the attached file, an empty list when it holds none

## Why

The plan pointer is never written in production, so every session in a cwd read,
nudged, compacted and adjudicated against whichever plan another session left
Active, and `/new` kept the old session's todo list in memory under the new file; a
resume reads the same file, so it keeps both

## Reversible via

Drop `with_owned` and the `owned_roots` filter in `canonical_plan`, and the
`rehydrate` call in `attach_store`
