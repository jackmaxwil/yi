# D68: binary_size runs in CI, startup is local-only

Status: accepted

## Decision

`ci.yml` builds the dist profile before running the aggregator, so `binary_size`
is enforced on every push and pull request. `check_startup.py` is skipped when
`CI` is set, and the aggregator prints that it skipped rather than staying
silent about it. Locally both gates run exactly as before.

## Rationale

Both gates read `target/dist/yi`, which no CI step built, so both reported a
missing binary and CI on main was red on every commit for reasons unrelated to
any of them. A gate that is red unconditionally is a gate nobody reads: the
five pull requests open when this landed all showed a failing `check`, and the
failure said nothing about their contents. The fix is not one change but two,
because the two gates fail for different reasons.

`binary_size` is deterministic. It reads a file's length against a budget
§13.3 states in bytes, and the answer does not depend on what else the machine
was doing. It guards a real constraint — the 6 MiB ceiling is what rejected
syntect in D63 — and a budget checked only when somebody remembers to run it
locally is a budget that drifts. The cost is an LTO dist build on every run,
which is minutes, and that is the honest price of enforcing it.

`startup` is wall-clock. It measures `yi --version` against a 5 ms budget on
whatever core a shared runner hands it, next to whatever else that runner is
doing. The repository's own workflow rules already say this number reads several
times its quiet value under a concurrent build and must be re-measured idle
before it is believed. A gate that has to be disbelieved is worse than no gate:
it trains everyone to re-run the job, and the one time it is right it looks like
the noise it usually is. Startup is measured where it can be measured — on a
quiet machine, by the person making the change — and the ledger rows that cite
startup figures come from there already.

The skip is announced. `check_startup.py` opens by refusing to run when
hyperfine is missing, on the stated grounds that a guardrail whose tooling is
absent must not silently pass; a guardrail whose *environment* cannot measure
what it measures deserves the same treatment, so the aggregator prints a skip
line naming this row instead of quietly dropping a check from the list.

## Reversible via

Delete the `CI` guard in `check_guardrails.sh` and `startup` runs everywhere
again; drop the dist build step from `ci.yml` and both gates go back to
reporting a missing binary.
