# D152: a turn repeated verbatim is sent back once, then ended

Status: accepted

## Decision

A turn repeated verbatim is sent back once, then ended: the loop keeps the previous
turn's tool batch (names and arguments, `batch_signature`); the third identical
batch in a row sends one hidden `custom{repeat_break}` message ("The same tool calls
have run the last three turns with the same result. Nothing is changing. Write the
final answer now; call no tools."), the sixth ends the run, and a batch that is only
bash job polls (no `command`) never counts; `extract.py` counts the message as
`repeat_break`

## Why

On the post-D151 v4 subset run two of three `html-js-filter` attempts passed the
verifier by turn 15-37 and then repeated one verification batch with no text for
290-330 turns until the hour wall, $0.49 and $0.69 against $0.005-0.013 for the
attempt that stopped; every result said the same thing, no harness message rode in
after the one nudge, and the loop had no rule for a turn that changes nothing (issue
#276). Provider-independent in the loop like D147; the poll exclusion is the one
legitimate repeat the tree has

## Reversible via

Delete `batch_signature`, `repeat_break` and the two counters in `run_loop`
