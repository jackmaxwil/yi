# D324: every sandbox hides the keys egress would carry and holds the wall (amends...

Status: accepted

## Decision

Every sandbox hides the keys egress would carry and holds the wall (amends D87, D216
and D323): `credential_stores` also lists `~/.yi/oauth`, `~/.config/gh`,
`~/.config/fgj`, `~/.config/gcloud`, `~/.netrc`, `~/.git-credentials`, `~/.npmrc`,
`~/.pypirc` and `~/.cargo/credentials[.toml]`, so the read gate, the bash read belt
and every Seatbelt profile refuse them and D15's destroy gate refuses a write to one
in every mode; `RuntimeWiring::session_sandbox` adds the wall's `deny_write` and
`deny_read`, so the kernel and its `bash()` jobs keep to a juror's wall as a
contained call does; in every profile a `deny_read` path is also write-denied, each
denied path binds as spelled and as `resolve_denied` resolves it (every link and
`..` taken, a missing tail as spelled), and every directory between a writable root
and a denied path is denied `file-write-unlink`, so a rename cannot carry a denied
path out from under its rule; `Sandbox::wrap` and `kernel_prefix` start the command
through `/usr/bin/env -u` for every inherited variable `names_a_secret` matches
(`KEY`, `TOKEN`, `SECRET`, `PASSWORD`, `CREDENTIAL`); `~/.yi/config.json` stays
readable (D323) and so does `~/.yi/mcp/sessions.json`, whose `env` the kernel's
contained `yi mcp` needs to launch a stdio server (#906 keeps that store); allowed
bash calls stay uncontained until stage 2b, so the wall binds them only at the tool
seam (#889)

## Why

A contained `cat` read `~/.netrc`, `~/.config/gh/hosts.yml`,
`~/.yi/oauth/<provider>.json` and the other CLI logins, and `env` printed
`*_API_KEY`; a walled juror's kernel cell and its `bash()` read `deny_read` files
and wrote the tree its `deny_write` walled, since the wall was a check at the tool
seam and in no profile; Seatbelt matches an open's resolved path, so a wall spelled
through a link bound nothing, and `mv` of a denied path's parent, or of the path
itself in a writable tree, carried it out of reach of the rule

## Reversible via

Drop the entries from `PROTECTED_CREDENTIAL_SUBPATHS`, the wall lines from
`session_sandbox`, and `scrubbed_env` from `wrap` and `kernel_prefix`
