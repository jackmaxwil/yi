# D171: `read` converts a file that is not UTF-8 through the kernel venv, never...

Status: accepted

## Decision

`read` converts a file that is not UTF-8 through the kernel venv, never through a
crate in the binary: `firecrawl-anydoc` and `pdf-inspector` join the default extras,
and the venv's directory is keyed by the ready check and the extras together, so two
commits whose extras differ never rebuild one venv back and forth; the bootstrap
asks the installed wheel for its formats (`typing.get_args(anydoc.Format)`) and
records them as `documentFormats` in `.bootstrap-version`, and `read`'s description
names exactly those, with the clause absent when the venv recorded none; the non-
UTF-8 read error is the trigger, plus the `{\rtf` marker because RTF is the one
document format written as 7-bit text, and the converter's content sniff, not an
extension list, decides whether the file is a document; the Markdown lands in a copy
under `~/.yi/converted/` keyed by path, mtime and length and is read through the
ordinary window, so offsets, byte budgets, `find` and anchors work unchanged; `edit`
and `write` refuse an original that has a copy and name the copy; a PDF with some
text pages converts those through `pdf_inspector.process_pdf` and names the pages
without a text layer, and only a PDF with none is refused, with its classification
and page count; OCR is pinned to `reject` and no argument, setting or message
reaches anydoc's hosted mode, the converter gets a 64 MiB input ceiling and a 30 s
timeout, and on macOS it runs under seatbelt with no network and one writable root

## Why

The in-process `anydoc` crate measured +3,585,376 bytes on the dist profile against
401,280 bytes of headroom and pulls `chrono`, which §13.5 bans, so the demoted
`docs` feature (§14.6) comes back as two abi3 wheels: 0 binary bytes, 0 Rust
dependencies, no new tool and no cargo gate; `read` failed on every office document
and PDF with `stream did not contain valid UTF-8`, and the model reached for
whatever converter the host had (`pdftotext -layout` in session 01a04c94) or none;
hosted OCR uploads the user's document to a third party on a read of a local file,
which is the shape of an exfiltration bug; a list of formats in a tool description
is a claim about the wheel, so it is derived from the wheel at the one moment the
wheel changes and checked against it (docs/plans/2026-09-09-anydoc-and-pdf-
inspector.md)

## Reversible via

Delete `crates/tools/src/document.rs`, `read_document`, the two refusals and
`document_converter`; drop the two extras, the extras from the venv key and the
`documentFormats` key; `read`'s description returns to its literal
