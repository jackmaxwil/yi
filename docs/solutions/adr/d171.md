# D171: `read` converts a file that is not text through the kernel venv, never...

Status: accepted

## Decision

`read` converts a file that is not text through the kernel venv, never through a
crate in the binary: `firecrawl-anydoc` and `pdf-inspector` join the default extras,
the venv's directory is keyed by the ready check and the extras together so two
commits whose extras differ never rebuild one venv back and forth, and a
`YI_KERNEL_PYTHON` may lack the two wheels; the bootstrap asks the installed wheel
for its formats and their aliases (`typing.get_args(anydoc.Format)`,
`format_from_extension`) and records them as `documentFormats` in `.bootstrap-
version` beside a hash of the probe, so a reworded probe re-asks the wheel at the
next readiness check without a rebuild; `read`'s description names exactly those
formats and their limits, asked again on every request so a venv built mid-session
shows up, and says nothing when the venv recorded none; a file is offered to the
converter when its head carries one of the four container markers (zip, OLE2,
`%PDF-`, `{\rtf`) and the converter's content sniff, not an extension list, decides;
csv is never converted, text in another encoding (UTF-16 by its mark, else Latin-1)
is decoded and shown, an image is named as one, and a NUL-bearing file that is no
document is refused as binary; the Markdown lands in a read-only copy under
`~/.yi/converted/` (mode 0700) named by the source's path, length and byte hash and
by the Markdown's own hash, so a saved original misses, a tampered copy is converted
again and parallel first reads each stage under their own name; copies older than 30
days or past 256 MiB in total are evicted; the copy is read through the ordinary
window under the original's path, unclipped, with an outline of headings when capped
and a heading section for `find=`; `edit` and `write` refuse any existing binary
document, NUL-bearing file or path under the copy dir, and RTF and decoded text stay
writable; PDF pages come through `extract_pages_markdown` under `[page N]` markers
(none on a one-page PDF), `pages="3-5"` reads only those, pages without a text layer
are named and left out and only a PDF with none is refused; a page the library
detects a table on arrives as plain text in reading order (`extract_text_in_regions`
over the full width, so a row stays whole), and a columned page as its left column
then its right, split at the gutter the fewest text runs cross, each under a note
that the conversion is lossy, with the page's Markdown headings restored; a line at
the edge of 40% of pages and never inside one is left out once as a running header;
decks read slide by slide under `[slide N]` markers; spreadsheets lose empty rows,
empty columns and cell padding, take the first row as the header under an empty one,
name each sheet from `xl/workbook.xml`, and gain a `[sheets: …]` line that points a
sheet past 500 rows at `pandas.read_excel`, with `openpyxl` in the default extras so
it works; a glob charges the Markdown, not the bytes on disk, to its budget,
converts a document only while it has room and the source is under 8 MiB, and lists
the rest with the reason; `grep` searches a document through the same Markdown (a
cached copy always, up to 20 new conversions per call, never in `replace` mode) and
names what it could not search; a copy's first look is 12 KB with its outline ahead
of the text, the outline keeps the shallowest heading levels that fit, sampled
across the whole text with repeated titles once, `find=` folds typographic quotes
and dashes, and a copy adds no code refs; OCR is pinned to `reject` and no argument,
setting or message reaches anydoc's hosted mode, the converter gets a 256 MiB
ceiling (1 GiB with `pages=`) and a 30 s timeout, and runs under seatbelt on macOS
with no network and the cache dir as its one writable root, or in a user and network
namespace on Linux where `unshare` allows one; `bash` names `read` when a command
reaches for `pdftotext`, `pandoc` or `textutil`

## Why

The in-process `anydoc` crate measured +3,585,376 bytes on the dist profile against
401,280 bytes of headroom and pulls `chrono`, which §13.5 bans, so the demoted
`docs` feature (§14.6) comes back as two abi3 wheels: 0 binary bytes, 0 Rust
dependencies, no new tool and no cargo gate; `read` failed on every office document
and PDF with `stream did not contain valid UTF-8`, and the model reached for
whatever converter the host had (`pdftotext -layout` in session 01a04c94) or none;
hosted OCR uploads the user's document to a third party on a read of a local file,
which is the shape of an exfiltration bug; a list of formats in a tool description
is a claim about the wheel, so it is derived from the wheel at the one moment the
wheel changes and checked against it (docs/plans/2026-09-09-anydoc-and-pdf-
inspector.md); a dogfood run over 141 real documents from this machine found RTF
never converting, mixed PDFs refused whole and a Word lock file shown as text, a
3-thread probe found parallel first reads sharing one staging name (40 of 60
failed), and the exhaustive review of 2026-09-10 listed 47 gaps, of which this row
answers the 43 that were a bug, a refusal or a cost the code could remove; a third
round of dogfood, playing Yi through 38 tool calls on two terminal-bench tasks and a
coursework folder, found PDF table detection pairing a course with its neighbour's
time and room (the library's own Markdown makes the same error; its reading-order
text does not), a spreadsheet hint the venv could not honour (no `openpyxl`), `grep`
missing a phrase inside a `.docx` while returning 28 KB of RTF markup, and a book's
outline made of its table of contents; the owner chose plain text for PDF tables
with a hint that the conversion is lossy

## Reversible via

Delete `crates/tools/src/document.rs`, `read_document`, the two refusals and
`document_converter`; drop the two extras, the extras from the venv key and the
`documentFormats` key; `read`'s description returns to its literal
