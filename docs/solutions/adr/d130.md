# D130: an orphan with nothing `main` lacks is a free slot

Status: accepted

## Decision

An orphan with nothing `main` lacks is a free slot: `Pool::claim` takes a slot whose
state names a dead session when its tree is clean and its branch is an ancestor of
`main` (or it has no branch), detaching it and deleting the merged branch exactly as
`reap` would; an orphan with an uncommitted file or an unmerged commit still counts,
still refuses, and still waits for `yi lanes reap`

## Why

Three lanes left by `pid-` sessions — headless drives killed by their harness, which
by construction can never resume — sat at `main` with clean trees and filled the
pool, and the next root session was refused with `no free lane: 0 held, 3 orphaned
of 3` until each was reaped by hand. D121's invariant is that an orphan's branch is
the only copy of its work; a branch `main` already contains and a tree with nothing
in it are no copy of anything, so taking the slot loses nothing and the manual step
guarded nothing. The check is two git reads under the pool lock, on the refusal path
only

## Reversible via

Drop the `abandoned` arm in `claim`; every orphan counts again and `reap` is the
only way out
