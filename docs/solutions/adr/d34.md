# D34: OpenRouter as the third native provider; no built-in default model

Status: accepted

## Decision

OpenRouter is the third native provider, filling the "3 + faux" slot as an openai-completions endpoint: bundled catalog (data/openrouter.json via Pi's generator) + `OPENROUTER_API_KEY` + per-model compat quirks (the A9 module begins: supportsDeveloperRole, thinkingFormat=openrouter, requiresReasoningContentOnAssistantMessages), no custom adapter. Yi carries no built-in default model: `--model`, else the user config's `"model"` key (`~/.yi/config.json`), else a typed error.

## Rationale

The dev/test target is `deepseek/deepseek-v4-flash-0731` via OpenRouter (user directive 2026-08-24). OpenRouter is wire-identical to openai-completions, so a custom adapter would be dead weight. A hardcoded default model in the binary is product opinion where Yi should be neutral.

## Reversal path

Drop the catalog file and auth arm; the quirks stay (they are per-model compat, not per-provider).
