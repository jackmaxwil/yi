# D249: the dist binary budget is a measured ratchet under a hard cap of 7 MiB, not...

Status: accepted

## Decision

The dist binary budget is a measured ratchet under a hard cap of 7 MiB, not a hand-
typed ceiling (amends the §13.6 v1 ceiling): `check_binary_size.py` gains
`HARD_CAP_BYTES = 7_340_032`, checked independently of `binary_size_budget.json` so
the baseline file can never be edited past it; `binary_size_budget.json` is lowered
to the measured 6,929,728 bytes (macOS arm64) and `deps_budget.json` to the measured
18 direct / 166 transitive, so `scripts/forge_pr.py`'s per-PR `binary_ratchet`
resumes writing a commit for every byte crossed; `.ruler/060-deps.md` and
`YI_DESIGN.md` §13.6 are amended from ≤ 6 MiB / ≤ 16 / ≤ 135 to ≤ 7 MiB / ≤ 18 / ≤
166; the 6 MiB rule is amended to 7 MiB

## Why

23852c41 (PR #436, merge 36f73f4f) raised `binary_size_budget.json` from 6,064,064
to exactly 7,340,032 with an empty commit body — not a measurement (`binary_ratchet`
only ever writes a measured size) but typed by hand in the ratchet subject's own
format; #436 is a −9-line wrap-width change (D202) whose merge builds byte-identical
to its base, so the raise bought it nothing. With the ceiling raised, nothing
crossed it again until this row, so `binary_ratchet` wrote no commit for 865,648
bytes of growth across 20 PRs (per-merge table, notes/533-536.md): #427's OS plan F0
alone crosses 6 MiB at +432,768, and #467, #483, #494 and #378 add most of the rest.
Main sat 638,256 bytes over the `.ruler/060-deps.md` rule (6,291,456) with no
external crate added since #436 and no `docs/size-ledger.md` row since 2026-09-04 —
all of the growth is Yi code. The dependency raises are traced and already recorded
(D41's TUI set to 19/165, D48's miniz_oxide + adler2 to 20/167), but D71's cut to
16/155 never lowered the baseline, so syntect (D74) and grep v2's `regex` spent that
unrecorded slack, landing at 18/166 with no raise on record

## Reversible via

Restore the 6 MiB / 16 / 135 ceilings by reverting D74's syntect adoption to D63's
hand-rolled highlighter — the only single cut that clears the 638,256-byte gap, at
about −860 KB and −1 direct / −11 transitive deps — and re-lower both baselines; the
hard cap in `check_binary_size.py` moves with it
