# D337: a compaction never replaces the history without a summary, except to make...

Status: accepted

## Decision

A compaction never replaces the history without a summary, except to make the next
request fit (amends D115): on the session's model the summarizer sends the loop's
request and a blank or failed reply retries once trimmed and cold; a history already
at or past the model's window skips the warm request, which could not go out, and
makes two cold attempts trimmed a quarter and then half, each advanced to the next
message that is not a tool result (`yi_context::is_cut_point`), so neither opens on
an orphaned result. If both fail `Compactor::maybe_compact` returns
`CompactError::NoSummary`, the history and the ledger stay as they were, a
`[compaction failed: <reason>; history left uncompacted, the next prompt retries]`
note (custom type `compaction_notice`, never a turn of its own; the model reads the
same host text as before, and the TUI and ACP clients show it as the host notice it
was) is queued, a newer one replacing one not yet read, a `/compact`'s schedule and
instructions are kept for the retry, the loop's hook asks no more for the rest of
that run, and the idle RPC `compact` returns the reason in `error`. Only when the
history is at or past the window does `Compactor::elide` step in, with no model: it
keeps the first user message after the summary (a child's brief, or the first ask a
floor or earlier rescue kept) and the message that opened the work in flight
(`Compactor::open_run`, recorded at every run's start whoever sent it, and again at
the first user message of a follow-up the run takes mid-run), carries the earlier
summary's own words forward, and keeps the newest messages from a cut point that is
never a tool result, as many as fit under window − reserve − the system prompt − the
tool schemas − the summary, each charged at bytes/3 rather than the trigger's
chars/4; the dropped messages leave one text in three places, the summary's last
line, a note where they sat and a notice on the same request: `[compaction elided N
earlier messages from the model's view: summary failed; the transcript keeps them]`.
The summary keeps D115's `<yi_compact_view>`, the JSONL keeps every original entry,
D310's re-delivery restores the late slots, nothing is elided when only the earlier
summary could go, and the idle RPC `compact` says `elided: N` beside `applied`

## Why

#871: two failed summary requests replaced the history with `compose_summary("")`,
the view and file lists alone, losing the session's content to one flaky summarizer.
The reviews of #946 then found that keeping the history with no backoff cost two
summary requests and one notice at every due boundary; that a history past the
window had no way out; that a first rescue dropped the task prompt of a long turn,
sized its budget from a latched prefix, lost a child's brief or a waking host
message by inferring the prompt from message kinds, threw away the earlier summary,
and that retries trimmed by message count opened on a tool result no provider
accepts

## Reversible via

Return `compose_summary("")` as the summary on the retry's failure, and drop the
`gave_up` latch in `compaction::loop_hook`, `Compactor::elide` and
`Compactor::open_run`
