## Design

ARC harness v2 — zero-Rust, all changes under evals/arc/. The adapter (one `yi ask --json --yolo --continue` process per action, unchanged process model) gains a disk-state protocol: before each turn it appends the new frame to `<work>/frames.jsonl` and, once at run start, copies `evals/arc/arc.py` to `<work>/arc.py`. GROUNDED MECHANICS, all verified on origin/flywheel-4: (1) the kernel process cwd IS the `--cwd` work dir — wiring.rs:280 passes `wiring.cwd` into KernelServiceOptions.cwd, kernel.rs:261 into KernelOptions.cwd, connection.rs:240 `command.current_dir(cwd)`; the kernel is spawned `python -m ipykernel_launcher` (connection.rs:230), and CPython `-m` puts cwd at sys.path[0], so `import arc` resolves with no sys.path surgery, no YI-side skills change (PYTHON_SKILLS is a compiled 4-entry list — adding to it would be Rust), and no prompt import boilerplate. (2) ipython is registered unconditionally (wiring.rs:316) and run 0011 already measured 9 ipython calls in exactly this `--yolo` ask configuration — kernel reachability is proven by prior execution, not assumed. (3) Kernel-variable persistence across the one-process-per-action loop is BEST-EFFORT ONLY: the K10 snapshot refreshes on a 1,500 ms debounce (kernel/src/lib.rs:22) and the final-flush path runs only in dispose(), which nothing in the ask CLI calls — and ipykernel's parent poller kills the kernel when the yi process exits. Therefore ALL durable state (hypothesis sources, plan, notes, tried-table inputs) lives in `<work>/arcstate.json`, written synchronously by arc.py on every mutation; kernel snapshot revive is treated as a latency optimization, never a correctness dependency (fail-closed). (4) Hypotheses are stored as Python expression strings over a Frame (`arc.hyp("row0", "f.grid[0][0] == 7")`), compile-checked at registration, evaluated by `arc.score()` against every recorded frame — executable, falsifiable, persistent, and reloadable in any process including rlm.run children. (5) Sub-search: a non-worktree child inherits the parent's cwd (subagent.rs:65-66 'otherwise the parent's own cwd'), so a hyp-check child imports arc and reads frames.jsonl itself; `context_keys` values are capped at 4,096 chars per key (rlm/__init__.py CONTEXT_VALUE_CAP), so the approved intent's `context_keys=["hyp","frames"]` is corrected to `context_keys=["hyp_note"]` (hypothesis text only) — frames travel by disk, never by brief. This is the one deliberate deviation from the stated intent, forced by measured transport semantics. The child must NOT use isolation='worktree' (a worktree child gets a different cwd and loses frames.jsonl). (6) The prompt shrinks to intent: no grid ever appears in the prompt (briefing ~2.1 KB once; per-turn line ~250 B), making transcription structurally pointless and 'board literals in ipython cells' a measured zero-target. Run-1 accumulated a 4.2 KB board per turn to a 418,485-token peak (run 0010); v2 accumulates ~80 tokens/turn plus bounded arc.py printer output — expected peak-ctx 25–45k, the ~10x drop. (7) Oscillation dies by a deterministic counter in the adapter: same-action-bigram streak over action signatures (name; for ACTION6, name plus (x//16, y//16) bucket); at streak>=N a notice plus the arc.tried() table rides the prompt; at streak>=M the turn becomes a reflection turn — a yi ask turn with a reflection-only --schema (no action field), so a board action is refused structurally, kernel use stays free, and no ARC action is spent; the streak then resets. No spend, cost, or score is visible in any counter text. (8) Preflight, fail-closed: before the paid loop, one ~$0.001 real turn asks the model to run `import arc; print(arc.selfcheck())` in ipython and must echo the check token; the run aborts on failure — this converts the single unverified assumption (sys.path[0] in this venv) into an executed gate and also forces the venv bootstrap before money is spent. All six new ledger metrics are pure functions of the event streams, scorecard, and adapter counters — deterministic control, no LLM in any control path or metric.

## Files

### `evals/arc/arc.py` (budget 220 lines)

NEW. Kernel-side stdlib-only library, copied verbatim by the adapter to <work>/arc.py at run start (single source of truth stays in evals/arc/). Reads frames.jsonl on every call (no caching; ~3 MB parse worst case is fine); writes arcstate.json synchronously on every hyp/plan/note mutation; tolerates one unparseable trailing frames line by skipping it. API: Frame dataclass (n, grid, state, score, levels, win_levels, available, action, changed); frame(n=-1) -> Frame; history(start=0, stop=None) -> list[Frame]; count() -> int; diff(n=-1, m=None) -> Diff with .cells [(x,y,old,new)], .count, compact __str__ capped at 40 listed cells; grid_str(n=-1) -> str (hex render, the only unbounded printer, discouraged in the briefing); tried() -> str (per-signature table: tries, frames changed, mean cells changed, last used); hyp(name, src) -> None (src compile-checked now, persisted); drop_hyp(name); hyps() -> dict[str,str]; score(name=None) -> dict {name: {pass, fail, first_fail, error}} evaluating each src over every frame in try/except (an exception is a fail with reason); plan(steps=None) -> list[str]; note(text); notes() -> list[str]; selfcheck() -> 'arc-ok <frames> <hyps>' (the preflight token). Grid convention declared in the module docstring: grid[y][x], y=row; ACTION6 x=column, y=row. __main__ selftest: temp dir, fake frames, asserts frame/diff/tried/hyp/score/plan round-trip, the partial-trailing-line skip, and that a falsified hyp reports its first_fail frame.

## Turn-prompt protocol (verbatim draft)

BRIEFING_V2 (turn 1 only; budget <= 2,200 bytes formatted, asserted in selftest) — verbatim draft:

"""You are playing an ARC-AGI-3 puzzle game called `{game}`. Nobody has told you the rules; discovering them by experiment IS the task.

You never see the board in this prompt. The frame history lives on disk in your working directory and the `ipython` tool is your only eye. A library `arc` is importable there:

  import arc
  f = arc.frame()      # latest Frame: f.grid[y][x] ints 0-15, f.state,
                       # f.levels, f.available, f.changed
  arc.history()        # every frame so far
  arc.diff()           # cells changed by the last action: (x, y, old, new)
  arc.tried()          # what you tried and what each action did
  arc.hyp("name", "<python expr over f>")  # register a rule hypothesis
  arc.score()          # every hypothesis checked against every frame
  arc.plan([...]); arc.note("...")         # durable notes across turns

Never retype grid contents into code; read them with arc. State rules as arc.hyp entries and run arc.score() before spending actions — actions are scarce, kernel calls are free. When arc.score() shows a fail, revise before acting.

For an expensive rule search, delegate without spending actions:
  h = await rlm.run("Find the rule. Start with `import arc`; frames.jsonl is in your cwd. Report which hypotheses survive all frames.", name="hyp-sweep", context_keys=["hyp_note"])
  await rlm.wait(120)
  r = await h.result(schema={"type":"object","required":["verdict"],"properties":{"verdict":{"enum":["holds","falsified","undecided"]},"first_fail_frame":{"type":"integer"},"evidence":{"type":"string"}}})
context_keys values are capped at 4096 chars — pass hypothesis text, never frames; the child shares your cwd and reads frames itself. Never pass isolation='worktree' here.

This game accepts exactly these actions and no others: {names}. Any other name is rejected and the turn is wasted. RESET restarts the current level.{clicknote}
The game has {levels} levels; you have {budget} actions total.

Reply with JSON only: {{"action": "<name>", "why": "<one line>"}}."""

CLICK_NOTE_V2 (appended when ACTION6 is available): " ACTION6 is a click and also needs `x` and `y` in 0..{maxxy}: x is the column, y is the row — f.grid[y][x]."

TURN_V2 (every action turn; budget <= 300 bytes formatted): "Action {i}/{budget}. Frame {n} appended: {changed} cells changed, state={state}, levels={levels}/{win}, available={names}. Inspect via ipython (import arc) before answering. Reply JSON only."

NOTICE_V2 (appended to TURN_V2 while N <= streak < M; budget <= 400 bytes plus the tried table, which contains no grid bytes): "You have repeated the pair {pair} for {streak} straight actions with no level change. Record so far:\n{tried_table}\nState a hypothesis (arc.hyp) for why this pair would ever clear the level, or pick a different probe."

REFLECT_V2 (replaces TURN_V2 at streak >= M; served with the reflection schema, which has no action field, so a board action is structurally refused; no ARC action is spent; budget <= 550 bytes): "Reflection turn: no board action is taken this turn and none is charged. You have repeated {pair} for {streak} actions without progress. Using ipython and arc (history, diff, score, tried), determine which hypotheses survived all frames and which are falsified, record a plan (arc.plan) for the next 5 actions, then reply JSON only: {{\"surviving\": [\"...\"], \"falsified\": [\"...\"], \"next\": \"<one line>\"}}"

REFLECT_SCHEMA (frozen): {"type":"object","required":["surviving","falsified","next"],"properties":{"surviving":{"type":"array","items":{"type":"string"}},"falsified":{"type":"array","items":{"type":"string"}},"next":{"type":"string"}}}

frames.jsonl schema (one object per line, appended by the adapter before each yi invocation; `action` is the action that PRODUCED the frame, null for an initial/post-reset frame; `available` holds the same name strings the --schema enum is built from, both derived from latest_frame.available_actions in one function): {"n": 57, "ts": 1756512000.1, "game": "ls20-9607627b", "action": {"name": "ACTION3", "x": null, "y": null, "why": "..."}, "state": "IN_PROGRESS", "score": 0, "levels": 0, "win_levels": 7, "available": ["ACTION1","ACTION2","ACTION3","ACTION4","RESET"], "changed": 14, "grid": [[...64 ints...] x 64]}

PREFLIGHT (before the paid loop, fail-closed): one yi ask turn, prompt "Use the ipython tool to run exactly: import arc; print(arc.selfcheck()) — then reply with the printed token."; the run aborts unless the answer contains 'arc-ok'. The awaited rlm.run forms above match flywheel-4's own identity.md/orchestrate.md teaching byte-for-byte (P8), and rlm.wait's signature is `wait(timeout: float = 300.0)` with host-side clamping.

## Oscillation thresholds

Signature: action name; for ACTION6, name + (x//16, y//16) bucket (a 4x4 coordinate grid — 0011's competent 61-distinct-coordinate exploration must not streak, while pounding one region must). Streak: maintained over the action log; the current unordered pair is {sig_{i-1}, sig_i} (a==b allowed, covering both pure repetition and two-action alternation); each new action whose signature stays inside the unchanged pair increments the streak, anything else resets it to 2 (or 1 at the start); any levels_completed increase resets to 0 (progress ends the episode). N = 8: notice + arc.tried() table appended to every turn prompt while 8 <= streak < 16. M = 16: reflection turn (no action requested, none spent), then streak := 0. Derivation from measured runs: 0010's collapse put the ACTION3<->ACTION4 bigram at 105 of 150 transitions with reasoning already degenerate by ~action 30 — dozens of uninterrupted same-pair actions; 0011's healthy exploration (80 clicks, 61 distinct coordinates, a real evolving theory) plausibly never exceeded a same-pair streak of 3-4 under this signature. N=8 sits above any productive alternation observed and one octave below the pathology; M=2N grants one full notice window (8 more actions with the tried-table in view) before escalation. Stationarity argument (the Kawase property — a fixed kernel applied identically at every step, never rescaled by run state): N and M are module constants fixed before the run; the trigger statistic is a pure function of the public action log, computed by the adapter, so the policy is time-invariant — the same log prefix produces the same decision regardless of wall clock, spend, score, or context size; the model cannot move the thresholds, the harness cannot drift them, and re-running the counter over a recorded log reproduces every notice and reflection exactly (the selftest does this with a 0010-style fixture). No counter text mentions cost or budget spend. Worst-case overhead is bounded: at budget 150, at most floor(150/16) = 9 reflection turns (~6% of turns), each costing one LLM turn and zero ARC actions.

## Risks

- import-arc resolution: the kernel is `python -m ipykernel_launcher` with current_dir = the work dir, so cwd is sys.path[0] by CPython -m semantics — but PYTHONSAFEPATH or a patched venv would break it, and this exact venv has not been executed against. Mitigated fail-closed: the ~$0.001 preflight turn must echo arc.selfcheck() before the paid loop; abort otherwise.
- Kernel state loss across per-action processes: nothing in the ask path calls KernelService::dispose, so the K10 final flush never runs; persistence rides only the 1,500 ms debounced snapshot, ipykernel's parent poller kills the kernel when the yi process exits, and dill cannot snapshot lambdas reliably. Mitigated by design: every durable thing (hyp sources as strings, plan, notes) is written synchronously to arcstate.json by arc.py; frames live in frames.jsonl; kernel revive is a bonus, never a correctness dependency.
- context_keys truncation: CONTEXT_VALUE_CAP = 4096 chars per key (rlm/__init__.py) silently truncates, so the approved intent's context_keys=["hyp","frames"] would hand a child a corrupt frames value. Corrected: hypothesis text only rides context_keys; the child reads frames.jsonl from the shared cwd (non-worktree children inherit the parent cwd, subagent.rs:65-66). isolation='worktree' would silently break this — the protocol forbids it and the README says why.
- Schema-enum drift: the per-turn --schema enum and frames.jsonl's `available` list must agree, or the model verifies against a menu the game rejects. Mitigated: both are derived from latest_frame.available_actions in one function; reflection turns use a separate frozen schema with no action field; an unknown-action answer still stops the run exactly as run 1 did.
- frames.jsonl partial lines / write races: the adapter and the yi process are strictly sequential (subprocess.run blocks), so there is no concurrent writer; residual risk is a crash mid-append, so arc.py skips one unparseable trailing line. The kernel snapshot writes into the session dir, not the work dir — no collision.
- Oscillation-counter leak-through: the notice must not smuggle grid bytes back into the prompt (that would quietly reopen the transcription channel). arc.tried() emits only per-signature counts — asserted in the selftest against the board-literal regex.
- Sub-search wall clock: rlm.run + rlm.wait(120) + result must fit the adapter's 300 s TURN_TIMEOUT; the fragment pins wait at 120 s and the child defaults to the parent's cheap model. A timed-out turn is the existing run-1 failure path (turn retried, then stop_reason), not a hang.
- Context balloon via ipython output instead of prompt: the model can print the whole history and rebuild run 1's problem in tool results. Mitigated: arc.py printers are bounded (diff caps at 40 listed cells, tried() is a small table, history() reprs summarize); grid_str is the only unbounded printer and the briefing discourages it; peak-ctx is the tripwire column either way.
- Reflection-turn gaming: the model could answer the reflection schema without touching the kernel. Accepted for run 2 — the reflection still costs it a prompt round and the streak reset re-arms the counter; verified-frac exposes the behavior in the ledger rather than a hidden gate enforcing it.
- Snapshot bloat: a model that binds large variables grows the session-dir snapshot; sync_after_compaction prunes oversized variables and the protocol keeps frames on disk, so nothing large needs to live in the namespace.
- Ledger law: the five new columns and two rows land post-run in their own commit (rows are written from harness output after the run, never beside code; columns append on the right only).

## Not building

- No Rust: no crate, module, prompt asset (identity.md/orchestrate.md), affordance, or wiring change; the cwd-drop injection path makes the compiled PYTHON_SKILLS list irrelevant.
- No new dependencies: arc.py is stdlib-only; yi_arc.py keeps its existing import set (requests/dotenv/arcengine come from the scaffold venv as in run 1).
- No scheduler, daemon, or watcher: the adapter stays a single sequential loop, one subprocess per action.
- No LLM in any control path or metric: thresholds are constants, triggers are pure functions of the action log, all six ledger columns are deterministic extractions.
- No adaptive/spend-aware thresholds: N and M never move during a run; retuning them is a new adapter version and a new config-fp.
- No reliance on kernel-snapshot revival for correctness (best-effort only; disk is the store).
- No board rendering in the prompt behind a flag or fallback: the zero-target means zero — there is no code path that puts a grid in a prompt.
- No new persisted artifacts outside the run dir and the per-game work dir; nothing lands in the repo from a run except the reviewed ledger rows.
- No yi_usage/parse_events changes: extraction reads existing event shapes (message_end, toolCall content, arguments.code).
- No multi-game parallel swarm, no game-specific heuristics or per-game prompt tuning, no changes to the ARC scaffold under ref/ (still read-only, still nothing written into the clone).
- No second adapter file: yi_arc.py evolves in place (production-duplication budget is 0); run-1 reproducibility is the git rev recorded in the ledger.
