## 0. Conflicts with the earlier drafts (recorded; the code wins)

1. The earlier security model said "revocation is one allowlist line".
   tailcat has no allowlist removal (`L:682-691`, append-only); this
   document says revocation is a listener restart, and designs so that
   is cheap (§7.3).
2. The earlier model said "one sidecar per node, N agents behind it".
   tailcat has no post-admission authorization (`L:487-492`,
   `L:553`); this document says one listener per link (§7.3).
3. The earlier model placed provider keys on the anchor. They live on
   the forge (§8, L5).
4. The earlier model treated "no secret enters model context" as a law
   enforced by the permission parser. It is a boundary only under
   sandboxing (§8, F1); until then it is a parser-enforced convention,
   stated as such.

## 1. What this is

Three primitives added to Yi, in dependency order:

- **Capsule** — a session as a value: entry tree, kernel snapshot,
  workspace reference, shell manifest, goal, budget lease. Freezes at a
  turn boundary, thaws byte-identically, forks, parks on disk for free,
  moves between prepared machines. Migration and crash recovery become
  the same code path.
- **Link** — a per-spawn, per-purpose encrypted connection whose entire
  address is a ~95-byte token, gated by an allowlist of exactly one key,
  served by exactly one listener, dead when its process exits. Carried by
  a sidecar transport behind a trait (tailcat first).
- **Node** — a named machine running `yi serve`, enrolled once, playing
  a role: the *cockpit* (laptops: attach, never own sessions), the
  *forge* (always-on homeserver: owns sessions, keys, the warden, mints
  sandboxes), *residences* (per-project VMs with warm caches), the
  *anchor* (small cloud container: reachability only, zero secrets).

Together: the **hive** — one person's three to eight machines behaving as
one place to run agents, with the human's own laptop treated as the
unreliable node it is.

Deferred to a later document, kept in view: the **pack** (Yi + local
inference + capsule as one executable for disconnected devices) and
**lineages** (multi-generation descent with cryptographic attenuation).
Every shape here leaves room for them; none depends on them.

## 2. Outcomes

What a user has when this lands, each testable:

| # | outcome | proof |
| --- | --- | --- |
| O1 | Closing the laptop lid stops nothing. Reopening anywhere shows the live transcript within seconds. | drive script: detach, advance the session 12 entries from another client, reattach; cursor resync delivers exactly 12 |
| O2 | A dangerous task runs fully autonomous inside a disposable VM and returns a diff, never a live process. | forge mints, child runs with `--yolo` inside, VM destroyed, diff lands in the ingest store, transcript shows the placement |
| O3 | Any session parks to disk for free and thaws with the kernel's variables intact. | freeze/thaw round trip: entry tree byte-identical, kernel probe equal, manifest lists what did not survive |
| O4 | No token, node key, or provider key ever appears in a transcript, a log, a `Debug` render, or model context. | the §11 tests; a grep of every fixture transcript for `tc[A-Za-z0-9_-]{40,}` and `privkey:` is empty |
| O5 | Enrolling a machine is one command; the model addresses machines by name and never sees an address. | `yi hive add forge` end to end; the spawn tool's `on` argument accepts names only |
| O6 | A session that must wait waits on the cheapest node and works on the strongest one. | a parked capsule woken by the forge's scheduler on a cron rule, then re-parked |
| O7 | Nothing about the hive costs anything when it is off. | `hive.enabled` false: binary size delta measured, startup unmoved, prompt bytes unmoved |

## 3. Feature set

Tiered; a tier ships only after the tier below has its exit gate green.

**H1 — remote attach** (the weekend). `yi serve --hive` bridges the
daemon socket over a Link; `yi console` and `yi acp` dial a node by name.
Cursor-based resync on reconnect; idempotency keys on mutating frames.
Roster file; `yi hive add|ls|rm|status|rotate`. Sidecar admission policy
(pinned, hashed, conformance-tested, scrubbed environment, mode
denylist).

**H2 — capsules, local.** `yi capsule freeze|thaw|fork|ls` on one
machine. Quiescence check, kernel snapshot with a survivor manifest,
workspace reference, shell manifest, thaw probe. Park/wake from the
daemon: a parked session is a capsule, not a worker.

**H3 — placement.** `SpawnSpec.placement`; a child on another node is
still `rlm.run(prompt, on="forge")`. One listener per link; the drop-box
ingest store; results return as addressable references. Capsule move
between residences (prepared habitats only). Console lanes per node with
path state and partition state.

**H4 — the warden and the forge.** Scheduler-driven wake of parked
capsules on the forge; `yi hive wake <capsule>` as the external trigger.
Disposable sandboxes: a Proxmox-backed skill that clones a template,
cloud-inits `yi serve --hive --link <key>`, and destroys on completion.
Spatial fork: freeze at N, thaw on two sandboxes, compare diffs.

**S — the sandbox track** (parallel, prerequisite for claiming L3 as a
boundary): the shell tool runs under an OS sandbox that denies the
runtime's key directories and the loopback bridge port. Until S lands,
L3 is enforced by the permission parser and documented as a convention.

## 4. Human usage

Every hive verb returns before config parse or runtime construction
where it can (the `sessions list` precedent). Names are the API; tokens
never print.

```
yi hive add <name> [--role cockpit|forge|residence|anchor] [--via <name>]
    # on the new machine: mints its saved key, exchanges public keys with
    # the initiating node over a one-time link, pins both allowlists,
    # writes the roster on both ends. One command, both sides.
yi hive ls                       # name  role  path(direct|relay|down)  leases
yi hive status <name>            # last seen, listeners, parked capsules
yi hive rotate <name>            # new key, re-pin every roster peer, old key dies
yi hive rm <name>
yi hive wake <capsule-id>        # external trigger for the warden

yi serve --hive                  # this node's daemon, reachable by roster name
yi console --hive [name]         # lanes per node; attach to any session on any node
yi acp --hive <name>             # editor protocol over a link

yi capsule freeze [session] [--label]   # at the next turn boundary, after quiescence
yi capsule thaw <capsule-id> [--on <name>]
yi capsule fork <capsule-id> [--at <entry>] [--on <name>]...
yi capsule ls [--parked] [--on <name>]
yi capsule move <session> --to <name>   # freeze here, thaw there, one verb

# inside the TUI/console
/park                            # freeze this session; the lane shows it parked
/move <name>                     # capsule move
/hive                            # the roster, inline
```

The permission surface grows one decision, not a parallel system: a link
request is a `ToolCall`; modes and rules decide; holds ask with a reason;
a denial carries evidence ("no roster node `forgee`; nearest: `forge`").

## 5. AI usage

The fixed prefix every request pays is ratcheted in CI, so the hive adds
**no tools**. It adds one optional argument and one triggered skill.

- `rlm.run(prompt, on="forge")` — the existing spawn call gains `on`,
  a roster *name*. Omitted means inline, as today. The child's view is
  identical to a local child: same tool table, same entry tree, same
  kernel, same parent. It never learns it is remote.
- Results come back as they do today (`ChildResult`), with `output`
  as an addressable reference into the ingest store when the child
  produced artifacts.
- A `hive` skill (byte-budgeted, triggered by placement words) tells
  the model what names exist and what each role is for. It never
  contains a token; the roster it renders is names and roles only.
- Partition is a state the model sees: `Blocked { on: Partition {
  since, last_seen } }` on the todo, visible in the transcript, never a
  hidden retry. Seamless in the happy path, loud at the boundary.
- `/park` and `/move` are host verbs and schedule actions, not model
  tools. The model can *ask* for a park via a stated intent the runtime
  recognizes at the turn boundary; it cannot move itself.

## 6. User journeys

**J1 — the lid.** You open a session on the cockpit against the forge
(`yi console --hive forge`). The session's worker, kernel, and
workspace are on the forge; the console renders. You close the lid and
drive to work. The link's WireGuard endpoint roams with your IP; the
console client's socket dies during sleep and re-dials on wake with
backoff (already built); it sends its cursor (`entries through N`) and
the daemon streams N+1 onward, including the twelve entries the session
produced while you drove. Elapsed: two to three seconds after the lid
opens. Nothing was kept alive.

**J2 — the dangerous task.** "Upgrade every dependency and fix what
breaks." The plan engine marks the todo `Delegation { isolation:
Sandbox }`. The forge's sandbox skill clones the Rust residence
template, cloud-init runs `yi serve --hive --link <one-time key>`, the
child dials home over its own listener, runs under `--yolo` — the blast
radius is `qm destroy` — and writes its diff to the drop box. The ingest
watcher moves it into the content-addressed store the instant it
closes; the VM is destroyed; the parent's todo goes `Done { output:
store://… }`. You review a patch. You never watched a live process.

**J3 — the warden.** A project's session is parked as a capsule on the
forge, costing flash. A cron job on the forge's scheduler (the existing
`Job` shape) thaws it every morning at 06:00 with the prompt "check CI
on main; fix and push if red; re-park". Most mornings it thaws, runs
one scripted probe that matches its prediction, re-parks in under a
minute, and spends nothing. The morning CI is red, it works. `yi hive
wake <id>` from a webhook does the same on demand.

**J4 — roaming.** Home WiFi, phone tether, work WiFi. WireGuard
identifies peers by key, not IP: the forge updates the endpoint on the
first authenticated packet from the new address. magicsock re-punches;
DERP carries the seconds in between, over 443 where UDP is blocked. The
console shows a latency blip, then `path: direct` again. Work's captive
portal is the only thing that interrupts you, and it interrupts the
browser too.

**J5 — the spatial fork.** A refactor has two credible strategies.
`yi capsule fork <id> --at 412 --on forge --on forge` freezes at entry
412, thaws two copies on two sandboxes, one prompted per strategy. Both
run against real filesystems with real tests. Two diffs arrive in the
store; you keep one; both VMs are destroyed. Best-of-N over side
effects, not tokens.

**J6 — the phone.** A terminal app on the phone reaches the anchor by
its roster DNS name, `yi console --hive` attaches to the forge through
it, and a parked capsule thaws. No port on the router, no VPN app, no
account. The laptop was only ever a screen.

## 7. Architecture

### 7.1 Nodes and roles

```
 cockpit (mac, roams, sleeps)          anchor (cloud, public, no secrets)
   yi console --hive  ──link──┐          yi serve --hive --role anchor
   yi acp --hive              │            relay (derper) · DNS · queue
                              │            parked-capsule store (encrypted)
                              ▼
 forge (proxmox host, always on) ◄──link── residence-rust (VM, warm target/)
   yi serve --hive --role forge            yi serve --hive
   provider keys · warden · scheduler      residence-cuda (VM)
   ingest store · sandbox skill            sandbox-7f3a (VM, disposable, one link)
```

Same-host children (forge → its own VMs on the bridge, or processes on
one machine) use Unix sockets, never a link. Links carry only the
cross-host edges: cockpit→forge, anchor→forge, sandbox→forge.

### 7.2 The Wire trait and the sidecar

```rust
/// yi-runtime::hive::wire — the only thing that knows a transport exists.
pub trait Wire: Send + Sync {
    fn listen(&self, allow: PeerKey, opts: ListenOpts) -> Result<Listener, WireError>;
    fn dial(&self, to: &ConnToken, key: &NodeKeyRef) -> Result<Stream, WireError>;
    fn probe(&self, to: &ConnToken) -> Result<PathState, WireError>;   // Direct | Relay | Down
}
```

Two implementations from day one: `LoopbackWire` (in-process, for tests
and the conformance harness) and `TailcatWire` (the sidecar). A third —
`dumbpipe`/iroh — is the planned proof that the trait is real; the
decision between transports is deferred behind it.

`TailcatWire` execs a runtime-owned binary, never one on `PATH`:

- **Admission:** one vetted version per hive, hash-pinned in
  `hive.json`; a binary with an unknown hash is refused. Before first
  use and after every upgrade, the **conformance test** runs: a
  hermetic server+client round trip with `--derpmap-url=none` (tailcat's
  own `pipe_test.go:17-68` proves the mode), checking the flag surface,
  the `--json` shape, allowlist behavior, and the `--allow=none`
  deny-all. The contract has no stability promise; the test is the
  contract.
- **Launch:** scrubbed environment (no `TS_DEBUG_*`, no `TAILCAT_*`
  except the one the runtime sets); explicit `--key=<runtime path>` or
  `--key=new` (never the silent `default`/`client-default` auto-load,
  `C:1079-1087`, `C:653-661`); never `--verbose`; embedded relay region
  so no DERP map is ever fetched (`--region=<host>`); token read via
  `TAILCAT_ADDR_FILE` (0600 file, `C:1261-1274`) or `--json` stdout —
  never by scraping stderr.
- **Modes:** `serve <port> --allow <key>` and `recv <dir> --allow
  <key>` only. Denied forever: pipe mode (peer-triggered `log.Fatal`,
  `C:1208-1211`), `serve all`, `exit-node` (unrestricted SSRF;
  `AllowProxy` is dead code, `L:350-352`), `no-auth-ssh` (shell as the
  server's uid, username ignored, full-filesystem SFTP), `files:rw`
  (symlink escape, `tailcat_sftp.go:228`).
- **Containment:** the sidecar has no internal bounds (`b.clients`
  append-only with O(n²) advertisement, unbounded goroutines, no
  timeouts). One client per listener makes n=1; a cgroup memory limit
  and an fd limit make the rest a restart, and the runtime supervises
  restarts.
- **Relay:** the hive runs its own `derper` on the anchor; every token
  embeds it. The public tailcat relays (four regions, rate-limited,
  revocable, metadata-logging) are never on the path. The relay learns
  who talks to whom and when — topology is an asset (§8) — and owning
  the relay is what keeps it one.

### 7.3 Links

A link is four things, and all four are required: a **token** (public
data with one unguessable field, the server key), an **allowlist entry**
(exactly one client key), a **dedicated listener** (one sidecar server
process, because tailcat cannot distinguish admitted clients), and the
**client's key**. The runtime mints all four; the model sees none.

Lifecycle: mint → hand the connected stream to the spawn (by move; a
`MintedLink` cannot arm two children) → the listener dies with the
child. Revocation is the listener's exit. Roster links (cockpit↔forge)
are the persistent case: saved keys, pinned both ways, rotated with `yi
hive rotate`.

The daemon side: a link terminates at a loopback port that the sidecar
forwards to (`C:1165-1175`). That port is a surface — any local process
can reach it — so the daemon authenticates frames at the application
layer even on loopback (a per-link session secret handed over inside
the WireGuard tunnel at connect, never on disk), and the S track
removes the shell tool's ability to reach the port at all.

### 7.4 Capsules

```
<capsule-id>/
  manifest.json      # schema-versioned; unknown fields survive in a bounded
                     # remainder never acted on (the session-entry precedent)
  entries.jsonl      # the entry tree, byte-identical on thaw
  kernel/            # K10 per-variable snapshots + survivors.json (what did
                     # not pickle, by name, with the reason)
  workspace.json     # base commit, dirty diff, untracked manifest, shadow
                     # checkpoint ref — a reference, never a copy
  shell.json         # cwd, exports, background jobs that were killed and why
  lease.json         # budget lease: allocation, spent, expiry
```

Rules: freeze only at a turn boundary and only after **quiescence** (no
background jobs; a running job blocks the freeze with evidence rather
than being killed). Thaw runs a **probe** — one kernel eval and one `git
status` compared against the manifest — and fails loudly at the
boundary rather than three turns later. Migration is between **prepared
habitats** (residences with warm caches and matching toolchains), never
arbitrary machines; `capsule move` refuses a destination whose habitat
tag does not match. Credentials, ambient identity, sockets, and live
processes never travel.

A parked capsule on the anchor is encrypted with a key that lives on
the forge; the anchor stores ciphertext it cannot read.

### 7.5 Placement

`Delegation` gains one field, and nothing else changes:

```rust
Placement { Inline, Local, Pinned(NodeName), Sandbox { template: HabitatTag } }
```

The placer resolves a name to a node, checks `hive ls` path state,
mints a link, ships the spawn spec and the child's context slice over
it, and returns a `ChildId` exactly as a local spawn does. A
`Sandbox` placement invokes the forge's sandbox skill to create the
node first. Authority overlays apply unchanged: the child's tools and
model never exceed the parent's; the budget is a lease sliced from the
parent's.

Results: the child writes artifacts to its link's drop box; the ingest
watcher moves each file out the instant it closes into a
content-addressed store; `ChildResult.output` is `store://<hash>`.

### 7.6 The warden

Not a new subsystem: the forge's existing scheduler with one new job
kind, `WakeCapsule { id, prompt, repark: bool }`. A wake thaws, delivers
the prompt (Steer or FollowUp as today), and re-parks at the next turn
boundary when the session's plan has no active todo. `yi hive wake` is
the external trigger. The anchor holds a queue of wake requests the
forge drains; the anchor never thaws anything.

### 7.7 Console

Lanes per node, not just per session: name, role, `path: direct|relay|
down`, lease burn, parked count, partition state on any child. The orb
already has `Connecting` and `Weaving`; a remote child's lane uses
them. Attachment is already a set in the daemon, so two terminals on
one remote session need nothing new.

## 8. Security model

Built per `har-threat`: assets named, boundaries drawn, STRIDE walked,
controls at the parser, every control tested (§11).

**Assets.** Provider keys · the machines (shell as the user) · the
workspaces · the entry trees (a transcript contains every secret a
session read) · the authority chain (every agent back to a human goal)
· node private keys and tokens · **topology metadata** (who talks to
whom, when, from where — what a relay sees).

**Boundaries.**

| boundary | what crosses | assume |
| --- | --- | --- |
| token parser | `tc…` blobs from the roster, the sidecar, a peer | untrusted: may name any relay host, may set `x:true` to disable relay TLS verification (`wire.go:58`, `derphttp_client.go:665-668`) |
| sidecar stdio + environment | token file, `--json`, exit status; env knobs | unversioned; env can make the process print secrets (`TS_DEBUG_CONNBLOB`, `L:716`) or load the wrong identity |
| tunnel payload | ACP/RPC frames | peer is key-authenticated; frames are still attacker-shaped after any compromise; bound everything |
| loopback bridge port | the same frames, from anything local | any local process, the shell tool included, can connect |
| drop box | files from a child | WO refuses list/read (`tailcat_sftp.go:271,144`) but **not** overwrite of existing names (`:160-184`, no forced `O_EXCL`); no quota; existence oracle |
| capsule at thaw | manifest, entries, snapshot | a program for this runtime; provenance first, probe second |
| roster file | name → key/token | config with root-like power; signed or forge-only |
| DERP relay | encrypted packets, rendezvous | honest-but-curious; can stamp `src` on a meow and poison an allowlisted key's disco key for the process lifetime (`L:1371-1373`) — a direct-path DoS, never access |
| model context | renderings of all of the above | a confused deputy; anything readable is exfiltratable |

**Laws.**

- **L1 — authority and budget only shrink, hereditarily.** Overlays
  never exceed the parent; budgets are leases with expiry that return
  unspent at contact. Within the hive this is trust among owned
  machines; for packs and lineages it needs cryptographic attenuation
  (Biscuit-class, deferred with them).
- **L2 — a capability is token + allowlist entry + dedicated listener
  + client key.** Any three without the fourth is not a capability.
- **L3 — no secret enters model context.** The runtime mints, dials,
  and hands over connected streams; the model addresses peers by name.
  *Enforcement today:* the permission parser's `command_reads_credentials`
  extended to tailcat's key directories on every platform
  (`~/.config/tailcat`, `~/Library/Application Support/tailcat`,
  `%AppData%\tailcat`) and Yi's own `~/.yi/hive`; the sidecar binary in
  the catastrophic tier. *What that does not cover:* a shell command
  connecting to the loopback bridge port, or reading `/proc`. L3 becomes
  a boundary when the S track sandboxes the shell tool; until then the
  plan says "convention" and means it.
- **L4 — disconnection compiles holds down, never up.** A hold is a
  question; a partitioned child cannot ask. At spawn, every hold-shaped
  rule compiles to a denial or a queued question. If the overlay cannot
  shrink authority until nothing hold-worthy is reachable, the spawn is
  refused with that as evidence.
- **L5 — secrets live on the least-reachable always-on node.** The
  forge holds provider keys, the warden, the capsule encryption key.
  The anchor — public, DNS-named — is sacrificial: relay, queue,
  ciphertext, nothing else.
- **L6 — field data is data.** Entries, artifacts, and comments from
  children or drop boxes are parsed under bounds, attributed, and
  presented as evidence, never instructions. Goals travel the other way
  only, verbatim.

**STRIDE, the rows that changed after reading the code.** *Spoofing:*
the allowlist is enforced at the only layer that matters (`L:1362-1369`
→ `b.clients` → wireguard-go `LookupPeer`); an empty allowlist is a
construction error in `TailcatWire`, not a default. *Denial:* the sidecar
has no bounds Yi can set; contain it (§7.2). *Disclosure:* `ConnToken`
has a redacting `Debug` and no `Serialize`; the sidecar's environment is
scrubbed; `--verbose` never; capsule export outside a team is killed.
*Elevation:* key-directory reads join the credential guard; the binary
joins the catastrophic tier; the loopback port gets application-layer
auth now and a sandbox later.

## 9. The shapes

```rust

NodeId(u64)  LeaseId(u64)  CapsuleId([u8; 32])  HabitatTag(String)

/// against the hive's relay set. No Display, no Serialize.

impl ConnToken {
    pub fn parse(raw: &[u8], relays: &RelaySet) -> Result<Self, TokenError>;
}
impl fmt::Debug for ConnToken {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result { f.write_str("ConnToken(..)") }
}

/// One dialed, allowlisted, single-listener link. Consumed by move.
pub struct MintedLink { /* stream + peer key + listener handle, private */ }

/// Typestate on the roster: a node is usable only once both allowlists
/// are pinned. `Enrolling` has no `link()` method.
pub struct Node<S> { name: NodeName, role: Role, key: PeerKey, state: PhantomData<fn() -> S> }
pub struct Enrolling; pub struct Pinned;

pub enum Role { Cockpit, Forge, Residence, Anchor }

pub struct Lease { id: LeaseId, allocation: Budget, spent: Budget, expires: Millis }

pub struct CapsuleManifest {
    schema: SchemaVersion,
    id: CapsuleId,
    session: SessionId,
    goal: GoalId,
    habitat: HabitatTag,
    frozen_at: EntryId,
    survivors: Vec<Survivor>,        // kernel variables that did not pickle
    killed: Vec<KilledJob>,          // background jobs, with reasons
    lease: Lease,
    #[serde(flatten)] remainder: BoundedRemainder,   // never acted on
}

/// Config: `hive` is Option, off by default; deny_unknown_fields like its peers.
pub struct HiveConfig {
    enabled: bool,
    this: NodeName,
    sidecar: SidecarPin { path: PathBuf, sha256: [u8; 32], version: String },
    relays: RelaySet,
}
```

The permission crate grows: `PROTECTED_CREDENTIAL_SUBPATHS` gains the
tailcat and hive key directories (per platform); the catastrophic tier
gains the pinned sidecar path.

## 10. Formats

**`~/.yi/hive/roster.json`** — names are the API; keys rot behind them.

```jsonc
{
  "schema": 1,
  "this": "forge",
  "sidecar": { "path": "~/.yi/hive/bin/tailcat", "sha256": "…", "version": "v0.4.0" },
  "relays": ["relay.hive.example:443"],
  "nodes": {
    "anchor":   { "role": "anchor",    "key": "nodekey:…", "token": "tc…", "dns": "yi.example.com" },
    "cockpit":  { "role": "cockpit",   "key": "nodekey:…" },
    "residence-rust": { "role": "residence", "key": "nodekey:…", "token": "tc…", "habitat": "rust-1.91" }
  }
}
```

Tokens in the roster are addresses; the allowlists on each node are
what make them capabilities. The roster is 0600, lives under a path the
credential guard protects, and is never rendered to the model — the
`hive` skill renders names and roles from it.

**Frames** over a link are the existing ACP/RPC frames plus two fields:
`cursor` on subscribe and `idem` on every mutating command. Bounds: the
console client's 32 MiB cap and tear-down-and-redial posture are the
template for every hive listener; `deny_unknown_fields` on every
control type; the capsule manifest is the one versioned format that
keeps a bounded remainder.

## 11. Test the control, not the feature

A control whose deletion breaks no test is decoration. The ledger:

| control | test that dies with it |
| --- | --- |
| allowlist mandatory | `TailcatWire::listen` with no key fails construction |
| token never serializes or renders | compile-fail: `ConnToken: !Serialize`; `Debug` is `ConnToken(..)` |
| token parser rejects `x:true`, unknown relay hosts, missing disco key, oversize lists | four fixtures, four denials with evidence |
| link is single-use | compile-fail: second spawn from a moved `MintedLink` |
| one listener per link | two children on one node produce two sidecar processes with distinct allowlists |
| sidecar pinned and conformant | wrong hash refused; conformance round trip passes on the pinned build and fails on a build with `--json` removed |
| sidecar environment scrubbed | spawn under `TS_DEBUG_CONNBLOB=1`; stderr contains no `tc` blob |
| key directories unreadable via bash | `cat ~/.config/tailcat/keys/x` and the macOS path denied by the parser with evidence |
| drop-box ingest | a peer that opens an existing name for write finds the directory empty; the store holds both versions |
| drop-box quota | a peer writing past the quota gets `ENOSPC`; the forge's disk is unaffected |
| frame bounds | over-size and over-depth frames rejected; session survives |
| cursor resync | detach, advance N, reattach; exactly N delivered, none twice |
| idempotent commands | the same `idem` twice submits once |
| freeze requires quiescence | a running background job blocks the freeze with its pid in the evidence |
| thaw probe | a tampered `workspace.json` fails the probe before the first turn |
| habitat match | `capsule move` to a mismatched habitat is refused |
| holds compile down | a spawn with a hold-shaped rule yields deny + queue, never allow |
| lease conservation | children's leases never sum past the parent's; expiry returns the remainder |
| anchor holds no secrets | the anchor's config, roster, and store contain no `privkey:` and no provider key; parked capsules there are ciphertext |
| hive off costs nothing | `hive.enabled` false: size ledger row, startup unmoved, prompt-bytes baseline unmoved |

## 12. Implementation plan

Each milestone: crate placement, exit gate (judged by exit code, never
piped output), and its D-row placeholder. Baseline edits land in their
own commits. Every dependency decision is measured before it is made
and logged in `docs/size-ledger.md`.

**M0 — the trait and the harness** (yi-runtime `hive::wire`, yi-types
`hive`). `Wire`, `LoopbackWire`, `ConnToken::parse` with a hand-rolled
base64url + CBOR-subset decoder for the four wire fields (measured
against a crate; the ~100-line rule decides), `PeerKey`, `NodeName`,
`HiveConfig` behind `hive.enabled=false`. The conformance harness runs
against a vendored tailcat under `ref/` in CI-optional mode. *Gate:*
every parser fixture in §11 green; size ledger row shows the delta
with the feature off. **D97.**

**M1 — remote attach** (yi-acp daemon, yi-console client, yi-cli
`hive`). `TailcatWire` with the launch, mode, and containment rules of
§7.2; `yi serve --hive` bridges the socket; per-link application-layer
frame auth on the loopback port; `cursor` and `idem`; `yi hive
add|ls|rm|status|rotate` with the one-command enrollment; the
credential guard extended; the sidecar path in the catastrophic tier.
*Gate:* O1's drive script green over a real tailcat link between two
machines; O4's transcript grep empty; a `hive rotate` that re-pins
every peer. **D98.**

**M2 — capsules, local** (yi-session, yi-kernel K10, yi-runtime
`capsule`, yi-cli `capsule`). Freeze with quiescence, the survivor
manifest, workspace and shell references, thaw with probe, fork via
the existing `ForkPosition`, park/wake from the daemon (a parked
worker becomes a capsule on disk rather than an in-memory parked
worker; `PARKED_MAX` stops being a limit). *Gate:* O3's round trip on
a session with a live kernel holding a dataframe, a lock, and an open
file: the dataframe survives, the other two are named in
`survivors.json`. **D99.**

**M3 — placement** (yi-runtime `subagent`, `hive::placer`, the drop-box
ingest watcher, yi-console lanes). `Placement` on `Delegation`; one
listener per remote child; context slice shipped over the link; the
ingest store; `ChildResult.output` as `store://`; `capsule move`
between habitats; partition as a visible blocked state; console lanes
per node. *Gate:* a remote child's transcript is byte-identical to an
inline child's except for placement metadata; pulling the cable
produces `Blocked { on: Partition }` in the parent within one
heartbeat and clears on reconnect. **D100.**

**M4 — warden and forge** (yi-runtime `schedule` job kind, the sandbox
skill under `skills/`, yi-cli `hive wake`). `WakeCapsule` jobs; the
anchor's wake queue; the Proxmox skill (clone, cloud-init with a
one-time link key, destroy); spatial fork. *Gate:* O2 and O6 end to
end on the user's actual forge; J5 produces two diffs from one frozen
entry. **D101.**

**S — sandbox the shell tool** (yi-tools `sandbox`, yi-permission).
The existing sandbox seam in yi-tools grows an OS-level policy
(Seatbelt on macOS, bubblewrap/landlock on Linux) that denies the
runtime's key directories and the loopback bridge port to commands the
model runs. Runs in parallel with M1–M4; L3 is upgraded from
"convention" to "boundary" in this document's successor when it lands.
*Gate:* the §11 key-directory and loopback tests pass with the parser
rules *deleted*. **D102.**

**Deferred, kept in view:** the pack (Yi + `llama-server` sidecar +
weights + capsule as a self-extracting archive; one provider entry, no
new subsystem); lineages beyond one generation with Biscuit-class
attenuation; a second `Wire` on `dumbpipe`/iroh to prove the trait;
capsule sharing outside a team (needs a scrubber that does not exist).

**Budgets, stated up front.** Binary: the hive is Rust inside Yi and a
Go sidecar outside it; the Rust side is estimated at 60–120 KB with
zero new dependencies if the decoders are hand-rolled (measured at M0,
ratcheted from there). Startup: unmoved — every hive path is behind
`hive.enabled` and constructed lazily. Prompt bytes: +0 tools; the `on`
argument's schema line is the only fixed-prefix growth and is
committed as its own baseline edit. Dependencies: 18 direct stays 18.

## 13. Killed on the way

Recorded so they stay dead: provider keys on the anchor · `no-auth-ssh`
reachable from anything · model-visible tokens, the sidecar on `PATH`,
sidecar stderr through the shell tool · pipe mode · `exit-node` /
SOCKS as an egress policy peer (the hook it needed is dead code) · DNS
TXT as discovery for anything that sends data (unauthenticated;
private roster instead, DNS only for the anchor's name) · one sidecar
per node with port muxing · "revocation is one line" · split residency
(loop here, kernel there) — the kernel opens files · migrate-anywhere
· raising the depth cap without hereditary invariants · public
capsule sharing · "no control plane" as a security claim (the anchor
runs a relay, DNS, and a queue; owned, small, named).

## 14. Decisions needed before M1

1. **Relay:** run `derper` on the anchor from day one (this document's
   assumption), or accept the public tailcat relays for H1 only and
   defer the anchor. The public relays log metadata and can be revoked;
   the derper is one container.
2. **Same-uid posture until S lands:** ship M1 with L3 as convention
   (parser rules, catastrophic tier, application-layer frame auth), or
   hold M1 until S. This document assumes ship-then-harden, documented.
3. **Transport reversibility:** commit to the second `Wire` as an M0
   deliverable (`LoopbackWire` proves the trait compiles, not that it
   abstracts), or accept tailcat-only until iroh or a Rust tailcat
   forces the question.
