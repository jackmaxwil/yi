The fixer now asks the forge whether a base is red before it waits on one. Its gate path took only the names of the red lanes from the forge and read every failing test from its own run of the lanes in its clone, so a test that fails there at the head and at `origin/main` alike read as main's own red test. On 2026-11-23 that parked #2237, whose real failures (its new admission rule refusing a second session at load 18 against a cap of 12) pass in the clone, and opened #2330 "The test lane of main is red" over a main whose lane was green. The job log that names the forge's failing tests is not served to a runner, so the fixer reads the commit statuses of the base instead: the newest finished run of `gate (test)` or `warm (test)` on its first-parent commits, where a cancelled job (written `failure`) and a skipped one (written `success`) do not count. When that run did not fail, the tests are the clone's and the head goes by the rule a flake already has: one rerun, then a hand-off that names the job log. A red-base issue standing over a base the forge has green is closed without asking the clone, which releases the pull requests waiting on it. A main broken by a merge whose `warm (test)` run was cancelled still never reads red on the forge, so no issue opens for it.
