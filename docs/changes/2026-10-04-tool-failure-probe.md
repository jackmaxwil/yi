Every plan and todo refusal now says what kind it is, and the tool-surface eval counts failures by kind (Closes #1078). A refusal was `tool_error` or nothing, so no count could tell a call the tool misread from a correct no. The plan and todo tools now tag each one `invalid_args`, `stale`, `verdict` or `denied` from the engine's own error, `evals/surface.py` reports misreads and stale views apart from verdicts, command exits and safety refusals, and the twelve plan-tool dogfood prompts run as its `plan-*` scenarios. The first run, ledger row 0073, is the zero-tool-failures baseline: 26 misreads and 3 stale views in 254 calls on glm-5.3-flash.
