A child's answer is read one way: `rlm.result`, a reap and a plan finish all skip a chase turn's reply, so the reply a parent's `rlm.request` chased out of a child is never taken as the answer to its brief. A respawned service's first message is its incarnation header alone, since its kept transcript already opens with the brief, so the brief's bytes appear once in its history. `rlm.wait` no longer sends the one-release `updated` alias (read `changed`), and the child roster rows lose their always-null `active_session_id` and `session_id`. A final text over the body cap still goes whole to the family board, which every member can read, and its head now ends in the shared cut row naming bytes kept of total and `HEAD_BYTES`. The stuck check runs at most once a second per host whatever the number of waiters, and it latches through the same `StuckLatch` the plan timer uses. A HIGH discovery when the session has no goal reaches the parent as a note saying no completion gate holds on it, instead of failing the child's result with a `goal.create` refusal; an unreadable plan and a failed ledger write still hold the result back. The plan finish runs its red check and its discovery routing as two named steps. The plan test rig moved from `plan/dispatch.rs` to `plan/rig.rs`, built on `yi_ai::faux::faux_model`, which the CLI's `faux/faux-1` resolution now shares.
