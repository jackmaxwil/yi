A request mailed to a session that no process holds now starts it while `yi serve` runs (Closes #1246). The daemon polls `<sessions>/channels/` every two seconds, a poll with no new file-watch dependency that never reads the daemon ledger. A request that no subscription has read after a held session's own cadence plus a margin, and that is not past its deadline, makes the daemon spawn the worker for the session's repository (found from the session file's header) and resume the session with no replay and no model turn, which binds its mailbox so the letter is delivered as for any loaded session. A session started this way has no client to ask: a permission ask it raises is cancelled at once, and the requester receives a `failure` letter naming the refused action with `inReplyTo` set to its request, instead of the worker waiting on an answer nobody sends. The ask is refused whatever its kind; the classifier-backed approval the issue names for reviewable auto-mode asks is not part of this change, and a refusal is the fallback it names. Without a daemon nothing changes: the letter waits in the channel file with receipt `stored`. The journey `serve_daemon::a_request_in_a_stopped_sessions_mailbox_starts_it_and_is_read` writes a session and an old request on disk, starts the daemon and sees the letter acked.
