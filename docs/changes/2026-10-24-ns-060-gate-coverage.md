The startup gate times a first request as well as `yi --version`. Its second entry runs `yi ask --model faux/faux-1 hi` on the dist binary, fifty runs scored on the minimum like the first, under a scratch HOME with kernel prewarm off and in an empty scratch directory under `target/`, never `/tmp`, whose whole tree the checkpointer would add, with `GIT_CEILING_DIRECTORIES` set so the checkout around `target/` is not seen: without it every timed run claimed a lane, a `git worktree add` of the whole repository, and the minimum read 317 ms instead of 142 ms. Its budget is 178 ms, 25% over the 142.4 ms minimum measured on this branch's dist build (three runs at load 30 to 34 read 157.9, 145.0 and 142.4 ms, a spread of 11%). The gate gains a `--selfcheck` that runs a stand-in binary sleeping 20 ms on one entry's first argument, asserts that entry alone fails a 10 ms budget, and fails if either entry is skipped, if the second entry is pointed at `--version` or if the scratch HOME or the git ceiling is dropped; `just guardrails` runs it beside the gate, off CI like the gate. The lint lane gains `clippy-no-tui`, `cargo clippy -p yi-cli --no-default-features -- -D warnings`: the build without the `tui` feature had six dead items no gate saw (the drive flags on `Args`, `print_resume_hint`, `ensure_daemon`, `DriveCommon`, `drive_common` and the launchers' imports). The launcher items now compile only with the feature, `print_resume_hint` moves beside its only callers in `shells.rs`, and `Args` carries a `dead_code` expectation in that build alone, so `main.rs`, already past the soft line below, shrinks by five lines rather than growing by fifteen `cfg` attributes.

Clippy now denies `unreachable!` across the workspace. The three production uses, the Anthropic and OpenAI chat mappers' accessors for an output that is always an assistant message, return `Option` as the Responses mapper's already did, with `block_mut` and `push_block` helpers so the callers stay one call each; a console layout test that used the macro returns a `Result`. `check_panic.py` and its zero budget stay beside the lint, since it matches spellings and clippy matches behaviour. The boundary gate reads `[dev-dependencies]` too: a test-only edge past a crate's row must be listed in a new `[dev]` table of `boundaries.toml`, which names yi-loop's edges to yi-ai and yi-context and yi-cli's to yi-tools, and a `[dev]` edge nothing uses fails. The env-var gate reads tests, scripts, the workflows and the justfile as well as src, fails a declared name nothing reads, and matches a name only on its own, so `ARC_YI_MODEL` and `docs/YI_DESIGN.md` no longer count. Five names in use are declared: `YI_BLESS`, `YI_FAKE_RIPWIRE`, `YI_WARM`, `YI_SIGNING_KEY` and `YI_ALLOWED_SIGNERS`; the plan's `YI_MODEL` and `YI_BINARY` were the eval harness's `ARC_YI_*` names and `YI_INSTALL_UV` appears only in fixture text, so none is declared, and one test's never-set probe name loses its `YI_` prefix rather than taking a row. Both gates gain a `--selfcheck` that plants one defect per rule and fails if any rule is switched off.

The gates that read production Rust find test code per item. `_common.code_lines` stopped at the first line starting `#[cfg(test)]`, so everything below a mid-file test helper was invisible to the panic, glob re-export, duplication, function size, orphan and comment gates: 1,352 production lines in 12 files, 557 of them in `runtime/src/provider.rs` below a four-line helper and 389 in `runtime/src/memory/store.rs`. A `#[cfg(test)]` attribute now covers the one item after it, to its matching brace or its `;`, read by a small lexer that skips strings, raw strings, char literals and comments, and the covered lines are blanked rather than dropped so every hit still names its line in the file. None of the newly visible lines trips a gate. `cli/src/stats.rs`, whose last 139 production lines sat below its test module, now ends with the module. The test budget counts inline `#[cfg(test)]` lines beside `crates/*/tests`, fork-relative on both sides, so no baseline moves; inline test lines still count in their crate's src lines too. The duplication gate also scans `crates/*/tests` and fails a 15-line window copied more often than at the fork, which holds 297 such windows. The autofixer's test-weakening check reads the same per-line mask instead of treating everything after the first marker as test code. `check_test_size.py` gains a `--selfcheck`, and the duplication and function-size selfchecks gain a production fn below a helper shaped like `provider.rs`'s; each fails when the old first-marker cut is restored.

The file ceiling counts production lines with the same per-item test detection, so `plan/dispatch.rs`, 1,200 lines of which 845 were tests, stands at 355. 1,200 stays the hard line, and a soft line at 1,000 production lines is new: a file past it may not grow on a branch, judged against its fork-point count with no baseline file, so the next addition to one of the 24 files over it today (`tui/app.rs` and `plan/state.rs` at 1,199, `schedule/mod.rs` at 1,198, `loop/run.rs` at 1,140 among them) splits it at a seam first, and a file may grow to exactly 1,000. `check_file_size.py` gains a `--selfcheck` with a file of 600 production and 800 test lines, one of 1,201, and growth from 1,000 to 1,001, 1,150 to 1,151, 999 to 1,000 and 900 to 901, which fails if the whole-file count returns or the hard line, the soft line or the fork comparison is switched off.
