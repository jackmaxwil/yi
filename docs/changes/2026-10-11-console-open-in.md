A console message can be opened in another app (Closes #1254). `open` in `~/.yi/config.json` lists the apps, each a name and a command whose `{path}` argument becomes the message saved as markdown under `~/.yi/exports` (the path is appended when no argument names it): `{"open": [{"name": "Zed", "command": ["zed", "{path}"]}, {"name": "Finder", "command": ["open", "-R", "{path}"]}]}`. A message's menu then has Open in ▸ with those names, and picking one asks the daemon to save the message and run the command, detached from the daemon, since the console never spawns a process. Yi ships no app list of its own; with no `open` key the row is absent. A saved message is kept seven days, in a directory only its owner can read, and the launched app is waited on so the daemon keeps no zombie. The console reads the names when it starts, so a new app appears in the next console; the command itself is read again on every open.
