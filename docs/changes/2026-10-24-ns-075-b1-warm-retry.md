B1-warm-retry: a completed schema-bearing child validates the answer to its latest task or follow-up with the existing tolerant extractor and schema validator on both initial and resumed runs. One invalid answer per run earns a single tool-less retry carrying the validation error; Anthropic uses a cold request with its history serialized as text only when that history holds tool blocks. Tools, the original turn cap and warm in-memory history are restored before another prompt, and a second failure remains an `rlm.result` refusal. Ordinary and request mail keep their own prose answers without reopening the schema task, while `rlm.result` reads the task's answer rather than later mail. The sender-supplied `context_chars` exact totals and their wrong-shape refusal remain unchanged. A fence the tolerant parser already accepts triggers no retry. This widens #992 and uses the structured-output and cold-history forms recorded for D309 and D338.
