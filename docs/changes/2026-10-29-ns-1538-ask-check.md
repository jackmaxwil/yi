`yi ask --check CMD` (repeatable) makes a headless run answer for the work it claims to have finished. After each turn the command runs outside the session — though the goal loop's own check, off the runtime thread — and a red one re-prompts the same session with that check's output through the view a goal check already produces, then streams the next turn. The loop lives in a new `crates/cli/src/ask_check.rs`; `main.rs` is untouched but for the module line.

A rerun is skipped when the re-prompted run made no writing or executing tool call, read from the event stream rather than a tree hash because a check's own writes read as progress; that skipped rerun is counted red and as a wasted re-prompt, so a model that claims success twice for the same untouched tree costs one check run, not two. Each check's budget is the goal check's ten minutes cut to the time left before the run's deadline reserve.

Every ending prints one `[…]` row on stderr and, under `--json`, one `{"type":"check"}` line: green, the 4th red run after 3 re-prompts, the deadline reserve, a run that ended on an error, a deadline or a refusal, and a check that could not spawn or timed out. A released red exits 4, and the run's leftovers print once after the last turn, never between them. No goal is created.
