`yi ask --check CMD` (repeatable) makes a headless run answer for the work it claims to have finished. After each completed turn the command runs in the session's tool directory, though the goal loop's own check and off the runtime thread. A red one re-prompts the same session with that check's output through the view a goal check already produces, then streams the next turn. The loop lives in a new `crates/cli/src/ask_check.rs`. Every check is probed in the session's work directory before the session is recorded, so a refused run writes no session; `yi ask --check CMD` with no prompt claims the lane the run would and probes there, so both forms give one verdict. `main.rs` carries that prompt-less probe, the module line and the `work_dir` helper, which `build_session`, `shells.rs` and both probes share. A refused probe prints the same `error:` line and, under `--json`, the same `final` row as a refused prompted run.

The loop releases an already-ended run before it starts a check. Each check's budget is the goal check's ten minutes cut to the time left before the run's deadline reserve, and only a green check returns the turn's success exit code.

Every ending prints one `[…]` row on stderr and, under `--json`, one `{"type":"check"}` line: green, the 4th red run after 3 re-prompts, the deadline reserve, a run that ended on an error, a deadline or a refusal, and a check that could not spawn or timed out. A released red exits 4, and the run's leftovers print once after the last turn, never between them. No goal is created.
