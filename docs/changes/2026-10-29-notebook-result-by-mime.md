A notebook result was drawn as plain text whatever the kernel sent. The value's display bundle was read for its `text/plain` member alone, so a `text/markdown`, `application/json` or `text/x-python` representation was discarded before the pane could see it. The kernel now keeps the richest textual member of the bundle and names it beside the result (`result_mime` on `ExecuteResult`, `resultMime` in the cell's details), and the pane dispatches on that name through one table: markdown goes through the chat's own renderer, JSON is pretty-printed and highlighted and collapses past the 20-row cap with the same `[…]` row every other cut speaks, python is highlighted, and a mime no row names draws the text it already was. A bundle that declares JSON it cannot parse says so in one row instead of pretending to be a tree. Sessions recorded before this carry no mime and draw exactly as they did.

The size raises are the price of six contract tests at the console's test seam plus the renderer itself: the tests live in `crates/console/tests/notebook_mime.rs`, whose fixtures are the recorded sessions already in `crates/tui/tests/fixtures/sessions` (a 6,934-character markdown assessment and one kernel result's details). What was weighed and deleted first: `highlighted` merged into `capped` as a language argument, the four per-kind cap paths folded into `row_capped`, and a two-line doc comment in `crates/kernel/src/client.rs` closed onto one line to keep that file at its 1,000-line ceiling.
