Review correction: the Seen red entry for `every_result_kind_survives_an_empty_and_a_control_ridden_value` is withdrawn. That test guards control-character sanitization that predates this change, and its single-line fixture cannot produce the newline-picture failure the entry described. The new `a_result_value_that_looks_like_a_cap_notice_stays_value` regression uses a hand-written value whose last row begins `[…]`; against the unfixed predicate it failed with `the value's own row was not rendered as markdown`, because that row had become the pane's notice.

A notebook result was drawn as plain text whatever the kernel sent. The value's display bundle was read for its `text/plain` member alone, so a `text/markdown`, `application/json` or `text/x-python` representation was discarded before the pane could see it. The kernel now keeps the richest textual member of the bundle and names it beside the result (`result_mime` on `ExecuteResult`, `resultMime` in the cell's details), and the pane dispatches on that name through one table: markdown goes through the chat's own renderer, JSON is pretty-printed and highlighted and collapses past the 20-row cap with the same `[…]` row every other cut speaks, python is highlighted, and a mime no row names draws the text it already was. A bundle that declares JSON it cannot parse says so in one row instead of pretending to be a tree, and one Yi's own byte cap cut says the cap rather than claiming the value was never JSON. The mimes the kernel ranks by live in one const beside `ExecuteResult`, and the console's renderer table is keyed by the named consts, so a reorder cannot remap a renderer. The cell's result is that member for the model too (markdown source or re-serialized JSON, not the `text/plain` repr), which is deliberate: the repr of a markdown display is an object address. A member too large for the cell's char cap falls back to `text/plain` where the value has one, and with none the kernel's `[…]` cut row speaks. The byte-cap notice on a markdown result draws as its own muted row, not inside a table or fence. Sessions recorded before this carry no mime and draw exactly as they did.

The size raises are the price of six contract tests at each crate's own seam plus the renderer itself: the pane's tests live in `crates/console/src/panes.rs` and `crates/console/src/app/notebook.rs`, the kernel's in `crates/kernel/tests/reduce.rs`, and their fixtures are the recorded sessions already in `crates/tui/tests/fixtures/sessions` (a 6,934-character markdown assessment and one kernel result's details). What was weighed and deleted first: `highlighted` merged into `capped` as a language argument, the four per-kind cap paths folded into `cap_rows`, the console's duplicate mime list replaced by `RESULT_MIMES`, and a two-line doc comment in `crates/kernel/src/client.rs` closed onto one line to keep that file at its 1,000-line ceiling.
