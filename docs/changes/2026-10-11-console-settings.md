The console has a settings page (Closes #1252). ⌥, (or `ctrl+b ,`) or the gear in the sidebar's bottom row opens it beside the focused pane, as a pane like Review or the Tape, so it closes with its `✕` or ⌥x and can sit beside the chat it configures.

The Session tab lists the focused session's live options (model, thinking, permission mode); Enter picks a value and sends it to the worker at once, and `d` keeps the current value as the default. The Models, Permissions, Tools, Agents, Budget and Interface tabs hold every leaf of `~/.yi/config.json`, 43 rows in all, each with its key, a sentence of help and when a saved change applies: now, the next session, after a daemon restart, or only in the solo TUI. Enter flips a toggle from the value in effect (an unset toggle reads `on (default)` or `off (default)`), opens a choice list or a text field; `u` unsets a key. Lists and JSON values (`keys`, `routing`, `lanes.land`, `skills.global`, `node.isolation`) show only how many entries they hold and say to edit the file: the daemon never sends their text, since the owner once kept an API key under `keys`. A change saves at once through the daemon, which refuses an edit whole when it breaks the row's rule or the strict parse and leaves the file untouched; the pane says `saved` or `not saved:` and why. The Keys tab lists every chord with its ⌘ or ⌥ form and its `ctrl+b` letter, and replaced the keys overlay: ⌥? opens Settings on it.

Until now every Yi process read the config once and kept it, so a saved default reached nothing until the daemon restarted. A session now re-reads the file as it starts and re-derives the model and thinking level the command line did not pin, so a default saved here reaches the next session. The config writer moved out of `yi setup` into the runtime, under one lock with its own staging name; two saves at once each staged at one shared file and could clobber each other.
