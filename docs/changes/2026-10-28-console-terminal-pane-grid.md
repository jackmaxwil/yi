A terminal pane's shell owns the box it is drawn in. The pane sized the PTY from the framed reading margin that keeps every other pane a column clear of its border, so the shell believed it had two fewer columns than the frame showed: `stty size` inside a split pane said 43 where the pane drew 45, and a full-width program stopped short of the border on both sides. Terminal panes now take the border alone, which is the interior the pane paints into; every other pane keeps its margin, and a selection's drag still maps to the rows the pane draws. The `console_drive` terminal journeys that main's postmerge ran red are repaired with it: the resize journey passes, and its 43-against-45 width is this change's proof; the wheel journey compares the row its three-row notch reveals instead of a stale row number the frame never reaches, a repair that passes against the binary main already had too, since the notch it checks does not read this margin; and the close journey waits for the shell's prompt and types its command at a human pace, because a machine-speed burst fills the capped PTY write queue and the keys it refuses corrupt the command line. The stall journey is deleted: on macOS a PTY accepts a write the child never reads (16 MB measured before a byte is held back), so its "queue full" frame came from the drive's key burst outrunning the writer thread, a CPU race that flips with load and pins no state. The capped queue keeps its gate as a unit test that fills the 64-slot write queue behind `Pty::send` and asserts the next key fails with the notice the user sees.
