A strict ACP v2 client, one built on the upstream alpha.5 schema, can now use Yi, and a test holds every frame to that schema (Closes #918, Closes #927, Closes #928). `initialize` advertises `session: {delete: {}}` on the worker and the daemon; without it such a client reads Yi as having no sessions. `session/prompt` answers `{messageId}` once the prompt is inserted, the same id as its `user_message`, and a prompt still queued at close gets −32800. An edit's approval carries its diff as the `subject` tool call's content, with `add`/`modify` changes and a `git_patch`, where before it rode a root `content` field no spec client reads. A `resource_link` in a prompt reaches the model as its URI. Config options are flat (`type`, `currentValue`, `options`) and a write must say `type: "id"`. Session lists carry `cwd` and `title`. Yi's own fields (`replayedTo`, `name`, `attached`, `unseen`, `lastState`, `lastEventMs`, `createdAt`, `replayUpdates`) move under `_meta.yi`, and the resume result drops `sessionId`. Tool calls carry `name` and report `cancelled` for a stop, a failed turn's stop reason is `_yi/error`, a negative exit code is omitted, and tool status, tool kind and permission option kind decode unknown values instead of dropping the update. The console and its drive fixtures read the new shapes.
