Seven fixes from the tool-ergonomics proposals (docs/plans/2026-10-02-tool-ergonomics-proposals.md, R1 R2 R3 R4 R5 R7 R8), each seen red before its fix.

A red build keeps its error. Rustc diagnostics are recognised by their shape, whatever the command or exit status, and each error block survives whole with its `-->` location, warnings counted with three shown. A cut capture says `[capture cut: kept K of T bytes (OUTPUT_CAP 30000); every byte: <path>]`, and an omitted-lines notice counts lines of the file its pointer names. Before, a two-crate build's E0308 at byte 23920 of 48279 vanished under either exit status.

A background job the model already polled to its finished output is no longer announced again as an `<async_result>` a turn later. A question-child given no fenced material is told the message is its whole task, instead of being told to look for yi-external blocks that are not there; haiku had answered 2 of 6 plain JSON requests. "This task has outgrown one-shot handling; write the plan now." follows a failed check after an edit (`cargo test|nextest|clippy|build|check`, `just`, `pytest`, `make`, `npm test`), not a failed `pwd`; any other failure attaches the protocol silently. The unsourced-number check counts the environment block's date, model, cwd and branch as printed, never its counts or costs.

`rlm.find_models` returns each model's `cost` (`{input, output}` per million tokens) in registry order, and `rlm.status` returns each child's summed `cost` in USD; the prompts call cost one input to choosing a reader's model. The bash description drops the false claim that `x | head` exits 141, and the `&&` chain notice fires only when the command's last top-level operator is `&&`, so `true && true; false` no longer claims a skipped segment.
