A session holding a message whose content block or stop reason this build does not know now loads instead of being refused as an invalid file. Before, one `{"type":"audio"}` block or one `"stopReason":"pauseTurn"` inside a `message` entry failed the whole line, because only an unknown entry `type` decoded to `Other`; an older daemon reading a session a newer build wrote after a variant landed lost the session. `Content` and `StopReason` now carry an `Other` arm: a block keeps its object as written and a stop reason its string, so the file re-emits byte for byte, field order included, and a known tag that does not decode (a `text` block with no text) is still refused. A block of an unknown type reaches no provider: the shared history transform, and the Cursor prompt, put the notice row `[… 1 content block left out: its type is newer than this build; the session file keeps it as written, and a newer yi reads it]` where it sat, so the model knows something was there and never reads the block's own `type`, which is file text. The TUI and console transcript, a compaction summary's input and the context estimate read the same row; search, brief lines and the other text extractions skip such a block as they skip an image. An unknown stop reason reads as a turn that ended: the run ends as `stop`, ACP reports `end_turn`, and the history keeps the message. `StopReason` is no longer `Copy`.
