A session holding a message whose content block or stop reason this build does not know now loads instead of being refused as an invalid file. Before, one `{"type":"audio"}` block or one `"stopReason":"pauseTurn"` inside a `message` entry failed the whole line, because only an unknown entry `type` decoded to `Other`; an older daemon reading a session a newer build wrote after a variant landed lost the session. `Content` and `StopReason` now carry an `Other` arm: a block keeps its object as read and a stop reason its string, and both re-emit as serde_json writes them, field order included, the same canonical-JSON limit an unknown entry has (`1e5` comes back `100000.0`). A known tag that does not decode (a `text` block with no text) is still refused, and the error names the missing or mistyped field as it did before: `Content` and `StopReason` read the tag first and send only a tag outside their own set to `Other`. A block of an unknown type reaches no provider: the shared history transform, and the Cursor prompt, put the notice row `[… 1 content block left out: its type is newer than this build, which cannot read it; the session file keeps it as written, and no call here returns it]` where it sat, so the model knows something was there and never reads the block's own `type`, which is file text; the row names no fetch, because the model is shown no entry id to put in one. The TUI, console and ACP transcripts and a compaction summary's input read the same row; an explicit whole-entry read, `history://<agent>/<entry-id>` or `user://<n>`, returns the entry as written, block and type included, as it does an unknown entry. Search, brief lines and the other text extractions skip such a block as they skip an image. An unknown stop reason reads as a turn that ended: the run ends as `stop`, ACP reports `end_turn`, and the history keeps the message. `StopReason` is no longer `Copy`.
