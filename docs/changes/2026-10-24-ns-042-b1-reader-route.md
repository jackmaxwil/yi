This is Bet 1 item 1 of Yi's next shape (B1-reader-route): the Reader half of #937.

A plan delegation used to spawn as a full root child whatever it asked for, so a Python `Reader` declared through `plan.todo(delegate=Reader(partition=[...]))` was sent the root's whole prompt and tool table to answer one question. The engine's spawn mapping (`plan/spawn.rs`) now spawns a delegation as `role="reader"` when it reads only: its spec role is `reader`, its accept is not a command, it has no isolation, its tools are within `read` and `grep`, no context URL is `kernel://` or `family://` (a reader's partition refuses both), and no `local://` context names a directory (a reader's partition reads each entry as one file, so `Reader(partition=["local://crates/auth"])` keeps the root child that can list it). Such a child gets its context as its partition, fenced and numbered as its first message, and the prose `Context:` list leaves its brief. Its schema is inlined as the reader's `schema` kwarg: the declared output's schema read through the engine's output resolver, or else the contract's schema item read from the plan's artifacts, which is where Python's `contract(schema(...))` freezes it. The engine carries that schema from the spawn's start to the spawn mapping in the delegation's transient extras, the way it already carries the brief's lines; nothing of it is journaled. Every other delegation (a Writer, a worktree or container child, a command-accepted reader, one that names a kernel value or a directory) spawns `role="root"` as before. At reap the engine measures context relevance only for a root child: a reader's partition is inlined at spawn, so no fetch row in its transcript could show it was read, and measuring it told the parent its context went unread.

The change is in `plan/spawn.rs` (the routing test, the schema lookup, the brief and kwargs edits) `plan/dispatch.rs` (the schema carried from `ensure_spawned`, the routing decided once per spawn against the host's cwd) and `plan/acceptance.rs` (no relevance measure for a routed reader). YI_DESIGN.md section 11's child-spawn paragraph and the plan row of the ARCHITECTURE feature ledger say the same.

Kill tests, zero spend. (a) S0's per-role report gains a `plan_reader` row, measured from a Reader declared on a root's own plan tool and spawned by its engine: 802 + 3,869 = 4,671 B in every workspace, the same bytes as the bare reader row and under the 6,000 B kill line. Before this change the same row read 45,561 B bare and 93,453 B in a lane, the leaf root child's prefix. The row is reported, not gated: check_request_budget.py gates the five bare rows it names. (b) A plan Reader with review_pod's schema contract reached `done` with resolution `verified_done` on the first try, through the real finish and verify path, with no fix needed. (d) is paid and runs later in the measure lane (B1-exp-d).

The runtime crate grows by 108 lines against this PR's base: 77 of production code (the routing test, the schema lookup and the kwargs and brief edits in `plan/spawn.rs`, 10 lines in `plan/dispatch.rs` and 2 in `plan/acceptance.rs`) and a 31-line unit test inside `plan/spawn.rs` for the declared-output schema, which an integration test cannot reach because the lookup is private to the plan module. The plan estimated 45; the difference is that unit test, the two-source schema lookup and the directory and reap fixes a cold review found. Tests grow by 365 lines: the new `plan_readers.rs` (324: the accepted reader, which also asserts no relevance note reaches the parent, and one-bad-part spawns that cover every clause of the routing test), the `plan_reader` row and its assertion in `request_budget.rs` (33), a resolver and a context file for `judge::a_brief_naming_context_its_wall_denies_is_refused` (7), whose last spawn is a plan Reader and now fetches its context as a partition at spawn, and `node.rs`'s `git_repo` made crate-visible (1) so a worktree-isolated root child has a repository to branch.
