A model gateway that speaks the OpenAI chat-completions API is now a provider of its own. `providers.<id>` in `~/.yi/config.json` names its `api` (only `openai-completions`), its `baseUrl`, where its key is (`apiKeyEnv`, else a literal `apiKey` for a gateway placeholder that is not a secret, else `yi login <id>`) and its `models`, each needing only an `id`, with `name`, `reasoning`, `input`, `contextWindow`, `maxTokens` and `cost` optional. A model of one is addressed `<id>/<model>` like any other. The declared models merge after the bundled catalog and the refreshed cache, so `yi catalog refresh` neither rewrites nor drops them and never fetches a custom provider. Requests go through the OpenAI completions adapter at the declared base URL with plain `max_tokens` and none of OpenAI's own fields. An id a built-in provider, `laya` or `faux` already holds refuses when the config loads, naming the id, and an `api` other than `openai-completions` refuses naming the accepted value. A provider with no key anywhere gets the same missing-credential refusal as a built-in one. `yi doctor` has a `providers` row naming each one, its model count and base URL, and where its key resolved.
