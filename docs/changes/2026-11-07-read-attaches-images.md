`read` on an image refused it and pointed at `attach_image`, so the model spent a kernel round trip on every picture and the user saw a failed read. An image the provider takes now comes back as the image itself, under one line naming its type, pixel size and byte count, and carries the same `attachmentMedia` row an ipython attachment does, so reclaim can cut it to a re-attach once it ages (Closes #2093). An image the provider would refuse keeps a refusal: one past a limit names `attach_image`, which resizes it, and a BMP names the re-encode, both as one cell with the file's path; a non-vision model is handled by the request-side downgrade that already turns tool images into a placeholder.
