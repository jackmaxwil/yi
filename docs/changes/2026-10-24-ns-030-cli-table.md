The units in this change are E-cli-tidy, E-cli-table and E-cli-refuse.

E-cli-tidy moves the shared argument parser (`Args`, `Resume`, `parse_args` and its two value parsers) out of crates/cli/src/main.rs into crates/cli/src/args.rs, and turns code that was repeated into one function each. The runtime builder that printed `error:` and exited 1 was written out six times, the session repository for the run's directory five times, the one-line JSON printer six times, the `--schema` load twice and the pinned `laya[serve]` package twice. Two behaviours change. `yi serve` now returns exit 1 when it cannot build its runtime, instead of calling `process::exit` inside a function that returns an exit code. The resume hint and the lane line printed at quit are dimmed only when stderr is a terminal, so a script that captures stderr gets plain text with no escape bytes.

E-cli-table adds crates/cli/src/commands.rs, one table of the 28 verbs (name, the function dispatch calls, the words it takes, a one-line summary) and the 32 flags (name, value hint, summary). `dispatch` looks the first word up in the table instead of a 28-arm match, so the help text and the routing cannot disagree, and the parser refuses a flag the table does not hold, so neither can the help text and the parser. The six verbs answered before the shared flags parse (update, plugin, login, logout, setup, mcp) are rows too; reached only when another word came first, they now exit 2 asking for the verb first, where the words used to go to the model. `yi --help`, `yi -h` and a bare `yi help` print both tables and exit 0; `yi help me debug` is still a prompt. The completion files under completions/ named 10 of the 28 verbs and 16 of the 32 flags; they now name all of them, and a test fails when they drift from `yi --help`. docs/YI_DESIGN.md section 17.1 loses its "there is no `--help`" line.

E-cli-refuse adds three refusals on the table, each exiting 2 and naming the call that does what the person meant. A verb that reads no words (version, rpc, acp, doctor, gc, serve, console) refuses trailing ones, and `undo` takes only `list`: `yi undo the last edit` used to restore the last turn's files and ignore the sentence, and now prints ``error: `yi undo` takes only `list`; to ask the model: yi ask undo the last edit``. A single word that is not a verb but sits one edit from one (four or five letters; two edits from six letters on; never below four) is refused with `error: did you mean "doctor"? to ask the model: yi ask doctr`, where `yi doctr` used to pay a model turn; two or more words, or a word far from every verb, still ask, and on a terminal still open the TUI. `yi console` (bare `yi` on a terminal included) and `yi serve` refuse `--thinking`, `--system`, `--schema` and `--deadline`, which they never hand a session (`serve_flags` forwards only the model, the session directory and the mode), naming the config key or the verb that reads it; a headless console drive still takes `--deadline`, which it reads. docs/YI_DESIGN.md section 17.1's first row now says so. Refs #1270, #1273.
