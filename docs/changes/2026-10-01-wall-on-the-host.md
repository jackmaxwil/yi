A walled session's commands that run on the host meet the wall's roots, and its kernel never runs unconfined (Closes #1001). A heartbeat's `exec://` source, which runs `sh -c` on the host on its cadence, was judged only by the permission broker; it now meets the same wall as an armed todo address: the wall's command-text check and its walled roots. A walled session's bash call that runs outside the sandbox, because an approval, a rule or yolo sends it there or because Linux has no Seatbelt, is refused when it names a spill root, a session store or a directory above one, quoted, escaped or by `~`, `$HOME`, a glob, `..` or a link; its own spill dir and transcript still read. Its contained calls no longer spare its own spill dir or transcript when the wall itself names a folder above them, so a glob or `/./` spelling the text check misses cannot reopen them. On Linux a walled session's kernel is refused before it boots, with a message naming the missing sandbox, so a walled session (every reader, a juror, a walled plan worker) has no ipython there; read, grep and bash still work.
