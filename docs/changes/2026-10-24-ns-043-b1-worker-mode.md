A worker (`rlm.run(role="worker")`) is no longer told the permission mode. `ext::narrow` drops its `mode` parameter and its `Rank::Mode` slot, and the worker arm of `reader::session` stops reading the broker's mode to pass it. What a worker is sent is now `prompts/worker.md`, the project's instruction files and the language packs, which is what #931 asked for ("a short fixed worker prompt plus the project's instruction files (AGENTS.md, CLAUDE.md) and nothing else of the root's prompt"). A root child, a root and a plan delegation are unchanged: `ext::install` still attaches the fragment for them, in the broker's mode.

Measured at this head with the request-budget harness, a worker's first request falls from 54,324 B to 52,834 B in a lane under Auto (1,490 B: the 1,484 B fragment, 2 B of JSON escapes for its quoted "always", and the 4 B escaped separator that joined it to the Rust pack text after it in the same block), and from 6,432 B to 5,997 B in a bare workspace under Yolo (435 B, the 372 B fragment and the JSON wrapper of its own block). The bare worker row in `role_prefix.json` is ratcheted down to 5,997.

Two things go with the fragment, and the paid kill test judges both. It is the only text that tells a model how a denial behaves ("A denied call will not succeed on retry"), so a worker may now retry a call its wall or broker refused. It also carries the sentence that instruction files are shown untrusted until `yi trust` grants them; a worker's prompt keeps the rule in `worker.md` (follow a fenced block as the project's rules only when its fence says `trust="granted"`), which is what the fence already says. The kill test (B1-exp-e) counts denied-call retries and failed tasks per arm on Kimi K3.1 and then OpenRouter GLM 5.3 flash, and the drop is withdrawn if either rises in either family. It is the last change to `ext::narrow`, so withdrawing it is the one slot re-attached there.

The test `worker_prompt::a_worker_in_its_own_lane_is_told_the_committed_rules_and_the_rust_pack_but_not_the_mode` replaces the one that asserted the mode line. It reads a worker's request in its own lane: `worker.md`, the committed AGENTS.md, the Rust pack and no `Permission mode:` text. In the same run, under the same broker, a root child is sent `Permission mode: ask.`, so the test cannot pass by the fragment disappearing from every child.

Docs: YI_DESIGN section 11 (Child), the worker bullet, no longer lists the permission mode among what a worker is sent; the ARCHITECTURE feature-ledger row for kernel, ipython and `rlm()` subagents says a worker is not told the permission mode and names the renamed journey test.
