The classifier now runs on TypeSafe's Jev through OpenRouter. `yi setup` saves `models.classifier: typesafe/jev-1.13` once an OpenRouter key exists and saves nothing without one; nothing is installed and `yi serve` starts no sidecar. A `models.classifier` that still names a retired Laya checkpoint (`english`) loads but does not run, and the refusal names `typesafe/jev-1.13` as its replacement: repointing it would bill a remote model the owner never chose. A configured `classifier.url` is honoured only at the provider's own host over TLS or on this machine, so the account key cannot reach a third party, and `yi setup` clears the Laya era URL it used to leave behind. `yi doctor` asks the endpoint one question with a short deadline and reports a dead one instead of a green row over an unreachable host; the row says that typed messages, judged commands and the working directory leave the machine. Jev's `choice` answer carries `probabilities` and `confidence`; the skill pointer reads the chosen option's probability when `answer_confidence` is absent. The approval question is the V2 question the measurement scored, each value capped at 1000 chars with the shared `[kept … cap …]` row naming the cap, and a recent call sent as its bash command or its tool and path, never the file body it carried and a judged command past 4000 chars left to the person. Approval allows at 0.8 (`allowAt`) and 0.9 for a destructive command (`allowDestructiveAt`). An unreachable endpoint keeps the breaker: skill pointers fall silent for 60 s and approval falls to the reviewer or the person. `LAYA_API_KEY` and the minted `laya` key are gone.
