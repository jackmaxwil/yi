The runtime's two remaining silent cuts are named (unit CAPS-runtime, finishing what 0.753.0 left open on #1487). A `rlm.find_models` search that matched more than `limit` already produced a `[… kept of total matching models (limit N); the rest: await rlm.find_models("", limit=T)]` row in the host reply, and the `rlm` shim read only `models`, so the row never reached a cell and the model saw a short list with nothing to say it was short. The shim prints the row now, and its docstring says the list it returns is at most the `limit` asked for.

A variable the snapshot left out came back as silence. The snapshot has always counted its skips (`KernelSnapshotResult.skipped`: over the 16 MiB per-variable cap, over the aggregate cap, or unpicklable), but only the snapshot's own marker line saw them; the resume read an index that no longer held the name and said nothing, so a revived kernel's notice claimed a namespace it did not have. The skip list now rides the index itself under a `_skips` key — the loops skip every name starting with `_`, so it cannot collide with a variable, and one write commits the names and the skips together instead of a second file that could describe a snapshot that never landed. The restore normalises each entry to `{name, reason}` with a string reason, so a stored shape cannot make the marker line undecodable and blank the revive notice, then appends those names to the `failed` names it reports. The notice names each one, cut at `RESTORE_FAILED_SHOWN` with a row naming the index read that holds the rest.

No type changed: `KernelSnapshotSkip` already says "one name the snapshot/restore helpers could not process, with a short reason", so a name the snapshot skipped is a name restore did not produce.
