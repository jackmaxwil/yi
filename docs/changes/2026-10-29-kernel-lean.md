The kernel holds less and does less per cell. It launches with IPython's output cache off (`--InteractiveShell.cache_size=0`), so a value shown as a cell's last expression is freed by `del`, and Yi's own snapshot and listing cells no longer store history, so `In` grows by one per model cell. The debounced snapshot after a clean cell re-dills only what the cells since the last pass could have changed: a name assigned, mutated through an attribute or subscript, or passed to a non-builtin call (and the globals a function named there reads), plus any name sharing an object with one of those; every other variable whose id, type and size are unchanged keeps its last blob. Every 20th cell and the final flush stay full passes. A read-only `print(len(x))` over 60,000 grep-hit dicts took 145, 170 and 20 ms against 8.6 to 35.8 s for a full pass in the kernel venv. Compaction no longer deletes a variable over the 16 MiB per-variable cap, which was its only copy: it stays live and unsaved, and `KernelManager::prune_oversized_variables` is gone, along with the `Out` chase it needed. The bootstrap's names (`fetch`, `bash`, `yi` and the four Python skills) join the snapshot's and the listing's skip set, so a fresh kernel's compaction note says it has no names yet, and that note lists at most forty names with a `[… 40 of N names (NAMES_SHOWN 40); the rest: %who]` row. `python/yi_runtime/uv.lock`, which nothing in the unpacked runtime reads, is left out of the embedded archive, cutting the deflated Python stream from 90,705 to 59,536 bytes. The plugin-installer code (`pinned`, `tarball`, `uv_install`) moves under `crates/kernel/src/install/` and `civil_from_days` to `date.rs`, re-exported at the old paths. The builder-path fallback in `python_root` the issue names was already gone on main (it falls back to `/nonexistent/yi/python`).
