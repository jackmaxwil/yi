A root child that cannot spawn is no longer registered for the orchestrate protocol. `ExtOptions` gains `can_delegate`; `ext::install` registers the `orchestrate` extension only when it is true. The root (`session_extensions` in the CLI) passes true, and `child_factory` passes `depth + 1 < max_depth`, which mirrors the depth refusal in `SubagentHost::spawn`. At the default `max_depth` of 1 every root child is a leaf, so a brief that tripped the trigger (the word "orchestrate", or a prompt the router scores Complex) used to attach the 11,222-byte protocol to a session that could never spawn. A leaf's bare first request falls from 57,052 B to 45,561 B when its brief triggers the protocol, a drop of 11,491 B; an untriggered leaf was already 45,561 B and is unchanged. The router's `route` record for a leaf's prompt is no longer written, because the extension that wrote it is not registered. The same extension's one nudge goes too: a leaf no longer reads "This task has outgrown one-shot handling; write the plan now.", which the protocol sent after an edit to a file not yet read and after a failed check that followed an edit. The plan tool stays available to a leaf as a todo list.

A fork gets no exemption. The strategy kept the protocol for a `fork=all` child only if its request prefix were its parent's, which would let the fork share the parent's cache. Measured at this head with a `yi ask` root and a `fork=all` root child: the system blocks differ (32,803 B against 30,709 B, first difference at byte 29,739, where the root's unattended fragment sits) and the tool tables differ (17,673 B against 15,181 B), and the tool table comes first in a request, so the fork shares no prefix with its parent whether or not the protocol is registered.

A leaf root child is also no longer taught to delegate. The delegation teaching moved out of `doctrine.md` and `identity.md` into a new `prompts/delegation.md`, which `ext::install` attaches as the `delegation` slot at the Doctrine rank only when `can_delegate` is true. It holds the identity bullet on RLM subagents, the working model's intro and its rules on solo work, readers and writers, the reader wall, the flow, ownership and waiting, and data in kernels, with the closing `rlm.run` example, and Planning's first two sentences. The identity example now shows `rlm.ask(q, [url], schema=SCHEMA)`, the common case, instead of a full `role="root"` child. The kept text is the working model's "Bash or the kernel" rule, now under its own heading, and the rest of Planning (ground unknowns by exploring, never invent a schema). The delegation rules are renumbered one to five. A leaf's bare first request falls from 45,561 B to 41,738 B, a drop of 3,823 B; a leaf whose brief trips the orchestrate trigger falls from 57,052 B to 41,738 B in all. The root's prompt carries the same text in a new order and with two new headings, so its bare first request grows by 45 B (50,233 B to 50,278 B), and the request budget rises with it. The order within the Doctrine rank is by slot name, so `delegation` sits after the identity sections and before `# Operating doctrine`. A session resumed from an older snapshot restores its old prompt whole, which still carries the teaching inline.

Three pointers to delegation stay in the text a leaf reads, left as known residue for a follow-up under #1442: Method step 4 (Ground) names "readers when the questions outnumber the turns", step 5 (Plan) lists "delegation" among the reasons to plan, and `identity.md` describes `plan` as "the delegation ledger ... for work you hand out". Each sits in a sentence that also carries text a leaf needs, so moving one rewrites the root's bytes as well; what they point at, the rules for readers and writers, is what moved. A leaf that follows one is refused with "RLM recursion depth limit reached", as it was before this change.

Docs: YI_DESIGN section 6 (Prompt) says `ext::install` attaches `delegation` and registers `orchestrate` only for a session that can delegate, and section 11 (Child) says what a leaf is.
