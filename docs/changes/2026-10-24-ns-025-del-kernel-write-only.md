The kernel stops writing five things that nothing reads. Every host request used to carry a `cellSourceCode` key holding the source of the running cell, or of the last user cell for a detached task; no host handler reads it, so the key, `KernelManager::last_cell_code` and the `CellState.code` field behind it are gone, and a handler now receives the payload exactly as the cell sent it. Each snapshot used to write a `<id>.kernel-state.json` manifest beside the `.dill` index, listing the saved names, the skipped names, the byte count, the Python version and a timestamp; the only reader was `snapshot_e2e`, and the marker line the kernel prints after every snapshot already returns the saved, skipped and pruned names, so `KernelSnapshotConfig.manifest_path`, `snapshot::manifest_path_in` and the manifest block of the generated program go, and `yi_runtime::kernel::snapshot_paths` becomes `snapshot_path` because it now names one file. The `YI_ORPHAN_JOURNAL` pid journal (`journal.rs`, the `child_pid` slot and the `kill_confirmed` flag that fed it) was written only when that variable was set, and nothing sets it; its row leaves `env_vars.json` in its own Ratchet commit. The bootstrap lock's stale-pid helpers (`lock_is_stale`, `read_lock_pid`, `lock_missing_pid_is_stale`) have not guarded a lock since the flock replaced the pid file, and had no caller but one test; `process_is_running` and `remove_stale_venvs` stay, with their real users. The `RLM_DEPTH` and `RLM_MAX_DEPTH` environment the runtime set on every kernel is read by no Python, because the host-side depth check decides, so it goes too; the model-facing refusal text that names both is unchanged.

A session's `kernel-state.json` already on disk is left where it is and nothing reads it; a continued session still finds its `.dill` index and blobs. `crates/kernel/src/client.rs` drops from 1,140 to 1,106 lines. `docs/YI_DESIGN.md` section 9 loses the manifest from the snapshot line and the two unread variables from the kernel env line.
