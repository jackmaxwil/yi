This is the harness for EXP-B3c (X-B3c), the experiment that decides whether a headless run should have the host enforce the checks the model declared. The question is how often a run stops while its own last check still prints FAIL.

evals/stops_on_fail.py reads a session file, or every session under a run directory, and prints one row per root session with its task, its stops and the stops taken over a FAIL. A child's session is skipped. A stop is the end of a turn: an accepted `answer`, or else the turn's final reply. A held answer is not a stop, and a reply after an accepted answer is not a second one. A FAIL line is the verifier shape unattended.md asks for, `FAIL <requirement>` at the start of a line of the last ipython cell's stdout, so `FAILED to import` is not one. The fixtures are two sessions the real binary wrote under faux/faux-1 and scrubbed with `evals/record.py --scrub-only`. Each runs two cells and then replies. One ends on `FAIL R2` after an all-PASS cell, the other the reverse, so a counter that reads any cell but the last gets both wrong. No TB task text or transcript is committed.

evals/kill/x-b3c.py is the experiment's kill-test module, ladder step 6. It runs main's binary on the 12-task slice in evals/drivers/tbv4_slice.txt, one fresh trial per task, on Kimi K3.1 and then z-ai/glm-5.3-flash, through `tbv4_sweep.sh --runner` with inference-net excluded. A task counts when any stop in its root session was taken over a FAIL. The verdict is KEEP when that happens in at least 2 of 12 tasks on each family, and KILL otherwise. It reads UNRESOLVED while a family has not finished all 12, with each family's count either way. `--check` survives either verdict. Today kill.py writes a harbor run on the Kimi subscription unrun, because a sweep spends OpenRouter on its own model and the TB container has no Kimi credential. So the Kimi family reads unrun and the verdict stays UNRESOLVED until the sweep can carry a Kimi route. The paid run belongs to the measure lane and does not run here, so evals/trials/ns-x-b3c.jsonl is written by that run, not by this change.
