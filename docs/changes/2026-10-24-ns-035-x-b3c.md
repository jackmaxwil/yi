This is the harness for EXP-B3c (X-B3c), the experiment that decides whether a headless run should have the host enforce the checks the model declared. The question is how often a run stops while its own last check still prints FAIL.

evals/stops_on_fail.py reads a session file, or every session under a run directory, and prints one row per root session with its task, its stops and the stops taken over a FAIL. A child's session is skipped. A stop is the end of a turn: an accepted `answer`, or else a reply that stopped with nothing after it but host notes before the next typed message or the end of the file. So a stop the host sent back, as the todo intercept does when todos are still open, is not taken, and the one that finally stands is. A held answer is not a stop, and a reply after an accepted answer is not a second one. A FAIL line is the verifier shape unattended.md asks for, `FAIL <requirement>` at the start of a line of the last ipython cell's stdout, so `FAILED to import` is not one. The fixtures are three sessions the real binary wrote under faux/faux-1 and scrubbed with `evals/record.py --scrub-only`. Two run two cells and then reply. One ends on `FAIL R2` after an all-PASS cell, the other the reverse, so a counter that reads any cell but the last gets both wrong. The third sets todos, stops over `FAIL R2`, is sent back by the todo intercept, runs an all-PASS cell, marks a todo done and stops again: one stop, none over a FAIL. No TB task text or transcript is committed.

evals/kill/x-b3c.py is the experiment's kill-test module, ladder step 6. It runs main's binary on the 12-task slice in evals/drivers/tbv4_slice.txt, one fresh trial per task, on Kimi K3.1 and then z-ai/glm-5.3-flash, through `tbv4_sweep.sh --runner` with inference-net excluded. A task counts when any stop in its root session was taken over a FAIL. The verdict is KEEP when that happens in at least 2 of 12 tasks on each family, and KILL otherwise. KILL is read as soon as one family that finished all 12 is under 2, because KEEP needs every family. Otherwise it reads UNRESOLVED while a family has not finished all 12, with each family's count either way. The sessions are read from the harbor job directories this sweep filed trial rows from: trials.py files each row with its `job`, and kill.py's harbor row names the jobs of the rows its own sweep appended, so a re-run under the same run id reads each task's latest sweep and never sums two. A sweep refused before harbor starts files no rows and names no job, and that family reads 0 of 0. `--check` survives either verdict. Today kill.py writes a harbor run on the Kimi subscription unrun, because a sweep spends OpenRouter on its own model and the TB container has no Kimi credential. So the Kimi family reads unrun, and until the sweep can carry a Kimi route the verdict is KILL or UNRESOLVED, never KEEP. The paid run belongs to the measure lane and does not run here, so evals/trials/ns-x-b3c.jsonl is written by that run, not by this change.
