The size gates read the change files once per run instead of once per question. `pending()` in check_changes.py listed the fork's change files with one `git ls-tree` for every file it looked at, and the size gates ask it once per crate or raise key, so check_crate_size.py alone spent 68 s on 187 change files; the listing is now read once a process and the scan is memoised, and the same script runs in 0.4 s. check_commit_style.py drops a subject-rule exclusion whose commit main has long held and its private copies of the shared `git` and fork helpers. `just check --quiet` prints one line on a green tree and only the failing lane's output otherwise, with the same exit code, and `just guardrails --quiet` does the same for the guardrail gates. The program-values tests cut at a lowered fuse that a tool call now carries in its context, so the same cut texts are asserted against about 3 MiB and 101 files where they wrote 197 MiB and 100,001 files and took 39 s. The read gate's open, write and remove take a hold run between the judgement and the act, so a link swapped into that window is now forced on every test run rather than raced by a thread for up to 20 s. The injection canary's marker and the deadline test's sleeper carry the process id, so two suites at once no longer read each other's files or processes. This PR bundles the units HD-G01-gate-speed and HD-P03-slow-and-global-tests.
