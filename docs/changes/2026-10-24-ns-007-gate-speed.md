The size gates read the change files once per run instead of once per question. `pending()` in check_changes.py listed the fork's change files with one `git ls-tree` for every file it looked at, and the size gates ask it once per crate or raise key, so check_crate_size.py alone spent 68 s on 187 change files; the listing is now read once a process and the scan is memoised, and the same script runs in 0.4 s. check_commit_style.py drops a subject-rule exclusion whose commit main has long held and its private copies of the shared `git` and fork helpers. `just check --quiet` prints one line on a green tree and only the failing lane's output otherwise, with the same exit code, and `just guardrails --quiet` does the same for the guardrail gates. This PR bundles the units HD-G01-gate-speed and HD-P03-slow-and-global-tests.
