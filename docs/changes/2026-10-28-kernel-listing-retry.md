The kernel's namespace query answers on a second attempt instead of reporting no names. `Snapshot::list_namespace_names` is a read of a live namespace, and a listing that arrives while the kernel is busy spends its five-second budget waiting for the queue rather than listing: it came back empty, the caller read that as "this kernel has no names", and gate run #94 reddened `yi-kernel::kernel_e2e prune_removes_oversized_variables_and_list_names_reports` on a tree that touched nothing under `crates/kernel`. It now makes up to two bounded attempts under one deadline of `LISTING_ATTEMPTS` times the 5 s listing budget, each attempt capped at that budget, and only a kernel that misses both reports no names. Every attempt's reason reaches the kernel diagnostic, tagged with its attempt, so a first-attempt timeout and a different second-attempt failure both survive to the line; an aborted attempt that carried no stderr or error is named for what it is, a timeout spent waiting on the execution queue, rather than printing an empty detail — that naming lives in `cell_detail`, so the snapshot, restore and listing diagnostics all read it. The retry is opt-in per caller: `list_namespace_names_once` runs one attempt, and that is what `crates/runtime/src/kernel.rs` pays inline after every non-aborted user cell, so the per-cell stall keeps today's bound of one 5 s budget plus one `KERNEL_ABORT_GRACE_MS` (1 s) grace. A caller that can afford the second chance (`sync_after_compaction`, the restart note, the e2e journey) gets two attempts under the single 10 s deadline. On that retrying path a hung kernel costs up to 10 s of attempt budgets plus one grace against the 5 s plus grace it cost before; a contended kernel whose first attempt is interrupted and whose second succeeds pays the second attempt's wait, which `execute` charges inside that attempt's own budget. The retry starts after the first attempt's abort has interrupted the stalled cell, so it measures a settled kernel when the slot did free. Run #95, the identical tree, was green, which is what made this a gate flake rather than a regression.
