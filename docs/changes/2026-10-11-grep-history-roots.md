`grep` now searches transcripts as well as files (Refs #1184). With `path` set to `history://self`, `history://parent`, a child's name or `history://repo`, it matches the pattern against every line of that transcript's messages, tool output and summaries, and each hit is a row `history://<agent>/<entry-id> #<seq> <kind>: <line>` that `read` opens whole. `history://repo` walks this repository's other root sessions newest first, leaving out the searching session, whose own messages name the pattern. The root goes through the same alias rewrite and wall checks as `read`, and `repo` is refused under any wall that denies history, since it would reach a walled transcript by another spelling. Every cut is named where it is made: 40 hits a page with the offset that continues, a hit line cut at 200 chars, session files that could not be opened, and a zero-hit search that says how many entries it read. `literal`, `ignore_case` and `offset` keep their file-grep meaning, and a file-only option such as `include` is refused by name. The compact `since/` and `tail/` views kept only the first line of a multi-line entry and did not mark the cut: a child read a 301-line bash result as `setting_000 = fb3f5c`, answered with that, and was wrong. A dropped line now counts as a cut: the line ends `… (+N lines)` and carries its whole-entry address. A root session that asks for `history://parent` is told that `grep`'s `history://repo` searches its past sessions. The `search` skill's table names the three roots. Paired on GLM 5.3 flash, k=3, graded on the acting agent's answer, with a fact printed only in a tool result: a child finding a line of its parent's output went from 16.0 calls and $0.0135 a run on main to 5.3 calls and $0.0106, and a session finding an earlier session's output from 11.0 calls and $0.0061 to 6.0 and $0.0034, with every run passing in both arms. The cut-line fix alone measured 7.3 calls and 2/3 on the first task, and 6.0 calls and $0.0077 on the second.
