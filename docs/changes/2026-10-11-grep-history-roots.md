`grep` now searches transcripts as well as files (Refs #1184). With `path` set to `history://self`, `history://parent`, a child's name or `history://repo`, it matches the pattern against every line of that transcript's messages, tool output and summaries, and each hit is a row `history://<agent>/<entry-id> #<seq> <kind>: <line>` that `read` opens whole. `history://repo` walks this repository's other root sessions newest first, leaving out the searching session, whose own messages name the pattern. The root goes through the same alias rewrite and wall checks as `read`, and `repo` is refused under any wall that denies history, since it would reach a walled transcript by another spelling. Every cut is named where it is made: 40 hits a page with the offset that continues, a hit line cut at 200 chars, session files that could not be opened, and a zero-hit search that says how many entries it read. `literal`, `ignore_case` and `offset` keep their file-grep meaning, and a file-only option such as `include` is refused by name. The compact `since/` and `tail/` views kept only the first line of a multi-line entry and did not mark the cut: a child read a 301-line bash result as `setting_000 = fb3f5c`, answered with that, and was wrong. A dropped line now counts as a cut: the line ends `… (+N lines)` and carries its whole-entry address. A hit inside an assistant's tool call is labelled `call <tool>`, so a pattern the agent passed to its own call never reads as output; a session directory whose checkout is gone is counted in a row, not skipped silently. A root session that asks for `history://parent` is told that `grep`'s `history://repo` searches its past sessions. The `search` skill's table names the three roots. A root takes `read`'s window after the agent (`history://parent/since/0`, `tail/<n>`, or an entry id), resolved by the same agent walk and window grammar `read` uses, and a selector that names no entry is refused as `read` refuses it rather than answered as zero hits: two children in the paired run copied the brief's `since/0` address into grep, were told no such agent existed, and gave up. A spawned child's brief now ends its address line with `· one line of it: grep with path=history://parent`. `history://repo` loads one session at a time. A spawned child is refused `history://repo` with a pointer to its parent, which searches past sessions for it, instead of being served an empty search or another root session. Paired on GLM 5.3 flash, k=6, graded on the acting agent's answer, with a value printed only in a tool result: a child finding a line of its parent's output passed 5/6 on main in 12.3 calls at $0.0101 a run, 6/6 with only the cut-line fix in 7.0 calls at $0.0055, and 6/6 with this change in 6.8 calls at $0.0048, every run calling the history grep; without the brief pointer the grep was chosen in 4 of 12 runs. A session finding an earlier session's output passed 6/6 in every arm, at 7.0 calls and $0.0066 on main and 5.2 calls and $0.0053 with this change. A `history://repo` grep over 215 real sessions (3,007 entries) costs about 0.65 s over a file grep.
