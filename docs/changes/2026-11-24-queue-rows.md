The merge queue's tick can now do, from the forge, three things only the owner's Mac did: add a clean, green pull request to the queue, take a clean, green draft out of draft, and move a stacked pull request to main once the pull request of the branch it was based on has merged into main. Each is the act of one row in the tick's state table. A new repo variable `QUEUE_ROWS` switches them: `off` (the default), unset or any other word computes nothing and makes the same forge calls as before; `shadow` records each decision as one `yi/would` check result on the pull request's head and writes nothing else; `on` also acts. An act re-reads the head it judged and skips a pull request whose head moved, every forge API call on the rows' path carries the tick's 60-second timeout, and a second tick repeats nothing.

A person's state is never acted on. The row enqueues only pull requests opened by the owner's login, and never one labelled `autofix:hold` (state `held`) or `external` (state `external`), one whose `queue` label a merger last took off with no push since (`taken out of the queue`), one the queue ejected since its last push and gate result (`ejected`), or one whose diff touches the workflows, the git hooks or a bot script (`changes the bots`): landing that deploys it, so it still needs the owner's own label. A held pull request that already carries `queue` reads `queued`. A draft is promoted only if no title edit made it a draft (`drafted by a person` otherwise); the bot never makes one. A child is re-pointed only when its base branch's pull request in this repository has merged; a parent closed without merging, a deleted or live branch with no pull request, or an unreadable answer reads `based off a closed branch`, waiting on a person. A refused re-point is said in one comment per head, and the row never closes and reopens a pull request. A `queue` label the bot itself adds counts only while `QUEUE_ROWS` is `on` and the row would add it at that moment; a failed read of it counts as no consent and leaves the other queued pull requests alone. The table's last row, `unknown`, has no act: no combination of facts reaches it.

Under `on` only, the queue tick and the fixer's pass each read the other's job records after their own work and keep one issue open while the other has failed three times running or not run for 165 minutes, closing it once it runs green. The issue carries `area:forge-ci` and no size or milestone, and the tracking hygiene check skips such an issue the bot opened. `just pr parked` opens with the age of the last successful queue tick.
