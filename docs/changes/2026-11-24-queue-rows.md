The merge queue's tick can now do, from the forge, three things only the owner's Mac did: add a clean, green pull request to the queue, take a clean, green draft out of draft, and move a stacked pull request to main once the branch it was based on has merged, closed or gone. Each is the act of one row in the tick's state table. A new repo variable `QUEUE_ROWS` switches them: `off` (the default) computes nothing, `shadow` records each decision as one `yi/would` check result on the pull request's head and does nothing else, and `on` also acts. An act re-reads the head it judged and skips a pull request whose head moved, and a second tick repeats nothing. The row enqueues only pull requests opened by the owner's login, and a `queue` label the bot itself adds counts only while `QUEUE_ROWS` is `on` and the row would add it at that moment. A pull request that matches no row gets one comment per head saying so. Unless `QUEUE_ROWS` is `off`, the queue tick and the fixer's pass each watch the other's job records and keep one issue open while the other has failed three times running or not run for 45 minutes, closing it once it runs green. `just pr parked` opens with the age of the last successful queue tick. The `held` state now applies only where the fixer would otherwise own the pull request, so a held pull request that is clean and queued reads `queued`.
