A `yi ask` run with nobody attached (no terminal on stdin, so no asker) is now told so (Refs #1315). Its system prompt gains an `unattended` fragment: nobody answers a question, checks it cannot see grade the result against the task's own text, so it lists every stated or implied requirement as a todo, gives each a check, and before stopping runs one cell that prints PASS or FAIL per requirement, stopping only when every line passes or the deadline leaves time only to report. A new bundled skill, `unattended`, carries the requirement checklist and the verifier cell. An rpc or acp client's session, and the TUI's, are not told this. The doctrine's "bash or the kernel" item adds one trigger: a check over many requirements, or a transform over many files, is one cell. Skills written for Yi's own repository (`gate`, `land`, `pr-review`) carry `within:` and are listed only in a repository holding the path they name, so other repositories' catalogs no longer offer this one's recipes. The harbor adapter stops a trial whose kernel failed to boot on a toolchain that is present, so a broken install is an environment failure rather than a scored zero; an image with no toolchain still runs bash-only. Harbor trials now carry the arm's bundled `skills/yi` tree (`EVAL_SKILLS`, else the checkout's own), as a real install does after `yi update`: the binary embeds only the kernel's own skills, so every earlier Terminal-Bench trial ran with no `plan`, `verify`, `debug` or `kernel` skill, and the trial fingerprint now names the tree it carried.
