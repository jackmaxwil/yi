This PR fixes the plan tool in six units, in commit order: HA-PLAN-arms, HA-PLAN-errors, HA-PLAN-oneparse, CAPS-plan, HA-PLAN-report and HA-PLAN-label.

HA-PLAN-arms. A plan row blocked on an `exec://` wait arms a shell command that later runs on the host, outside any sandbox. The plan tool's `arms` read only a top-level `on`, so the row form its own schema documents, `todos[].on`, armed its command with no gate, and `plan.op` from a cell armed with no gate at all. `schedule::clock::armed_commands` now walks every object of a call for an `on` and returns each command it arms. The tool and `plan.op` share one reading, `plan::request::armed`, over the args as sent and as the whole-plan reading mends a string of rows, each command once. `plan.op` judges each command through the gate a heartbeat's `exec://` source meets, the one `rlm_heartbeat.create` uses, and refuses with the code `denied`.

HA-PLAN-errors. The schema shows three ops, `set`, `view` and `accepted_by_user`, while an unknown or missing op listed sixteen and the hints named `init`, `start`, `op=block`, `append`, `decompose` and `op=accept`. The legal-op list is now the schema's own `SHOWN_OPS`, and the no-plan, open-plan, illegal-step, misplaced-`on`, depth and checker-timeout hints say the move as a `set` row or `accepted_by_user`. Hidden ops still parse on every surface; only the teaching changed. A drop on a running todo still reads "ends with fail and a cause", since a dogfood fixture pins those words, and now adds the set row that does it. Each wall names what the model can do: a plan or journal record over its cap says to send fewer or shorter rows, a checkpoint changed behind the engine says to delete it so the next op rebuilds it from the journal (a test runs that remedy), and a workspace past the hash cap says to run the check by hand and close the todo with `accepted_by_user`. `PlanOpError`'s code, census kind and journaled flag were three matches over the same 52 variants; they are one table now, in kinds.rs, which takes 78 lines out of the plan engine.

HA-PLAN-oneparse. The engine's `set` keeps only the rows it names and reads a struck row as pending. The tool hid that with its own reading: a JSON-string todos list is read as the list, a row the set does not name is carried as it stands, and a struck row is dropped once the rest lands. `plan.op` and `yi plan` (with the console's submit, through `authority::submit`) called the parser and the reducer directly, so a cell's or a shell's set deleted every row it left out, reopened a struck row, and refused a string todos list as missing. Every surface now goes through one `apply::apply_set`, and `tool::request` reads a string todos list itself. The notes the tool prints ("2 rows not named stay as they are", "y was struck, so it was dropped") are notices on `plan.op` and the CLI. The reducer is untouched, so old journals replay the same. A struck row's drop carries no request id or revision of its own, since the set it follows already moved the plan.
