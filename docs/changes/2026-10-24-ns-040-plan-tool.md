This PR fixes the plan tool in six units, in commit order: HA-PLAN-arms, HA-PLAN-errors, HA-PLAN-oneparse, CAPS-plan, HA-PLAN-report and HA-PLAN-label.

HA-PLAN-arms. A plan row blocked on an `exec://` wait arms a shell command that later runs on the host, outside any sandbox. The plan tool's `arms` read only a top-level `on`, so the row form its own schema documents, `todos[].on`, armed its command with no gate, and `plan.op` from a cell armed with no gate at all. `schedule::clock::armed_commands` now walks every object of a call for an `on` and returns each command it arms. The tool and `plan.op` share one reading, `plan::request::armed`, over the args as sent and as the whole-plan reading mends a string of rows, each command once. `plan.op` judges each command through the gate a heartbeat's `exec://` source meets, the one `rlm_heartbeat.create` uses, and refuses with the code `denied`.

HA-PLAN-errors. The schema shows three ops, `set`, `view` and `accepted_by_user`, while an unknown or missing op listed sixteen and the hints named `init`, `start`, `op=block`, `append`, `decompose` and `op=accept`. The legal-op list is now the schema's own `SHOWN_OPS`, and the no-plan, open-plan, illegal-step, misplaced-`on`, depth and checker-timeout hints say the move as a `set` row or `accepted_by_user`. Hidden ops still parse on every surface; only the teaching changed. A cell's `plan.op` and `yi plan` read no set row's block or fail, so their refusals respell those three hints as the op that does it there (`op block`, `op fail`); a test follows each hint from a cell, and one from the shell. A drop on a running todo still reads "ends with fail and a cause", since a dogfood fixture pins those words, and now adds the set row that does it. Each wall names what the model can do: a plan or journal record over its cap says to send fewer or shorter rows (a test sends a change past the plan cap, then the same change with fewer rows, which lands), a checkpoint changed behind the engine says to delete it so the next op rebuilds it from the journal (a test runs that remedy), and a workspace past the hash cap says to run the check by hand and close the todo with `accepted_by_user`. `PlanOpError`'s code, census kind and journaled flag were three matches over the same 52 variants; they are one table now, in kinds.rs, which takes 78 lines out of the plan engine.

HA-PLAN-oneparse. The engine's `set` keeps only the rows it names and reads a struck row as pending. The tool hid that with its own reading: a JSON-string todos list is read as the list, a row the set does not name is carried as it stands, and a struck row is dropped once the rest lands. `plan.op` and `yi plan` (with the console's submit, through `authority::submit`) called the parser and the reducer directly, so a cell's or a shell's set deleted every row it left out, reopened a struck row, and refused a string todos list as missing. Every surface now goes through one `apply::apply_set`, and `tool::request` reads a string todos list itself. The notes the tool prints ("2 rows not named stay as they are", "y was struck, so it was dropped") are notices on `plan.op` and the CLI. The reducer is untouched, so old journals replay the same. A struck row's drop carries no request id or revision of its own, since the set it follows already moved the plan.

CAPS-plan. Four cuts in what the plan shows the model said nothing at the cut. A child's failure cause and a refused contract's item tail were cut to `CAUSE_CHARS` (500) chars with no mark; past it the cause now keeps its first 500 chars, then a row `[… 500 of N chars (CAUSE_CHARS 500); the rest: read plan://<plan>/artifacts/<hex>]`, and the whole text is a plan artifact at that address, which `read` opens. The view's window notice said "N more todos not shown"; it is now the same row, naming the shown count over all todos, the `WINDOW` (8) cap and the call `plan {"op": "view", "full": true}`. `frontier_text` and the compaction directive listed every row; each now lists `FRONTIER` (16) and names the rest the same way, and the frontier's cut takes ready rows before the running and blocked ones. Each row is written by yi-tools' `cut`, the one writer of the row. A rendered outcome printed `dispatched:` for every newly admitted row, the owner's own included; it now names only rows a child takes. Juror reasons are left to the approved judge.rs deletion.

HA-PLAN-report. The plan report set a todo's resolution from the last record that named the todo with a `to` state, so an edge added to a done todo, which records `to: done` again, reset the resolution to none. Only a record that moves the state now ends the todo anew; the time buckets read the same. `yi why <plan>/<todo>` found commits with a fixed-string grep for `Plan: plan://<plan>/<todo>`, which `p/todo-2`'s trailer also contains; it now asks git for the trailer as a whole line, as a basic regexp named on the command line so a user's `grep.patternType` never reads it, and a todo lists only its own commits. Its git log read cuts at `CAP` (64 KiB), keeping the head and the tail, and said nothing; past it the reply ends with `[… K of T bytes of git log (CAP 65536); the rest: git log --format='%H %s' --basic-regexp --grep '<the same pattern>']`, in the text and as `cut` in `--json`. `yi why` has no narrower form of a todo's reverse query, so the row names the git call it runs, which no cap cuts.

HA-PLAN-label. `Todo::from_text` cut a long text to its first 80 chars, so two todos that shared that head got one label, and the todo store and the plan validator refused the second as a duplicate. A text past the cap is now labelled by its head and the first 8 hex digits of the SHA-256 of the whole text, within the 80 chars, and the text stays whole in the note. The same text always gives the same label, and no stored label is recomputed: a list written by an older build keeps its labels, which still read as cut. The todo tool named an item by running the name through `from_text`, which would now give a copied label and its ellipsis a digest of their own. It now reads a whole text past the cap as that text's own label, so each of two todos sharing a head is named by its whole text; it cuts a copied label or an id-led line plainly, and its lookup matches a cut item by the text it was cut from as well as by its label. A whole text retyped in another case misses that digest, so the lookup then reads the digest label's head as a prefix, as a plain cut did. The head alone names a cut item only while no other todo shares it. A rendered list sent back through the todo tool's `set` reads each `…` row as the label it shows, so the row keeps its label and the note, intent and ask its label carries. The todo replay goldens keep main's text; their compare spells each long row's label as today's code does before it reads the rest word for word, so every recorded call still replays. A `local://` address could not name a path with a space, since a raw space is refused and `%20` was kept literally; in a `local://` path `%20` now decodes to a space and prints back as `%20`, and a `deny_url` prefix written with a raw space walls that spelling too. Only `%20` decodes, so a file whose name holds a literal `%20` has no spelling. The yi-types golden fixtures and schemas.lock are unchanged.
