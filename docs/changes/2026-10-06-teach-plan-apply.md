The plan tool teaches one call: `plan set` with a goal and every todo as a row, sent again with the rows' new state to change anything (Closes #1076). The tool description, the orchestrate fragment and the plan skill now say this, so a model no longer has to choose between sixteen ops.

The natural reader also accepts the shapes glm-5.3-flash sent in the stage 5 surface runs and that were refused before. A label past the 80-char cap is cut to the cap, with a note. An `init` sent while a plan is open adds its new todos to that plan. A `retry` on a todo that is already running changes nothing and says so. An op sent with no rows shows the plan as it stands. A `todos` string whose braces do not balance, which glm-5.3-flash sends for rows with contracts, is mended where each row opens and closes. A `decompose` naming no todo splits the one that is running, an op on a label that lives in a sub-plan runs there, and a `block` on a failed todo retries it first. GLM's call markup leaking into a key (`block<arg_key>note`) is read back as that op. A whole-plan `set` whose every row is left out is refused, because nothing in it landed.
