This is Bet 2's goal tail (unit B2-goal-tail). A failed check used to reach the model as the last 2,000 chars of its output with nothing saying it was a tail. That tail now goes through the view B2-view added, `yi_tools::view`, and `output_tail` is gone. One function, `check_view` in `goal/mod.rs`, takes the check's command, the directory it ran in and its capture, and returns the view's text. Past `VIEW_CEILING` (16,384 B) the text is the head, one row and the tail, and the row names kept over total, the cap and the rerun that writes the rest to a file: `bash (cd '<dir>' && <command>) > view.log 2>&1, then read view.log`. The `cd` is the point: a check that ran in a child's lane or a `cwd_subdir` is read by a parent whose bash is rooted elsewhere, and a bare command would rerun in the wrong tree and could pass. Output under the ceiling now arrives whole where it used to be cut at 2,000 chars.

Three places print a failed check, and all three call `check_view`: the goal gate (`run_check`, which the gate, the discovery drain, a child's result check, the child finish hold-back and the discovery router all call), a checker item's refused detail (`verdict_of` in `plan/verify.rs`) and the `exec://` source of a heartbeat (`schedule/adapter.rs`). The pass evidence of `run_cmd_said` keeps its own 300-char tail and its own loud row, now taken from the raw streams.

A refused checker item cannot name a rerun, because the tree it ran in is a materialized snapshot or a verification lane removed before the author reads the refusal. It passes the plan's new `Artifacts::spill_dir` as the view's spill directory instead, so the reducer foreground bash uses can run on it and the cut row reads `read <file>`; the file holds the capture, redacted, and lives and dies with the plan. A real `pytest -v` run now reads as the reducer's view (the head, the FAILED row, the verdict, the passing tests counted and omitted) plus a `[full output: <file>]` pointer, where the goal gate, which has no spill directory, shows the middle-cut view.

A check's capture is cut at `OUTPUT_CAP` (30,000 B a stream) before the view sees it, so the view's total can be smaller than what the check printed. `check_view` appends the capture's own cut row after the view's, and both capture sites name `OUTPUT_CAP` in place of the literal, so that row quotes the real cap. A 32,955 B `pytest -v` run through the goal gate reads `[… 16074 of 30038 bytes kept (VIEW_CEILING 16384); the rest: bash (cd '…' && …) > view.log 2>&1, then read view.log]` and `[capture cut: kept 30000 of 32955 bytes (OUTPUT_CAP 30000 per stream); no file kept the rest]`.

The view is printed once whole, in the refusal, and two later copies of the same evidence shrank to what a reminder needs. The goal's stored `check_failure`, which every continuation prints, and the note of a todo blocked by the refusal cap, which every frontier prints, keep the first line and the last 2,000 B with a row naming `REPEAT_BYTES` and where the whole went. Rows of a discovery drain or of a child's result that name one red task print its evidence once and say so on the later rows. Without this the change would have multiplied a 2 KB tail by eight in each of those places.

The `exec://` source needed one more guard. A channel refuses a message past `MESSAGE_MAX_BYTES` (16,384 B) whole, with its data set to null, so a red level with a ceiling-sized view in it would stop matching an `ok=false` filter and the todo that filter makes would never be created. When the level and its output would serialize past the cap, the message keeps `ok` and `exit`, a row naming the cap and the rerun, and the end of the output, where the verdict and the capture's cut row are; it drops the head until the message fits, counting each byte as JSON sends it (a quote or a newline is two bytes there). A `ceiling` argument on `view`, set from the channel's cap, would keep more of the view's own shape here, and belongs to B2-view's owner.

The behavior fixture `done-claim-red-check-refused` is unchanged: its check is `false`, which prints nothing, and its assertions name only `completion rejected` and the exit line.
