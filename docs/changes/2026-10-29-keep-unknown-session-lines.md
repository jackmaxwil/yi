A session file with lines this build cannot read now loads instead of being refused as invalid. An unknown mutation `kind`, `fact` or entry `type` (a Pi `session_info`, `custom_message`, `label` or `context_edit` entry, a Pi `value` line, a fact from a newer Yi) decodes to an `Other` variant that keeps the line's object as written, so it re-emits byte for byte; an unknown entry keeps its id, parent and seq, so the tree and the sequence stay whole and later turns append after it. A known tag that does not decode is still refused. The context leaves unread lines out, and a resumed session tells the model on its next turn how many lines it kept unread and the line number of the first. The legacy `plan` fact is now raw JSON that nothing reads: the typed task DAG, `SessionState::plan`, `SessionStore::set_plan` and the plan view's doc-pointer branch (with `CanonicalPlanError::Pointer`) are deleted, so a session carrying an old plan fact resolves to the Active root it owns. The dead `tape` module and the unused ACP-shaped `PermissionRequest`/`PermissionResponse` types are deleted too. A failed append (a short write when the disk is full) is cut back to the length the file had before it, so a half line can no longer make the session unloadable.
