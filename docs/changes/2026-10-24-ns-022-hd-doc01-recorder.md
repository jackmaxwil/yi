The recorder that the version line, the changelog and check_changes.py all promised now exists. `scripts/record_changes.py` takes every change file that carries no `version:` yet, in the order main's first-parent history added them (name order inside one commit), and for each one bumps the minor version in docs/ARCHITECTURE.md, puts its row on top of docs/CHANGELOG.md dated the day main landed it, appends each `decision:` as the next D-row with its ADR and index line through scripts/adr.py, and stamps the file with `version:` and `decisions:`. A stamped file is never recorded again. `--dry-run` prints the plan and writes nothing; without `--backfill` it refuses a tree where no file was ever recorded, since that is a backlog of every file since 2026-10-01. check_changes.py now accepts a branch whose edits to the version, the changelog rows, the decision rows, the ADRs and main's change files are exactly what the recorder writes from the fork's tree, and refuses any other edit to them as before. postmerge.yml gains a `record` job that runs it and pushes to main, off until the repository variable `RECORD_CHANGES` reads `on` and a `RECORDER_TOKEN` that branch protection lets through is set. No backfill runs here: a dry run over the 189 files on this branch, this one included, plans versions 0.526.0 to 0.714.0 and decisions D342 to D443, and the first real run is the owner's call.
