`read` and `edit` take at most 16 MiB of one file (`READ_FILE_CAP`); past it the call is refused with a row naming the size, the cap and the grep call that reaches the rest, and a text that large is never held in the snapshot store, so one huge view no longer evicts every other file's tags. A text file that quotes `%PDF-` is no longer mistaken for a PDF: the marker counts past the first byte only in bytes that are not UTF-8. `write` and `edit` replace a file through a sibling temp file renamed over its name, after checking the name still names the file the gate opened, so a reader or a crash never sees a short file and a symlink swapped in before the rename is refused; the file's mode is kept, and a hard-linked file is still written in place so its other names see the new bytes. An edit whose header names a missing path is refused with the one same-named file this session read, as `[path#TAG]`, instead of being rebound and written without the permission rules seeing that path. A section that changes nothing is noted while the other sections land, a file a formatter stripped of trailing spaces still edits under its old tag, a stale `REM` or `MV` warns about the delete or move rather than a head/tail insert, a stale-tag refusal points at the header its last line names rather than a re-read, and a program's read lines stay anchorable across consecutive edits.
