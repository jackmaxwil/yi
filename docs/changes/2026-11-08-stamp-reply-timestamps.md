Every reply Yi stores now carries the time it ended (Closes #2109). Reclaim, which cuts old tool results out of the model's view, decides from the replies whether the route reads its cache and whether that cache has lapsed. No reply ever carried a time, so it saw none of them. On a route priced at $0 that still reads its cache, such as a subscription lane, it cut every aged result at once and rewrote the cache each time. It also never noticed a lapsed cache. A reply now gets the time it ended from the runtime's clock before it joins the history and the session file. Pi's writer stamps every reply too, at the start of the request; Yi stamps the end, as its cache record does, so a lapse is never read early. The field, its shape and its place in the bytes are unchanged.

This also changes priced routes. Before, every reply was 0, so the lapse test never ran on any route. Now a session whose newest reply is older than its cache's lifetime (five minutes, or an hour) cuts every aged result at once as `expired` on its first request, whatever the route's price. That covers a resumed session and one the user left idle. The cache is cold by then, so the cut costs no extra rewrite.

Sessions written before this change keep their 0 times. Reclaim still reads a 0 as no evidence, so an old session behaves exactly as before until its first new reply, which carries a time.

The reclaim tests now stamp replies with a real epoch time, as production does. A new test runs a $0 route whose replies read the cache through the real loop and store, and checks that nothing is cut and every stored reply has a time. Another resumes a priced session six minutes after its last reply and checks that the first request cuts as `expired`.
