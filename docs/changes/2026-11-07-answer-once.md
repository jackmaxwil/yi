The reply prints once. A model that wrote its reply as text and also sent it through `answer` showed it twice, and the first copy had never passed the stop checks: in the recorded session the checks refused a draft whose words already stood on screen. Prose streams and commits as it always did. The loop appends an accepted draft as a message inside the turn whose reply called `answer`, the only model message a turn opens twice, and it appends one after the last word too, when the call itself fails. When that message starts, the drafts it repeats are emptied in place, so no other cell moves: the prose beside an `answer` with a body, and a plain reply the stop check held. A summary alone with nothing held heads the prose beside it, so that prose stays as the body. A refused draft stays until an appended answer replaces it, and a message cut off before its answer ran is never a draft. A stream with no turn events marks nothing appended. On resume there are no turn events, so the appended answer is the saved reply with no response id and no usage, the shape no provider writes. The solo chat rebuilds its scrollback from history once when it empties a cell, the same rebuild a resize runs, so rows past the reflow cap are not redrawn. The `answer` call draws no card, so neither "Answer delivered; the turn ends." nor a refusal addressed to the model reaches the screen.
