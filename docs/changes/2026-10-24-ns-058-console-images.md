A console chat pane's orb and question card now draw on one of a hundred kitty id pairs the pane leases (E-uilife-kitty-ids). The ids were `7800 + 2 x pane` for the orb and `7200 + 2 x pane` for the card, where the pane id counts every pane the console ever opened and is never reused, so the hundredth pane's orb transmitted on 8001, an id the avatar pool had already given a pane's close button, and its close deleted 8000 and 8001 under the gear and that button; at pane 250 a close deleted the notebook's 7701. The per-frame map of which pane drew which chat's images now also holds the pane's slot: a pane that first draws a chat takes the lowest slot no other entry holds, and the entry's removal, when the pane closes, is rebound or parks its chat, deletes the pair and frees the slot. Slots run 0 to 99, so orbs stay in 7800-7999 and cards in 7200-7399. A pane past the hundredth live one holds no slot, draws its mark as text and says so once in its transcript, `[…] 100 of 100 image slots in use · this pane's mark is text until a pane closes`, and takes the first slot a close frees. A chat brought back from the parked set starts fresh image state, so it never re-places an id deleted when it left. The lease runs before the frame is drawn, so a new pane's first frame already knows whether it draws an image. The whole id map, from the cards' 7200 to the browser frames' 0xF00000, is one module comment in app/ids.rs, and the browser's comment points there. The console notebook now keeps image data for a session's newest cell with images only (E-uilife-notebook-mem). A cell kept up to four PNGs of up to 512 KiB of base64 and a session kept fifty cells, never evicted while the console ran, so a plotting loop of 200 KB figures held about 13 MB per session in the notebook alone though only one image was ever drawn and the rest were listed by size. A cell now records each kept image's base64 length, which its `▲ image · N KB png` rows read, and the cell an update gives images clears the data of every other cell of the session; the cap rows for dropped and older images are unchanged. The kitty placement read the first kept image of that cell while its comment said the newest; it now places the newest. The chat port's replayed and committed entries carry the same images and stay whole on purpose, since `/tree` and the cell-to-entry match read every entry; a comment there now says so. The recorded fixture is a real kernel cell that writes a 203,188-byte PNG with the standard library and hands it to `attach_image`'s emitter, scrubbed by `evals/record.py --scrub-only` with the image's base64 put back, since the scrubber masks it. Units E-uilife-kitty-ids and E-uilife-notebook-mem.
