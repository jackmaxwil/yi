`just tui-see run <scene> --host term` also plays the scene in real Ghostty inside the yi-term container and swaps its grabs in for the agg pictures, so the crops `tui-see diff` hands an agent carry kitty images (avatars, the orb), the Yi mark and true colour. `just yi-term` builds the image and a static Linux yi for the host's architecture. On that host the proxy sends each step as a terminal would (C0 codes and ESC prefixes for plain keys, xterm's modifier parameter for named keys, kitty's CSI u for `cmd-`), reads `wait-frame` off a pyte screen fed the same bytes, and refuses any step it cannot play; `wait-idle` means output that started after the step and then stopped for a second, because the real binary's turn state is not visible from outside it. A Linux binary older than the host one, a dead binary, a daemon that never listens and a snap taken while the output never paused are all named in the run's output.
