Yolo's destroy belt now reads every segment of a command. It used to read only the first word of the whole string, so `cd build && rm -rf ~/.ssh`, `true; rm -rf .git` and `echo done && rm -rf ~` ran in yolo although the yolo prompt promises catastrophic targets are always denied. The belt now splits where a shell may start another command (`;`, `&`, `|`, a newline, a parenthesis, a backtick), reads past a shell keyword such as `then`, `do`, `{` or `!`, and once any segment runs `rm`, `rmdir`, `shred` or `unlink` it sends every word of the whole command, quotes stripped, through the denylist. Reading the whole command keeps `rm -rf "x (1)" ~/.ssh` denied, whose quoted parenthesis would cut its own segment short, and stripping quotes denies `rm -rf "$HOME"`, which ran before. The cost is that a protected path anywhere beside a destroying verb is denied, so `cd ~ && rm -rf build` is now denied in yolo, as `rm -rf build && cd ~` already was. It splits the raw text rather than taking the classifier's segments, because the lenient splitter strips a leading `$` and would stop `$HOME` from expanding to the home directory. On macOS the destroy gate also compares paths with letter case folded, since a default volume opens `~/.SSH` as `~/.ssh`; folding both sides only ever denies more. The belt, the wall's write-target reader and the classifier's splitter now share one separator set and one keyword list, so the wall also reads a command inside backticks and BSD `sed -I` as an in-place edit, and the classifier reads the program behind `!` or `{`.

Auto mode's classifier now reads flags the way the programs do. A short flag counts anywhere in its cluster, so `git clean -df`, `-xdf` and `-fxd`, `git checkout -f` and `git switch -f` ask, as do `git checkout .`, `..`, and any path a ref name cannot be (one starting with `.`, `/` or `~`, or ending in `/`) after the subcommand. A wrapper's own flags (`nice -n 5`, `timeout -s KILL 5`) and an environment assignment (`FOO=1`) no longer hide the program they run: every later word is read as that program and the worst reading wins, so `nice -n 5 rm -rf x` and `FOO=1 rm -rf x` ask, and nothing behind such flags or an assignment is proven read-only. Programs the classifier proved read-only stop being proven when a flag or script runs a program or writes a file. `fd -x`, `fd -X`, `fd --exec`, `rg --pre`, `rg --hostname-bin`, `sort --compress-program`, `find -okdir`, `find -fprint` and `find -fprint0` ask, like `find -exec`. `sed` with `i` or BSD's `I` in any cluster or with `w`, `W` or `e` in its script (an `s` command read by its own delimiter, an address's `I` or `M` read past, and an `s` flag it cannot read counted as acting), `awk` with `system`, a pipe, a `>`, `-f`, or gawk's `-E`, `-i`, `-l`, or the file-writing `-p`, `-o` or `-d`, `sort -o`, `tree -o`, `uniq` with two operands, a bare `-` counted as one, `git --output` and a `git -c` or `--config-env` before the subcommand are contained, like `sed -i`; awk's `system` and sed's `e` run a program yet are contained rather than asked, because their scripts are read by fragment and off macOS a containment asks anyway. A `c` in a subcommand's own flags, as in `git ls-files -co` or `git log -c`, stays a read. A long flag counts by any prefix, since getopt takes `--out` for `--output`, but a longer flag is not taken for a shorter one, so `git diff --output-indicator-new` stays a read and `fd --exec-batch` is its own row. An ask or containment now names the program behind an assignment, so `FOO=1 rm -rf x` reads "`rm` is destructive", not "`FOO=1` is destructive", and a git network reason names the subcommand after `git` itself, so `FOO=1 git pull` and `nice git pull` read "`git pull` needs the network", not "`git git`". The cost is that more commands are contained or ask in auto: an awk filter comparing with `>` or matching `a|b`, a sed script with a backslash, a sed long flag even a read-only one such as `--expression` or `--quiet` (no long flag is read), `git -c color.ui=always log`, `uniq -f 1 in` and an awk `-v` or `-F` cluster holding `i`, `E` or `l` are now contained where they ran, which off macOS means they ask. Member units: HA-PERM-belt, HA-PERM-classify.
