A session runs one compaction at a time. `Compactor::maybe_compact` takes the session's in-flight flag with a compare-and-swap before it spends anything, and a request that arrives while another compaction is summarizing returns at once with `Compacted::Busy`: it makes no summarizer call, takes neither the pending request nor its one-shot instructions, and writes no history. Before, only the flag's value was shared — both callers set it and either one's end cleared it — so an idle `/compact` mid-summarization and a turn crossing its own threshold could each read the window, call the summarizer and advance the window and the history on their own, and whichever finished last won a write the other had already made stale. `AgentSession::compact_now` reports the refusal as `CompactOutcome::Busy`, whose RPC frame reads `applied: false, scheduled: true` because `/compact` stays pending and the next boundary runs it; the loop's own boundary simply keeps its history and carries on. `Compactor::compacting`, which the scheduler reads to defer a heartbeat, is now true for exactly as long as one compaction runs rather than until the first of two finishes.
