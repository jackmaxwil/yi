A contained `git fetch`, `pull`, `ls-remote` and `clone` now run with no question, and so does `git push` to any branch but trunk, `main` or `master`. The host refreshes a mirror before a command that names a read, and forwards what a contained push left in an outbox after the command ends, with no hooks and never in the outbox. `--force`, `--delete`, `+x` and `:x` still ask and leave. A push to main asks with a diffstat; headless it is refused and origin stays put.

What happened reaches the model as a row: `[pushed feature to origin: …]`, `[not pushed: origin/feature has commits this lacks; merge, or git push --force asks]`, `[not pushed: main asks a person, who declined or is not here: +300 -20 in 7 files]`, or `[push of feature unknown after 120 s: it may have landed; git fetch and compare before pushing again]`. A remote's own words are fenced and redacted. An origin URL holding a credential gets no lane, and its git keeps today's ask.

`refs/remotes/origin` is host-only in a main checkout now, so a moved `origin/HEAD` cannot make a real main push skip its ask.
