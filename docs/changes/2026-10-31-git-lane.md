A contained `git fetch`, `pull`, `ls-remote` and `clone` now run with no question, and so does `git push` to any branch but trunk, `main` or `master`. The host refreshes a mirror before a command that names a read, and forwards what a contained push left in an outbox after the command ends, with no hooks and never in the outbox. `--force`, `--delete`, `+x` and `:x` still ask and leave. A push to main asks with a diffstat; headless it is refused and origin stays put.

What happened reaches the model as a row: `[pushed feature to origin: …]`, `[not pushed: origin/feature has commits this lacks; merge, or git push --force asks]`, `[not pushed: main asks a person, who declined or is not here: +300 -20 in 7 files]`, or `[push of feature unknown after 120 s: it may have landed; git fetch and compare before pushing again]`. A remote's own words are fenced and redacted. An origin URL holding a credential gets no lane. Its git has transports off by config, so an ordinary push fails contained and the next call asks; a process that removes that config can still leave through a seeded host, which the trust table records.

`refs/remotes/origin` is host-only in a main checkout now, so a moved `origin/HEAD` cannot make a real main push skip its ask.

A network refusal is read from git's own line, `fatal: transport '…' not allowed`, rather than from any line naming a transport, which a tool's own message could print.

The no-transport block follows any repository, not only one whose `origin` resolves, so a named remote's `file://` push meets it too.
