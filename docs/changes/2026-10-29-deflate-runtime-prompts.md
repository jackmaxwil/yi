The runtime's fifteen embedded prompts no longer ride the binary as raw text: `crates/runtime/build.rs` deflates each one and proves the round trip, `yi-runtime::packed::Packed` inflates it once on first use, and every accessor reads through it. The dist binary measured 8,670,176 -> 8,637,152 bytes on this host, **-33,024 bytes**, two 16 KiB `__TEXT` pages back under the measured ratchet (8,686,704 + 16,384 jitter = 8,703,088: headroom 32,912 bytes before, 65,936 after), which sits under the 9 MiB hard cap of #1354; #1401's 8 MiB arithmetic and its "next 3.8 KB fails every build" are stale against that ratchet. `miniz_oxide` was already in the graph through `yi-ai`'s catalog and `yi-orb`, so nothing joins the dependency table and no new crate is linked. The deflate step is one `pack` function in `crates/ai/pack.rs` that the `yi-ai` and `yi-runtime` build scripts both `include!`, so `yi-ai`'s catalogs gain the round-trip proof; `yi-kernel` and `yi-tui` still carry their own copies of the step. Each prompt static is one `packed!("stem")` line, and the graph inflates inside its one `OnceLock`. Nothing about a prompt's bytes changes: `every_packed_prompt_inflates_to_its_own_file`, `every_packed_prompt_reads_as_its_own_file` and `the_shipped_graph_is_its_own_file` compare all fifteen with the file each was built from.
