The kernel no longer parses two display payloads nothing sends. A cell's `display_data` carrying `application/vnd.yi.diff+json` used to become a diff row on the `ipython` result, and one carrying `application/vnd.yi.agent-message+json` a "sent message" receipt, plus a late-delivery queue, capped at 256 handlers, that held a handler only when a caller set `on_late_sent_agent_message`. No Python code under `python/` emits either type and no caller ever set `on_late_sent_agent_message`, so the parses, the handler queue, `ExecuteResult.diffs` and `.sent_agent_messages`, the `diffs` and `sentAgentMessages` keys of the `ipython` result's `details`, and the TUI's `╰─ path` diff rows under a kernel cell are gone. The yi-types shapes with no remaining reader (`KernelDiffDisplay`, `KernelSentAgentMessage`, `KernelAgentMessageTarget`) go with them, and so does `crates/types/src/harness.rs`, a Rust copy of the Python harness entry that nothing used.

A recorded session still opens: its `ipython` rows keep `"diffs":[]` and `"sentAgentMessages":[]` inside `details`, which is a free-form JSON value, so they decode and render as before. `crates/kernel/src/client.rs`, which sat at the 1,200-line ceiling, drops to 1,140. `docs/YI_DESIGN.md` §9 never described either payload, so it needs no edit.
