HB-utf8-rest: yi-ai, yi-context, yi-kernel and yi-mcp-cli now deny `clippy::string_slice` at their crate roots, so no byte-index slice of a `str` compiles under clippy in those crates. The fifteen slices they held were boundary-safe, each behind a `find` of an ASCII byte or a hand-written walk back to a char boundary; they are now `split_once`, `str::get`, or `floor_char_boundary` and `ceil_char_boundary`, which deletes the five hand-written walks. The pending list keeps only runtime and tools, which other changes clear.

HA-INT-abort: an abort now cuts the provider request as well as the loop's reading of it. `InterruptSignal::fire` sets the cut flag the HTTP adapters already read between SSE events, so the pump stops at its next event and drops the connection instead of letting the provider generate, and bill, to `max_tokens`; on Kimi's recorded 91-event bash stream an abort at the third event now reads three events, where it read all 91. The cut flag is now per request: opening a request installs a fresh flag and leaves the old one set, so the next prompt cannot un-cut a pump still blocked on its read. An aborted OpenRouter turn now takes the cut path's settlement, so its cost is booked from the generation record. A turn cut at the reasoning budget waits up to 45 s for the provider's settled `Done`; an abort during that wait now ends it at once and is recorded as an aborted turn, with no length redrive. YI_DESIGN.md §4.5 says both: a fire sets the request's cut, and each request opens with a fresh one. Two races in the signal are closed: `wait` creates its `Notified` before it checks `fired`, so a fire between the check and the await is heard, and `fire` moves the epoch before it sets `fired` while `reset_if_epoch` re-reads the epoch after clearing and restores `fired` when a fire raced it; a three-thread stress lost 496 of 10,000 fires before and loses none now. Cursor's stop function keeps reading both flags: with `fire` setting the cut it is equivalent to the cut alone, and reducing it deletes runtime lines, which reads red under the Kimi change's declared runtime raise until that change merges.

HA-PLAN-leak: GLM's argument markup is repaired once, in yi-ai's tool-call decoder, for every tool. When GLM's call channel leaks `<arg_key>` and `<arg_value>` into a call's arguments, as in `{"done<arg_key>evidence": …}` or `{"done": "evidence</arg_key><arg_value>…"}`, the OpenAI-compatible and Responses mappers now read the field back before any tool sees the call, and keep the stray word in front of the markup as a `true` flag, which the plan tool reads as the op; the todo tool infers the op from the repaired field. Before, only the todo and plan tools repaired it, each with its own copy, and every other tool received the leaked key as a field; those two copies are deleted.
