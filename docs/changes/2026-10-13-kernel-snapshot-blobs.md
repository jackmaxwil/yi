A kernel cell that changes one variable now writes that variable's blob, not the whole namespace (Closes #1392). Each clean cell still pickles every user variable, but a variable whose pickled bytes hash (BLAKE2b, 128-bit) to a blob already on disk is not written again, and `kernel-state.dill` holds only the name-to-digest index. Blobs are written to a temporary file, fsynced and renamed, then the blob directory is fsynced, then the index is replaced the same way, so a crash leaves either the old index with its blobs or the new one with its blobs. A blob that is missing at restore costs only its own variable, which the restore notice names among those that could not be restored; a snapshot written before this change, a dict of name to pickled bytes, restores as before.
