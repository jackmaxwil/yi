Yi installs with one command: `curl -fsSL https://raw.githubusercontent.com/jackmaxwil/yi/main/scripts/install.sh | bash`. Piped into bash, `scripts/install.sh` names this machine's target, reads the release's `SHA256SUMS`, downloads the archive it lists, and installs it only when the archive's sha256 matches; a mismatch exits 1 with `nothing installed`, and a release with no `.sig` prints `this release is unsigned; integrity is the sha256 check only`. Run from an unpacked release it installs that tree as before. `YI_VERSION` picks a release, `YI_RELEASE_BASE` reads one from elsewhere (an `https://` or `file://` directory), and `--dry-run` and `--help` change nothing. It is a bash twin of `yi update`'s install half because no `yi` exists yet to run; it unpacks with the system `tar`, which strips a leading `/` and refuses a `..` member, and the digest it checks is the trust root, as a hostile host could serve any binary at all. `just publish` folds the archives' `.sha256` files into the `SHA256SUMS` a release carries, and refuses an archive with no `.sig` unless `YI_RELEASE_UNSIGNED=1`; `scripts/package.sh` signs by default, removes an archive it could not sign, and under `YI_RELEASE_UNSIGNED=1` prints `UNSIGNED:` and that `yi update` refuses it. The GitHub release is `scripts/mirror/publish.sh`, an owner-run tool that never runs in CI: it builds a clone of the mirror's tag, refuses an archive in which any deny.txt estate pattern matches, and uploads with `gh release create --verify-tag`. The mirror now pushes each forge `v*` tag on main at its rewritten commit, on main pushes and on tag pushes, checked by `scripts/mirror/sync_test.sh` in the mirror job before every push.
