Yi installs with one command: `curl -fsSL https://raw.githubusercontent.com/jackmaxwil/yi/main/scripts/install.sh | bash`. Piped into bash, `scripts/install.sh` names this machine's target, reads the release's `SHA256SUMS`, downloads the archive it lists, and installs it only when the archive's sha256 matches; a mismatch exits 1 with `nothing installed`. With `ssh-keygen` on PATH it then checks the archive's `.sig` against the release key it embeds (the one line of `allowed_signers`, which `--help` prints), refuses a bad signature, or a `.sig` fetch that failed for any reason but absence, with `nothing installed`, and says when the release has no `.sig` or the host no `ssh-keygen`. Run from an unpacked release it installs that tree as before. `YI_VERSION` picks a release, `YI_RELEASE_BASE` reads one from elsewhere (an `https://` or `file://` directory), and `--help` changes nothing. The binary and the runtime go in by rename, so a `yi` already running keeps its file and one starting meanwhile never reads a half-copied one. It is a bash twin of `yi update`'s install half because no `yi` exists yet to run; it unpacks with the system `tar`, which strips a leading `/` and refuses a `..` member, and the digest it checks is the trust root, as a hostile host could serve any binary at all. `just publish` folds the archives' `.sha256` files into the `SHA256SUMS` a release carries, headed by a line naming the forge build and its commit, and refuses an archive with no `.sig`; `scripts/package.sh` removes an archive it could not sign. The GitHub release is `scripts/mirror/publish.sh`, an owner-run tool that never runs in CI: it runs `just package` in a clone of the mirror's tag, and `scripts/mirror/scan.py` refuses the archive when a text file matches any deny.txt pattern (the planted fakes .gitguardian.yaml names excepted) or the binary an estate pattern or a private key header, and uploads the archive, `.sha256`, `.sig` and `SHA256SUMS` with `gh release create --verify-tag`. The mirror now pushes each forge `v*` tag on main at its rewritten commit on every run (a push to main, or `workflow_dispatch` on main after a tag push; never a tag trigger, and the job runs only on `refs/heads/main`), checked by `scripts/mirror/sync_test.sh` in the mirror job before every push, and `scan.py --selfcheck` runs in the guardrails. README.md is rewritten for a new user: install, quick start, login, plugins and skills, configuration, environment, CLI, plans, subagents, programmatic use, the SDK's status and how contributions arrive.
