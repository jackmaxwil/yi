This is the harness for EXP-S5-E2, the 27-trial A/B that decides whether children that keep a kernel are worth building (unit S5-kc-ab): on heat-pump-warranty, legacy-utility-triage and medical-claims-processing, three repeats each, three arms (solo; a parent with gathered `worker` children; a parent with gathered `root` children), on Kimi K3.1 and then GLM 5.3 flash. No Yi code changes.

The harbor adapter gains one hook. When `EVAL_ARM_FILE` names a text file, its text follows the task's own instruction in what the trial is told, after the budget rewrite, and its hash rides the config fingerprint as `+arm<sha12>`. A named file that is missing stops the trial instead of running it as another arm. `evals/kill/s5-kc-ab.py` is the kill test. It writes the two child arms' text, which differs in one line (the `role` of `rlm.run`) and has the parent copy the rules into its working directory before naming the copies as the partition, since a partition address resolves only inside it and the rules sit outside it on all three images, runs one sweep per arm, and reads each trial's verifier files and sessions. It records the score, whether the trial passed, the parent's peak context and the children's input tokens, a session recording tokens and not request bytes. Its verdict applies the pre-registered rule: K3.1 first, then flash only if K3.1 cleared. `python3 evals/kill/s5-kc-ab.py precheck` runs the zero-spend oracle and nop passes.

The pre-registered score is the ctrf tally, passed over tests, and the precheck found it cannot be read from ctrf. heat-pump-warranty and legacy-utility-triage write no ctrf.json: their verifier is a plain script that writes `trace_results.json` with 20 and 19 cases. medical-claims-processing writes a ctrf with one pytest test, which passed with a reward of 0, so a ctrf score reads 1 of 1 for every trial; its real count is the `Scoring: X/Y lines correct` line its verifier prints, 116 lines. Read literally, the guard "ctrf holds fewer than 10 tests" leaves all three tasks UNRESOLVED before a trial runs. The module therefore scores a trial by the verifier's own count (trace cases, else that stdout line, else the ctrf) and the guard counts those steps. That reading is not the pre-registered one and carries no `decision:` line yet, so the owner decides it before any paid sweep runs, and the module holds it in code: while `SCORE_DECISION` is None, `runs()` refuses every sweep before a reserve is written and every verdict reads UNRESOLVED. If it stands, a `decision:` line records it with the owner's words. If it does not, EXP-S5-E2 reads UNRESOLVED from the rule as written, no sweep runs, and S5-kc-worker-kernel is not built, with the precheck's counts as the report.

Run it on an x86 host. On this arm64 Mac, with the amd64 images emulated, legacy-utility-triage's own oracle could not commit one case through the GUI in two runs, and medical-claims-processing's playwright sidecar did not turn healthy in two runs. Kimi through harbor is not built here either: `kill.py` writes a subscription family's harbor spec unrun, as it does for EXP-B3c, so until a Kimi route exists in the sweep and the adapter the Kimi family reads unrun and the verdict is UNRESOLVED (no Kimi trial ran). A flash-only run decides nothing, so flash is not run with `--without-kimi` for this test. The route is a follow-up that EXP-B3c needs too, and it has to land before the measure lane's wave 7.

One change reaches the runner ns-023 owns, at review's request: `kill.py`'s `seed_home` now gives a run HOME only its own route's provider key (`<provider>.json`, the file name yi's credential store writes), where it copied every key in the store. A `--yolo` run can read its HOME, and an OpenRouter key on a Kimi run is spend outside the ledger's cap. This harness's harbor sweeps never seed a HOME this way; EXP-B3d's ask runs do.
