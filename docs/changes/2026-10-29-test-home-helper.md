Every test that spawns the `yi` binary now spawns it through one harness, `crates/cli/tests/support/yi_bin.rs`, which pins `HOME` to the test's own scratch dir, and `scripts/guardrails/check_test_home.py` refuses a test file that names `CARGO_BIN_EXE_yi` anywhere else, or takes the bare path from `yi_bin::bin()` outside a short allowlist, so a new spawn cannot forget. The issue records 11,633 of the 11,635 checkpoint dirs under the owner's real `~/.yi` (2.8 GB) on 2026-10-07 belonging to test temp dirs that no longer existed — `yi-rpc-*` 2,703, `yi-*` 1,942, `yi-acp-*` 1,883 — because a spawn that left `HOME` alone wrote the developer's home. The gate also proves its own refutation: `--selfcheck` builds a tree with a stray reference beside the harness and requires the stray to be the one refused, and a harness that drops the `HOME` pin turns the new test red with the developer's home in the failure line. Tests that must prove the binary's refusal of an unset `HOME` keep that ability through `yi_command_homeless`, named so the exception is visible.
