Frozen scenes now play in real Ghostty. `tui_see.py run <scene> --host term`, and the `tui` workflow on every TUI pull request, play scenes with `tick`, `snap-strip`, `hold` and `release` on the term host: the proxy types the keys into the real binary as before and sends the timing steps over the binary's new `--control <socket>`, where the interactive TUI or console plays them on the same code as the headless drive and answers each once done. The grabs carry the orb's kitty frames and true colour, and they land on the same frames as the headless snaps; `tui_see` names any snap whose words part from the headless one. `wait-idle` on that host is now the binary's own idle state rather than a screen held still for a second, so an answered snap no longer catches a turn still finishing. A `tick` waits for an armed hold to be reached before it moves the clock, so a scene no longer needs a `wait` between the prompt and its first tick. The orb steps on the app's clock, so a frozen scene's orb moves only when it ticks. The proxy waits for Ghostty to reach the scene's grid before it starts the binary (the binary drew an 80x18 scene at 79x17), its screen emulator now scrolls a region on `CSI S` and `CSI T` (after the first commit its rows were not Ghostty's), and the binary runs from a small cwd there, because a turn's checkpoint of the mounted repository took from 20 s to minutes.
