`rlm.merge_worktree` takes an optional `check`, a shell command run in the child's lane before its work is merged into this checkout. A parent that wanted to test a child's work before landing it had no way to: the lane path is not in any reply, and after the hand-back the lane is gone. The check meets the same host gate a spawn's `check` meets (the user's gate rules, the wall's command-text check and walled roots, then the broker's decision on the bash call it amounts to), and a refused one never runs: the call answers `the check is refused before it runs on the host: ...` and the lane stays held, so a merge without the check still works. An allowed check runs in the lane with a cleared environment (`PATH`, `HOME`, `LANG`, `TMPDIR`) under the session deadline, or ten minutes when the session has none, off the kernel's executor like the rest of the hand-back.

A check that is not a string is refused, as `rlm.run` refuses one, and a blank one is no check. A green check proceeds to the merge as before. A red or cut one settles the lane and keeps its branch, the outcome a conflict already gives, so this is not a third hand-back road and no disposition is recorded: the reply is `merged: false` with the `files` it changed, `check: {exit, tail}` and a `next` sentence naming the kept branch with the `git merge` that lands it anyway and the `git branch -D` that drops it. A child that changed nothing has its branch deleted at release, and its `next` says no branch was kept. The check runs before the settle because the settle releases the lane, so the files it writes outside the ignored paths are committed with the child's work. `tail` is the check's output through the view the goal gate uses (`check_view`): whole under `VIEW_CEILING` (16,384 B), past it the head, one row naming kept over total and the cap, and the end, and a capture past its 30,000 bytes a stream adds the capture's own `[capture cut: ...]` row. `exit` is null when the check was cut, and the tail then opens with a `[… cut at the session deadline; ...]` row (or the 600000 ms check timeout with no deadline). Each row's remedy is one bash call that runs the check on the candidate commit in a scratch worktree and removes it, so it leaves this checkout's branch alone and works whether or not the branch was kept. The Python `rlm.merge_worktree` gains the `check` keyword. Section 14 of the design names the check; the lanes ledger row names its journeys.
