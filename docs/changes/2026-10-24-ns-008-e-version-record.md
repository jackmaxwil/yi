The product has one version of record, the `version:` line of docs/ARCHITECTURE.md, which `yi --version` already printed. Two places still read the workspace placeholder `0.2.0` or trusted the tag. `just prerelease <tag>` compared the tag with the first `version =` in Cargo.toml, so the repo's own release failed with `tag 0.525.0 disagrees with Cargo.toml 0.2.0` on every `v*` push through the pre-push hook. It now compares the tag with the version of record and names docs/ARCHITECTURE.md in the refusal. `scripts/smoke.sh` now also checks the artifact itself: the unpacked binary's `--version` must be the version in the tarball's name, so a tag built from a stale tree no longer packs a binary that reports another release. The `yi mcp` client advertised `clientInfo.version` as `0.2.0` to every server it met; `yi_mcp_cli::run` now takes the version from yi-cli, which passes the same `ARCHITECTURE_VERSION` that `yi --version` prints, and hands it to `client::one_shot` and `client::one_shot_with_auth`. Nothing is written to Cargo.toml.
