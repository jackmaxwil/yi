This is Bet 2's cell producer (unit B2-cell). `cell_output` takes the recovery dir. The ipython tool passes its context's dir, and a user cell from a client passes none.

A cell's joined traceback now goes through `view(Involuntary::Traceback)`. A traceback under the 8,192 B floor reaches the model byte for byte, as before. A recursion traceback the kernel joined at 73,479 B now arrives as the reduced frames with the `RecursionError` line inline and a `[full output: …]` file holding every byte. With no dir, the ceiling's row names the cell that prints the exception again.

A `%%bash` cell, or a cell with `!cmd` lines, sends its stdout and stderr through `view(Involuntary::ShellCell)`. The two streams are joined exactly as before, with the `stderr:` label, so a small shell cell reads the same. The command is the cell's shell body, so `%%bash\ncargo test` takes the cargo reducer. When the kernel cut a stream at 65,536 chars, the spill pointer in the cell's notes is handed to the reducer as the cut capture's file. The reducer then reads the whole run from the spill, and the pointer is shown once, at the end of the view, not again among the notes. IPython's `!cmd` does not raise when the command fails, so a `!cmd` cell has no exit signal; it is read as a failing run, which keeps a failing test and its panic inline and costs some bytes on a passing one. Only a `%%bash` cell, which raises `CalledProcessError` on a non-zero exit, takes the passing path when it did not raise. A cell that mixes Python prints and `!cmd` lines is treated as shell output whole, which is the closed list's own wording. A line that opens with `!=`, a continued comparison, is Python and not a shell escape. A Python print in a plain cell is read as printed.
