This is Bet 1 items 4 and 7 of Yi's next shape (B1-loud-returns): every cut of a child's return now says what it cut.

Four places shortened what a child sent its parent and said little or nothing about it. A `context_keys` value past 4,096 chars ended `… [truncated to 4096 chars]`, with no total and no road to the rest. The whole scope past 16,384 chars was cut the same way. The preview of a child's answer, which rides the completion notice's `Last answer:` line and the status the TUI card reads, was cut at 240 chars with a bare ellipsis. And a schema refusal (`rlm.result` of a child that answered prose where a schema was given) embedded the child's whole answer, however long. The first three now end in one row, `… [kept N of M chars · cap <name> = N · <call>]`, written by the one `clamp` in `mailbox.rs` that every cut of a child's return goes through, and the fourth is bounded by it.

- A value past `mail.context_value` names the way to pass it whole: `write a value to a file and give local://<path> in partition`. The scope past `mail.context_total` names the same way. The total is the sender's own count when the rlm.run kwargs carry `context_chars`, an object of variable name to whole-number char count, which the kernel's `_resolve_context` will send once the Python release lands; the kernel cuts each value at the cap plus one, so until then the host cannot know the size and the row says `over 4096`, never a length it did not count. The `rlm.run` allowlist accepts `context_chars` so that count can arrive.
- The answer preview names `PREVIEW_CHARS = 240` and `read history://<name>`, which resolves for a live child and a reaped one alike.
- A schema refusal, and the refusal of a checked child whose answer is no result object, carry at most `RESULT_TAIL_CHARS` (2,000) chars of the answer and name `history://<name>` for the rest.

The TUI reads a child's preview as the head of the answer it is already streaming and replaces its card's text only when that head is not found there. The cut row is no part of the answer, so the match now stops at `… [`; without that, every long answer's card would have shown the 240-char preview and its row in place of the streamed text until the child finished. The change is one line in `tui/src/app/children.rs`; a TUI test streams a long answer and then delivers the cut preview.

The plan estimated tests +70 and the measurement is +243: four runtime tests (the context value at and one past its cap with the sender's count, without it, and on a non-ASCII value; the whole scope at and one past 16,384; the schema refusal at 2,000, 2,001 and 10,000 chars; the preview at 240 and 241), whose fixtures are built to the shape the kernel's `_resolve_context` produces (a helper of about 15 lines), and the TUI test.

The feature-ledger row for the kernel and `rlm()` subagents says it, and names the four runtime tests among its journeys.
