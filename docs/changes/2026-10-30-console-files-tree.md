The console's Files button opens a tree of the workspace instead of the command palette: the popup lists the focused root folded by folder, a click or ⏎ on a folder folds it, a click or ⏎ on a file opens it in an editor pane and closes the tree, and ← → walk out and in with the cursor kept on a row the frame draws. `.git` and every path a `.gitignore` declares stay out, read from the root and from each folder the walk enters, so a nested rule judges only what is under it and a `!` line puts back what an earlier line hid. The walk stops at 20,000 files, keeps them in name order, and the popup's last row says what it kept, names the cap and says where the rest is, so the button costs a bounded read rather than a whole checkout.

`⌥e` and the header button reach the same tree, and the tree is rooted where the focused pane works (`App::session_dir`, cwd then the session's root then the console's) rather than at the console's own launch root, so a lane worktree's session browses its own checkout and the file opens with that root as its workdir. A folder the walk reaches through a link is the folder it points at, with a canonical-path set keeping a link back up the tree from walking forever; a row is chosen by a press, so a pointer move neither moves the cursor nor repaints; a wheel notch scrolls the window and leaves the cursor where the user left it; PageUp/PageDown resolve a page in one pass over the drawn rows. `r` rereads the disk, and a root the walk cannot read says why instead of drawing an empty popup.

File size cost: `app.rs` and `render.rs` are past 1,000 lines at the fork, so the tree's keys and clicks live in `files.rs` with the model, both popups place themselves through one `palette::popup_in`, and `render.rs` lost a pane's shadowing `body` binding to pay for the tree's arm.
