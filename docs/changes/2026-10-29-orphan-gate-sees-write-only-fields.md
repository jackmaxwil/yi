The orphan gate (`scripts/guardrails/check_orphans.py`) now counts a read only where code reads: `.name` in production source, or a name a destructuring pattern binds (`let S { a, .. } = s`, a match arm, a `..` rest pattern, a thiserror `{field}` interpolation). A struct or variant literal that sets a field is no longer a read, and a test is no longer a reader. Enum variant fields are scanned like struct fields, and a `pub struct` or `pub enum` in yi-types that no production code names outside its own definition is reported as dead. `--selfcheck` carries the three shapes the issue names (a field only a struct literal sets, a variant field only a variant literal sets, an unused yi-types shape) and fails with each scan disabled in turn. What the stricter scan found is deleted: `ViewState::split_borders`, `Preparation::messages_to_summarize` and `turn_prefix_messages`, `Connection::info`, `Relevance::unsupplied`, the unused `AcpNotification` and `AdvisoryOutcome` types, and the lever manifest's `Spec` min/max/tunable fields are now what `Levers::set` validates against, so the table is read by the loader and not only by a test.
