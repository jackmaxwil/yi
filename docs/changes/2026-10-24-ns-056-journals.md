This PR makes the plan and memory journals cheap to read and fixes three memory faults, in five units, in commit order: HB-plan-read-cache, H41-journal-move, H41-journal-tail-append, H41-memory-guards and H41-memory-list-readonly.

HB-plan-read-cache. `PlanStore::read` and recovery's `reconstruct` read, verified and reduced the whole `ops.jsonl` on every call, so one `set` on a thirty-todo, two-hundred-record plan reduced its journal seven times, and sixteen first reads of one journal reduced it sixteen times. A new `plan::cache` holds the reduced journal per path and hands it back while the file's device, inode, length, mtime and last line are what they were; the stamp is taken before the read, so a write racing a read can only make the next reader reduce again. A damaged chain is refused there, as both readers did, and a torn tail is never held. The plan schema compiles once instead of on every checkpoint read. `reduce` now records a `plan.reduce` span under `YI_TRACE`, which the tests count: one `set` reduces twice (load, then the read of what it committed) and sixteen readers reduce once.
