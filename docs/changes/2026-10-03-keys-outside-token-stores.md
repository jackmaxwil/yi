Keys kept beside yi's token stores stay away from the model (Closes #906). The MCP config `~/.yi/mcp.json` and session store, which keep each stdio server's `env`, are now refused to read, grep, globs, edit and write however it is spelled, a hard link in the working directory included, and a bash command naming one asks first; the model can no longer read or edit `~/.yi/mcp.json`. Bash, the kernel, goal and todo checks, heartbeat `exec://` sources and a lane's toolchain sync and warm-up no longer inherit yi's provider key variables (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `OPENROUTER_API_KEY`, `GEMINI_API_KEY`, `LAYA_API_KEY`), contained or not, so `printenv` in yolo mode or on a host without a sandbox prints none of them. `~/.yi/oauth` was already a credential store.
