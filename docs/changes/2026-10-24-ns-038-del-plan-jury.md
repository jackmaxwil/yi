This is DEL-plan-jury, with HD-D01-jury folded in. The plan judge tier had no author: no schema, prompt or recipe writes a `judge` item, and only the `done` path ever seated a jury. It is gone: `plan/judge.rs` (317 lines), `prompts/judge.md`, the verifier's `Judge` trait, `Seat` and `Snapshot.jury`, `with_judge`, the jury cap and its escalation, `SubagentHost::spawn_seated` and `Standing::Juror`, `family_of` and `other_families`, `fetch::as_served`, `Permit::purpose`, the done path's jury counter and juror tally, and the `plan.jury` and `plan.judge_cap` levers. yi-types loses `JUDGE_CAP_PER_TODO`, `JurorAnswer` and `Quote`, which only the jury read.

`start` now refuses a contract with a `judge` item. The refusal names the item and the deciders that run: "item taste: no judge runs a `judge` item; decide it with `cmd`, `schema` or `example`". Before, such an item started and then abstained "no judge" on every `done`. `Decider::Judge`, `JuryPolicy`, `JurorLine` and `ItemLine.jurors` stay, so a journal that already holds them still replays. A judge item an old journal started still abstains "no judge" and holds its todo. The golden is `crates/types/tests/fixtures/journals/plan-judge-verdict-v1.jsonl`, which the unfixed tree's own done path wrote with a one-juror jury sitting. It sits beside the other journal goldens because the session-file round trip reads every top-level `.jsonl` as a session.

The `plan.scatter_rounds` lever stays. It mirrors `SCATTER_MAX_ROUNDS` in `python/yi_runtime/src/yi/shapes.py`, which is live and has nothing to do with the jury. The unit's own decision already counts 45 -> 43, and that count leaves it in. Design sections edited: §3 (the capability table), §11 (child admission and standing) and §13.1 (contracts).
