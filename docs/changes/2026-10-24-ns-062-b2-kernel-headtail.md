This is Bet 2's kernel capture fix (unit B2-kernel-headtail). It revises D316's list of producers that cut with no file: a displayed value (`execute_result`) past the kernel's cut now spills like a stream.

The kernel's model-facing capture of a cell's stdout and stderr keeps its 65,536-char budget, but as the first 32,768 chars and the last 32,768 instead of the first 65,536. A chunk that lands exactly on the cap no longer stops the capture: every char is counted, so text after it is cut with a row instead of dropped with none. The held text is trimmed back to its two ends once it passes eight times the cap in bytes, so a long cell holds at most about 512 KiB per stream. A displayed value is capped the same way. Every cut writes one row between the two ends that names the chars kept, the total, `DEFAULT_MAX_OUTPUT_CHARS 65536`, and the full output file named below it.

The displayed value now reaches `CellSpill` through the kernel's uncapped `on_stream` hook under the name `execute_result`, so a value past the cap is kept whole in the cell's spill file and the cut names `[full output: path]`. The spill file holds the cell's whole output: its stdout, its stderr and its displayed value. A `%%bash` or `!cmd` cell's view, when it has no file to name, ends with any kernel cut row its own middle cut dropped, so the first cut stays named. The ipython tool description drops "a displayed value past that is cut with no file" and says the three keep their first and last halves.
