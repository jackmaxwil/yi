A cell can now call the session's own tools: `await yi.tools.read(path=...)`, `yi.tools.grep(...)`, `yi.tools.edit(patch=...)` and the rest (Refs #1242). Each call goes through the same adapter a model call does, so the user's rules, the wall and the permission check judge it on its own arguments, never covered by the cell's approval. It returns a `Result` whose `text` is the model's view, and a failure raises `UnknownTool`, `InvalidInput`, `Refused` or `ToolFailure`, so a program can tell a gate's refusal from a tool's failure. `ipython` itself (a nested cell would wait on its own kernel) and a root's `ask_user` (its answer ends the turn) are left out, and `yi.tools.excluded()` says why. Every call that ran is listed on its cell's `ipython` result by the files it named, never their content, so compaction's modified files and the todo landed count see a program's edits, even in a cell that raised afterwards. A call is answered only while the agent's cell runs: a background task that outlives the cell, a call made after an interrupt, or a cell typed into the console is refused. Gathered calls keep the loop's order, reads beside reads and a write alone, and a cell's rows stay bounded: past 1,024 writes they fold into one row per tool that still names every file.
