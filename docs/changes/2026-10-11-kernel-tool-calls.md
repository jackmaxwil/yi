A cell can now call the session's own tools: `await yi.tools.read(path=...)`, `yi.tools.grep(...)`, `yi.tools.edit(patch=...)` and the rest (Refs #1242). Each call goes through the same adapter a model call does, so the user's rules, the wall and the permission check judge it on its own arguments, never covered by the cell's approval. It returns a `Result` whose `text` is the model's view, and a failure raises `UnknownTool`, `InvalidInput`, `Refused` or `ToolFailure`, so a program can tell a gate's refusal from a tool's failure. `ipython` itself (a nested cell would wait on its own kernel) and a root's `ask_user` (its answer ends the turn) are left out, and `yi.tools.excluded()` says why. Every call that ran is listed on its cell's `ipython` result by the files it named, never their content, so compaction's modified files and the todo landed count see a program's edits, even in a cell that raised afterwards. A call is answered only from the agent's running cell: each call carries the execute request its cell ran as, which a task inherits, and only the request the agent's cell holds the kernel as is answered, so a background task that outlives its cell is refused even while a later cell runs, as are a call made after an interrupt and a cell typed into the console, even one running while the agent's cell waits for the kernel. Gathered calls keep the loop's order, reads beside reads and a write alone. A cell keeps one read row per tool and files, 256 of them, and every write row whole; reads past that are counted, and the compaction summary's read-files list says how many it could not name, that their paths were not kept, and which cells made them, through every later compaction. A call that finishes after its cell closed is marked outlived on a later cell's result, and the todo landed count does not credit it to that turn.
