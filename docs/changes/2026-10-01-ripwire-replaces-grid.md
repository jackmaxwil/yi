Ripwire replaces grid as the code map Yi reads (Closes #1018). Where a `ripwire` binary is on PATH, an edit ends with `[ripwire check]`: each changed definition's contract against HEAD, with the callers that still call the old one. Up to four changed regions are asked at once, and the fifth is named with the call that asks it. A region that has not answered in 3 s is named on its own row, the others are kept, and its run is left to finish, because a cold index took 8 to 18 s on Yi and killing it meant no edit was ever checked. Ripwire flags broken callers only in Python, TypeScript, JavaScript and Java; elsewhere the row lists the callers and says arity is not checked, where it had printed "0 incompatible" for callers a cut parameter broke. Outside git there is no HEAD to compare, and the row says so instead of reading clean. `get_context` takes a `task` and answers with ripwire's ranked signatures; a cut names `--token-budget`, the call that returns the rest, with the task quoted for the shell. Its `symbol` layer cuts a path to `name` or `Type::name`, lists twenty callers and callees a side with the cut named, says they are matched by name, and points a type with no calls at grep. A ripwire command whose root is a git URL is no longer read-only, since ripwire clones it. Grid's extension, seam, prompt card, bash allowlist, `grid_answer_empty` predicate, edge, and its behavior cassette are gone. Two ripwire behaviors stay outside Yi's reach: its index cache is about 50 MB per repository in `$TMPDIR/ripwire`, and with `markitdown` on PATH it runs it on each PDF or Office file it indexes.
