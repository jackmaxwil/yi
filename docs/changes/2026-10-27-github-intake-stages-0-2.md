GitHub intake stages 0 through 2 add real-producer fixtures, read-only dry-run decisions, strict signed checks, deterministic draft import and an offline real-git journey. The mirror rewrite now shares one helper with intake and retains its ephemeral commit map long enough to translate a mirror base. No schedule or contributor-code execution is enabled.

`yi ask --no-tools` installs an empty tool table, so the intake lens receives only the fenced diff and cannot read the repository or call tools. The draft import always carries `external` and `autofix:hold`, never `run-ci`, `live` or `autofix`. The network check refuses URLs, IPs (a clock such as `12:30:45` and a MAC such as `aa:bb:cc` are not addresses: one needs `::` or all eight groups), `localhost`, hostnames on common TLDs and any ported, `@`-led, scp or rsync destination or command-argument hostname; a bare hostname on a rarer TLD, quoted or not, and a host on `rs`, `md`, `py` or `sh` off the well-known ports pass it, because `row.id`, `"response.failed"` and `main.rs:4444` read the same, and are left to the lens and the review. A refusal names every line it refused and an override carries all of them, so one approved line cannot waive a hit the owner never saw. Build-time execution covers a `build.rs`, a manifest's `build` key or `[build-dependencies]` section, a `proc-macro` crate and the vendored tree, which is denied whole. The dependency check reads both sides of a delete, so removing `Cargo.lock` is a dependency edit. Dry-run follows the open PR list to its last page instead of stopping at the first hundred, and every workflow installs git-filter-repo from `scripts/mirror/filter-repo.version`, its single spelling. The real transport carries no branch, draft or comment writes yet: they land with the stage-3 hold, and the journey drives the import through an injected transport. Runner hardening, owner CI admission and landing feedback remain stages 3 and 4.
