A root's `ask_user` call now opens a question card in place of the composer. The card carries one question per page, as many as one turn asked (the guide advises four): a plain sentence, each option as a bold label with a one-line trade-off under it, a number key on the right edge, the first option marked recommended, an Other row that takes the person's own words, and `s` to skip. A question with no options is the answer field alone, already taking typing, and once answered a question leaves one tool row, the question with its option labels, in place of five rows cut by `… N more lines`. A highlighted option that carries a `preview` shows up to five lines of it under its trade-off, and a longer one says how many lines it kept and the cap. The last page's pick goes out as one user message, so the session ledger keeps the person's words; a skip tells the model to go with its recommendation and say so.

`ask_user` options are now `{label, description?, preview?}` (a bare string still reads), and the tool is registered for a root whether or not auto-review names a reviewer, which reverses the cut that demoted it when `annotate` entered. Its guide and one line of the doctrine's Planning paragraph tell the model to ask more in design talk (a brainstorm, a change plan, an architecture, target metrics and eval targets, a choice between looks), in rounds of up to four, after reading what a file already answers. The old doctrine sentence that proceeded on a default when unanswered now applies to unattended runs only; an attended question waits for the person.

Not built yet: markdown and highlighted-code rendering inside a preview, image previews with zoom, open-in-pane for an artifact, a card for a blocked todo's `Ask`, and the paired run on the target model that the context rules require before the doctrine counts as proven.
