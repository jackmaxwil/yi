A root's `ask_user` call now opens a question card above the composer. On a kitty-protocol terminal (kitty, Ghostty) the card's panel, option tiles, key badges, answer field and Skip and Next buttons are one image placed under its text at a negative z: rounded, anti-aliased, with a soft shadow, drawn in alpha over the terminal's own background so any theme shows through, while every glyph stays the terminal's text. Elsewhere the same layout reads as text. At 110 columns or wider an option's preview sits in a pane beside the tiles. A key repaints only the tiles it changed over a cached panel, and an idle wake lays nothing out. The card carries one question per page, as many as one turn asked (the guide advises four): a plain sentence, the question wrapped whole, each option as a bold label with a one-line trade-off under it, a number key on the right edge, the first option marked recommended, an Other row that takes the person's own words, `s` to skip, and Tab to fold the card to its question (the head's `⌄`, added with the image chrome when the owner asked for the reference card's look; Down moves the highlight). A question with no options is the answer field alone, already taking typing, and once answered a question leaves one tool row, the question with its option labels, in place of five rows cut by `… N more lines`. A highlighted option that carries a `preview` shows up to five lines of it under its trade-off, and a longer one says how many lines it kept and the cap. A card due while another view is up waits for that view to close, and in the console each pane keys its own card image. The last page's pick goes out as one user message, so the session ledger keeps the person's words; a skip tells the model to go with its recommendation and say so.

`ask_user` options are now `{label, description?, preview?}` (a bare string still reads), read by one function for both the result text and the card, so the number the model sees is the key the person presses, and the tool is registered for a root whether or not auto-review names a reviewer, which reverses the cut that demoted it when `annotate` entered. Its guide and one line of the doctrine's Planning paragraph tell the model to ask more in design talk (a brainstorm, a change plan, an architecture, target metrics and eval targets, a choice between looks), in rounds of up to four, after reading what a file already answers. The old doctrine sentence that proceeded on a default when unanswered now applies to unattended runs only, and the runtime holds it: on a root nobody attends, `ask_user` returns the default (or option 1) to act on and the run goes on; an attended question waits for the person. The dist binary measures 8,405,328 bytes, 16,512 over main's 8,388,816.

Not built yet: markdown and highlighted-code rendering inside a preview, image previews with zoom, open-in-pane for an artifact, a card for a blocked todo's `Ask`, and the paired run on the target model (GLM 5.3 flash) that #1381 owes, measuring whether design talk now asks before it writes up.
