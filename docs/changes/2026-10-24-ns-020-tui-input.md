A paste reaches the model as the person pasted it. The composer used to rewrite a paste before storing it, turning every tab into three spaces and dropping every other control character, so a tab-indented Makefile recipe or a terminal capture with colour escapes arrived as different text. It now keeps the bytes and only turns CR and CRLF line endings into LF; the box draws a tab as four spaces and a control as its one-cell picture, and wraps and moves the cursor by those widths. A paste while a question card, a popup or a tree is open goes to that view's text field (one line, whitespace runs become a space) instead of the composer hidden behind it; a card showing options has no field and swallows the paste, so a pasted `2` or `s` is never taken for the key that answers. The test that pinned the rewrite is replaced by one that pins the bytes.

Three inputs the TUI used to lose now say what happened. A second Enter before the first turn's `AgentStart` reached the screen met a busy session, and the bridge threw the refusal away; the text now steers the running turn, a notice says `a turn was already running · your message steers it`, and the prompt count the headless drive waits on is taken back, since no turn of its own will start for it. A line whose first word is `/word` is a command even when the word names none: `/plna` and `/pr` answer on the spot, the first with `unknown command: /plna · start the line with // to send it as a prompt`, and `//word` sends `/word` as a prompt; a path (`/usr/local/bin`) or a comment (`/*`) is no word and still prompts. Enter in the `/` popup on a name nothing matches now reaches the same notice instead of closing on a vanished line. A `keys` binding of two keystrokes (`ctrl-x ctrl-e`) parsed into a sequence nothing ever resolved; `KeyInput::Sequence` is gone and the config refuses the binding, naming it. Units HB-tui-paste and HB-tui-input.
