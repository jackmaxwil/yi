A paste reaches the model as the person pasted it. The composer used to rewrite a paste before storing it, turning every tab into three spaces and dropping every other control character, so a tab-indented Makefile recipe or a terminal capture with colour escapes arrived as different text. It now keeps the bytes and only turns CR and CRLF line endings into LF; the box draws a tab as four spaces and a control as its one-cell picture, and wraps and moves the cursor by those widths. A paste while a question card, a popup or a tree is open goes to that view's text field (one line: control characters dropped, whitespace runs become a space, ends trimmed) instead of the composer hidden behind it; a card showing options has no field and swallows the paste, so a pasted `2` or `s` is never taken for the key that answers. The test that pinned the rewrite is replaced by one that pins the bytes.

Three inputs the TUI used to lose now say what happened. A second Enter before the first turn's `AgentStart` reached the screen met a busy session, and the bridge threw the refusal away; the text now steers the running turn and a notice says `a turn was already running · your message steers it`. The headless drive keeps waiting on a prompt until a run has read its text, whether the loop injects it or, having missed the last boundary, the steer opens a turn of its own, so `wait-idle` neither walks on between the two runs nor counts a later prompt as begun. A line whose first word is `/word` is a command even when the word names none: `/plna` and `/pr` answer on the spot, the first with `unknown command: /plna · start the line with // to send it as a prompt`, and `//word` sends `/word` as a prompt, typed into the `/` popup as well as pasted; a path (`/usr/local/bin`) or a comment (`/*`) is no word and still prompts. Enter in the `/` popup on a name nothing matches now reaches the same notice instead of closing on a vanished line. A `keys` binding of two keystrokes (`ctrl-x ctrl-e`) parsed into a sequence nothing ever resolved; `KeyInput::Sequence` is gone and the config refuses the binding, naming it.

The TUI's tool tables now name the tools that exist. The glyph, card hue, orb state and turn-receipt tables listed `ls`, `glob`, `find`, `document`, `web_search` and `fetch`, none of which is registered, and left `todo`, `answer` and `get_context` to the generic gear and the fallback hue; they now give `todo` and `plan` a list mark and purple, `answer` and `ask_user` their own marks and blue, and `get_context` the read family's arrow and cyan. The summary line reads the arguments the schemas declare (`command`, `path`, `pattern`, `code`) and not `cmd`, `file_path`, `query`, `glob` or `url`, which no schema has, and the `i` intent a tool call might carry, which no schema declares either, is gone with the chain that carried it from the call to the card and the working line. A mail or human answer injected into the transcript lost every `<...>` in its body to a tag stripper meant for advisories, so a review comment on `Vec<String>` read `Vec, not &[String]`; the stripper now runs on advisories alone, and every displayed message drops a row that is only an opening or closing element, so the wrappers of a mail, a reaped child and a goal prompt go while a body's own `<...>` stays. Two new recorded sessions sit beside the old ones: `01a16f24.jsonl` (`yi ask --faux` over a three-file tree: a grep and an `answer`) and `01a16f6f.jsonl` (a read and an insert-after edit of a five-line file).

A finished call's digest is drawn from the typed `details` the result carries and from its text only where no detail exists. It parsed the model-facing text, so a grep recorded from the real tool, whose rows are `N:text` under a `[path#TAG]` header and not `path:N:text`, drew `0 hits` for six; it now draws `6 hits` from `details.hits`. A read's `N lines` comes from `shownLines` (or `dirs` plus `files` for a directory). An edit's `updated; first change at line N` is the tool's own number, which no detail carries (an insert after line 2 reports 2 where the patch's first changed row is 3), so it is the text's `updated`, `deleted` or `unchanged` row, found by its shape wherever the header above it wraps. Spreading a result's `[path#TAG]` header over two lines, as a token-saving rewording might, moves none of them. A result with no details, an older session's included, reads its text as before.

Dead TUI items are gone. The stream-finish repair flags, which render.rs wrote and nothing read, so the rebuild their comment promised never ran (a headless run that resizes mid-stream draws the same final frame before and after); the thinking glyph cycle, its two tables and the test that checked a table against itself; `name_accent_rgb`, `App::has_run`, `App::live_tool_status`, `App.exit_code`, which was never assigned and left `run_tui` returning 0, and `HudInput.follow_up`, which was always empty, so its "After yield" rows could not draw. `a_call_held_at_the_permission_gate_says_so` read the deleted accessor and now watches the live region draw the held call's `△` and lose it when the gate opens. The `insta` dev-dependency, which no test used, leaves both manifests, the design's dev-dependency line and `Cargo.lock`, which drops `insta`, `similar`, `tempfile`, `fastrand` and a second `rustix` and `linux-raw-sys`; with them `deny.toml`'s `windows-sys` skip, which matched only that second `rustix`, is gone too. The working label, orb state and tool-to-orb table move to `app/working.rs`, taking `app.rs` from 1,199 lines to 1,095. Kept, and named here: `markdown::work()`, the one instrument of `settled.rs`'s linear-streaming-cost test, which is a contract and not dead weight. Units HB-tui-paste, HB-tui-input, HB-tui-cleanup, HB-tui-digest and HD-X03-tui-dead.
