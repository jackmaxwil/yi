The fixer sorts a red gate lane, from the forge's job records alone, into the pull request's own or shared: red at the base's tip on a lane that names no tests (a red test lane goes to the gate path, which reruns the head's failing tests at the base), red on three open pull requests and on main within thirty minutes either side, or failed in a few-second sweep across workflows as the runner machine's nightly rollback does. For a shared red it pays no model and skips the two-hour wait: one comment, and one rerun after the lane has run green on another commit. A red main keeps one issue per lane, and a stacked pull request waits on its parent with one comment; that wait lasts while the base's lane is red, then the head reruns once, and a lane still red is fixed like any other. Every rerun posts its ledger row first, and a rerun the forge refuses hands the head to a person. The spend caps refuse only model calls and are checked against the price of the call about to be made; past the day cap one issue opens for the day. A pull request that changes the bots' own scripts or workflows is handed to a person, never fixed. A trial of choosing the model tier from the finding's own size sits behind the repo variable `FIXER_TIER_SPLIT`, off by default. The lines the two scripts lose are rewrites, not removed behaviour: the reruns moved into one function, the flake path's own rerun and wait went into it, and the queue's job-record lister now serves both bots.
