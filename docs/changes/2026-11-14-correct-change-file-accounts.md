Seven change files recorded an account that the code or the repository does not bear out. The rows the recorder wrote for them stay as history, and this is the correction.

Fixer guard removal (#2132). The account said a recorded `cut:` or `keep:` line covers the two incidents the guard existed for, the README install block cut in #2062 and the upstream pin cut in #1829. It does not. `check_intent.py` reads the register of change files landed on main at the fork point, so a cut that lives only in an unmerged branch is not in it, and in both incidents the owner's cut was inside the pull request the fixer then reversed. After this removal nothing stops an autofix push from putting back a cut the same pull request made. The removal also deleted `scripts/fixer_guard.py` although its own header says the land-fix script calls it before its push, and that script lives outside this repository, so it has to drop the call.

Reply status line (#2006). The recorded rule says the todo gate sends a plain-text `Done` back "once", apart from the ladder a structured `Done:` answer climbs. The shipped gate has one path: in `crates/runtime/src/todo/coupling.rs`, `says_done` is true for any non-JSON reply whose first word is Done, and both kinds go through `TurnCycle::intercept`, so a plain-text `Done` repeated over an unchanged blocked list is sent back until the send-back ladder tops out at `LADDER_TOP` (3), then let go. It is not sent back once. The same change file also says the guardrails lane reports `FAIL <cmd> (exit N, printed no FAIL line)` "only when the gate printed nothing at all". `named` in `scripts/guardrails/check_guardrails.sh` runs whenever a gate exits non-zero with no line starting `FAIL`, and prints the gate's output under the row, so a gate that printed only a traceback gets the row as well.

Private test TMPDIR (#2019). The account said the wrapper removes its directory "on exit, including on a kill". `scripts/test_tmp.sh` removes it on a normal exit and on TERM, INT and HUP, which it traps. A SIGKILL cannot be trapped and leaves the directory behind, as does a signal the script does not trap, such as QUIT. `scripts/test_tmp_test.py` proves the SIGTERM case only.

Streaming tool rows (#2045). The account said a finished card "grows one row at a time as the result streams in". Nothing streams a result into a card: `settle_tool` in `crates/tui/src/app/stream.rs` is the only place a card's preview is set, so no result row exists before the call finishes and the whole preview arrives in one step. The removed blank-row reservation is still gone for the reason given, no empty whitespace under a running call, and the card grows in one step when the result lands, the jump D516 reserved rows to avoid.

Binary size gate removal (#2051). The removed `check_binary_size.py` also failed the build when the dist binary embedded a build or checkout path (its `leaks` check, added because the kernel crate embedded its checkout path). That check is gone and nothing replaces it. `scripts/build_dist.sh` still passes `--remap-path-prefix`, but nothing reads the binary to prove the remap held.

Tool values in compaction summaries (#1876). Its Seen red block lists four tests that other, already-landed changes added: `a_kept_tail_over_the_ceiling_compacts_once_not_on_every_request`, `a_summary_quote_the_addressed_message_lacks_is_marked_unverified`, `a_span_stored_without_a_count_is_never_summed_as_zero` and `a_demoted_brief_names_what_was_kept_the_cap_and_the_read_that_restores_it`. It omits three tests the pull request did add: `an_edited_values_section_is_trusted_not_topped_up` (`crates/context/tests/primitives.rs`, the test for the trusted edited Values section), `a_summary_with_nothing_to_carry_is_left_alone` and `both_summary_prompts_ask_for_values_and_what_was_dropped`. No failure against the unfixed code was recorded for those three.

Tool result highlighting (#2165). The row recorded for it repeats half a sentence about a card that opens inside a string or a comment, a line that stops after "colours wrong at most until the next break" and then starts the next sentence over. The sentence is meant to appear once, in the form its change file now carries. The old row stays as history, and this row is the recorded correction.
