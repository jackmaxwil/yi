A walled session reads no session's transcript file but its own (amends D340 and D335; Closes #971). A juror walled by `deny_write` and `deny_url: history://` could still `read` and grep its author's transcript under `~/.yi/sessions`, which holds every tool output, file and turn the wall hides. A walled session now walls every session store, `~/.yi/sessions` and the `--session-dir` in use, the way #968 walls the spill root: the stores join its calls' `deny_read`, its own transcript file is spared at the read gate (`ReadGate::except` now takes a list) and re-allowed in a later Seatbelt rule (`Sandbox::spared` is a list), and every fetch scheme that serves a host file (`local://`, `checkpoint://`, `tree://`, `plan://`) judges by the reader's wall with the stores in it, a store inside the workspace included. A walled broker refuses outright a retry after a contained refusal in a protected dir, where an asker or the auto reviewer could have run it outside the sandbox (spills had the same hole since 0.524.0), and a refusal at or naming a path under the own walls is no longer remembered, so the own transcript is never refused after it. A child broker now keeps the `--session-dir` as host-owned, which `for_child` dropped. Reader children, always walled, lose transcript files too. An unwalled session reads as before, and the host-side readers (resume, `/sessions`, the compaction rescue) are not gated. Still open: `history://` serves any transcript to a walled session whose `deny_url` lacks it, and kernel cells and uncontained bash of a walled session read transcript files, as they read spills (#885).
