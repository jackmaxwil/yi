`yi ask --scope GLOB`, repeatable, confines a run's writes inside its working tree to the paths the globs name. Two Kimi fix passes on eval-only PRs (#1630, #1638) added runtime lock edits and a test in crates/runtime to turn a CI-red test green; the brief named what to touch and nothing held them to it. A write the scope does not name is denied in every mode, yolo included, and the result names the scope and the path. Judged: `write`, `edit` (every section and `MV` destination), `grep` with `apply`, and the unquoted redirects of a bash command, read as a shell reads them, so a `->` or `=>` in a heredoc body, a comment or a quoted string names no file. A path is named when it or a directory above it matches (`*` stops at a `/`, `**` does not), a link out of the scope is judged where it leads, and a path outside the working tree is left to the sandbox. The scope is a kept command rule that is never journaled, so a child inherits it, a walled one too, and `--continue` opens unscoped. A glob that is absolute, empty or malformed exits 2 before the model runs, and `--scope` on any verb but `ask` is refused. A run that ends on a scope refusal exits 4 like any headless denial. A redirect into scratch inside the tree, a log under `target/`, is judged like any write and wants a scope of its own.

Not judged: what a program writes (`sed -i`, `tee`, `cp`, `mv`, `rm`, a build, a kernel cell), a redirect inside quotes or built by expansion, and an absolute path in a lane child's own worktree, whose broker keeps its parent's tree. A redirect after a statically readable `cd` is judged from that directory; one after a dynamic `cd` is refused because its directory cannot be proven inside the brief. No `permissions.scope` key: a standing scope would confine every run, not the one a brief names.
