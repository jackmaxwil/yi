This is unit B2-jobs of Bet 2. A finished background job reached the model raw. Its `<async_result>` carried every byte of the capture, up to 30,000 B a stream, and reclaim never cuts that text. A poll of the job carried the same raw bytes. `JobReport::view` now runs the capture through `yi_tools::view` with the `Job` producer, and both the poll and the announcement print it, so the two bodies are byte for byte the same and the no-reannounce rule is untouched. A job keeps the recovery dir its call ran with, so a lossy view can point at a file. `JobReport::output` stays whole: a program's polled value and the kernel's job reply read it, not the view.

A cut capture used to print two notices for one cut: the `[capture cut: kept K of T bytes …; every byte: <file>]` row and then the `[full output: <file>]` pointer (#1048 item 5). It now prints one row, `[full output, kept K of T bytes (OUTPUT_CAP 30000 per stream), every byte: <file>]`. That row is the pointer the reducer is handed, so the view counts it against the ceiling and the selector still finds the file in it. A cut with no file still says `[capture cut: …; no file kept the rest]`. The program value's `cut` field carries the same one row.

A red `cargo test` of 2,000 cases, recorded for this unit from a real scratch crate (64,656 B), now reaches the model as its failing test, the `left`/`right` lines and the summary inside 16,384 B. A 258,672 B build whose one error is its last line keeps that error inline and names the one file holding every byte. The kill test is B2-view's corpus, which this unit does not change.
