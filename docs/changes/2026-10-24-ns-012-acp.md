The console's review pane gets its why chains again (HB-acp-why). The ACP worker listed its `_yi/` methods by hand and the list had lost `_yi/why`, so every review hunk's "why" answered `unknown method _yi/why` although its handler was written. Every `_yi/` method the control arms do not take now reaches the extension handler, which resolves the session per arm, so a method nothing handles still answers METHOD_NOT_FOUND whatever its params name. A long session resumes again (HB-acp-drops). Replay frames closed at 512 entries whatever their size, so 512 entries of 64 KiB tool output went out as one 35.6 MB frame, past the console's 32 MiB reader cap: the console dropped the link, re-dialed and was sent the same frame. A frame now also closes at 8 MiB serialized; an entry is never split. What a request carries that the agent does not read is named instead of dropped in silence: a prompt block other than text or a resource link leaves a `[…]` row in the prompt the model reads, and a non-empty `mcpServers` on `session/new` or `session/resume` gets a `[…]` row in the session's first notice. The daemon writes its workers' stderr to `<socket>.worker.log` instead of /dev/null. The replay code moved from crates/acp/src/lib.rs to crates/acp/src/replay.rs.
