A worker no longer keeps every session it has opened (Closes #1410). When a session finishes loading and more than eight are loaded, `resident::evict_idle` unloads the longest-idle one nothing pins: a turn running, prompts queued, a child running, a user cell running, or a kernel whose last snapshot is behind or left a name out (`KernelManager::unsaved`, from a new `lossy` flag set by each snapshot's skipped list). If every other session is pinned, the cap is exceeded and the worker says so on stderr. Before it unloads a session, the worker holds that session's schedule hub, so `shared::release` keeps its timer running with no lane. A job that comes due for it — a heartbeat, a clock wait, or its mailbox with an unread letter (`channel::unread`) — finds no lane, asks the process's `on_absent_lane` hook, and is deferred while the worker loads the session again; once it is back, `rearm_channels` makes its subscriptions due at once. A request naming an unloaded session loads it first, so `session/prompt` on one answers instead of "unknown session". A letter still waits in the session's mailbox and is read when it loads, as before; it never starts a turn on its own.
