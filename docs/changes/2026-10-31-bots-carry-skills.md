The review bot and the autofixer can read the owner's skills, which a job's HOME never held: asked to name its skills, a `yi ask` with the job's HOME and clone answered NONE. `just install-skills` now copies `.ruler/skills` beside `skills/yi` into `~/.yi/skills`, `review.yml` and `autofix.yml` run it from their main checkout, and `.ruler/skills` gains `ponytail`, `caveman`, `har-io` and `har-target` so that main holds them. When a change touches Rust, a lens or fixer prompt opens by making `har` and `har-api` its first two reads, and it lists the other HAR skills with the trigger the catalog's 60-character clip would cut. The prompts use absolute paths because a PR's `.yi/skills/har` shadows `yi://skills/har` in the bot's checkout. Refuters read no skill: they test whether a claim holds in the code. A round's or a fix's footer now says which skills it read, so a job that lost the install shows `skills read none`.
