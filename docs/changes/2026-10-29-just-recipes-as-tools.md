A justfile was the one cheap source of tools every repository already had, and reaching it cost a `bash` call the model had to spell from memory: `yi tool import just` now dumps the project's recipes with just's own `--dump --dump-format json` and writes one exec-tool wrapper per recipe into `~/.yi/tools`, the directory `session_tools` already scans. The schema is the recipe's real parameters — a default makes one optional, `*` and `+` become an array of strings — and the doc comment is the description, so the model reads the signature just enforces instead of guessing it.

A call reaches the recipe as an argv array built from the JSON the exec-tool contract hands the wrapper, never through a shell string; the argument carrying a space and a quote arrives as one element. A recipe is a `read` tool when its doc line is `yi: read` or its name opens with a read word, `yi: skip` and `[private]` leave a recipe out and are named in the run's output, and a recipe whose name is a built-in tool's is refused by that name before anything is written. Each wrapper's second line is a marker naming its justfile and recipe: a rerun reports `added`, `updated` and `unchanged`, deletes the wrappers it wrote for recipes the justfile dropped, and never deletes or overwrites a hand-written tool.

The wrapper is `/bin/sh` around a `python3` one-liner that maps the call's JSON to argv, so it needs `python3` on PATH and says so by name when it is missing; a machine with only `uv` still imports, and the wrapper's own `--schema` path needs nothing.
