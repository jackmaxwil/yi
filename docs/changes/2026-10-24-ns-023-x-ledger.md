Named kill tests now run against a built yi through one runner, evals/kill.py, under one spend ledger shared by every worktree at ~/Development/yi-runs/next-shape/ledger.jsonl. Each test is its own module under evals/kill/, so the units that own tests never edit a shared registry. A family starts only if the dollars spent, the open reserves, the reserves of earlier ladder steps not yet settled and its own reserve stay within $30. A family that cannot fit is written unrun with the dollars it needed, and `report` lists every test with its verdict or that figure. Every run goes through one budgeted ask. It gets a fresh HOME seeded with a clone of one prebuilt kernel venv, a fresh shared git clone as its cwd, and a Kimi access token without the refresh token, and the HOME and the clone are deleted once its row is written. The stream is killed live when its cost crosses what is left, and a run with an unpriced turn is charged its ceiling. An exhausted Kimi quota parks the Kimi runs until the window resets, and a reset past the test's deadline writes the run unrun with its estimated cost. The routes live in evals/kill/providers.json. `yi catalog refresh openrouter` confirmed z-ai/glm-5.3-flash, z-ai/glm-5.3, deepseek/deepseek-v4.1-flash and moonshotai/kimi-k3.1-pro on 2026-10-24. The OpenRouter Kimi route ships disabled, and the Kimi subscription route stays unconfirmed until the Kimi login's live checks name the K3.1 id.

`yi login <provider> --refresh <seconds>` refreshes through the native profile-aware OAuth flow and prints an access-token file with no refresh token, or refuses when the token cannot cover the requested lifetime. The kill runner shells out to it instead of keeping a second refresh grant and token-store writer.
