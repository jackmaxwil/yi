A compaction summary now carries the values that sat only in tool results. The summarizer prompt (both the first and the update form) asks for a `## Values` section of exact identifiers, paths, numbers, hashes and error strings, including values still visible in the kept tail, and a `## Dropped` section listing what the summary left out and where to read it back. After the summarizer replies, `yi_context::keep_values` checks the new summary: a reply with no `## Values` section at all gets the previous summary's rows back as one, up to `VALUES_CARRIED_CAP` rows, past which a `[… N of M earlier value rows carried (VALUES_CARRIED_CAP); the rest: …]` row names the cut and the `history://self` grep that reads the rest. A reply that has the section is trusted, so a corrected value replaces the old one. The stored session ledger is unchanged; a cut stays a view over it (`compaction_faux::a_second_compaction_keeps_the_values_the_first_recorded`, `primitives::a_summary_that_lost_its_values_section_gets_the_previous_rows_back`, `primitives::an_edited_values_section_is_trusted_not_topped_up`, `primitives::both_summary_prompts_ask_for_values_and_what_was_dropped`).
