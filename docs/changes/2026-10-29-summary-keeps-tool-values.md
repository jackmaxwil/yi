A compaction summary now carries the values that sat only in tool results. The summarizer prompt (both the first and the update form) asks for a `## Values` section of exact identifiers, paths, numbers, hashes and error strings, including values still visible in the kept tail, and a `## Dropped` section listing what the summary left out and where to read it back. After the summarizer replies, `yi_context::keep_values` checks Values and Dropped independently: a reply missing either section gets the previous summary's newest rows back, up to `VALUES_CARRIED_CAP` or `DROPPED_CARRIED_CAP`. A cut row at the point of the cut names the numeric cap and the `history://self` grep that reads the rest. A reply that has the section is trusted, so a corrected value replaces the old one. The stored session ledger is unchanged; a cut stays a view over it (`compaction_faux::a_second_compaction_keeps_the_values_the_first_recorded`, `primitives::a_summary_that_lost_its_values_section_gets_the_previous_rows_back`, `primitives::a_summary_that_lost_its_dropped_section_gets_the_previous_rows_back`, `primitives::carried_values_past_the_cap_say_how_many_were_left_out`, `primitives::carried_dropped_rows_past_the_cap_keep_the_newest_and_name_the_cut`).
