A compaction summary now carries the values that sat only in tool results. The summarizer prompt (both the first and the update form) asks for a `## Values` section of exact identifiers, paths, numbers, hashes and error strings, including values still visible in the kept tail, and a `## Dropped` section listing what the summary left out and where to read it back. After the summarizer replies, `yi_context::keep_values` checks the new summary against the previous one: every `## Values` row the previous summary had that the reply lost is appended under `## Values carried from the previous summary`, up to `VALUES_CARRIED_CAP` rows, past which a `[… N of M earlier value rows carried (VALUES_CARRIED_CAP); the rest: …]` row names the cut and the `history://self` grep that reads the rest. A summary of a summary can no longer lose an earlier value because the model forgot it. The stored session ledger is unchanged; a cut stays a view over it (`compaction_faux::a_second_compaction_keeps_the_values_the_first_recorded`, `primitives::a_summary_of_a_summary_keeps_the_values_the_model_dropped`).
