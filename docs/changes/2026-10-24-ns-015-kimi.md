Yi reads the Kimi account's own model list (units K-kimi-catalog, K-kimi-wire, K-kimi-quota and K-kimi-login, stacked on ns-004's device-code login). `yi catalog refresh kimi` fetches `GET <api_base>/models`, where `api_base` comes from the `kimi` login profile, and writes `~/.yi/catalog/kimi.json`: each entry becomes a `kimi/<id>` model with its display name, its context window from `limit.context`, a completion cap from `limit.output` or the window, its input kinds, and its thinking ladder from `reasoning.type` and `reasoning.effort.valid` (an `only` model cannot turn thinking off, a `none` or absent object does not think). The `protocol` field picks the wire. An entry with no positive `limit.context` or an unknown protocol is kept in the file as its reason, which `yi doctor` names. Cost is zero, since the account is a subscription. Without a login the refresh row reads `kimi no credential (yi login kimi)` and the run stays green, as Cursor's does. On a Moonshot route (a host under kimi.com, kimi.ai or moonshot.ai, or the `kimi` provider) the chat request carries effort as `thinking: {type: enabled, effort}`, `{type: enabled}` for a model with no effort list, or `{type: disabled}` when effort is off and the model can stop thinking, never `reasoning_effort`; it sends the session id as `prompt_cache_key` and replays `reasoning_content` on every assistant turn of a thinking model, empty where the turn had none. Usage is read from `choices[0].usage` when a chunk has no top-level usage, which is where Moonshot puts it. An anthropic-protocol Kimi model posts to `/v1/messages?beta=true`. Every agent Yi builds for a provider, a catalog read or a login now sends `User-Agent: yi/<version>` instead of ureq's; a profile's `stream_headers` can still replace it, and Yi sends no `X-Msh-*` header. A 429 whose body names an exhausted quota or balance, by Moonshot's `exceeded_current_quota_error` or OpenAI's `insufficient_quota` code or by billing wording such as "check your account balance" (a bare "quota", which a per-minute throttle also says, never matches), now ends the request at once as `HTTP 429 quota exhausted: <body>` instead of being retried inside the 300 s wall; a throttling 429 still retries. `yi catalog usage kimi` prints the account's usage windows from `GET <api_base>/usages` as one JSON line, `{"5h": {"used": 0.3, "reset": "…"}, "7d": …, "month_total": …, "month_code": …}`, leaving out a window the account does not report; without a login it exits 1 naming `yi login kimi`.
