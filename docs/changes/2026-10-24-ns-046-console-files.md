The console editor now saves a file the way it found it (E-uifile-write). A save wrote a temp file with default permissions and renamed it over the path, so a saved script lost its execute bit, a link became a regular file and left its target unedited, CRLF came back LF, a file without a final newline gained one, and an empty file became one newline, while the status said `CRLF written as LF` even for an LF file. A save now writes beside the link's target with the target's mode, and writes back the line endings and the final-newline state read at open, so a save that changed nothing is byte-identical (YI_DESIGN.md §17.4); a reload takes the fresh file's endings, a file empty at its save gains a final newline once typed into, and a file mixing endings saves with the one most of its lines use. The solo composer's external-editor draft was `yi-compose-<pid>.md` in the temp directory, readable by other users, and a link planted at that name was written through; it is now a new file of mode 0600 under a name that carries the pid and a per-call random salt. The temp-and-rename stays local to the console: yi-console never depends on yi-tools, whose gated write is the shared replace #831 tracks. The palette's `e`, `md` and `diff` now open a relative path in the focused chat's working directory (E-uifile-workdir): they joined it to the root the console was started in, so a session working in a lane worktree had its editor open the main checkout's copy of the file the agent was editing, and the agent's patch, which names the lane's file, never refreshed it. The terminal pane already chose the chat's working directory, then the session's root; both now ask the one `session_dir`, and a path starting `~/` expands from the HOME the console was started with. An editor or viewer opened this way replaces the chat pane's content, so it keeps the directory its path was resolved in, and the next relative path from that pane resolves there too; a Review pane resolves through its session. The Review pane and the `md` and `diff` viewers now open at their top (E-uilife-viewer-top). A pane's offset counts rows from the bottom and they opened at 0, so a Review taller than its pane opened on the tail of its last patch, with the file list, the `▸` selection and the key hint above the window, and a README opened on its last page. They now open at `usize::MAX`, which the window reads as the top and keeps there while the rows grow, as Inspect already relied on; a scroll down from there counts from the top, so the first one moves the view. The window function moved from render.rs to panes.rs beside the pane renderers. The console's markdown, diff and Review panes now keep their rows (E-uiperf-panes). Every frame re-ran the markdown renderer, the diff renderer with syntax colour for up to 10,000 rows, and the Review view, which opens beside the chat on the first tracked edit, so it was redrawn on every event batch of a streaming turn; only the Notebook kept its rows. Measured before the change on the largest Review this repository's history gives, eight files and 2.3 MB of `git diff` (the session diff's cap is 4 MiB), one frame took 2.04 s in a debug build and 4.32 s in the dist profile (min of 5: fifty frames outran the test's 60 s), against the 2 ms the kill test set; with the rows kept, a frame took 20 µs in debug. Each viewer variant now holds the rows it drew and the key they were drawn under: the width for markdown and diff, whose source never changes after open, and for Review the width, scope, note and the session diff's revision, which `diff_mut`, the one way the console writes a session's diff, moves on every write; the Notebook's existing cache goes through the same helper. The console editor now draws tabs and maps columns by what it draws (E-uifile-tabs). The editor handed raw lines to the buffer, which keeps no tab as a column, so a Makefile's recipes and Go drew flush-left, and a click mapped a tab, and a wide character, to one column, landing left of the character under it. A tab now runs to the next four-column stop in the drawn row, and the click and the cursor cell map columns both ways by display width. The editor's cursor jump takes a u16 row, so a file over 65,535 lines is now refused at open by name, beside the 8 MB limit, where a find or click below that row landed on it. A find that wrapped never came back to the start of the cursor's own line, so a match there read `no match`; the wrap now ends on that line. The editor's view moved from render.rs to editor_view.rs. Units E-uifile-write, E-uifile-workdir, E-uilife-viewer-top, E-uiperf-panes and E-uifile-tabs.
