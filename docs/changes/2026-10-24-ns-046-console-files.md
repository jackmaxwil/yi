The console editor now saves a file the way it found it (E-uifile-write). A save wrote a temp file with default permissions and renamed it over the path, so a saved script lost its execute bit, a link became a regular file and left its target unedited, CRLF came back LF, a file without a final newline gained one, and an empty file became one newline, while the status said `CRLF written as LF` even for an LF file. A save now writes beside the link's target with the target's mode, and writes back the line endings and the final-newline state read at open, so a save that changed nothing is byte-identical (YI_DESIGN.md §17.4). The solo composer's external-editor draft was `yi-compose-<pid>.md` in the temp directory, readable by other users, and a link planted at that name was written through; it is now a new file of mode 0600 under a name that carries the pid and a per-call random salt. The temp-and-rename stays local to the console: yi-console never depends on yi-tools, whose gated write is the shared replace #831 tracks. The palette's `e`, `md` and `diff` now open a relative path in the focused chat's working directory (E-uifile-workdir): they joined it to the root the console was started in, so a session working in a lane worktree had its editor open the main checkout's copy of the file the agent was editing, and the agent's patch, which names the lane's file, never refreshed it. The terminal pane already chose the chat's working directory, then the session's root; both now ask the one `session_dir`, and a path starting `~/` expands from the HOME the console was started with.
