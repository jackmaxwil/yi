A console no longer leaves a worker blocked on an approval nobody can answer (HB-console-life). A permission ask lived only in the chat of the pane it landed in, so closing that pane, or quitting the console, dropped it and the session stayed at `?` until the daemon was stopped. Closing the pane and quitting now answer each ask they hold, in a pane, in a parked chat or still waiting for a pane, as `cancelled`, which the worker takes as a refusal, so its turn ends (YI_DESIGN.md §17.2). Every request the console makes now checks the link first: with the daemon gone an abort keypress shows `not connected — session/cancel not sent` at once, where it was queued behind a dead writer and its pending entry was cleared by the next disconnect, so it never said anything. A paste into the palette, which opens on `e ` for a file, now lands in its query with control characters dropped, and the banner that says the console is not connected clears when the link comes up. A resumed session now fills the Notebook and Review (HB-console-replay-scopes, YI_DESIGN.md §17.4). The worker's `_yi/replay` entries already carried every tool call and result whole, but only live frames fed the two panes, so a console started after the work ran showed `no kernel cells yet` and an empty Review. The replay's calls and results now go through the same absorbers as live tool-call frames: the kernel cells, with a stored plot, and the edits and reads, with one `_yi/tracked` request for all the edited paths. A replay from entry 0 is the branch as it now stands, so it starts the Notebook over and counts the turns itself, one per message its requester typed, the rule the TUI's replay reads, so a notice the host wrote mid-turn opens no turn: a reconnect's second replay renumbers no cell, even past the 50 the pane keeps, and Review's Turn scope lists only the edits of the last prompt, each replayed edit without a todo label because a replay cannot know which todo was running. A host message that wakes an idle session, a job report or a mail, opens a live turn the replay does not count, because its stored entry reads the same as one the running turn took after an answer, so after a reconnect that turn's edits sit in the previous prompt's Turn scope. A replay is history, so it opens no pane by itself: the Review and Notebook panes still open on the first live edit or kernel call, and on ⌘⇧R and ⌘I. Units HB-console-life and HB-console-replay-scopes.
