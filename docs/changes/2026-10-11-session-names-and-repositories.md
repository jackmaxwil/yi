`history://` now reaches every session you have on this machine, not only this repository's (Closes #1244). A root session reads by its id in any repository, or by its name, case aside and with spaces read as dashes: `history://forge-root/tail/40` finds the session named `forge-root`, this repository's first, then another's. A child reads as `history://forge-root/worker-3`, found through the spawn record its root keeps. A name several sessions share is refused listing up to eight `history://<id>` addresses with their repositories. A wall is judged against the session a read or a grep opens by every name it has, its id and its name (lowercase as an address resolves it, and as typed) as well as the address as written, and a reader under a history wall resolves no name or `root/child` at all and is told why. An id matches a session's file name exactly, so no spelling of its path stands for it. A child is found through its root's spawn record only while the record's path stays below the root's directory. Names are looked up only after every id along the address misses, in one pass over the sessions per read, and a lookup writes nothing into another session's directory. Session search stays this repository's. A session header whose directory was spelled through a symlink (`/var` for `/private/var`) is now recognized as this repository's.
