A turn now ends with an `answer` tool call (Closes #1398). The model passes the whole answer as `text` and a one-line `summary`; the stop checks that used to run after a reply was shown (open todos, a number no tool printed, an unfinished plan step) run first. A refusal comes back as the tool's result with the draft held in a file under the spill dir, shown the way `read` prints it, so the model fixes the work, patches the draft with the ordinary `edit` tool and calls `answer` with only `summary`. An accepted answer is appended as the model's own message, so `yi ask`, a parent reading its child and every client see an ordinary final reply, and the turn ends: a host note queued after it is dropped instead of reopening the turn, while typed input, a task, mail and child news still start the next one. A model that ends on plain text is judged once; a refusal sends one note asking for `answer`, the next stop ends the turn, and a reply that passes once the work is done stands without being printed again. An `answer` called on the deadline's or the turn cap's last word is still the answer, unless the reply was cut at the length limit. Input the user types while the turn runs survives the answer and opens the next turn. The appended answer reports its usage as unknown, so the next context estimate is not read as empty. The doctrine tells the model to report through `answer`, and the refusal texts no longer assume the reply is already on screen.
