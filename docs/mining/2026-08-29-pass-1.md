## 8. Proposals

Ranked by the outcome ladder: **eval case > tool/affordance TODOS row >
doctrine/prompt edit > fitted constant > trigger rule.** Nothing here is

### Rung 1 — eval case

**E1 · `RLMSubagent` has no `.name`, `RLMSpawnHandle` does.**
Cluster `076dc628ba79`, n=2 across 2 sessions (2026-08-28..29), both `pivot`.
Backtest of the exact strings fires **2 times in 2 of 10 substantive sessions**:

```
AttributeError: 'RLMSubagent' object has no attribute 'name'      01a04771 seq=16
AttributeError: 'coroutine' object has no attribute 'session_dir' 01a04c94 seq=35
```

Confirmed in the tree, not inferred: `python/yi_runtime/src/rlm/__init__.py`
declares `RLMSpawnHandle{rlm_child_id, name, session_dir, model, next}` and
`RLMSubagent{rlm_child_id, active_session_id, session_id, session_name,
session_dir, status}`. `spawn()` hands back the first, `list_subagents()` the
second, and the same concept is called `name` on one and `session_name` on the
other. `.status` on the same object works — the model's second cell proves it.
Smallest change that would have prevented it: one identity field name shared by
both dataclasses. Lands as a behavior cassette asserting `list_subagents()[0]`
exposes the same identity attribute a spawn handle does, seen red first.

*Not covered by the two cassettes a sibling session has in the tree*
(`mined-0001` is the un-awaited-coroutine repr; `mined-0002` is read-on-a-
directory). Neither mentions `RLMSubagent` or `list_subagents`.

### Rung 2 — tool/affordance rows (extractor defects)

All four are in the skill's *deterministic* column: they are wrong code, not
judgement calls, and each blocks a plan row that is already open.

**X1 · orientation misclassifies bash and ipython as mutations. Blocks P13.**
`extract.py:30 READ_ONLY_TOOLS = {read, glob, grep}`. 65 of 67 bash calls in the
corpus mutate nothing; all 67 currently end orientation. Consequence:
`orientation.callsBeforeFirstMutation` is 0 for 6 of the 9 sessions that reached
a mutation, the trace is empty for 7 of 10, and `mu.readRatio` reads 0.0 for a
session whose 8 calls were all read-only ipython. P13's "which layers earn their
bytes is fitted from orientation mining" cannot start from this table.
The fix is a third use of one existing vocabulary rather than a new one:
`read_only_command`/`READ_ONLY_VERBS`/`READ_ONLY_GIT` in
`crates/tools/src/builtins.rs:323-372` already classify a bash command, and the
permission layer is its second consumer. Port those two lists into the extractor
and screen `bash` arguments with them.

**X2 · `mu.model` and `mu.provider` are null in all 364 rows.**
`extract.py:288-289` reads them from the header; a v4 header carries exactly
`{kind, version, id, createdAt, cwd}` and nothing else. The values live on every
assistant message (`message.model`, `message.provider`) — that is how §3's model
table above was produced, outside the extractor. Consequence: no metric in
`mu.jsonl` can be sliced by model, which is what an eval-ledger config
fingerprint and a D72 route→effort map both need. Fix: take the model from the
first assistant message, and record a set when a session switched mid-run.

**X3 · `type:"usage"` records are counted and dropped.**
34 rows, every one `cause:"child_usage_attributed"`, in 2 session files:
104 485 input / 17 896 output / 823 040 cacheRead / 1686 reasoning tokens and
$0.0247. `extract_session` only reads usage off assistant messages, so all child
spend is invisible: the corpus reports $0.0878 where $0.1125 was spent. This is
precisely §4-E's "child tokens/pass per delegated unit" and the numerator of the
delegation-overhead multiple. Fix: fold `type:"usage"` entries into the μ row as
a separate `childTokens` block — separate, so the parent/child split survives.

**X4 · `ext_record` route telemetry has no store.**
104 rows (`route` 34, `cache` 34, `turn` 34, `orchestrate_attached` 2). The
runtime already writes exactly the P4 feature vector
(`{route, words, repo_dirty, named_paths}`); mining counts the `customType` and
throws the payload away. Fix: a fifth derived store, `route.jsonl`, one row per
`ext_record`. It is the cheapest item on this list and it is the one that turns
P4 from "unmeasured" into "measured and blocked on corpus shape" (§6).

**X5 · the report's denominators are the file count, not the work count.**
`wins: 329/364` and `orientation: 9/364` are both dominated by 316 single-turn
faux runs. Fix: the coverage line grows one clause — `N of M sessions carried a
tool call` — and the win/orientation lines quote that denominator. Two lines in
`report()`; it is the difference between a 90% win rate and a 40% one.
